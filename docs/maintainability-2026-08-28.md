# 保守性の点検（2026-08-28、v0.5.0 時点）

`origin/main` = `3f2affe`（v0.5.0）に対して測った。

**起点は t2y 氏の指摘である。** 2026-08-11 に issue #2〜#17 の 16 件を受けた。すべて Rust の
作法についてで、「動くか」ではなく「その言語の書き方になっているか」を見ている——
`Buffer::pop()` が `bool` を返す、`arith::finite()` が述語に見えて関門、`polar::to_polar` は
`From` にすべき、`CalcError`/`CalcResult` のクレート名重複、`complex/` の分割が「種類」単位。
**15 件クローズ、#4 だけ open。**

この点検の問いは 2 つ。**Rust 側はあれが定着したか。** そして **TS と Python にも同じ目を
向けたらどうか。**

### 指摘

**R-3【価値 高 / コスト S・1 行】wasm に panic 禁止が無い**

```
crates/calcarc-core/src/lib.rs:5   deny(clippy::unwrap_used, clippy::expect_used)  在り
crates/calcarc-wasm/src/lib.rs                                                     無し
```

**panic が JavaScript の例外になるのは wasm 側である。** base-spec §27 の
「WASM 境界は JavaScript 例外を投げない」を実際に破れるのはこちらなのに、
コンパイラが見張っているのは core だけ。いま違反 0 件なので、1 行足せば即日緑になる。

**R-1【価値 中 / コスト S】`bool` を返す可謬な mutator が 2 つ**

```
engine/state.rs:317  pub fn toggle_exponent_sign(&mut self) -> bool         2026-08-13
engine/state.rs:307  pub fn push_sexagesimal_separator(&mut self) -> bool   2026-08-16
```

#9（`pop()` が `bool` を返す）と同じ型。std の `Vec::push` は `()` を返し失敗しない。
「押せたら true」は `push` という名前が偽っている契約で、`api-style.md:9` の
「名前の嘘」の定義に当たる。**`#[must_use]` は crate 全体で 0 件**なので戻り値は黙って
捨てられる。呼び出し側は 1 か所。

**R-2【価値 中 / コスト S】`convert::convert` のスタッター**

`api-style.md:30` が「スタッター: `module::module()` の形を避ける」と書いた**後に**足された。
wasm 側は実際に困っていて `convert as convert_core` で回避している。
**規約に例外条項が無い**ので、例外を書き足すか改名するかが要る。
**放置すると規約のほうが嘘になる。**

## Issue #4 について

**唯一 open だが、予言された負債は積まれていない。**

issue の要求は「`ln` / `log10` / `exp` / `x^y` / `asin` / `acos` / `atan` の実装**前に**
主値の取り方・分枝切断の位置・切断上の符号を決めろ」だった。**S-1（2026-08-16 の裁定）が
「関数は実数に閉じる」を決め**、issue が「唯一の実装済み多価」と名指した `sqrt` の複素経路
（`sqrt(-4)=j2`）まで**逆に倒して DomainError 化**している。要求より強い決定である。

| t2y 氏の懸念 | いま |
|---|---|
| `asin(2)` が妥当に見える値を返し、打ち間違いが黙って通る | `engine_table.rs:316` に `assert_eq!(main_of(&["2","asin"]), "Math ERROR")`——**名指しされた入力が仕様書テストに載っている** |
| `ln(-1)` が近づく向きで `±jπ` に割れる | 定義域 `x>0` で DomainError。分枝の問題ごと消滅 |
| `(-8)^(1/3)` が `1+j1.73` になる | DomainError。`-2` も返さない——「答えず断る」を選び、規約として両実装に明記 |

`CalcError` は 4 分類から **5 分類**になり、`DomainError` が実在する。
規則は `docs/numerical-policy.md` の「関数の定義域」節に、裁定日つきで記録済み。

**残るのは 1 件だけ** — `is_tan_pole()` が複素数引数に常に `false` を返し、複素 `tan` が
極の近くで `TrigPole` にならず巨大値を返す。**挙動は現存、仕様化は未了。**
所在は `docs/superpowers/plans/2026-08-16-release-0-2-0-publish.md:1140` と
`docs/superpowers/specs/2026-08-16-release-0-2-0-design.md:43`。

**処方**: #4 は close できる。close 文で上記 4 点を指す。
**残件は新しい issue に切る**——plan と spec は「済んだ作業の文書」であり、
**閉じる主体の居ない台帳**である。外部の指摘者や将来の読者が宿題を探す場所は open issue しかない。

仕様化（「複素は極判定をしない」と明記＋テスト 1 本）は **S**。
挙動を変える（複素でも極検出）は **M で価値低**（盤面からの到達性が低い）。
