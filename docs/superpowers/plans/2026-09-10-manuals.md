## T1 撮影の台本と README の写真（**T2 と並行**）

- **台本**: `web/tests/shots/shots.ts` が `SHOTS` を持つ——1 枚は
  `{ name, hash, keys?, use: "readme" | "manual" }`。**T2・T4 はこの形に合わせる**
- **撮る道具**: 別の Playwright 設定 `web/playwright.shots.config.ts`（`testDir: ./tests/shots`、
  `webServer` はいまの E2E と同じ——ポート 4179）。`pnpm shots` で回す
- **書体を固定する**（設計書 §3、裁定 #6）: `@fontsource/noto-sans-jp` を画面に当ててから撮る。
  **当たったことを確かめてから撮る**（`document.fonts.check`）
- **README の 3 枚を撮り直す**（裁定 #5）: `docs/images/{scientific,data-scale,finance}.png`。
  **フッタ（版数）は写さない**（設計書 §1）
- **古くなったら気づく番人**: 撮るときに画面の文字（`textContent`）を
  `docs/images/<名前>.txt` に書く。**E2E（`web/tests/e2e/readme-images.spec.ts`）が
  今の画面の文字と突き合わせる。** 文字を取る関数は撮る側と E2E で 1 つを共有する
- **README が載せる写真がすべて台本に在り、`.txt` が在る**ことを単体テストで見る

## T2 PDF を作る道具と、キー名の番人（**T1 と並行**）

- **純関数**（`web/scripts/manual/`）: Markdown → HTML（`marked`）、`【…】` と `shot:名前` の抜き出し
- **CLI**: `docs/manual/*.md` を HTML にして Chromium の `page.pdf()` で PDF にする。
  出力は `web/manual-dist/`（追跡しない）。**マニュアルが 1 冊も無ければ落ちる**
  （作らずに緑、を作らない）
- **キー名の番人**（設計書 §6）: `【…】` は、画面のラベルの定義元（`web/src/ui/Keypad/*.ts`、
  `web/src/ui/Finance/FinancePanel.tsx`）から集めたラベルのどれかと一致すること
  （2 行のラベルは改行を除く）。**本文がまだ無いので、検出器は試験用の Markdown で確かめる。**
  集めたラベルの件数に下限を置く（集め損ねて空になった集合で緑にしない）
- **`shot:` の番人は T4 で**（T1 の台本が要る）

## T3 CI とリリースへの配線（**T4 のあと**）

- `ci.yml` に PDF を作るジョブ（普段の CI。どこにも付けない）。時間制限は実測から表の規則で
- `release.yml`: `Manuals`（`needs: deploy`）→ `Evidence`（`needs: [deploy, manuals]`、
  `Manuals` が落ちても `Deploy` が成功なら走る）。**`tools/release-evidence.mjs` は `Manuals` だけを
  例外にし、「マニュアル: 作れなかった」と書いて続ける**（設計書 §5）
- 番人: `release-workflow.test.ts` の流儀で、並びと例外が 1 つだけであることを固定する
  （既存の「always() の意味を分ける」番人と両立させる）

## T4 本文（**章立ての承認待ち**）

- マニュアル用の撮影を台本に足す。`shot:` の番人（双方向）と、`【…】`・`shot:` の件数の下限
