## T1 撮影の台本と README の写真（**T2 と並行**）

- **台本**: `web/tests/shots/shots.ts` が `SHOTS` を持つ——1 枚は
  `{ name, hash, keys?, use: "readme" | "manual" }`。**T2・T4 はこの形に合わせる**
- **撮る道具**: 別の Playwright 設定 `web/playwright.shots.config.ts`（`testDir: ./tests/shots`、
  `webServer` はいまの E2E と同じ——ポート 4179）。`pnpm shots` で回す
- **書体を固定する**（設計書 §3、裁定 #6）: `@fontsource/noto-sans-jp` を画面に当ててから撮る。
  **当たったことを確かめてから撮る**（`document.fonts.check`）
- **README の 3 枚を撮り直す**（裁定 #5）: `docs/images/{scientific,data-scale,finance}.png`。
  **フッタ（版数）は写さない**（設計書 §1）
- **古くなったら気づく番人**: 撮るときに画面の文字（`textContent`）を
  `docs/images/<名前>.txt` に書く。**E2E（`web/tests/e2e/readme-images.spec.ts`）が
  今の画面の文字と突き合わせる。** 文字を取る関数は撮る側と E2E で 1 つを共有する
- **README が載せる写真がすべて台本に在り、`.txt` が在る**ことを単体テストで見る

## T2 PDF を作る道具と、キー名の番人（**T1 と並行**）

- **純関数**（`web/scripts/manual/`）: Markdown → HTML（`marked`）、`【…】` と `shot:名前` の抜き出し
- **CLI**: `docs/manual/*.md` を HTML にして Chromium の `page.pdf()` で PDF にする。
  出力は `web/manual-dist/`（追跡しない）。**マニュアルが 1 冊も無ければ落ちる**
  （作らずに緑、を作らない）
- **キー名の番人**（設計書 §6）: `【…】` は、画面のラベルの定義元（`web/src/ui/Keypad/*.ts`、
  `web/src/ui/Finance/FinancePanel.tsx`）から集めたラベルのどれかと一致すること
  （2 行のラベルは改行を除く）。**本文がまだ無いので、検出器は試験用の Markdown で確かめる。**
  集めたラベルの件数に下限を置く（集め損ねて空になった集合で緑にしない）
- **`shot:` の番人は T4 で**（T1 の台本が要る）

## T3 CI とリリースへの配線（**T4 のあと**）——**済み（2026-09-11）**

- `ci.yml` に PDF を作るジョブ（普段の CI。どこにも付けない）。時間制限は実測から表の規則で
- `release.yml`: `Manuals`（`needs: deploy`）→ `Evidence`（`needs: [deploy, manuals]`、
  `Manuals` が落ちても `Deploy` が成功なら走る）。**`tools/release-evidence.mjs` は `Manuals` だけを
  例外にし、「マニュアル: 作れなかった」と書いて続ける**（設計書 §5）
- 番人: `release-workflow.test.ts` の流儀で、並びと例外が 1 つだけであることを固定する
  （既存の「always() の意味を分ける」番人と両立させる）

**作ったもの**:

- **手順は `web/package.json` の `pnpm manuals` の 1 行**（`pnpm shots --grep @manual` →
  `pnpm manual --shots manual-shots`）。撮影の台本の `use` を Playwright の札
  （`@readme` / `@manual`）にして、CI ではマニュアルの写真だけを撮る
- `ci.yml` の `manuals`（`name: Manuals`、`needs: wasm`）: checkout → setup-web →
  `wasm-pkg` → Chromium → `pnpm manuals`。上げる物は無い
- `release.yml` の `manuals`（`name: Manuals`、`needs: deploy`）: 同じ段 + PDF を
  artifact `manuals` に上げる（`if-no-files-found: error`）。wasm は同じ走行の
  `CI` が上げた `wasm-pkg` を取る
- `evidence`: `needs: [deploy, manuals]`、
  `if: ${{ !cancelled() && needs.deploy.result == 'success' }}`。PDF は
  `needs.manuals.result == 'success'` のときだけ `evidence/` に取る
- `tools/release-evidence.mjs`: `MANUALS_JOB = "Manuals"`（`release.yml` 自身のジョブなので
  `A / B` の形にならない。同じ走行の `CI / Manuals` は例外に入らない）と
  `MAY_FAIL = [MANUALS_JOB]`。落ちたら「**マニュアル（PDF）は作れなかった**」、成功して PDF が
  無ければ「作ったが、添付されていない」、在れば冊数と名前
- 時間制限は両方 25 分——実績が無いので `End-to-end` から借りた（理由は各ファイル）
- **書体（T4 からの持ち越し）**: 3 冊で `ʸ` `ˣ` `π` `▸` を端末の書体が描いていた。
  `@fontsource/arimo` と `@fontsource/noto-sans-symbols-2`（どちらも 5.3.0、2026-07-19 公開）を
  足し、**固定した書体の外で描かれた字が 1 つでもあれば PDF を作らずに落ちる**ようにした
  （設計書 §4 の追記）。写真は本文の書体の要素に同じ規則、表示部は和文だけ（§3 の追記）
- 番人: `release-workflow.test.ts`（並び・条件・名前・例外 1 つ・2 つの `Manuals` の段の一致）、
  `release-evidence.test.ts`、`webkit-gate.test.ts`（撮影の設定が project を持たず Chromium だけ）、
  `web/tests/unit/manual-fonts.test.ts`（書体の並び・厳密な版・判定の純関数）
- **Actions の実走では 1 度も確かめていない**（PR の CI が普段の `Manuals` の最初の走行、
  次のタグが `release.yml` の最初の走行になる）
