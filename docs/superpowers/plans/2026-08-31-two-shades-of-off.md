## 段 A: 型を通す

### Task 1: 表を**導出**する（測らない）

**やること**: `isDeadOperator` ∪ `token === null` から、**盤面ごとの永久／一時の表**を
機械的に出す。**打鍵しない。**

```
永久 = token === null
     ∪ DEAD_OPERATOR_TOKENS（lparen rparen div mul sub add eq）
       ただし isDeadOperator を呼ぶ 3 盤面（DataScale / Transfer / LLM）でのみ
一時 = それ以外の keyDisabled の true
```

**★ 打鍵は検算に回す。** **導出が「一時」と言ったキーが、実際に生き返る操作を
1 つ見つける**。**見つからなければ導出が疑わしい**（あるいは到達不能な一時である
——**そう分かったら書き留める。直さない**）。

**止まる点**: **導出と検算が食い違ったら止めて報せる。** **これは設計の分岐である**
——「到達不能な一時」が在るなら、それを永久に寄せるかどうかは裁定が要る。

**★ 候補は分かっている**——`UnitPanel.tsx:214` の通貨キー（`rateOf(unit) === null`）。
**レート表というデータで決まり、盤面内のどの操作でも生き返らない。**
**裁定の種を先に書いておく**（止まったときの往復を 1 回で終えるため）:

| 案 | 中身 |
|---|---|
| **(あ)** | **データ依存を「永久」に寄せる**——利用者から見れば生き返らないので、見た目は永久側でよい。**ただし「盤面のいかなる操作でも」の定義に「データが変われば生き返る」が含まれるかが曖昧になる** |
| **(い)** | **第 3 種として書き留め、見た目は「いまだけ」のまま**——**レートが届けば生き返る**ので事実に忠実。**ただし利用者は「待てば押せる」と読めない** |

**★ 裁定（2026-08-31、ユーザー）: (い)。データ待ちは「一時」の一種である。**

**理由**: **`—` は永久に何も来ないが、通貨キーは数秒後に押せるかもしれない。
同じ絵にするのは事実に反する。**

**分類の規則としてはこうなる:**

> **生き返る条件が「盤面の操作」か「データの到着」かは、利用者から見た絵を
> 分けない。分けるのは「いつか生き返るか／永久に生き返らないか」である。**

**★ この裁定が守れていない道**（承知のうえで採った）: **レートが永久に届かない
環境——オフラインのまま、プロバイダが落ちている、レート表に無い通貨——では、
利用者は「永久に押せないキー」を「いまだけ」の見た目で見続ける。**
**次に「あれは永久にすべきでは」と思った人へ**——**それは 1 度検討し、
「絵を分けるのは永久かどうかだけ」という規則を優先して退けてある。**

**そして第 3 の形は 1 件だけである**（通貨キー）。**何件も在れば型を増やす議論に
なったが、1 件なので `"transient"` に収まる。**

**赤確認**: この Task はコードを変えないので**置けない**。**代わりに Task 2 のテストが
守る**——表が間違っていれば、そこで赤くなる。

### Task 2: 表を固定するテストを置く（**まだ型は変えない**）

**やること**: **Task 1 の表を主張として書く**。**この時点では 2 段の区別を作らず、
「永久であるべきキーが押せないこと」まで。**

**★ `keyDisabled` は非 export なので、直接は読めない。** 経路は 2 つ:

| 案 | 中身 | 評価 |
|---|---|---|
| **(A)** | **各盤面を jsdom で render し、`data-token` でボタンを拾って `toBeDisabled()` を読む** | **`disabled` は属性なので jsdom で読める**。**盤面の外から見た事実**を主張できる |
| **(B)** | **`keyDisabled` を export する** | 直接読めるが、**テストのために公開面を広げる**。Task 3 で署名が変わるので**2 度動く** |

**推奨: (A)。** **ただし罠が 1 つある**——**LLM の既定は候補面で、死んだ演算子のキーは
初期 DOM に居ない。** **数字面を出す操作（項目を押す等）が要る。**
**旧 §1.4 が「LLM 未測定」で踏んだのと同じ角である。**

**★ そして、その罠は赤確認を素通りさせる**——**当該キーが render されていなければ、
`isDeadOperator` の呼び出しを消しても緑のまま**になる。**だから件数を主張する**
（Task 1 の表の数）。**「0 個を検査して緑」を作らない。**

**★ このテストは Task 3 で書き直しになる**——**足場として意図的である。**
**Task 3 が、このテストを「押せない」から「永久か一時か」の主張へ昇格させる。**
**Task 3 の差分でテストの書き換えを見た人が、回帰と読まないように。**

**赤確認**: **`DEAD_OPERATOR_TOKENS` から 1 つ落とす** → 該当の盤面で赤くなる。
**`isDeadOperator` の呼び出しを 1 盤面から消す** → その盤面で赤くなる。
**★ 両方とも、件数の主張が在って初めて意味を持つ**（上のとおり）。

**止まる点**: **`Set` の一致で書く**（件数だけにしない）。**同じキーが 2 つ在って
別のキーが 1 つ欠けても数は合う**——昨夜これで 1 度やり直した。

### Task 3: 型を置き換える（漏斗 3 段とも）

**やること**:

```
5 盤面        keyDisabled(token): boolean
              → keyOff(token): null | "permanent" | "transient"
Keypad.tsx:20 disabled?: (token: T) => boolean
              → off?: (token: T) => null | "permanent" | "transient"
Keypad.tsx:77 受け渡しを新しい形へ
Key.tsx:29    disabled?: boolean → off?: "permanent" | "transient"
Key.tsx:50    const off = reserved || disabled === true
              → reserved は "permanent" に合流（§1.1 の裁定 A）
```

**★ `disabled?: boolean` を廃したこと自体を検査で固定する。** **残っていれば、
A1 と同じ「永続を一時の口に入れる」事故がまた通る。**

**置き方（案）**: `tools/check-boundary.mjs` と同じ流儀で、**`Key.tsx` と `Keypad.tsx` に
`disabled` という prop 名が現れないこと**を見る検査。**`grep` の否定なので、
「無いこと」を主張する形になる**——**そう書く。**

**★ 対象文字列は「`disabled?: boolean`」ではなく「`disabled` という prop 名そのもの」。**
**`disabled?: boolean | undefined` のような綴り替えで素通りする否定 grep は、
見張りにならない**（2026-08-31 のレビュー）。**`<button disabled={...}>` は残るので、
prop の宣言部だけを見る形にすること**——**そこの切り分けは実装時に決める。**

**赤確認**: **`Key.tsx` に `disabled?: boolean` を戻す** → その検査が赤くなる。

**止まる点**: **見た目はまだ変えない。** 段 A が終わった時点で
**`opacity: 0.4` は 1 種類のまま**で、**全部の検査が緑**であること。

## 段 B: 見た目を分ける

### Task 4: 形と読み上げを足す（**濃さは補助**）

> **★ 2026-09-02 に差し替わった。** **形（破線）は 1 度入れ、撮って取り下げた**
> ——「**逆に目立って押せそうに思う**」（ユーザー）。**いま在るのは:**
>
> - **押せないキーは 1 つの見た目**（`opacity: 0.4`）。**濃さの 2 段もやめた**
> - **予約スロットは空欄**（`—` を出さない）。**セルは残す**
> - **`aria-describedby` は残る**——**見た目で分けないので、区別を持つのは
>   読み上げだけになった**。**下の検査 3 本は、むしろ重みが増している**
> - **番人を 1 つ足した**: **予約枠に文字が無く、読み上げ名は在る**
>
> **以下は当時の指示である**（**破線の部分だけ効力を失っている**）。

**やること**:

- `Key.module.css` に **`"permanent"` の段**を足す（**形**——破線の縁など）
- `Key.tsx` が **`aria-describedby`** で説明を付ける（**`aria-label` に足さない**
  ——`getByRole("button", { name })` でキーを拾うテストが広範に壊れ、
  `vertical-slice.spec.ts:99` の「全キーに accessible name」も揺れる）
- **濃さは補助**として併用してよい

**★ id の振り方も決める。** `aria-describedby` は**このリポジトリに 0 件**なので、
**新しく入れる仕組み**である。**盤面ごとに 1 つの説明要素を置いて全部の永久キーが
同じ id を指すのか、キーごとに振るのか**——**前者を推す**（説明文は同じなので）。

**★ 読み上げ側の検査を、この Task で置く（jsdom でよい）:**

1. **永久のキーに `aria-describedby` が付いていること**
2. **その id が、実在する要素を指していること**（**宙に浮いた id は読み上げに
   何も届けない**）
3. **一時のキーには付いていないこと**（**付いていたら 2 段になっていない**）

**`aria-describedby` の id 解決は属性の話であって見た目ではない**ので、
**jsdom で足りる**——CLAUDE.md の「jsdom はアクセシビリティツリーを組み立てない」
とは矛盾しない。

**★ この検査は、フォールバックのときに唯一の区別になる。** **破線が見えなくて
「濃さ ＋ 読み上げ」に落ちた場合、意味的な区別は読み上げだけ**である——
**そこが無検査だと、落ちた瞬間に「2 段」の主張が誰にも守られなくなる。**

**赤確認**: **`aria-describedby` を外す** → 上の 1 が赤くなる。
**id を実在しない値にする** → 2 が赤くなる。
**一時のキーにも付ける** → 3 が赤くなる。
**`"permanent"` の段（形）を消す** → Task 6 の検査が赤くなる（**Task 6 が先に
無いと形の赤確認が置けないので、Task 4 と 6 は続けて進める**）。

## 段 C: 固める

### Task 6: 見た目の検査を 3 群に広げる

**やること**: `convert.spec.ts:721` の `currencyKeyLooks` と**同じ流儀**で、
**3 群が computed style で分かれることを主張する**:

```
生きている        opacity=1   cursor=pointer   border-style=...
永久に押せない     opacity=... cursor=default   border-style=dashed など
いまだけ押せない   opacity=... cursor=default   border-style=...
```

**★ `border-style` を読む**（形で分けるなら）。**`opacity` と `cursor` しか読まないと、
「見た目で分けた」と書いてある検査が、見た目の差を見ていない。**

**件数も主張する**（Task 1 の表の数）。**ループが 0 周でも緑にならないように。**

**★ 期待値は 2 通りありうる。** **Task 5 で破線が見えれば `border-style` を含む 3 群、
見えなければ濃さだけの 3 群**（`opacity` の 3 値）である。**どちらになるかは Task 5 が
決める**ので、**この Task は Task 5 の結果を受けてから書く**。**破線に落ち着かなかった
場合、形の主張をそのまま残すと「在るはずのものが無い」で赤くなる。**

> **★ 2026-09-02: 3 通り目になった。** **見た目は 3 群ではなく 2 群**である
> ——**生きている／押せない**。**永久と一時は画の上で同じ**なので、
> **`border-style` は読まなくてよく、3 群を主張してはいけない**（**在らぬ差を
> 主張することになる**）。
>
> **★ さらに 2026-09-02 の後半で 1 往復あった**——**空欄にしたら箱ごと
> 消え、「薄い箱は残してください」で地の色を与えて戻した**。**枠線では
> 出していない**（`keypad-shell.spec.ts` が「枠線で出していない」まで見る）。
>
> **この Task に残る仕事:**
>
> - **2 群が computed style で分かれる**こと（`opacity` / `cursor`）
> - **★ 予約枠に文字が無い**こと——**jsdom には置いた**（`operators.test.tsx`）。
>   **実ブラウザでも見るかは、この Task で決める**
> - **読み上げの区別**（`aria-describedby`）は **jsdom で置いてある**。
>   **CLAUDE.md の規律に従えば、ロールの意味論は E2E の仕事**なので、
>   **E2E に 1 本置くかを検討する**
>
> **★ 実際に置いたもの（2026-09-02、`keypad-shell.spec.ts`）:**
>
> 1. **空きセルが「空いている箱」に見える**——箱が見える／どのキーより
>    弱い／**枠線で出していない**。**地の上に掛けてから比べる**
>    （`background-color` は `opacity` を含まないので、色だけ比べると
>    「薄めて消す」変更を捕まえられない）
> 2. **押せない側の見た目が 1 通り**——**盤面をまたいで**見る。
>    **1 つの盤面には永久と一時が揃わない**（Finance は式を組むので
>    永久が 0 件、Scale の 3 盤面は初期状態で一時が出ない）。
>    **主張が空にならないよう、両側の件数を先に数える**

**★ jsdom では見ない**（CLAUDE.md の規律）。**E2E で実ブラウザに。**

**赤確認**: **2 群を同じ見た目に戻す** → 集合が 3 でなく 2 になって赤くなる。
