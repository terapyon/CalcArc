## Global Constraints

- **償還表の各行利息に f64 を通さない**（spec §1-1。floor(残高×分子/分母)、u128 中間）。
- **f64 は候補のみ。逆算の答は厳密償還表が確定する**（spec §5 の原則）。

- `calcarc-core` は panic しない。checked 演算。`loan/` は `Value`/`engine`/`data_scale` と相互 import しない（spec §9）。
- golden は完全一致・tolerance なし。金額は JSON で文字列。

```rust
//! 金利。パーセント文字列を分数のまま保持する(設計書 §1-5)。
//!
//! f64 に直変換すると、償還表(厳密整数経路)と月額決定(f64 経路)が
//! 別の値から出発してしまう。両経路は同じ分数から出発する。

use crate::{CalcError, CalcResult};

/// 月利。分子/分母の分数。約分しない(生成元が読めるまま保持)。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Rate {
    pub numerator: u64,
    pub denominator: u64,
}

impl Rate {
    /// 年利のパーセント文字列から月利分数へ。
    ///
    /// "1.5" -> 15/(10·100·12) = 15/12000。小数 4 桁まで。
    /// 空・非数字・負・100% 超・5 桁以上は SyntaxError。
    pub fn from_percent(text: &str) -> CalcResult<Rate> {
        let (int_part, frac_part) = match text.split_once('.') {
            Some((i, f)) => (i, f),
            None => (text, ""),
        };
        if int_part.is_empty() && frac_part.is_empty() {
            return Err(CalcError::SyntaxError);
        }
        if frac_part.len() > 4 {
            return Err(CalcError::SyntaxError);
        }
        let all_digits =
            |s: &str| !s.is_empty() && s.bytes().all(|b| b.is_ascii_digit());
        if !(int_part.is_empty() || all_digits(int_part))
            || !(frac_part.is_empty() || all_digits(frac_part))
        {
            return Err(CalcError::SyntaxError);
        }
        let scale = 10u64.pow(frac_part.len() as u32);
        let int_val: u64 = if int_part.is_empty() {
            0
        } else {
            int_part.parse().map_err(|_| CalcError::SyntaxError)?
        };
        let frac_val: u64 = if frac_part.is_empty() {
            0
        } else {
            frac_part.parse().map_err(|_| CalcError::SyntaxError)?
        };
        let numerator = int_val
            .checked_mul(scale)
            .and_then(|v| v.checked_add(frac_val))
            .ok_or(CalcError::SyntaxError)?;
        // 100% 超は拒否: numerator/scale > 100  <=>  numerator > 100·scale
        if numerator > 100u64.saturating_mul(scale) {
            return Err(CalcError::SyntaxError);
        }
        let denominator = scale
            .checked_mul(100)
            .and_then(|v| v.checked_mul(12))
            .ok_or(CalcError::SyntaxError)?;
        Ok(Rate { numerator, denominator })
    }

    pub fn is_zero(&self) -> bool {
        self.numerator == 0
    }

    /// 利息 = floor(残高 × 分子 / 分母)。厳密整数、u128 中間(設計書 §1-1)。
    ///
    /// 残高 ≤ u64::MAX、分子 ≤ 100·10^4 なので積は u128 に必ず収まる。
    pub fn monthly_interest_floor(&self, balance: u64) -> CalcResult<u64> {
        let product = balance as u128 * self.numerator as u128;
        let interest = product / self.denominator as u128;
        u64::try_from(interest).map_err(|_| CalcError::Overflow)
    }

    /// f64 の月利(閉形式の候補計算にのみ使う。設計書 §1-3)。
    pub fn as_f64_monthly(&self) -> f64 {
        self.numerator as f64 / self.denominator as f64
    }

    /// ボーナス列の半年利 = 年利÷2(設計書 §4 の採用決定)。
    /// 月利分数の 6 倍: 分子×6/分母 = 分子/(分母/6)。分母は 12 の倍数なので
    /// 割り切れる。
    pub fn half_year(&self) -> Rate {
        Rate { numerator: self.numerator, denominator: self.denominator / 6 }
    }
}
```

実装:

```rust
//! 償還表エンジン(設計書 §2 の中心)。
//!
//! 各行: 利息 = floor(残高×分子/分母)(厳密整数) → 元金 = 支払額 − 利息
//! → 残高更新。f64 はこのファイルに存在しない。
//! 内部は「期間ごとの利率列」を受けられる形(変動金利 M7-8 への拡張点。
//! 公開 API は単一金利で、内部で同じ利率を繰り返すだけ)。

use crate::{CalcError, CalcResult};
use super::rate::Rate;

/// 償還表の実行結果。行そのものは持たない(表の表示はスコープ外)。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Schedule {
    /// 実際に支払いが発生した回数(縮退入力では n より小さい)。
    pub rows_paid: u32,
    pub total_payment: u64,
    pub total_interest: u64,
    pub final_payment: u64,
    pub final_balance: u64,
}

/// 元利均等の償還表を走らせる。
///
/// residual > 0 のときは設計書 §3 の実慣行モデル: 均等 payment × (n−1) 回
/// + 最終回 = residual のみ。端数は n−1 回目(定例最終回)で吸収する。
/// residual = 0 のときは最終回 = 残高 + 利息で端数吸収。
pub fn run_schedule(
    principal: u64,
    rate: &Rate,
    n: u32,
    payment: u64,
    residual: u64,
) -> CalcResult<Schedule> {
    if n == 0 || principal == 0 || residual >= principal {
        return Err(CalcError::SyntaxError);
    }
    if residual > 0 && n < 2 {
        // n=1 の残価は「均等 0 回 + 最終回 = 残価のみ」となり元本を返す回が
        // 存在しない。構造的に成立しない入力(設計書 §3 の帰結)。
        return Err(CalcError::SyntaxError);
    }
    let first_interest = rate.monthly_interest_floor(principal)?;
    if payment <= first_interest && rate.numerator > 0 {
        return Err(CalcError::SyntaxError); // 発散(設計書 §2)
    }

    let mut balance = principal;
    let mut total_payment: u64 = 0;
    let mut total_interest: u64 = 0;
    let mut rows: u32 = 0;
    // 定例回数: 残価ありは n−1 回が均等、無しは n−1 回が均等 + 最終回調整。
    let regular_rows = n - 1;

    for _ in 0..regular_rows {
        if balance == 0 {
            break; // 縮退(設計書 §2): 以後の回は支払 0
        }
        let interest = rate.monthly_interest_floor(balance)?;
        rows += 1;
        // 定例回の途中で残高+利息が月額を下回ったら、その回で完済(縮退の亜種)。
        let due = balance
            .checked_add(interest)
            .ok_or(CalcError::Overflow)?;
        if due <= payment {
            total_payment = total_payment
                .checked_add(due)
                .ok_or(CalcError::Overflow)?;
            total_interest += interest;
            balance = 0;
            // 残価ありでここに到達するのは residual を先に返し切る矛盾入力。
            if residual > 0 {
                return Err(CalcError::SyntaxError);
            }
            return Ok(Schedule {
                rows_paid: rows,
                total_payment,
                total_interest,
                final_payment: due,
                final_balance: 0,
            });
        }
        total_payment = total_payment
            .checked_add(payment)
            .ok_or(CalcError::Overflow)?;
        total_interest += interest;
        balance = due - payment;
    }

    // 最終回。
    let interest = rate.monthly_interest_floor(balance)?;
    total_interest += interest;
    let final_payment = if residual > 0 {
        // 定例最終回(n−1 回目)で端数吸収済みの前提を検査:
        // 残った balance+interest が residual と一致しなければ、月額(候補)が
        // 表と噛み合っていない——呼び出し側(Task 2)が調整の責務を持つ。
        // エンジンとしては「最終回 = 残高 + 利息」を支払い、それを返す。
        balance.checked_add(interest).ok_or(CalcError::Overflow)?
    } else {
        balance.checked_add(interest).ok_or(CalcError::Overflow)?
    };
    total_payment = total_payment
        .checked_add(final_payment)
        .ok_or(CalcError::Overflow)?;
    Ok(Schedule {
        rows_paid: rows + 1,
        total_payment,
        total_interest,
        final_payment,
        final_balance: 0,
    })
}
```

**残価の端数吸収の実装位置について**: エンジンは常に「最終回 = 残高 +
利息」。残価モードの「n−1 回目で吸収し最終回 = B ちょうど」は、Task 2 の
正算が**均等月額を n−2 回 + 調整付き n−1 回目 + 最終回 B** という形で
`run_schedule` を「残価を最終残高として扱う」呼び方で実現する（具体的には
Task 2 で `run_schedule_with_residual` として薄い wrapper を足してよい。
テストの意味論——最終回 = B ちょうど、調整は n−1 回目——が仕様であり、
内部分担は実装者に委ねる。このテストが緑になる形なら可）。

実装の指定（式は逐語で）:

```rust
//! 閉形式による月額の候補計算。f64 はこのファイルと inverse.rs にしか
//! 存在しない(設計書 §1-3)。
//!
//! (1+r)^n − 1 は素朴に計算せず expm1(n·log1p(r)) で評価する(低金利での
//! 桁落ち回避。素朴式は年 0.001% で ~1e-5 円まで悪化する——設計書 §1-3)。

/// 元利均等の月額。残価 B(既定 0)は設計書 §3 の実慣行モデル:
/// P = A·annuity(n−1) + B/(1+r)^n を A について解く。
pub fn monthly_payment(
    principal: u64,
    rate: &Rate,
    n: u32,
    residual: u64,
) -> CalcResult<u64> {
    if n == 0 || principal == 0 || residual >= principal {
        return Err(CalcError::SyntaxError);
    }
    if residual > 0 && n < 2 {
        return Err(CalcError::SyntaxError);
    }
    if rate.is_zero() {
        // (P − B)/n ではない: B は最終回に返すので、均等部分は
        // 残価 0 なら P/n、残価ありは (P − B)/(n−1)。
        return Ok(if residual == 0 {
            principal / n as u64
        } else {
            (principal - residual) / (n as u64 - 1)
        });
    }
    if n == 1 {
        // 厳密経路(f64 不要)。residual は n<2 で拒否済み。
        let interest = rate.monthly_interest_floor(principal)?;
        return principal.checked_add(interest).ok_or(CalcError::Overflow);
    }
    let r = rate.as_f64_monthly();
    // annuity(m) = (1 − (1+r)^{−m})/r を expm1 経由で:
    // (1+r)^{−m} = 1/(x_m + 1)、x_m = expm1(m·log1p(r))
    let x_n = f64::exp_m1(n as f64 * f64::ln_1p(r));
    let pow_n = x_n + 1.0; // (1+r)^n
    let x_m = if residual == 0 {
        x_n
    } else {
        f64::exp_m1((n - 1) as f64 * f64::ln_1p(r))
    };
    let annuity_m = (x_m / (x_m + 1.0)) / r; // (1 − (1+r)^{−m})/r
    let pv = principal as f64 - residual as f64 / pow_n;
    if pv <= 0.0 {
        return Err(CalcError::SyntaxError);
    }
    let a = pv / annuity_m;
    if !a.is_finite() || a < 0.0 || a >= u64::MAX as f64 {
        return Err(CalcError::Overflow);
    }
    Ok(a as u64) // 円未満切り捨て(設計書 §2 の 1 語)
}
```

```rust
fn term_is_the_smallest_n_that_clears() {

fn zero_rate_term_is_integer_ceil() {
    // 0% は f64 不要: n = ceil(P/A) を整数演算で。
    let r = Rate::from_percent("0").unwrap();
    assert_eq!(term_for(1_200_000, &r, 100_000).unwrap().n, 12);
    assert_eq!(term_for(1_200_001, &r, 100_000).unwrap().n, 13);
}

#[test]
fn principal_is_the_largest_that_clears() {
    let r = Rate::from_percent("1.5").unwrap();
    let p = principal_for(85_000, &r, 420).unwrap();
    // 定義の両側: p.principal は n 回以内に完済し、+1 円は完済しない。
    let ok = run_schedule(p.principal, &r, 420, 85_000, 0).unwrap();
    assert_eq!(ok.final_balance, 0);
    assert!(ok.rows_paid <= 420);
    let over = run_schedule(p.principal + 1, &r, 420, 85_000, 0);
    assert!(over.map(|s| s.rows_paid > 420 || s.final_payment > 85_000)
        .unwrap_or(true));

```

実装方針（コードの細部は委ねる。仕様は上のテスト）:
- `term_for`: 発散チェック（`payment <= 初回利息`）→ 0% は整数 ceil →
  それ以外は f64 候補 `m = -ln_1p(-P·r/A)/ln_1p(r)`（数式は
  `1−P·r/A` の log を `ln_1p(-P·r/A)` で——引数が 0 近傍のときの精度）→
  `ceil` 近傍 {n−1, n, n+1} を表で走査し「完済する最小の n」。
  ここで「完済する」の判定は「`run_schedule(P, r, n, A, 0)` が Ok で、
  最終回支払 ≤ A ×2 のような曖昧な閾値**ではなく**、
  『n−1 回の定例払いで残高が尽きない **かつ** n 回目の最終回で払い切れる』
  を表の出力（rows_paid == n）で判定する」。
- `principal_for`: 0% は `A·n`（checked）→ f64 候補 `P₀ = A·annuity(n)` →
  `floor(P₀)` から表検証で ±数円の範囲を確定（可/不可の境界。walk は
  高々数歩——候補誤差は ulp 級）。
