**Goal:** Convert の 8 番目のカテゴリとして為替換算を足す。**このリポジトリで唯一ネットワークを使う。**

**Architecture:** **取得と保存は web、換算は core**（spec §2）。`fetch` と IndexedDB はブラウザの持ち物で計算ではない。

**レートは 10 進の文字列のまま core へ渡し、`Rational` にする**——`number` を経由した時点で誤差が入る。

**Tech Stack:** Rust（`calcarc-core` / `calcarc-wasm`）、Python 3（参照実装）、TypeScript + React、IndexedDB、Playwright / vitest / pytest。

## この計画が先に決めること

### 裁定 1: **「core に置かない表」と「core に置く表」を分ける**

spec §3 は「**通貨の表は core に置かない**——レートは外から来るデータであって定義値ではない」と書き、
§3.1 は「**ここには表を書く**」（小数桁は ISO 4217 の定義値で陳腐化しない）と書いている。**別の表の話である。**

| 表 | 中身 | 置き場 | 理由 |
|---|---|---|---|
| **レート表** | `USD → 155.23` など。**日々変わる** | **web**（IndexedDB） | 定義値ではない。外から来る |
| **小数桁の表** | `JPY → 0`、`USD → 2`。**ISO 4217** | **core** | **定義値である。U-1 の係数表と同じ立場** |
| **通貨トークンの並び** | 16 通貨 | **core（`Currency::ALL`）** | 面の並びと `token_parity` の契約（U-1・U-2 と同じ） |

**間違えたときの代償**: 小数桁を web に置くと、**同じ定義が 2 か所になり `token_parity` が見張れない**。
レートを core に置くと、**`calcarc-core` が I/O を持つ**ことになる。

### 裁定 2: **通貨の表示規則は U-1 と別の関数にする**

U-1 の `format_rational` は**有効数字 10 桁**。通貨は**小数桁が通貨ごとに固定**（0 か 2）。
**同じ関数に分岐を足さない**——別の関数（`format_amount(value, decimals)`）を置く。
**共有するのは 3 桁カンマと round-half-to-even の規則だけ**（U-1 の `group` と同じ判断）。

**なぜ**: U-1 の関数は「有効数字」で切る。通貨は「小数点以下」で切る。**切る場所が違うものを 1 つの関数にすると、
どちらの規則も読めなくなる**（`DIGITS` が 2 つの意味を持った U-1 の Important 2 と同じ型）。

### 裁定 4: **spec が沈黙している 5 点**（Task 2 が golden に固定した。**Task 3 は同じ判断をすること**）

**spec §3・§3.1 はここに答えを持たない。** golden が先に固定したので、**Rust 側が違う判断をすると golden が赤くなる**
——それが golden の役目だが、**「どちらが正しいか」を spec に探しに行っても答えは無い**。以下が根拠である。

1. **トークンは小文字の ISO コード**（`usd` `jpy` … `brl`）。**並びは spec §3.1 の表を左列 → 右列で読んだ順**
   （`jpy krw vnd usd eur gbp chf cny thb sgd hkd twd aud cad inr brl`）。
   — U-1/U-2 の単位トークンが全部小文字なので、**flat な名前空間の綴り規則を 2 つにしない**。
   — **`Currency::ALL` はこの並びと一致すること**（Task 4 の `token_parity` が順序込みで見る）。
2. **golden の `input` は `{value, from, to, from_rate, to_rate}`**、`id` は
   `currency/{value}{from}to{to}@{from_rate}-{to_rate}`。
   — **レートまで `id` に入れないと、0 レートのエラーケースが正常ケースと衝突する。**
3. **`from_rate == 0` だけが `DivisionByZero`。`to_rate == 0` は正当な `0`。**
   — **割り算をしているのは from 側だけ**で、エラー名が言っているのはそれである。
4. **丸めた結果が 0 なら符号を出さない**（`-0.001 USD` は `-0.00` ではなく **`0.00`**）。
   — **決めずに置くと 2 実装が別々に決めて静かに食い違う。** `-0.006 → -0.01` を対に置いてある。
5. **レートも値と同じリテラル規則**（`-?\d+(\.\d+)?`、ASCII のみ）。
   — **規則を 2 つ持たない。** レートに符号を許すかは spec が沈黙しているが、
   **別規則を作るより同じ規則を当てるほうが食い違いが少ない。**

### 裁定 3: **赤確認 4 の tie は、探索して実測で見つける**

spec §8 の赤確認 4 は「**素朴にやると空振りする**」と spec 自身が警告している。
出力は 0〜2 桁に丸めるので、**`f64` の誤差はほとんど常に吸収される**。

**必要なのは「厳密有理数では half-even の tie にちょうど乗るが、`f64` では境の反対側に落ちる」値である。**
**この値は推論で決めない。探索で見つけ、両方の数を導出記録に残す**（spec §8 が「判別力は実測でしか信じない」と書いている）。

**golden の tie ケースと、この赤確認のケースを同一にすること**（spec の指定）。

- [ ] **Step 1: tie を探索する（**このタスクの山場**）**

spec §8 の赤確認 4 は「**素朴にやると空振りする**」と警告している。**探索で見つけること。**

**探すもの**: `value`（10 進リテラル）と `rate_from` / `rate_to`（10 進文字列）の組で、
- **厳密有理数**の `value × rate_to / rate_from` が、**丸め桁のちょうど半分に乗る**（tie）
- **同じ計算を `f64` でやると、その境の反対側に落ちる**

**探索には先に打ち切りを置くこと**（監視役の指示）。**試行回数か時間の上限を決めてから始め、
上限に達したら「見つからなかった」の一種として記録する。**
**見つかるまで回す形にすると、探索の成功が質の代わりになる**（[[success-is-not-quality]]）
——「緩めれば見つかるパラメータ」が背後にいないかを、上限を先に決めることで断つ。
**上限は報告に書くこと**（何回／何秒回して、どこまでの範囲を見たか）。

**使い捨てのスクリプトで探すこと**（Python でも Rust でもよい）。**見つけたら次の 3 つを記録する**:
1. 厳密値（分数と 10 進展開）
2. `f64` で計算した値（**桁を全部**。`{:.20}` などで）
3. **それぞれを丸めた結果が違うこと**

**この 3 つを報告に貼り、`currency.rs` のテストのコメントにも残すこと。**
**「たぶん赤になる」で通さない**（spec の指定）。

**見つからなかった場合**: 探索の範囲と試行回数を報告し、**「この丸め桁では `f64` と厳密有理数が
判別できない」という結論を spec §8 に訂正印として書くこと**——**空振りする赤確認を「実施済み」で

### Task 6: 更新方針（`rates.ts`）——**I/O を持たない純関数**

**Files:** Create: `web/src/currency/rates.ts`、`web/src/currency/rates.test.ts`

**Interfaces:**
```typescript
type RateDecision =
  | { kind: "use"; set: CurrencyRateSet; refresh: boolean }  // 描いてよい。refresh なら背後で取りに行く
  | { kind: "none" }                                          // キャッシュ無し。§5 の案内
export function decide(cached: CurrencyRateSet | null, now: Date): RateDecision
export function validate(raw: unknown, allowed: readonly string[]): CurrencyRateSet | null
export function shouldWrite(cached: CurrencyRateSet | null, fetched: CurrencyRateSet): boolean
```

**`decide` は時刻を引数で受け取る**——**現在時刻を関数の中で読まない**。読むと 24 時間の境がテストできない。

**守ること**（spec §4.2・§4.3・§8）:
- **キャッシュがあれば、まず画面に出す。通信を待たない**
- **24 時間以内 → そのまま／24 時間超 → 背後で更新を試みる。失敗しても古いまま使う**
- **`date` が変わっていなければ書き戻さない**（`shouldWrite`）
- **検証は項目ごと**（spec §4.3）:
  - **通貨 1 つのレートが 10 進として読めない → その通貨だけ落とす**（他は生き残る）
  - **`baseCurrency` か `date` が読めない → セット全体を捨てる**
  - **知らない通貨が入っている → 捨てる**

**テスト**（spec §8 が名指ししたもの）:
- **23:59 では取りに行かず、24:01 では行く**（**境をまたぐ 2 件**）
- **`date` が同じなら書き戻さない**
- **取得失敗でも古いキャッシュで換算が続く**
- **1 通貨だけ壊れたセットで、その 1 つだけが落ちて残りが生きる**（**件数で主張する**）
- **`baseCurrency` が無いセットは丸ごと捨てる**

**赤確認**: **24 時間の判定を 24 秒にする** → 境のテストが赤（spec §8 の赤確認 2）。
**取得失敗時にキャッシュを捨てる** → 「失敗を致命的にしない」が赤（同 3）。
