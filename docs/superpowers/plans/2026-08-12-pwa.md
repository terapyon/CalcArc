> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** manifest・アイコン・SW・オフライン動作（§38/§39）と、その意図が成果物に到達していることの機械検査。MSRV 1.87 宣言を同乗。

## Global Constraints

- **registerType は `"prompt"`、プロンプト UI は配線しない**（spec §2。
  `autoUpdate` は skipWaiting+clientsClaim 注入＋予告なしリロードで、spec が
  避ける挙動そのもの）。
- **precache のみ。runtime caching を書かない**（spec §2）。
- **dev で SW を有効にしない**（`devOptions` は既定 false のまま。spec §7）。
- **検証コマンドは ci.yml から導出**（fmt / clippy / cargo test /
  wasm-pack test / typecheck / lint / vitest / vite build / playwright /
  pytest / ruff check / ruff format --check / golden 再生成 diff /
  uv sync --locked）。本ブランチで ci.yml に足すのは `pnpm check:sw` のみ。
- コミット前に `cargo fmt`。`git push`/PR 禁止。
- コミット末尾に `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`。
- ベースライン: Rust 141 / wasm 10 / vitest 44 / e2e 26 / Python 17。
  Rust・Python の件数は最後まで不変（このブランチはコア不触。MSRV は
  メタデータのみ）。

- [ ] **Step 2: vite.config.ts の本配線**

```typescript
import { VitePWA } from "vite-plugin-pwa";

// plugins 配列に追加:
VitePWA({
  // "prompt" は登録戦略の名前であって UI の有無ではない(設計書 §2)。
  // UI は配線しない: 新 SW は waiting に留まり、全タブ閉鎖後の再訪で
  // 切り替わる。"autoUpdate" にしてはいけない——skipWaiting+clientsClaim が
  // 注入され、実行中のページの下で世代がすり替わり予告なくリロードされる。
  registerType: "prompt",
  workbox: {
    // 既定の glob は {js,css,html} だけで .wasm が precache に載らない。
    // wasm が落ちると「オフラインで開くが計算できない」抜け殻になる。
    globPatterns: ["**/*.{js,css,html,wasm,svg,png,webmanifest}"],
    // 既定 2MB。超過は警告どまりで precache から黙って外れるため、
    // 余裕を持って明示する。番人は scripts/check-sw.mjs(設計書 §7)。
    maximumFileSizeToCacheInBytes: 4 * 1024 * 1024,
    navigateFallback: "index.html",
  },
  manifest: {
    name: "CalcArc",
    short_name: "CalcArc",
    lang: "ja",
    display: "standalone",
    start_url: "/",
    scope: "/",
    // tokens.css の --surface-bg(ライト)と一致させる。manifest は CSS を
    // 読めないので値の重複はやむを得ない(設計書 §3)。
    theme_color: "#f2f2f7",
    background_color: "#f2f2f7",
    icons: [
      { src: "icon-192.png", sizes: "192x192", type: "image/png" },
      { src: "icon-512.png", sizes: "512x512", type: "image/png" },
      {
        src: "icon-512-maskable.png",
        sizes: "512x512",
        type: "image/png",
        purpose: "maskable",
      },
    ],
  },
}),
```

- [ ] **Step 1: check-sw.mjs を書く**

```javascript
// ビルド成果物が設計書 §2 の意図を実装していることの機械検査。
// 設定ミスはこの層でしか捕まらない(vite.config は意図、dist は事実)。
import { readFileSync, existsSync } from "node:fs";
import { resolve } from "node:path";

const dist = resolve(import.meta.dirname, "..", "dist");
const fail = (msg) => {
  console.error(`check:sw NG — ${msg}`);
  process.exit(1);
};

const swPath = resolve(dist, "sw.js");
if (!existsSync(swPath)) fail("dist/sw.js が無い(SW が生成されていない)");
const sw = readFileSync(swPath, "utf8");

// 1. 無条件の即時活性化が無いこと(設計書 §9-3b)。
//    注意: prompt モードでも SKIP_WAITING メッセージ応答として skipWaiting は
//    ガード付きで現れる。「skipWaiting が無い」は検査にならない。
//    autoUpdate 注入の痕跡は clientsClaim で見る。
if (sw.includes("clientsClaim")) {
  fail("sw.js に clientsClaim がある(autoUpdate 化の痕跡。registerType を確認)");
}
if (!sw.includes("SKIP_WAITING")) {
  fail("sw.js に SKIP_WAITING ガードが無い(prompt の形をしていない)");
}

// 2. precache に wasm が載っていること(設計書 §7。2MB 上限ドリフトの番人)。
if (!/\.wasm/.test(sw)) {
  fail("precache に .wasm が無い(glob か上限を確認。オフラインで計算不能になる)");
}

// 3. manifest の中身。
const manifestPath = resolve(dist, "manifest.webmanifest");
if (!existsSync(manifestPath)) fail("manifest.webmanifest が無い");
const manifest = JSON.parse(readFileSync(manifestPath, "utf8"));
if (manifest.display !== "standalone") fail(`display が ${manifest.display}`);
const sizes = (manifest.icons ?? []).map((i) => i.sizes);
for (const need of ["192x192", "512x512"]) {
  if (!sizes.includes(need)) fail(`icons に ${need} が無い`);
}
for (const icon of manifest.icons) {
  if (!existsSync(resolve(dist, icon.src))) fail(`${icon.src} が dist に無い`);
}

console.log("check:sw OK — prompt 形 / wasm precache / manifest 完備");
```

### Task 3: PWA E2E（オフラインの赤の対つき）

**Files:**
- Create: `web/tests/e2e/pwa.spec.ts`

**Interfaces:**
- Consumes: Task 1 のビルド（playwright.config は既に build+preview）
- Produces: spec §9 の完了条件 1〜3 の E2E 固定

- [ ] **Step 1: テストを書く**

```typescript
// 検査内容(コードは house style で。要点):
// installable:
//  1. link[rel="manifest"] が存在し、fetch すると display === "standalone"、
//     icons に 192x192 と 512x512。各 icon.src を fetch して 200。
//  2. navigator.serviceWorker.ready が resolve する(page.evaluate)。
// offline:
//  3. 通常ロード → SW ready を待つ → reload(1 回目のロードは SW の制御下に
//     ない——clientsClaim を使わない設計の帰結。reload して初めて controlled
//     になる。この理由をコメントに書く) → context.setOffline(true) →
//     reload → Scientific で 3+4= が 7、nav で Data Scale へ → 基準例
//     307.2 GB が出る。
//  4. 赤の対: 新規 context で最初から setOffline(true) → goto が失敗する
//     (expect(...).rejects か response null 判定)。これが無いと 3 の緑は
//     「切れていなかった」と区別できない(設計書 §6)。
// 注意: 3 と 4 は独立した context を使う。SW 登録は context 単位。
```

- [ ] **Step 2: 検証してコミット**

Run: `cd web && pnpm e2e`
Expected: 26 + 4 前後 = 30 前後、既存 26 は無変更のまま緑（SW 有効環境での
回帰——spec §6）。

```bash
git add web/tests/
git commit -F - <<'EOF'
Prove offline works, and prove the proof can fail

After one controlled reload the network goes away and both calculators
keep working from the precache — and a sibling test visits cold with the
network already off and watches the load fail, because "worked offline"
is indistinguishable from "was never offline" without the failing twin.
The first load is deliberately uncontrolled: no clientsClaim means the
worker takes over on the next navigation, so the test reloads once
before pulling the plug, and says why in a comment.
```
