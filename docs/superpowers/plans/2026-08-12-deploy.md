# デプロイワークフロー 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** main → Cloudflare Pages の自動デプロイ（Direct Upload）と、M5 の安全性証明が依存する 2 前提のデプロイ後スモーク。§50 DoD の 3 項目を実機実証可能に。

**Architecture:** spec は docs/superpowers/specs/2026-08-12-deploy-design.md。4 タスク: composite 化と ci.yml 再編 → deploy.yml とスモーク → docs とフルスイープ → 初回実行の確認（マージ後）。**Task 4 だけはマージ後にしか実行できない**——yml は初回実行でしか完全検証できない性質（spec §5）。

**Tech Stack:** GitHub Actions composite actions、cloudflare/wrangler-action、curl。

## Global Constraints

- **バージョン固定は composite action にのみ存在する**（wasm-pack v0.15.0、
  node 22。写しを作らない——spec §1）。wrangler-action も**バージョン固定**
  （wasm-pack v0.9 事件の教訓を同形式のコメントで）。
- deploy.yml は CI の成功を待たない。ただし `check:sw` は配る dist に直接
  掛ける（spec §2）。
- 刻印 `build-info.json` は **vite build の後**に dist へ書く（public/ に
  置くと precache に入り、スモークが自分の尾を食う——spec §4）。
- **コミットを含むコマンドは先頭にブランチ確認**:
  `test "$(git branch --show-current)" = feature/deploy` を && で繋ぐ
  （共有ワークツリー事故の再発防止。2026-08-13 の実例あり）。
- `git push`/PR 禁止。コミット末尾に
  `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`。
- ベースライン: Rust 141 / wasm 10 / vitest 44 / e2e 30 / Python 17。
  アプリコードは `_headers` の 1 行以外不触。

- [ ] **Step 1: setup-wasm-pack**

```yaml
name: Setup wasm-pack
description: >
  Rust(wasm32) + rust-cache + wasm-pack。バージョン固定はここに一本化する。
  ci.yml と deploy.yml の両方がこれを使う——写しで持つと片方だけ更新される
  (スイープ一覧の lint 欠落と同じ、手写しリストの宿命)。
runs:
  using: composite
  steps:
    - uses: dtolnay/rust-toolchain@stable
      with:
        targets: wasm32-unknown-unknown
    - uses: Swatinem/rust-cache@v2
    - uses: jetli/wasm-pack-action@v0.4.0
      with:
        # バージョンを指定しないと実行ごとに入るものが変わる。
        # 実際に main で v0.9.1 が降ってきて、license.workspace を
```

- [ ] **Step 2: setup-web**

```yaml
name: Setup web toolchain
description: >
  pnpm + node + 依存インストール。バージョンと cache 設定はここに一本化。
runs:
  using: composite
  steps:
    - uses: pnpm/action-setup@v4
      with:
        # package.json はリポジトリ直下ではなく web/ にある。
        package_json_file: web/package.json
    - uses: actions/setup-node@v4
```

### Task 2: deploy.yml・スモーク・_headers・刻印

**Files:**
- Create: `.github/workflows/deploy.yml`
- Modify: `web/public/_headers`（`/build-info.json` の no-cache 1 行）

**Interfaces:**
- Consumes: Task 1 の composite 2 つ、既存の `pnpm check:sw`
- Produces: main push で走るデプロイ + スモーク

- [ ] **Step 1: deploy.yml**

```yaml
name: Deploy

on:
  push:
    branches: [main]
  workflow_dispatch:

concurrency:
  group: deploy
  # デプロイは途中中断より直列完走(設計書 §1)。
  cancel-in-progress: false

jobs:
  deploy:
    name: Build and deploy to Cloudflare Pages
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/setup-wasm-pack
      - run: wasm-pack build crates/calcarc-wasm --target web --out-dir ../../web/src/wasm
      - uses: ./.github/actions/setup-web
      - run: pnpm exec vite build
        working-directory: web
      # 刻印はビルドの後に書く。public/ に置くと precache に入り、
      # 「いまサーバが何を配っているか」にキャッシュが答えるファイルに
      # なってしまう(設計書 §4)。
      - name: Stamp the build
        run: |
          printf '{"commit":"%s","builtAt":"%s"}\n' \
            "$GITHUB_SHA" "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
            > web/dist/build-info.json
      # CI も check:sw を回すが、あれは別のビルドに対してである。
      # 検査した物を配るには、配る物を検査するしかない(設計書 §2)。
      - run: pnpm check:sw
        working-directory: web
      - uses: cloudflare/wrangler-action@v3.14.1
        # バージョンを指定しないと実行ごとに入るものが変わる(wasm-pack
        # v0.9 事件と同じ穴)。上げるときは意図して上げる。
        # 実装時: このタグの実在を gh-ro release list -R cloudflare/wrangler-action
        # で確認し、無ければ最新の v3 系タグに固定して報告に記すこと。
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          # Direct Upload は --branch が本番/プレビューを決める。
          command: pages deploy web/dist --project-name=calcarc --branch=main
      - name: Smoke — _headers are respected
        run: |
          set -eu
          base="https://calcarc.pages.dev"
          # ヘッダ名の大文字小文字は不定なので -i。
          curl -fsSI "$base/sw.js" | grep -i "cache-control:.*no-cache"
          curl -fsSI "$base/manifest.webmanifest" | grep -i "cache-control:.*no-cache"
          asset="$(ls web/dist/assets | head -1)"
          curl -fsSI "$base/assets/$asset" | grep -i "cache-control:.*immutable"
      - name: Smoke — the latest deploy is being served
        run: |
          set -eu
          base="https://calcarc.pages.dev"
          # 伝播遅延に備えて 10 秒間隔で最大 12 回(設計書 §3)。
          for i in $(seq 1 12); do
            served="$(curl -fsS "$base/build-info.json" | head -c 200)" || served=""
            case "$served" in
              *"$GITHUB_SHA"*)
                echo "serving $GITHUB_SHA"
                exit 0 ;;
            esac
            echo "attempt $i: not yet ($served)"
            sleep 10
          done
          echo "deploy did not converge to $GITHUB_SHA" >&2
          exit 1
      - name: Smoke — the app answers
        run: |
          curl -fsS "https://calcarc.pages.dev/" | grep -q 'id="root"'
```

- [ ] **Step 2: _headers に 1 行**

```
# 刻印は「いまサーバが何を配っているか」に答えるファイル。エッジに
# キャッシュされたら照合の意味が消える(sw.js と同じ理由)。
/build-info.json
  Cache-Control: no-cache
```

- [ ] **Step 3: ローカルで素振りできる部分の素振り**

1. `cd web && pnpm build` → 刻印ステップを手で実行
   （`printf ... > dist/build-info.json`）→ `pnpm check:sw` 緑
   （刻印が precache 外にあることの傍証: `grep -c build-info dist/sw.js` が 0）。
2. `pnpm preview` を起こし、スモーク 1 のヘッダ検査ロジックを
   `base=http://localhost:4173` で実行 → **no-cache 欠落で赤が出るはず**
   （vite preview は `_headers` を尊重しない）。**この赤が検査ロジックの
   生存確認である**（spec §7-2）。出力を報告に貼る。
3. スモーク 2 のロジックを preview に対して実行 → build-info.json は配信
   される（dist に在る）ので、`GITHUB_SHA` の代わりにローカルの
   `git rev-parse HEAD` で一致（緑）と、わざと違う SHA で不一致（リトライ後
   赤）の両方を確認。**赤の実出力を報告に貼る。**

- [ ] **Step 4: コミット**

```bash
test "$(git branch --show-current)" = feature/deploy || exit 1
git add .github/workflows/deploy.yml web/public/_headers
git commit -F - <<'EOF'
Deploy from Actions, then make the deployment prove itself

wrangler uploads the same dist that check:sw just inspected — the one
property a CF-side build cannot offer. After the upload, the workflow
interrogates the real URL: sw.js and the manifest must arrive with
no-cache and a hashed asset with immutable (the _headers assumption),
and build-info.json must name this very commit, with retries for
propagation (the latest-deploy assumption). Those are the two legs M5's
update-safety argument stands on, checked on every deploy from now on.

The stamp is written after vite build, outside the precache — a stamp
the cache can answer for cannot answer the question.

Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
EOF
```

- [ ] **Step 1: docs/deploy.md**

内容（spec §5 の手順を清書）:
- 仕組みの 3 行要約（Actions ビルド → Direct Upload → スモーク。CI 独立の理由は spec §2 へのリンク）
