# 間欠的に落ちるテストの一覧

**この一覧は「壊れている」の一覧ではない。「赤を見た人が照合するための一覧」である。**

CI や手元で赤が出たとき、**まずここを見て、同じテスト・同じエラー原文が載っていないか
を確かめる**。載っていれば、**その走行の条件を下に足す**——標本が増えるほど、原因の
当たりが付く。載っていなければ、それは新しい赤である。

**直しは、ここに書くこととは別の判断である。** 待ちの上限を伸ばして緑にするのは
**「緩めれば緑になる数字」を 1 つ増やすだけ**なので、この一覧に載せることの帰結には
しない。

### 何を根拠にしてよくて、何を根拠にしてはいけないか

- **`git status` を健全性の根拠にしない。** **3 バイトとも長さが同じ**なので、
  **stat キャッシュは「変更なし」と言い続ける**（今日 2 回とも見落とした）
- **`json.load()` が通ることも根拠にしない。** **`'4'` が `'5'` になった破損は
  JSON として完全に妥当**である——**パースでは原理的に見つからない。**
  2026-08-30 に「19 枚パースし直して全枚健全」と報告し、**その時点で
  1 枚壊れていた**
- **使える手はこれである**（`git` が全ファイルの SHA を持っている）:

```bash
git ls-files -s | while IFS= read -r line; do
  sha=$(echo "$line" | awk '{print $2}'); path=$(echo "$line" | cut -f2-)
  [ -f "$path" ] || continue
  cur=$(git hash-object "$path")
  [ "$sha" != "$cur" ] && echo "MISMATCH: $path"
done
```

- **復元は `rm` してから `git checkout HEAD -- <path>`。** **`git checkout --`
  だけでは戻らない**——git が「変更なし」と思っているので何もしない（実測）

### `.git` は無事である

**両リポジトリの `git fsck --full --strict` が、dangling 以外の指摘を 1 件も
出さない**（2026-08-30 夜に実測）。**git のオブジェクトは SHA で検証されている
ので、壊れていれば fsck が言う。** **壊れているのは、誰も検証していない
作業ツリーのファイルだけである。**

**2026-08-30 の夜に 3 種類が出そろった。** **見分けの要点は「誰が名乗るか」である:**
