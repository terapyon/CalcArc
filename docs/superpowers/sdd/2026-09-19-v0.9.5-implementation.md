## PDF の応急（利用者の裁定 2026-09-18「PDF のリンクを GitHub Release の URL へ」）

**行き先を組むのは `web/src/ui/Footer/LinksPopup.tsx` の `manualPdfUrl` の 1 か所**。
形は **その版の Release の添付を直に指す**（`/releases/download/v<版>/calcarc-<版>-<冊>.pdf`）。

**実測は 2 つだけ**（どちらも 2026-09-18）:

- **利用者の iPhone**: ホーム画面のアプリから、**サイト内の PDF は窓ごと切り替わって戻れない**。
  **GitHub のページは上にバツの付いた窓で開いて戻れる**
- **監視役の `curl`**: 本番の PDF に `content-disposition: attachment` が付いていた
  ——**付いていても上の「戻れない」は起きた**

**推測（測っていない）**: 窓がアプリの外に出るかは移る先の生成元で決まり、
GitHub の窓の中なら PDF でも戻れる。**iOS で直ったかは、利用者が実機で確かめるまで
「直った」と書かない。** **外れたら `manualPdfUrl` を 1 行替えて Release のページ
（`/releases/tag/v<版>`）を指す**（番人は `Footer.test.tsx` の 1 行を替える。
E2E の `footer.spec.ts` は GitHub の Release の下であることしか見ないので動かない）。

**赤の撮り直し（`f8a77d0` の差分にもコミット文にも残っていない経緯）**: 新しい番人
（`Footer.test.tsx` の「sends each manual to this version's PDF on the GitHub release」）を
`de50c40` で最初に回したときの赤は **`manualPdfUrl is not a function`**——**関数がまだ
無いという、間違った理由の赤**だった。**改名（`manualPdfPath` → `manualPdfUrl`、出力は
`/manual/` のまま）だけを先に入れて回し直し**、**`/manual/calcarc-0.9.4-quick-ja.pdf` と
Release の URL の食い違いで赤くなる**ことを見てから行き先を替えた。**`f8a77d0` は改名と
行き先の変更を 1 コミットにしている**ので、**差分から赤の理由は読めない**。

## ★ 0.9.6 の宿題: サイト内の PDF 配信を撤去する

**0.9.5 では残した。理由は「出荷前の夜にリリースの経路を動かさない」**であって、
**「残すのが良い」ではない**。**この理由は 0.9.6 で腐る**——腐ったまま居座らせない。

**対象（2026-09-19 に `git grep` で数えた。行番号はその日の座標）**:

1. `functions/manual/[[path]].js`（Function そのもの。`PDF_DISPOSITION` を含む）
2. `.github/workflows/deploy.yml:116` の段 `Put the manuals into what we deploy`
3. `.github/workflows/deploy.yml:220` と `:233` のスモーク 2 本
   （無い PDF が 404／配った PDF が pdf＋attachment）
4. `tools/tests/release-workflow.test.ts` の describe
   「リリースの走行だけ、PDF を dist に入れてから配る（0.9.3）」の 5 本（`:836` から）
5. `web/scripts/check-sw.mjs` の 3b（`/manual/…pdf` が navigation fallback の除外に当たる）
6. `web/tests/unit/manual-function.test.ts`（ファイルごと）

**撤去しないもの**（**混ぜると Release の PDF が消える**）:
`release.yml` の `manuals` ジョブと、その artifact を `Evidence` が取って添付する段
（`release-workflow.test.ts` の `:782`・`:797`・`:808` の周り）。**リンク集が指しているのは
この添付である。** `Manuals` が落ちたら `Deploy` を走らせない並び（`release.yml:95`）も、
**添付の無い版を出さない**ために要る——理由は「サイト内の PDF」から「Release の添付」へ
移るが、**並びは残る**。

**撤去したときに変わること**: `/manual/<何か>.pdf` は `_redirects` の
`/* /index.html 200` に落ち、**アプリの画面が 200 で返る**（0.9.3 で Function を
置いた理由そのもの）。**そこを指す画面が 1 つも無くなってから**消すこと
——**0.9.4 の画面（SW に残った古い版）はそこを指している**。
**`docs/deploy.md` のロールバックの節**も同じコミットで直す。
