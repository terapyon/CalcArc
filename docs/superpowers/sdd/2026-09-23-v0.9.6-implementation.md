## なぜこの版が在るか（**実測 2 件**）

**iPhone のホーム画面アプリでは、PDF を開く道はどの経路でも行き止まりだった。**

| 版 | 手 | 結果（利用者の実機） |
|---|---|---|
| 0.9.4 | サイト内の PDF ＋ `Content-Disposition: attachment` | **窓ごと PDF に変わって戻れない**（ヘッダは本番で付いていた。監視役の `curl`） |
| 0.9.5 | GitHub Release の添付（別の生成元） | **内部のブラウザ表示から戻れない**。利用者の言葉「**PDF が開くが、閉じる・戻るのボタンが見当たらない**」 |

**どちらも「端末が PDF をどう扱うか」に賭けていた。** 0.9.6 は賭けをやめ、
**本文をアプリの中の画面（`#manual`）で読ませる**。**PDF はそこから開く
保存・印刷用の副経路**である。

## 写真を撮って見つけた 3 件（**全段緑のまま出ていた**）

**2026-09-23、`--project mobile` の幅で撮った写真から**（監視役も同じ写真で確認）:

1. **戻る道が、本文を全部スクロールした先にしか無かった。** **タブは貼り付かない**
   （`position: static`。3000px スクロールすると箱の `y` は `-3000`＝画面の外。
   **詳細マニュアルはページ全体 32,869px**）——**利用者が 0.9.4・0.9.5 で困ったのと
   同じ形**である。**裁定（利用者 2026-09-23）: 画面の頭に貼り付く 1 行を置く**
   （代償は本文の上 44px＝5.2%。承知のうえ）。**番人は `manual.spec.ts` の
   「the way back stays on screen while the reader scrolls」**で、**箱の座標で見る**
   ——**`isVisible()` は DOM に在って `display:none` でないことしか言わない**
   （**スクロールして画面の外に出たタブにも true を返した**。実測）。
   **赤確認**: `position` を `static` に戻すと「the way back is above the viewport」で赤。
2. **説明の 1 行は落とす**（**利用者の裁定**。実行役は「残す」を選んでいた）。
   簡易マニュアルの 2 章で **4 行続く**所を見ての判断で、理由は「**写真が無い以上、
   説明だけ残っても読み手には空振り**」。**空の段落も残さない**（写真だけの行は
   段落ごと消える）。
3. **表の 1 列目が語の途中で折れていた**（「【Conv／ert】」）。`word-break: keep-all` と
   1 列目の下限で直した。**これを見張る番人は無い**——**写真でしか分からない。**

## 出荷後に利用者が確かめること（**私たちには測れない**）

- **画面の中の PDF を開いたとき、電卓に戻れるか。** **PDF の副経路は同一生成元の
  `target="_blank"`** なので、**iOS の standalone では窓ごと PDF に変わる可能性が残る**
  （レビュー役の指摘。設計 §6 が承知のうえ）。**マニュアルの「PDF が開けないときは
  画面の中で」は、「戻れない」場合を言っていない**——**文言は、実機の結果を見てから決める。**
  **測れないものを、また推測で埋めない。**
