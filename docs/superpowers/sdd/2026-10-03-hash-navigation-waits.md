## 穴の形

**この巡回は hash だけで画面を移る**（`page.goto("/#manual")` は同じ文書内の
遷移なので、**ページは読み直されない**）。**`<h1>` も盤面も、React が
`hashchange` を受けて描き替えるまで前の画面のまま**である。

**だから「`main` の最初のボタンが見える」「`display-main` が見える」で待つと、
前の画面で通る。** **どちらも全画面に在るものだからである。**

**実測（2026-10-03。`App.tsx` の `onHashChange` を 300ms 遅らせて競合の向きを固定）**:

```
金融 = {"h1":"金融計算","buttons":37}
旧 ready を抜けた時点 = {"h1":"金融計算","buttons":37}   ← #manual へ移った直後
掃いた本数 = 37                                          ← 金融をもう 1 度数えた
新 ready のあと = {"h1":"マニュアル","buttons":3}
```

**出方は 2 つある**:
- **床が「以上」の検査では、前の画面を数えて緑のまま間違える**（上の 37 本）。
- **CI が赤くなったのは逆向き**——**ボタンが見えた時点では金融、`sweep()` が
  走る時点ではマニュアル（冊はまだ別チャンクの中）**で、**3 本足りなかった**
  （`checked` 425／床 428）。

**`#manual` が効くのは、あの画面だけ中身が別チャンクで届くから**である
（`ManualPage.tsx` の `import("virtual:manuals")`）。**`<h1>` が出たあとに
ボタンが増える画面は、いまここだけ。**

## ★ 絞り込みが落としたもの——**3 つの走査が、3 つ別のものを落とした**

- **「hash を変数で渡す `goto`」で絞ると、文字列直書きの `goto` が落ちる**
  ——**`rotation:138`（`goto("/#scale/llm")`）は、表に在る `:140` の 1 行上**である。
- **「テストの中で 2 回目以降の `goto`」で絞ると、ループの中とヘルパの中が落ちる**
  ——**テキスト上 1 回でも実行は 13 回**（`landscape-layout:244`）、
  **`panel-sizing:42` はループから呼ばれるヘルパの中に在る**。
- **どちらの走査も `beforeEach` の `goto` を落とす**
  ——**`keypad-shell` の 3 本はテストの中に `goto` が 1 度しか現れない**が、
  **`beforeEach` が `/` を開いている**ので、その 1 度が画面の切り替えである。
  **これは読んでも見つけられず、変異を入れた全走の赤が教えた。**

**結局、1 件ずつ読み、そのうえで変異を全走に当てた。** **読むだけでも、
機械で絞るだけでも足りない**——**前者は `beforeEach` を見落とし、後者は 3 通りに落とした。**

## ★ 赤が撮れない番人がある

**「直す前の赤を撮れ」は、この穴の半分には当てられない。**
**床が「以上」の検査では、前の画面を数えても床を満たす**ので、
**数えすぎる向きは赤にならない**（実測: `#finance` → `#manual` で金融の 37 本を
もう 1 度数え、**37 本すべて緑**）。

**だから証拠は 2 通りになる**:
- **緑のまま間違える側**——**待ちが返った時点の `<h1>` が前の画面の名前である**という印字。
  実測（`onHashChange` を 300ms 遅らせた）:

```
[証拠] #convert          旧い待ちの直後=関数電卓      新しい待ちの直後=長さの換算
[証拠] #scale/data-scale 旧い待ちの直後=為替の換算    新しい待ちの直後=データ量の規模
[証拠] #finance          旧い待ちの直後=データ転送    新しい待ちの直後=金融計算
[証拠] #manual           旧い待ちの直後=金融計算      新しい待ちの直後=マニュアル
```

- **赤くなる側**——**同じ変異のもとで、直す前 5 failed / 330 passed、直したあと 335 passed。**

### ★ `panel-sizing` の巡回は、別の画面を測っている（確かめた）

**監視役の懸念**: **10 キーの二重化の裁定（2026-10-02）は、`panel-sizing` の
「5 面で決まり方が揃っている」の赤が根拠だった**——**あれが前の画面を測って
いたら、5 面とも同じに見えて緑になる。**

**同じ順・同じ待ち方で `<h1>` を印字した（2026-10-03、`390×844`）**:

```
Scientific:     h1=関数電卓        aspect=1 / 1  キー=66.8x66.8
Convert 長さ:   h1=長さの換算      aspect=1 / 1  キー=66.8x66.8
Data Scale:     h1=データ量の規模  aspect=1 / 1  キー=66.8x66.8
LLM のメモリ:   h1=LLM のメモリ    aspect=-      キー=-
データ転送:     h1=データ転送      aspect=1 / 1  キー=66.8x66.8
```

**6 つとも違う名前**なので、**巡回は別の画面を測っている**。**昨日の数は正しい。**
