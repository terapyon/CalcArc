## 6. 追加の指摘 —— **上部のボタンに `tab` ロールを付ける**（2026-09-03、別経路）

**★ 先の指摘と正面から食い違う。** 1-1 の「やらなくてよい」に
**「複雑なタブ UI や ARIA Tab パターンへ作り替える」が明示的に入っている。**

**★ 出どころを利用者に確認した。「人から気軽に言われた」**——自動検査の
指摘ではない。**利用者の裁定: 「難しければ無しでも OK」。**

### 現物（`web/src/ui/Nav/Nav.tsx`）

```
<nav aria-label="計算機の切り替え">
  <a href="#scientific"       aria-current={…}>Scientific</a>
  <a href="#convert/length"   …>Convert</a>
  <a href="#scale/data-scale" …>Scale</a>
  <a href="#finance"          …>Finance</a>
</nav>
```

**押すと URL が変わる。** ブックマークでき、共有でき、戻るボタンが効く。
`href` を既定カテゴリまで書いているのは設計上の裁定（`Nav.tsx:6-9` の註:
「`#scale` だと同じ画面に URL が 2 つでき、E2E の `toHaveURL` 期待が
その曖昧さを引き継ぐ」）。

### 結論 —— **見送る**

**ARIA の Tab パターンは「URL が変わらない、画面の中の切り替え」のためのもの。**
`role="tab"` を名乗ると契約が丸ごと付いてくる——`aria-selected`（**`aria-current`
ではない**）、`aria-controls` で `role="tabpanel"` を指す、**roving tabindex**、
**矢印キーでのタブ間移動**。

**いま矢印キーは何もしない。** `role` だけ付けると、**「タブ」と読み上げられた
利用者が矢印を押して何も起きない**——**いまより悪い。**

**クラス名が `styles.tab` なので見た目はタブである。** **視覚的なタブと ARIA の
Tab が別物である、というのがこの食い違いの正体。**

### ただし、感じ取られたものは当たっている

**「タブに見えるのに、いまどこに居るか分かりにくい」**——それに効くのは
`role` ではなく **1-1 の優先順位 1**（タイトル更新・隠した `<h1>`・`aria-live` の通知）。
**Tab パターンが与える「4 の 1」という位置の読み上げと同じ目的を、URL も
戻るボタンも壊さずに達成できる。** しかも **`<h1>` は `web/src` のどこにも無い**ので、
穴としてはそちらのほうが大きい。
