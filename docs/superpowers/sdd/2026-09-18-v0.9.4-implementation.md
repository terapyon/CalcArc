## 1. F14 —— 負の答えの符号が、次の値に残る

**利用者の実機**（出荷済みの 0.9.3）。`1 − 2 =` の答え −1 のあとに `5` で **−5**。

**原因は置き場が 2 つに分かれていたこと**——**数は `entry`、符号は `negative`**
（`fromSettled` が符号を受けないため）。**新しい入力は `entry` だけを空にしていた。**

**★ いつから在ったか**: **`020485b`（2026-08-20、換算の最初の実装）**。
**私は最初「0.9.2 から」と書き、1e が差分で見つけた**——**`git log -S` で当て直した**。
**間違った日付は、次に原因を辿る人を間違った差分へ送る。**

**DEL も同じ穴**（`1 − 2 = DEL 5` が −5）。**裁定は「見えないものは持たない」**
——**欄が空になったときだけ符号も落とす**。

### ★ 検査の表が、升を踏んでいなかった

**「1 本ずつ書くと組み合わせが抜けるので表で回す」と書いた、その表が抜けていた。**
**1 つの `it` に `.` と `000` を詰めたので、前半が残した `0.5` が後半の頭に付き、
`0.52 − 1 =` という別の式**になっていた——**3 行とも「負の答えのあと」を測り、
正 × `000`・ゼロ × `000` は 1 度も踏まれていなかった**（1e が発見）。

**直しは 2 つ**: **升ごとに画面を作り直す**ことと、**新しい値のキーを押す前に
「いまその答えが出ている」と主張する**こと。**後者が「踏んだつもり」を赤にする。**

**監視役の案は「1 度印字で確かめる」だった**が、**印字は見た人にしか効かない**
——**主張は次に壊した人にも効く**。**さらに部分一致でも足りなかった**
（`toHaveTextContent("値 -1")` は「値 -1.49」にも一致する。1e の変異 (c)）
——**末尾まで固定して初めて 3 行で効いた。**

## 2. F7 —— 大きな複素数の割り算が、エラー無しで 0 に

**外部報告**。`10^308 ÷ (10^308 + 10^308 j)` が **0**（真の答えは `0.5 − 0.5j`）。

**Smith 法は入っていたが、塞いだのは「二乗で溢れる」形だけ**だった。
**残っていたのは `d = re + im*t` そのものが溢れる形**である
（`|re| + im²/|re| > f64::MAX`）。**分子が有限なら `有限/inf = 0` に潰れ、
`finalize()` も捕まえない**——**base-spec §25 が禁じる「暗黙の overflow」。**

**★ 註が「この対策で塞がった」と読める形だった**のが出発点である。
**直しと同じコミットで、註を 3 段にした**: **①Smith 法が塞いだもの／
②スケーリングが塞いだもの／測っていないもの。**

### 直し

**分子と分母を、それぞれ 2 の冪で `[1,2)` へ寄せてから割り、商を `2^(ks−kn)` で戻す。**
**2 の冪倍は仮数を変えない**ので、**商は倍率に依らない**——**精度を足すのでも
削るのでもなく、中間値を安全な帯へ移すだけ**である。

**88 の 572 件で 80 → 8。** **静かに嘘の答え（24）と偽 Overflow（40）は 0 に。**
**「範囲外なのに値を返す」は前後とも 0**——**エラーにする範囲は広げていない。**

**残る 8 件は 1 ULP**（`e-320` の `double` 族の実部優勢・虚部優勢だけ。
**4 符号 × 2 形 = ちょうど 8**）。**許容は `testdata/*.json` の `rel = 1e-15`**
（裁定）——**許容をテストコードに書かない**ため。

**`mul_add` は測ってから退けた**（虚部が 25 ULP 悪化）。
**「融合すれば速くて正確」は一般には真でも、桁落ちの列では丸めの位置が変わる。**

### 呼び出し元は 2 か所だった

**`Value::checked_div` を呼ぶのは `tan = sin/cos` と engine の `BinOp::Div` だけ。**
**「5 か所」には `Rational::checked_div` が 3 つ混ざっていた**——**単位換算・為替・
式の評価は f64 を通らない厳密計算**で、**この壊れ方を初めから持っていない**。
**同じ名前の別の型の別の関数を、綴りで数えると混ざる。**

**`tan` は実際に直った**（`tan(1 + 710.4j)` は 0.9.3 で `Err(Overflow)`）。

## 3. 畳み込み・iPhone・下線

**iPhone のホーム画面のアプリから PDF を開くと、電卓に戻れない**（利用者の実機）。
**`target="_blank"` は効かない**——**iOS の standalone は同じ生成元への navigation を
アプリの窓の中で起こす**。**握っている口は応答のヘッダだけ**なので
`Content-Disposition: attachment` にした。**iOS はこの開発機に無いので、
「直った」とは書かない**——**確かめ方を註に書き、利用者が実機で見る。**

**`#manual` の画面はリンク集に畳んだ**（裁定）。**画面名は 14 → 13**。
**`#manual` は知らないハッシュに戻り、電卓に着く**（互換分岐は作らない）。

**下線は `text-decoration` だけ**（`text-underline-offset` も `padding` も足さない
——**行の高さが動く**）。**足したあとに測った**: 下部 33px・要る幅 288px・
複利の余白 33.31/22.28px——**前と同じ**。

## ★ この版で繰り返し出た形（**次の版へ**）

### 1. 規律は、読まれた場所でしか効かない

**`checked_div` の註に「『塞いだ』と読まないこと」と書いた直後、別のファイルに
「代償は測ってある」と書いていた**（**測っていなかった**）。
**規律は、書いたファイルの中でしか止めてくれない。**

**効かせたいなら置き先を変える**——**主張（assert）にするか、破れない構造にする**。
**同じ日に 3 回、それで効いた**:

- **表が升を踏んだか** → 印字ではなく**主張**に
- **下書きの SHA** → 注意書きではなく **`<SHA>` の穴**に（**貼れる数字を置かない**）
- **件数の読み違え** → 規律を思い出す前に**印字の上限を外す**

### 2. 測ってから書く

**「書いた数字を測って裏を取る」と「測ってから書く」は、結果が同じでも別の作業**
である。**前者は、数が合わないときに「測り方が悪いのでは」と思いやすい。**
**この版で 3 回出た**——監視役の「全部事実に変わっているはず」、私の「12 本」、
88 の「呼び出し元 5 か所」。**どれも先に書いた文に、あとから測定を合わせに行く形。**

### 3. 印字は 3 通りの欠け方をする

**上限で切れる**（`examples.len() < 6` で 6 行しか出ず、件数 8 を 6 と読みかけた）／
**段を回していない**（`heavy:ui` はタグの走行でしか回らず、12 本目・13 本目は
そこで初めて出た）／**型で混ざる**（`git grep checked_div` が `Rational` を拾った）。
**「見えている項目」は件数ではない。**

### 4. 生きている註は直す／過去の記録は直さない

**0.9.3 の CHANGELOG は書き換えない**——**あれは出た版の記録**で、
**`#manual` の画面は本当に 0.9.3 に在った**。**書き換えれば記録が嘘になる。**

**マニュアルは「いまどう動くか」を書く場所**で、**直した不具合は変更履歴の仕事**。
**★ ただし判別は時制ではない**——**「0.9.3 では戻れなくなった」（過去形）も
「ホーム画面からでも隠れない」（現在形）も、同じ「iPhone でこう動く」を
主張していて、どちらも測っていない。** **線は「何を主張しているか」。**
