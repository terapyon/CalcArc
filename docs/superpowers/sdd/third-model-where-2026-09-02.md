# 試験空間モデル 第 3 段の置き場——候補を測った（2026-09-02）

**モデルの本体はまだ書いていない。** **置き場を実測で決めるところまで**である。

**出発点は引き継ぎ §2 の材料 3**——「第 3 段階をどこへ置くか。`convert` は候補から
外してよい（軸が 2 本、単位はすでに満点。**産物が当てる前に分かっている**）」。

## 判定の物差し（3 つ）

1. **軸が何本あるか**（データから読める／読めないと思える、を分けて）
2. **いまのコーパスが水準をどれだけ覆っているか**
3. **★ 産物が当てる前に分かっているか**——**`convert` を外した理由がこれ**

**★ そして第 2 段の教訓を効かせた。** あちらでは**「この軸はキー列から読めない」と
宣言していた 6 軸のうち、正しかったものが 1 つも無かった。**
**だから「読めない」と思った軸を、根拠を現物で確かめずに外していない。**

## 覆われていない領域（実測）

**コーパス 19 枚のうち、`scientific-v1` が 11 枚、`finance-v1` が 1 枚を覆う。
残り 7 枚:**

```
corrections 2000 / data-scale 2000 / entry 36 / equivalence 2000
errors 30 / scientific 2000 / typed 2000
```

**`testdata/` 側で、まだモデルが当たっていないもの:**

```
convert 55（外す） / currency 43 / data_scale 28 / llm 18 / transfer 11
```

## 候補ごとの実測

### ★ 推し: `llm`（18 件、軸 7 本）

| | |
|---|---|
| 軸 | **7 本**——`parameters` / `weight_precision` / `layers` / `kv_heads` / `head_dim` / `context_length` / `kv_precision` |
| 水準の一次資料 | **`PRECISION_TOKENS`（5）と、KV から `int4` を外した 4**（`web/src/ui/Keypad/llm.ts:47` が理由ごと書いている） |
| 被覆 | **重み × KV の精度: 9 / 20**（仕様の水準で。覆われていない 11 組を名指しできる） |
| 産物 | **★ 当てる前に分からない** |

**測って初めて出たもの:**

- **`fp8` が golden に在るのに `PRECISION_TOKENS` に無い**——2 件とも
  `SyntaxError` を期待する**エラー経路**だった。**盤面が出せない綴り**である
- **精度の組は 9/20。** 覆われていないのは
  `fp32×fp32` `fp32×bf16` `fp32×int8` `fp16×fp32` `fp16×bf16` `fp16×int8`
  `bf16×fp32` `bf16×bf16` `bf16×int8` `int4×fp32` `int4×bf16`
  ——**「重みと KV が同じ精度」がほとんど無い**（`fp32×fp32` も `bf16×bf16` も空）
- **18 件で 7 軸**である。**pairwise が覆えないことは事前に分かる**が、
  **どの組が空かは分からなかった**

### 次点: `transfer`（11 件、軸 4 本）

| | |
|---|---|
| 軸 | **4 本**——`bandwidth` / `bandwidth_unit` / `duration` / `duration_unit` |
| 水準の一次資料 | **`transfer_ref.BANDWIDTH_FACTOR`（4）と `DURATION_FACTOR`（4）** |
| 被覆 | **単位の組: 6 / 16** |
| 産物 | **当てる前に分からない**（ただし `llm` より軸が少ない） |

**測って初めて出たもの:**

- **`tbps` と `week` は仕様の表に無い**——golden の 5 水準に見えたのは、
  **エラー経路 2 件が混じっていた**からである。**仕様では 4×4 = 16**
- **覆われていない 10 組**: `bps×day` `bps×hour` `bps×minute` `gbps×minute`
  `kbps×day` `kbps×hour` `kbps×second` `mbps×day` `mbps×minute` `mbps×second`

**次点にした理由は 2 つ。** **軸が 4 本で `llm` の 7 本より狭い**こと、
**11 件しかないので「足す」以外の結論になりにくい**こと。

### `data-scale`（コーパス 2000 + golden 28、軸 3 本）——**有力だが 3 番手**

**1-way は満点に見える**（`dtype` 10 水準すべてに件数あり）。**組で見ると違う:**

```
dtype × count の帯   26 / 60 のセルが覆われている
  ★ 負とゼロは int8 にしか無い（各 1 件）
  ★ float128 は「小」の 1 件だけ（他の dtype は 200 件前後）
```

**「1-way 満点／組は 43%」という形は、`convert` と違って産物が事前に
分からない。** **3 番手にしたのは、軸が 3 本で `llm` より狭いから**である。

### 外す候補と、その理由

| 候補 | 外す理由 |
|---|---|
| `convert` | 引き継ぎの裁定どおり（軸 2 本・単位 63/63 満点） |
| **`corrections`** | **軸が実質 1 本。** 層 4 つは満点で、**訂正キー（`ac`/`del`）は層で決まる**（`ac-rebuild`/`error-recovery` → `ac`、`paren-edit`/`typo-del` → `del`。実測）——**独立した 2 本目の軸ではない** |
| `entry`(36) / `errors`(30) | **手で書いた固定の列挙**であり、**数え上げが仕様そのもの**。モデルを当てても写すだけ |
| `scientific-000` | **`scientific-v1` と軸が重なる**（現れる関数は `sin/cos/tan/neg/sqr/sqrt` の 6 種で、9 領域が既に持つ） |
| `currency` | **未測**（下記） |

### ★ `typed` は外していない——ただし単独では薄い

**軸は「打ち方」3 本**（`dot` / `zeros3` / `exp`）。**8 通りのうち 6 通りが在る:**

```
在る: (素) / dot / zeros3 / dot+zeros3 / dot+exp / dot+zeros3+exp
★ 無い: exp 単独 / zeros3+exp
```

**`exp` が `dot` 無しで 1 度も現れない**——**これは当てる前に分からなかった。**
**軸が 3 本で狭いが、`llm` に足すなら「打ち方」の軸として使える。**

## 推しと次点

**推し: `llm`。** **軸が 7 本で最多**、**18 件しかない**、**水準の一次資料が
コードに在る**（`PRECISION_TOKENS` と、KV から `int4` を外した理由）、
**そして測って初めて出たものが 2 つあった**（`fp8` の綴り、精度の組 9/20）。

**次点: `transfer`。** **軸 4 本・11 件で、仕様の 16 組中 6 組。**
**単位の表が一次資料としてきれい**だが、**`llm` より狭い。**

## ★ 実測でなく、推測に留まる部分

**ここから下は測っていない。**

- **`currency`（43 件）を測っていない。** 軸は `from` / `to` / `from_rate` /
  `to_rate` / `value` の 5 本に見えるが、**通貨の水準がどこに在るか（仕様の表か、
  golden から起こしたものか）を確かめていない。** **`llm` より軸が多い可能性がある**
- **`equivalence`（2000 件）の軸を起こせていない。** **「何と何が等価か」を
  仕様がどう定めているかを読んでいない**——**軸が在るのに読めていないだけ**
  かもしれない。**第 2 段で 6 回間違えた形なので、外したとは書かない**
- **`llm` の残り 5 軸**（`parameters` / `layers` / `kv_heads` / `head_dim` /
  `context_length`）**の水準を、仕様から起こしていない。** 精度 2 軸だけ
  一次資料に当てた。**盤面には `1B`〜`70B` の presets が在る**ので、
  **そこが水準の出どころになりうる**（未確認）
- **「産物が当てる前に分かるか」は、当ててみるまで完全には言えない。**
  ここで言えているのは**「私が測る前には分からなかった」**までである
- **どの候補も、モデルを当てたときの要求セル数を見積もっていない。**
  第 2 段は 78 セルだった（実測）

# 追測（2026-09-02、同日）——`currency` と `equivalence` を空けたまま確定しない

**前半で「`currency` は軸の数で `llm` を上回る可能性がある」「`equivalence` は
在るのに読めていないだけかもしれない」と書いて、どちらも測っていなかった。**
**その 2 つを埋めた。**

## `currency`（43 件）——**外す。産物が当てる前に分かる**

**水準の一次資料は `currency_ref.MINOR_UNITS`**——**ISO 4217 List One の
minor unit で、16 通貨・小数桁は 0 か 2 のみ**。**spec §3.1 が
「0 か 2 のどちらか」という単純さを明示的に選んでいる**（小数桁 3 の
`KWD` `BHD` などを入れない、と書いてある）。**2026-08-20 に `list-one.xml` と
16 行すべてを突き合わせた記録つき。**

**被覆（実測）:**

```
通貨            16 / 16      触れていないものは無い
★ 小数桁の組    4 / 4        from 桁0×to 桁0 が 10 件、0×2 が 1、2×0 が 7、2×2 が 24
エラー経路      3 種すべて   Overflow 4 / SyntaxError 5 / DivisionByZero 1
値の帯          負 6・ゼロ 1・整数 28・小数あり 8
レートの帯      ゼロ 1（DivisionByZero 用）・構文外 2
```

**仕様が言う唯一の構造的な区別（小数桁 0 と 2）は 4 組すべて覆われている。**
**`convert` と同じ形**である——**当ててもモデルは「満点」としか言わない。**

**★ 軸の数では `llm` を上回らなかった。** 通貨の 16 は**水準であって軸ではなく**、
**構造としては「小数桁 2 値 × 2 辺」に畳まれる**（仕様がそう畳んでいる）。

## `equivalence`（2000 件）——**残す。ただし単独では小さすぎる**

**「読めない」で外さなかったのは正しかった。読めた。**

**水準の一次資料は `EQUIVALENCE_FORMS = 3` と `_equivalent_pair`**
（`generate_corpus.py`）——**生成器が名前で 3 つの形を選んでいる:**

```
sqrt_round_trip   √(x²)        ★ 非負のときだけ（負では成り立たない）
double_negation   -(-x)        負でも成り立つ
plus_zero         x + 0        負でも成り立つ
```

**そして 3 つともキー列から読める**（右辺の末尾 3 キー。実測）:

```
plus_zero        809
double_negation  787
sqrt_round_trip  404
```

**★ 2 本目の軸（値の符号）は、読めないが記録できる。**
**生成器は符号を知っている**——`_equivalence_candidate` は `value` を返しており、
docstring が**「生成器のテストが『負の値が実際に残っているか』を見られるように
するため」**と書いている。**しかしケースに書いていない。**
**`cancellation/shape` と同じ形である**（第 2 段で「測れない」と宣言していたが、
実は「記録していない」だけだった）。

**キーから読もうとすると engine の移植になる**——それは生成器自身の
コメントが書いており、**正しい理由である**。

**要求セルは 3 × 2 = 6、うち 1 つ（`sqrt_round_trip × 負`）は仕様が
不可能と言っている → 5 セル**（実測前の数え）。**小さすぎて単独では当てる
価値が薄い。**

## 要求セル数の見積り（**すべて実測前**）

**第 2 段は 78 セルだった（実測）。桁を揃えて比べる。**

| 候補 | 1-way の内訳 | 選択ペア | 合計（実測前） |
|---|---|---|---:|
| **`llm`** | parameters 8 / kvHeads 6 / headDim 5 / context 7 / weight 5 / kv 4 / layers 帯 4 | 重み × KV = 20 | **約 59** |
| `transfer` | 帯域幅の単位 4 / 時間の単位 4 / 帯域幅の帯 4 / 時間の帯 4 | 単位の組 = 16 | **約 32** |
| `data-scale` | dtype 10 / count 帯 5 / dimensions 帯 5 | dtype × count = 50 | **約 70** |
| `equivalence` | 形 3 / 符号 2 | — | **約 5** |
| `currency` | 通貨 16 / 小数桁 2 / 帯 4 | 小数桁の組 = 4 | 約 26（**が、すでに満点**） |

**`llm` と `data-scale` が第 2 段（78）と同じ桁**である。
**`transfer` は半分、`equivalence` は 1 桁小さい。**

## ★ 推しを確定する: `llm`。変えない

**追測で変わらなかった。** **`currency` は満点、`equivalence` は小さすぎる。**

**そして追測で `llm` の根拠が 1 つ増えた。** **盤面が出す presets を、
golden はほとんど踏んでいない:**

```
parameters        2 / 8    踏んだのは 8B と 27B だけ
kv_heads          3 / 6
★ head_dim       1 / 5    128 だけ
context_length    2 / 7    4096 と 8192 だけ
weight_precision  5 / 5
kv_precision      4 / 4
★ 合計           17 / 35
```

**精度の 2 軸だけが満点で、数の 4 軸は半分以下**である。
**`head_dim` は 5 水準のうち 1 つしか踏んでいない。**

**水準の一次資料は `web/src/ui/Keypad/llm.ts` の `CANDIDATE_VALUES`**
——**盤面が実際に出すボタンの値**であり、**「利用者が押せる水準」そのもの**である。
**第 2 段の `Rad × 逆三角` と同じ形**——**押せるのに 1 件も無い**。

**次点は `transfer` のまま。** **軸 4 本・仕様の 16 組中 6 組**で穴は明確だが、
**セル数が第 2 段の半分以下**で、**11 件しかないので「足す」以外の結論に
なりにくい。**

**3 番手の `data-scale` は、セル数では `llm` に並ぶ**（約 70）。
**`llm` を採ったのは、`llm` のほうが「押せるのに踏んでいない」が濃いから**である
——`data-scale` の穴は**帯の組**（26/60）で、**`llm` は水準そのもの**（17/35）。

## この追測で、推測に留まる部分

- **要求セル数は全部（実測前）である。** **因子表を書くまで確定しない**
- **`llm` の `layers` に presets が無い**（自由入力）。**帯を私が起こすことになる**
  ——**第 2 段で 6 回間違えた形**なので、**着手時は仕様に切れ目が在るかを先に当てる**
- **`equivalence` を「単独では小さい」と書いたが、他の候補に足す形は測っていない**
  ——**`typed`（打ち方 3 本）と合わせると「打鍵の等価性」という括りになりうる**（未検討）
