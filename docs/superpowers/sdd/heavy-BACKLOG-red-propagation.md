## 何が問題か

`heavy-corpus.yml` の `corpus` ジョブは、**コメントで宣言した含意を守る仕掛けを
持っていない。**

`:112-116` のコメント:

> **これが固定コーパスの土台である。** コミットされた JSON が生成器の出力と
> 1 バイトでも違えば、期待値が手で触られたことになる。**ここが赤いまま下の照合が
> 緑でも、その緑は何も意味しない。**

**順序は守られている。しかし含意は守られていない。** 2026-08-27 に監視役が全ステップの
`if:` を並べた結果（**実測**）:

| 段 | `if:` |
|---|---|
| 固定コーパスの再現性 | （なし） |
| 検出力の測定（`heavy:power`） | （なし） |
| 盤面を叩く（`heavy:ui`） | `always()` |
| コーパスの照合（`heavy`） | `always()` |
| 判定をサマリーへ / artifact | `always()` |

**再現性が赤でも、照合は `always()` で走って緑になれる。**

## 同じ穴の別の面（2026-08-27 に固定した 2 件と地続き）

**検出力の測定には `if:` が無いので、再現性が赤だと飛ばされる。** すると報告書の
検出力の節が「測っていない」になる——**`heavy:power` を順序で固定して潰したばかりの
症状が、別経路で出る。**

つまり `release-workflow.test.ts` の「レポートを書く段は最後」で固定した 2 件と、
この項目は**同じ穴の別の面**である。順序ピンでは解けない。

## 選択肢（少なくとも 3 つ。どれも一長一短）

1. **再現性が赤なら後続を止める。** 含意に忠実。ただし「片方の赤でもう片方を隠さない」
   という既存の方針（`:130-133` と `:150-155` のコメント）と正面からぶつかる。
2. **報告書が「土台が赤だった」ことを載せる。** 走行は全部やり切り、読み手に伝える。
   `uiHealth` の 4 状態と同じ作りにできる。**報告書の状態が 1 つ増える。**
3. **`always()` の意味を分ける。** 「集めるため（artifact・サマリー）」と
   「判定のため（照合の緑）」を別の条件にする。いちばん素直だが、いちばん手が入る。

- 「片方の赤でもう片方を隠さない」の方針が今も生きているか（コメントの日付を見る）
- 報告書の 4 状態（`uiHealth`）が、この設計とどう噛み合うか
