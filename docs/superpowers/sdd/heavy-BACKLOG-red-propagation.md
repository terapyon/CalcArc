# 先送り: 重量級の走行で「赤をどう伝播させるか」（2026-08-27 起票）

**0.5.0 には入れない。** 締め切りの中で選ぶと選び方を間違える種類の問題だ、という
判断（監視役 calcarc-25 と合意）。**0.5.0 の後に設計として扱う。**

## 何が問題か

`heavy-corpus.yml` の `corpus` ジョブは、**コメントで宣言した含意を守る仕掛けを
持っていない。**

`:112-116` のコメント:

> **これが固定コーパスの土台である。** コミットされた JSON が生成器の出力と
> 1 バイトでも違えば、期待値が手で触られたことになる。**ここが赤いまま下の照合が
> 緑でも、その緑は何も意味しない。**

**順序は守られている。しかし含意は守られていない。** 2026-08-27 に監視役が全ステップの
`if:` を並べた結果（**実測**）:

| 段 | `if:` |
|---|---|
| 固定コーパスの再現性 | （なし） |
| 検出力の測定（`heavy:power`） | （なし） |
| 盤面を叩く（`heavy:ui`） | `always()` |
| コーパスの照合（`heavy`） | `always()` |
| 判定をサマリーへ / artifact | `always()` |

**再現性が赤でも、照合は `always()` で走って緑になれる。**

## 同じ穴の別の面（2026-08-27 に固定した 2 件と地続き）

**検出力の測定には `if:` が無いので、再現性が赤だと飛ばされる。** すると報告書の
検出力の節が「測っていない」になる——**`heavy:power` を順序で固定して潰したばかりの
症状が、別経路で出る。**

つまり `release-workflow.test.ts` の「レポートを書く段は最後」で固定した 2 件と、
この項目は**同じ穴の別の面**である。順序ピンでは解けない。

## 選択肢（少なくとも 3 つ。どれも一長一短）

1. **再現性が赤なら後続を止める。** 含意に忠実。ただし「片方の赤でもう片方を隠さない」
   という既存の方針（`:130-133` と `:150-155` のコメント）と正面からぶつかる。
2. **報告書が「土台が赤だった」ことを載せる。** 走行は全部やり切り、読み手に伝える。
   `uiHealth` の 4 状態と同じ作りにできる。**報告書の状態が 1 つ増える。**
3. **`always()` の意味を分ける。** 「集めるため（artifact・サマリー）」と
   「判定のため（照合の緑）」を別の条件にする。いちばん素直だが、いちばん手が入る。

## 進捗（2026-08-29、ユーザー裁定）

**裁定は「(2) の信号を先に作って、(3) に進む」。** 理由は、(2) は単独では番人に
ならないが **(3) の中で必要になる**から——土台の赤で後続を飛ばすなら、**飛ばされた
ことを報告書が言えないと「測っていない」の曖昧さがむしろ増える。**

### (2) は入った（枝 `feat/reproducibility-signal`）

再現性検査が `heavy/reproducibility.json` を書き、報告書が読む。状態は 5 つ
（確かめていない／古い／途中で落ちた／食い違っている／通った）。
**「測っていない」の 2 つの理由が、報告書の上で別の文になる。**

**★ この信号は (3) の門の前提である。** (3) が土台の赤で後続を飛ばすようにすると、
報告書の「測っていない」は**飛ばされた結果**になる。**そのとき信号が無ければ、
読む人には回し忘れと区別できない。** つまり (2) は (3) の**部品**であって、
単体で完結する改善ではない。

### 次にやること: **(3) `always()` の意味を「集める」と「判定する」に分ける**

**これが次の spec である**（この台帳の項目ではなく、**名前のある次の作業**）。
持ち主は**重量級セッション**。着手時に確かめること:

- `always()` を**①集めるため**（artifact・サマリー・ブラウザ導入）と
  **②赤を独立させるため**（盤面の赤で計算の赤を隠さない）に仕分ける
- **順序ピン（`tools/tests/release-workflow.test.ts`）は障害ではなく条件である。**
  組み替えて壊せばピンが赤くなる
- **本当の代償は「入ったことを確かめる手段」である**——`always()` の付け外しは、
  **「赤くなるべき日」を人為的に作らないと入ったか分からない。** その道具は
  (2) の赤確認がそのまま使える（期待値を 1 バイト書き換えて `pnpm heavy` を回す）

**チャットの中にだけ住む宿題は消える**（T-5 で踏んだ型）。**ここに名前で書いた。**
