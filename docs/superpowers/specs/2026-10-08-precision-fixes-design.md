## §1 F2: `ln`・`log` が印 k=0 を読む

### §1.1 形——**`apply_trig` と同じ形の `apply_log` を 1 つ足す**

- 今の `apply_unary(state, f, mark)` は、`f` に `Value` しか渡さない。`ln` が印を読むには、**印つきの値（`Held`）を見て値の計算を選ぶ**形が要る。
- **`apply_unary` を広げない。** 広げると、印を読まないほかの後置関数すべての呼び方が変わる。
- **`apply_trig` と同じく、専用の小さな遷移を 1 つ足す**（`fn apply_log(state, base)`。`engine/mod.rs` の中で private）。値の計算は次の順:
  1. **今の `scientific::ln`（または `log10`）を先に呼ぶ**——**定義域の誤り（`x ≤ 0`・複素）は今と同じ道で出る**。
  2. 引数の印が k=0 で、虚部が 0 で、**`1/2 ≤ q ≤ 3/2`** なら、`log1p(q − 1)` で値を置き換える。`log10` は `log1p(q − 1) × LOG10_E`。
  3. 印は今と同じく落とす（`ln` の答えは一般に無理数）。

### §1.2 `log1p` を使う範囲——**`1/2 ≤ q ≤ 3/2`**

- **常に使うと、遠ざかる値が出る**（試作で実測）。
  - 「常に」: `elementary` の 219 件で生の f64 が動き、**172 件が遠ざかった**。
  - **`q ≥ 1/2` に限ると 156 件・遠ざかる 111 件**（例 `ln(log10(487))`。`log10` を `log1p × LOG10_E` にすると、1 から遠い引数では丸めが 1 回増える）。減った 63 件は q < 1/2 の分で、そこでは `q − 1` を f64 にした丸めが `q` 自身の丸めより大きくなる（理屈どおり）。
  - **`1/2 ≤ q ≤ 3/2` に限ると、`elementary` は 1 件も動かない**。動くのは `cancellation` の 365 件だけで、**365 件すべてが近づいた**。`q ≤ 2` に広げても数は同じだった。
- **桁落ちが起きるのは 1 の近くだけ**なので、範囲を 1 の近くに絞るのが式の意味にも合う。

### §1.3 `q − 1` は有理数で引いてから f64 にする——番人を 1 つ置く（条件 2）

- **`q − 1` を有理数で引いて `ratio_to_f64(n − d, d)` で f64 にしてから `ln_1p` に渡す。** f64 で `q.to_f64() − 1.0` と引くと、引く前の丸め（相対 1.1e-16）が答えの大きさ（1e-7 級）に対して増幅され、直しの意味が無くなる。
- **番人**: `1.000000117 ln` の生の値が、**`ln_1p(117e-9 を正しく丸めた f64)` とビット一致する**ことを単体テストで主張する（**試作で一致を確かめた**。真値との相対は 1.1e-16）。
- **註（数の読み方）**: 第 1 版の §5.2 の「cancellation の最大相対誤差 3.8e-10（canc-001137 = `1.000000117 ln`）」は、**10 桁に丸めた表示の誤差**であり、計算の誤差ではない（重量級の報告書と同じく、表示を読み直して比べた値）。**試作も有理数で引いており、生の値の相対誤差は 1.1e-16** だった。**表示の誤差は 10 桁の丸めで最大 5e-10 まで出る**ので、3.8e-10 は丸めそのものである。**§0 と §5 の「最大」は、実装の日に生の値と表示の両方で取り直す。**

### §1.4 i128 が溢れたとき

- `q − 1` は `(n − d)/d` で、`1/2 ≤ q ≤ 3/2` なら `|n − d| ≤ d` なので**溢れない**（分子も分母も `q` 自身の範囲に収まる）。
- **それでも `checked_sub` が `Err` を返したら、印を使わずに今の f64 の答えを返す**（1.2.2 と同じ「印が使えなければ今の道」）。**エラーにはしない。**

**`1 ln` の答えに印 `(0, k=0)` を付けるか**は、実装の判断として残す（注記）。付けないと `1 ln + π = sin`（RAD）は `1.224646799e-16` のまま、付ければ 0 になる。**付けるなら、`log1p(0) = 0` は厳密なので嘘にはならない。**

## §2 F3: DEG で表に載らない分数の角を、印のまま畳む

### §2.1 順——**「印が表 → f64 が表 → どちらでもないときだけ畳む」**

```text
exact::turn(arg, mode)
  = 印から決めた正体（今と同じ。RAD k=1 の表と畳み、DEG k=0 の整数の表）
  or scientific::turn_of(arg.value, mode)   // f64 の規則（今と同じ）
  or 畳み（新しい）: DEG で印が k=0、分母 ≠ 1 のときだけ
```

- **畳みを先に当ててはならない**（台帳の条件 1）。`30 + 1 EXP 15 +/− = sin − 0.5 =` は、f64 の和が 30.0 ちょうどなので f64 の規則で表に載り、今は `0`。畳みを先にすると `-5.551115123e-17` に後退する。
- **分母が 1 の印（整数の角）は畳まない。** 整数は f64 で厳密なので、今の `re % 360` で既に厳密である。**試作で整数の角も畳み直したら、生の f64 が 738 件動き、142 件が遠ざかった**（(−180, 180] に寄せたことで丸めが変わるため）。**分母 ≠ 1 に限ると 165 件で、遠ざかるのは 9 件（最大で相対 1.2e-15）**。
  - **実装の註（2026-10-08、再レビュー）**: 738・142・165・9・1.2e-15 は **(−180, 180] に寄せた試作の数**で、**実装（切り捨ての剰余。§2.2）には当てはまらない**。**実装での当て直しは未確認**（試作は実行役が読まない取り決めなので回していない）。整数の角を畳まない理由として残るのは「**`|q| ≤ 2^53` の整数は f64 で厳密なので、`% 360` が既に厳密**」だけで、**2^53 を超える整数は f64 で厳密ではない**（既知の欠陥。台帳 `../sdd/2026-10-06-rust-review-backlog.md` §6）。

### §2.2 畳んだあとの f64 化

- `r = n % (360·d)`（**切り捨ての剰余。符号は `n` と同じ**——`to_rad` の `re % 360.0`（IEEE の `fmod`）と同じ向きにそろえる。(−180, 180] に寄せない）。
- `x = ratio_to_f64(r, d)?.to_radians()` で `Turn::Folded(x)`。**`ratio_to_f64` を再利用する**（RAD の `pi_turn` と同じ。正しく丸める）。
- **`360·d` が i128 で溢れたら `None`**——今の f64 の道に戻る（エラーにしない）。

### §2.3 tan の極と複素

- **極は表の位置（90°・270°）にしか無い。** 分母 ≠ 1 の角はちょうど 90° にならないので、畳んだ角は極にならない。**ただし f64 が 90.0 ちょうどになる角**（`90 + 1 EXP 15 +/−`）は、§2.1 の順で f64 の規則が先に表を引き、**今と同じく TrigPole**（1.0.0 からの挙動。監視役の注記 (4)）。**この設計はそれを変えない。**
- **複素**: 畳むのは実部の正体だけで、虚部は `to_rad` のまま（1.2.2 の §4.4 と同じ）。`Turn::Folded` は既に複素の公式 `sin x·cosh y` の `sin x` に入る作りで、RAD の k=1 と同じ経路を通る。**印は `re` の正体なので、虚部があっても畳める。**

## §3 F1: √ の印

### §3.1 型——**`Exact` に種類を足さず、`Held` に欄を 1 つ足す**

```rust
// engine/exact.rs に Exact と並べて置く
#[derive(Debug, Clone, Copy, PartialEq, Serialize, Deserialize)]
pub struct Root { c: Rational, r: Rational }   // re == c × √r、r > 0。欄は private。
                                              // serde は Exact と同じく rational_text("num/den")

pub struct Held {
    pub value: Value,
    pub exact: Option<Exact>,
    #[serde(default)]
    pub root: Option<Root>,   // 新しい
}

/// 印の計算の戻り値を 1 つにまとめる（条件 1）。
pub struct Marks { exact: Option<Exact>, root: Option<Root> }
impl Marks { pub const NONE: Marks = …; }
```

**運び方は 1 つにそろえる（レビュー役の条件 1）**:
- **今の `apply_unary(state, f, mark: fn(Held) -> Option<Exact>)` では root を作れず運べない**——`√`（作る）・`+/−`（符号を反転して運ぶ）・`x²`（root を印 `c²r` にする）の腕は root を返せず、`Held::settled(value, exact)` を通ると root が `None` になる。
- そこで **印の関数の戻り値を `Marks` にし、`mark: fn(Held) -> Marks`、`Held::settled(value, marks)` にそろえる。** 二項演算（`exact::add` など）と三角関数（`exact::sin` など）の印の関数も同じ `Marks` を返す。
- **`exact::dropped` は `Marks::NONE` を返す。** 既存の 12 の腕は `Marks { exact, root: None }` を返すだけで、規則は変わらない。
- **専用の遷移を 3 つ足す案は採らない**——新しい `pub` は `Held.root` の欄と `Root`・`Marks` の型名だけで済む。

- **`Exact` を enum にしない理由**: `Exact` を読む関数（`add`・`sub`・`mul`・`div`・`neg`・`sqr`・`recip`・`turn`・`sin`・`cos`・`tan`・`settled`）が全部、新しい種類の腕を持つことになる。**√ の印が意味を持つのは「√ の直後」と「桁落ちする ± の 1 段」だけ**なので、別の欄にして、読む所を 3 つ（§3.2）に閉じ込める。
- **不変: `root` が `Some` のとき `exact` は `None`**（√ の答えは一般に無理数）。
- **`Held::settled` の丸め直し（k=0 の印から `re` を作り直す、1.2.2 の段階 2）は root には及ばない。** root を持つ値の `re` は √ の f64 のままである（√ の答えを正しく丸める手段が無いので、作り直さない）。
- **`Root` の欄は private**、`Copy`。作る道は `exact.rs` の中の `√` の印の関数 1 つだけで、`pub` の面に `Root` の作り方を出さない（§8）。

### §3.2 伝わり方の表

| 演算 | 引数 | 結果 |
|---|---|---|
| `√` | 印 k=0、`q > 0`、実数 | `root = (1, q)` |
| `√` | 印 k=0、`q = 0` | 今と同じ（`(0, k=0)`） |
| `√` | それ以外 | 今と同じ（印なし） |
| `+/−` | `root = (c, r)` | `root = (−c, r)` |
| `x²` | `root = (c, r)` | **印 `(c²·r, k=0)`**——√ を 2 乗すると有理数に戻る（`2 √ x² − 2 =` が 0 になる） |
| `a ± b` | どちらかが `root`、もう片方が `root` か k=0 の印、両方実数 | **桁落ちするなら書き換え**（§3.3）。しないなら今と同じ |
| ほかのすべて（`×`・`÷`・関数・`=` の繰り返しなど） | | **`root` を落とす**（今と同じ f64 の道） |

**`×`・`÷` で保たない**のは、1.2.3 の範囲を最小にするため（`2 × √3 − √12` は保てば書き換えられるが、コーパスにも利用者の報告にも無い）。**保つ範囲は後で広げられる**——欄が別なので、広げても `Exact` の規則は動かない。

### §3.3 書き換えは「二項演算を畳む段」で——`apply_binop` の `Add`・`Sub` の腕

- **√a と √b は、それぞれ別の値として被演算数のスタックに積まれる**（`√` は後置関数で、押した瞬間に `current` に入る）。**両方を同時に読めるのは、二項演算を畳む `apply_binop(op, lhs, rhs)` だけ**である。そこで書き換える。
- **書き換え**: 各項を「符号と 2 乗」で読む（`root = (c, r)` なら符号 `sign(c)`・2 乗 `c²r`。k=0 の印 `q` なら符号 `sign(q)`・2 乗 `q²`）。`−` なら右の符号を反転する。
  - **符号が同じ**（足し合わせになる）なら、桁落ちしないので今と同じ f64 の和。
  - **符号が逆で、2 つの大きさが 2 倍以内**（`|A|/2 ≤ |B| ≤ 2|A|`。**f64 ではなく 2 乗の有理数で比べられる**——`A²/4 ≤ B² ≤ 4A²`。レビュー役の注記）なら、**`(A² − B²) ÷ (|A| + |B|)`** に符号を付けた値にする。分子は有理数で厳密、分母は正の数の和で桁落ちしない。分子が 0 なら答えは `(0, k=0)`。
  - **2 倍の門を置く理由**（試作で実測）: 門を置かずに書き換えると、桁落ちしない引き算（`667 ÷ 833 = − 334 √ =` など）でも丸めが 1 回増え、生の f64 が 49 件動いて 19 件が遠ざかった。**門を置くと 19 件動いて遠ざかるのは 2 件**（相対 1.9e-16 まで）。
- **【実装時の註 2026-10-08】答えの符号は `s × sign(A² − B²)`**（`s` は左の項の符号、`sign(A² − B²)` は
  分子の符号）であり、**式は `s × (A² − B²) ÷ (|A| + |B|)`** になる。上の「符号を付けた値」は、
  **どの符号かを書いていなかった**——左の項の符号だけを付けると、右の項のほうが大きい差
  （`2 √ − 3 √ =`）が `+0.3178372452` に化ける（正しくは `-0.3178372452`）。**実装はこの書き漏らしの
  とおりに入り、`34b3d26` で直した**（番人は engine_table の
  `a_rewritten_difference_keeps_the_sign_of_the_larger_side`）。
- **√a − √b 以外に効く形**: `√a − q`・`q − √a`（有理数との差。例 `15241383943 √ − 123456 =`）と、`−√a + √b`（`+/−` で符号を入れた和）。どれも同じ書き換えで直る。

### §3.4 STATE_SCHEMA と保存済みの状態

- **`EngineState` の形が変わる**（`Held` に欄が増える）ので、**`STATE_SCHEMA` を 9 → 10 に上げる**。
- **`EngineState` は保存されない**（`web/src/settings/index.ts`「STATE_SCHEMA とは別物……保存しない」）。**保存済みの状態の移行は要らない。** 欄には `#[serde(default)]` を付ける（境界の往復で欠けても `None`）。

### §3.5 i128 の溢れ

### §5.1 typed-001490 の上書きを外す

### §5.2 cancellation の許容を表示分解能（5e-10）に締める

- **今は rel 1e-6**（`generate_corpus.py` の `CANCELLATION_TOLERANCE`。註は「表示分解能では実測で 99.8% が外れ、スイートが永久に赤くなる」）。
- **3 つを入れた試作で、cancellation の最大相対誤差は 3.8e-10**（canc-001137。**10 桁の表示を読み直した誤差**で、生の値は 1.1e-16。§1.3 の註）。**5e-10 に締めても赤は 0 件**。
- **締めないと、この直しは重量級で見張れない**——1e-6 のままでは、F1 を外しても誤差 2.08e-7 は許容の内側で緑のままである。
- **締めたときの赤**（試作で直しを 1 つずつ外して実測）:
  - F1 を外す → cancellation **521 件**
  - F2 を外す → cancellation **42 件**（真値の 10 桁と違う 223 件のうち、相対誤差が 5e-10 を超えるもの）
  - F3 を外す → typed **1 件**（§5.1 で上書きを外した場合）
- **【実装時の註 2026-10-08】許容には写しがあった。** `corpus_science.py` の `CANCELLATION_TOLERANCE_REL`（1e-6）は
  シャードの `tolerance.rel` の写しで、**帯の切れ目**（`near_tolerance` / `mild`）として使われ、テストが等しさを見ていた。
  重量級担当の裁定で、**切れ目は 1e-6 のまま許容から切り離し**、`CANCELLATION_NEAR_CUT` に改名した。新しい理由は
  「近さの比 r の 2 数を f64 で素朴に引くと相対誤差は約 u/r（u = 2^-53）。r = 1e-6 で 1.11e-10、許容 5e-10 の約 1/5」。
  テストは `rel / 10 < u / CUT <= rel` の関係を見る（許容を 1e-6 に戻す・切れ目を 1e-5・1e-7 に動かすの 3 つで赤を確認）。
  **帯の分布（571 / 1,429 / 2）とシャードの差分（tolerance の 1 行）は動かない。**
- **既存の変異 `display-digits` が cancellation にも反応するようになる**（9 桁にすると 2,002 件中 586 件が 5e-10 を超える。試作の表示から計算）。`detection-power.mjs` の表にこのシャードを足し、床を置く。

### §5.3 10 桁で比べる網——**常設を推す（Rust の native テストで）**

## §6 版の切り方——**推し: 1 本にまとめる**

- **推しは 1 本**（F1・F2・F3 と重量級の締め直しを同じ版に）。

## §7 マニュアルと CHANGELOG

- **CHANGELOG**: 利用者向けの節に 3 行（数の例は実物の印字から取る）。

## §8 Rust の書き方（利用者の方針「Rust の追加は慎重に」）
