## §0 なぜ作るか——**利用者の言葉**

> **式と結果を表示する。たとえば、前々回の答えと今の答えが違うけど何で?
> に答えられてる**

**★ これは診断のための履歴である。** 「あとで見返す」ためではなく、
**目の前の食い違いの理由を言うため**にある。この一文が、以下の裁定のうち

## §1 「履歴」という言葉が指していた 3 つ — **(C) だけを作る**

コードの註に、既に 3 つが別々に現れている。

| | 現物 | 何を指しているか |
|---|---|---|
| **(A) 打鍵の履歴**（打った通り） | `crates/calcarc-core/src/engine/display.rs`（`echo_of` の docstring） | 「**打鍵履歴ではなくスタックの形**を見せる。後置関数は押した瞬間に値へ畳まれ（`30 sin` は `0.5`）、優先順位でも畳まれる（`2 × 3 +` は `6 +`）。**打った通りを見せるには状態に履歴が要る**」 |
| **(B) undo のための履歴** | `crates/calcarc-core/src/engine/mod.rs`（`delete_one` の docstring） | 「**undo は状態に履歴スタックを要求し**、EngineState が毎打鍵で WASM 境界を往復する設計（D7）に正面から効く」 |
| **(C) 計算の履歴** | 未着手 | **終わった計算を並べて、あとから見る／呼び戻す** |

### 裁定 1 — **(C) だけ。(A) と (B) は含めない**

**理由**: (A) と (B) は **core の内側の設計変更**であり、
**`engine_table.rs`（電卓の挙動の仕様書）が全面的に動く**。どちらも
`EngineState` に手を入れるので、**WASM 境界を毎打鍵で往復する物が太る**。
**(C) は §2 の選び方によって core をほとんど触らずに作れる**——
**小さく出せる側から始める。**

**★ (A) を作りたくなったときのために**: (C) の 1 件が持つ「式」は
**打った通りの文字列**である（§4）。**(A) は「途中の表示」の話で、
(C) の式は「終わった計算の記録」**——名前が似ているだけで別物である。

## §2 どこに置くか — **折衷（core は形だけ、貯めるのは web）**

**CLAUDE.md の第 1 の規律に正面から触る**:

> **計算ロジックは `calcarc-core` に置く。** `calcarc-wasm` と `web` に計算を書かない。

### 裁定 2 — **core は「1 件の形を作る純関数」だけを持ち、貯める・捨てる・呼び戻すは `web`**

```
calcarc-core   キー列 → 式の文字列（純関数。状態を持たない）
     │
web/src/history/   1 件を組み立て、50 件まで貯め、溢れたら捨てる（localStorage）
     │
web/src/ui/        履歴の面、入口、設定
```

**理由 3 つ**:

1. **`EngineState` を太らせない。** 状態は毎打鍵で WASM 境界を往復する（設計 D7）。
   **履歴が n 件あれば n 件が毎打鍵でシリアライズされる**のが「core の状態に持つ」案の
   代償で、これは払えない
2. **`STATE_SCHEMA` を動かさない。** 0.6.0 で境界を `Outcome<T>` にしたばかりである
3. **保存は既に `web` の仕事**であり、**前例が 2 つとも「掴むのは 1 ファイルだけ」で
   書かれている**——`web/src/ui/useSetting.ts:4`（「**localStorage を掴むのは
   このファイルだけ**である」）と `web/src/currency/cache.ts:4`
   （「**IndexedDB を掴むのはこのファイルだけ**——`localStorage` を掴むのが
   `useSetting.ts` だけなのと同じ形」）。**履歴もこの形に合わせる**

**★ なぜ「core を 1 行も触らない」案にしなかったか。** 式の綴りは
**キーの意味を知っている側でしか書けない**（`sin` が後置か、`Exp` が何を挟むか）。
**それを `web` に書くと、CLAUDE.md の「計算を web に書かない」に触る。**
純関数 1 つを core に置けば、**web が持つのは文字列だけ**になる。

## §3 1 件は何を持つか — **式・答・角度モード**

### 裁定 3

| 欄 | 何 | 一覧に出すか |
|---|---|---|
| **式** | 表示文字列（`30 sin`） | **出す** |
| **答** | 表示文字列（`0.5`） | **出す** |
| **角度モード** | `Deg` / `Rad` の 2 つだけ | **出す** |
| 記法（`ENG`） | — | **持たない・出さない** |

**理由**:

- **角度モードを出すのは §0 の用途がそれを要求するから**である。
  **取り得るのは `Deg` と `Rad` の 2 つだけ**——`AngleMode::ALL` は
  `[AngleMode; 2]`（`crates/calcarc-core/src/numeric/angle.rs:13`）。
  **`DRG` というキー名は 3 つあるように読めるが、実装は 2 択のトグルである**
  （**【訂正 2026-09-03】** この表は当初 `GRAD` を含めて書いていた。誤り）。
  `30 sin` は Deg で `0.5`、Rad で `-0.988031…`。**モードが見えないと、
  「前々回と今回で答が違う理由」がまさに言えない**
- **`ENG` は出さない。** 記法は**値を変えない**——同じ数の見せ方が変わるだけで、
  **「なぜ答が違うか」の答えにならない**。1 件に持たせると、
  **診断に効かない欄が全件に付く**

**★ 角度モードは「その計算のときのモード」であって、「いまのモード」ではない。**
一覧を見ている最中にモードを変えても、**過去の件の表示は変わらない。**
（`AC` で表示状態が戻らないのと同じ形の落とし穴である——
記憶「AC で表示状態は戻らない」）

## §4 式をどう綴るか — **打った通り。綴るのは core の純関数**

### 裁定 4a — **打った通りに並べる**

`3` `0` `sin` → **`30 sin`**。**`sin(30)` にはしない。**

**理由 2 つ**:

1. **純関数が単純になる。** キー列を左から文字にするだけで、
   **構文木を組まなくてよい**。組むなら「計算」であり、
   **同じアルゴリズムを参照実装にも書くことになって照合の意味が消える**
   （CLAUDE.md「参照実装を Rust の移植にしない」）
2. **表で固定できる。** 入力（キー列）と出力（文字列）が両方ただの列なので、
   **`engine_table.rs` と同じ形の表**にそのまま入る

**【訂正 2026-09-03】** ここは当初「`testdata/*.json` の golden に入る」と
書いていた。**誤りである**——`testdata/` は `reference/` の Python が生成する
ものであり、**綴りの規則を Python に書けば、それは同じ手順の写しになる**
（CLAUDE.md「参照実装を Rust の移植にしない」）。**綴りに golden は置かない。**
置き場は `crates/calcarc-core/tests/` の表である。理由 1 は変わらない。

**★ 代償**: **`2 × 3 + 4` は演算子の優先順位を語らない。** 打った通りなので
`2 × 3 + 4` と出るが、これは診断には十分である（利用者が打った通りだから）。

### 裁定 4b — **`calcarc-core` に純関数を 1 つ足す。`EngineState` は変えない**

形は `&[KeyToken] -> String` 相当（Rust 側では `&[Key] -> String`）。

**動かないもの**（**現物で当てた**）:

| | なぜ動かないか |
|---|---|
| `crates/calcarc-core/tests/engine_table.rs` | キー列と**表示**の対応表。**表示は変わらない** |
| `crates/calcarc-core/src/engine/key.rs:175` の `Key::ALL` | **`[Key; 46]` のまま**。キーを増やさない（§9） |
| `web/src/calc/types.ts` の `KEY_TOKENS` | **46 件のまま**（実測） |
| `crates/calcarc-wasm/tests/token_parity.rs:45` | `KEY_TOKENS` と `Key::ALL` を突き合わせる。**両方動かない** |
| WASM 境界 / `STATE_SCHEMA` | 純関数は状態を持たない |

**新しく要るもの**: この純関数の golden（`testdata/`）と、
**独立性の 1 行**（CLAUDE.md「公開関数の docstring に
`独立: 別手順／不可能／一部／未確認` を 1 行書く」）。

**★ 「独立」は何と書くか。** 綴りの規則は**設計上の取り決め**であって
数学ではないので、**参照実装が別手順で同じ文字列に到達する道が無い**。
**`独立: 不可能`** が正直な見立てである（**実測前**——参照実装を書く段で
確定させる）。§13 に残す。

## §5 呼び戻したとき何が起きるか — **見えるのは両方、入るのは答**

### 裁定 5

- **一覧には式と答が両方見える**
- **1 件を押すと、その答が入力に入る**（式は再現しない）

**理由**: **式の再現は「打鍵の再生」であり、(A) の話に踏み込む**（§1）。
**答を入れるだけなら `web` は文字列を 1 つ渡すだけで済む**。
**そして §0 の用途は「見比べる」ことであり、「打ち直す」ことではない。**

**★ 押した結果は「数を打ったのと同じ」**である。`0.5` を呼び戻すのは
`0` `.` `5` と打つのと同じ状態になる——**特別な状態を作らない。**
（実装時の確認事項。§13）

## §6 消す手段 — **`AC` では消えない**

### 裁定 6

| 操作 | 履歴はどうなるか |
|---|---|
| **`AC`** | **消えない** |
| **1 件ずつ消す**（一覧の各行） | その 1 件だけ消える |
| **全消し**（一覧の下） | 全部消える |

**理由**: **`AC` は「次の計算を始める」操作**であって、
**「前々回を捨てる」操作ではない**（§0）。**`AC` で消えると、
この履歴が答えるはずだった問いが `AC` のたびに消える。**

**★ これは `AC` の意味を広げないという判断でもある。** `AC` は既に
「角度モード・記法・表示形式を越えて残す」側に倒してある
（記憶「AC で表示状態は戻らない」）。**履歴も同じ側に置く。**

## §7 既定と無効化 — **既定は入。切っても既存分は残る**

### 裁定 7

- **既定は「記録する」**
- **設定で切れる。切る＝これから記録しない**
- **切っても既に貯まった分は残る**
- **「切る」と「消す」は別の操作である**（消したいなら §6 の全消しを使う）

**理由**: **切ることと消すことを 1 つの操作にすると、
「もう記録したくない」だけの人が過去を失う。** 逆に、
**消したい人には §6 の全消しがある**——**2 つ揃えば、どちらの意図も表せる。**

**★ base-spec `:1017` の要求はこれで満たされる**:

> 履歴保存はユーザーが無効化できる設計を検討する。

## §8 上限と保存先 — **`localStorage` に 50 件**

### 裁定 8

- **保存先: `localStorage`**（`useSetting.ts` と同じ場所）
- **上限: 50 件**
- **溢れたら古いものから捨てる**

**理由**: **§0 の用途は「前々回」であり、50 件は十分に深い。**
`IndexedDB`（通貨のキャッシュが使っている）を選ばないのは、
**1 件が小さく、件数に上限があるから**——**非同期の口を増やす理由が無い。**

**★ 件数で切るのであって、バイト数では切らない。** 表示文字列の長さは
上限を持たないので、**理論上は 50 件でも大きくなりうる**。
**実測していない**ので §13 に残す。

### §9.2 「別の面」を採った理由

**帯（B-1）は畳んでいるあいだの代償が 0 だが、開いた瞬間に盤面を押す**
——sp で 83px、履歴 3 件のときの実測である。**件数を増やせばもっと出る。**
**別の面なら盤面の高さに一切影響しない**し、**入口が裏機能である以上、
出た先は専有していてよい。**

### §9.3 **この裁定が要求する型の変更**（★ 裁定の前提には無かった）

**`hist` を「`j` の裏の、トークンを送らないキー」にすることは、
いまの型では表せない。**

- `web/src/ui/Keypad/types.ts` の `ShiftFace<T>` は
  **`{ token, label, ariaLabel, variant }` の 4 つだけ**を持つ。
  **`kind` も `onActivate` も無い**
- `web/src/ui/Keypad/Keypad.tsx` は **`kind === "shift"` のときだけ
  `onActivate` を渡す**。それは `key.kind` を見るので、
  **第 2 面（`face`）には効かない**
- `web/src/ui/Key/Key.tsx:67` は `reserved = token === null && !onActivate`。
  **`onActivate` が渡らない `token: null` の面は「予約スロット」に落ちる**
  ——押せず、ラベルも出ない（`Key.tsx` の `{reserved ? null : label}`）

**つまり `ShiftFace<T>` に「この面は UI の操作である」と言う口を足さないと、
`hist` は空きマスとして描かれる。** 口の形（`kind?: "action"` を足すか、
`Keypad` に `onAction` を足すか）は**実装時の選択**なので §13 に残す。

**★ 併せて要る**: 第 1 面のキーは押すと `setShifted(false)` でワンショットが
解ける（`Keypad.tsx` の `onPress`）。**UI の操作キーも同じように面を降ろす**
必要がある——**`kind === "shift"` の枝はトグルするだけで、降ろさない。**

> 利用者が選んだ表示の好みだけで、計算した内容は 1 バイトも含まれない）。

案:

> **履歴は 0.8.0 で入った**（設計書 `2026-09-03-history-design.md`）。
> **ここで初めて、計算した内容そのものが端末に残る**——Scientific で
> `=` を押した式と答と角度モードを、`localStorage` に 50 件まで貯める。
> **だから `1017` 行の「無効化できる設計」がここで要る**: 既定は入で、
> 設定で切れる（切る＝これから記録しない。既に貯まった分は残る）。
> 消すのは別の操作である（1 件ずつ／全消し）。
> **`AC` では消えない。**
>
> **端末から出ないことは変わらない**——`72` 行と `1073` 行の
> 「送信しない」は履歴にもそのまま効く。**変わったのは「保存されるのは
> 表示の好みだけ」のほうである。**

**本体の書き換えは実装のときでよい**（版数が確定してから。上の案の
「0.8.0」は**実測前**——§13）。

## §11 番人 — **1 本要る**

### §11.1 なぜ既存の番人では届かないか

**★ つまり「盤面から届くか」の網に穴が 1 つ空く。** CLAUDE.md の
**「規律を書いたら、同じコミットで番人を置く」**に従い、**置く。**

### §11.2 置く番人

**E2E に 1 本**（`web/tests/e2e/` に置く。`heavy` ではない——
`hist` は重量級のコーパスと関係が無い）。1 本で次を通しで見る:

1. **`Shift` を押す前に `hist` は無い**（`getByRole("button", { name })` が 0 件）
2. **`Shift` を押すと `hist` が出る**（`j` の位置に、**空きマスではなく
   ラベル付きで**——§9.3 の型変更が効いていることの番人でもある）
3. **押すと履歴の面へ行く**（見出し「履歴」が見える。**盤面が消える**）
4. **`‹ 戻る` で盤面へ戻る**

**★ なぜ 1 本にまとめるか。** 1〜4 は**経路であって独立した性質ではない**
——2 が壊れれば 3 も 4 も到達しない。**分けると、1 つの原因で 4 本が
同時に赤くなり、どれが原因か読めなくなる。**

## §12 README に 1 行要るか — **要る**

### 裁定

**要る。`README.md` と `README.en.md` の両方に 1 行足す。**

**理由**: **「端末に残る」と「外へ出る」は別の話であり、この電卓は
前者を初めて増やす。** README は既に「送信しない」を謳っている
（それは変わらない）——**その隣に「端末には残る（切れる／消せる）」が
無いと、読んだ人は「何も残らない」と読む。**

**★ 増えたのは事実であって、謝ることではない。** 文面は
**「何が残り、どう切れて、どう消せるか」の 3 つを 1 行で**書く。
**「安全です」と書かない。**

**番人**: `README.md` と `README.en.md` の 2 本を揃える番人は**無い**
（`pnpm check:version` が見るのは版数の 6 箇所だけである）。
**置けない**ので、**代わりに何が守るかを書く**: **これは
`docs/deploy.md` の版数と同じで、人が揃える。** 揃わなくても赤くならない。
**§13 に「番人の無い規律」として残す。**
