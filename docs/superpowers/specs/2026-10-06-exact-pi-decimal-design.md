## §2 方針——「打った数に対する答え」へ

**1.0.0 の線引き**（`2026-09-29-degree-quadrants-design.md` §3.1）は「**入力が厳密なら、答えも厳密に**」だった。
DEG の `180` は f64 で厳密に持てるので直し、RAD の π は持てないので直さなかった。

**この設計は、その線引きを変えずに「入力が厳密」の範囲を広げる。**
- **値に「この f64 は、本当はこの有理数（× π）である」という印を添える。**
- 印があれば、π は本当の π として扱える。印が無ければ、今までどおり f64 に対する答えを返す。
- **打った `3.14159265359` は、印が「有理数 314159265359/10^11」なので π ではない**（打てる桁は `MAX_ENTRY_LEN` = 12 まで）。`sin` の答えは今までどおり `8.979318434e-11` で、それが正しい答えである。**(a) の反例（`32993.006048 sin`）はこの区別で起きなくなる。**

## §3 値の表現（①）

### §3.1 印の形

```rust
/// 値の厳密な正体。`value == q × π^k`。
pub struct Exact {
    pub q: Rational, // expr::rational::Rational(i128 の既約分数)を使う
    pub pi: bool,    // k = 1 なら true
}
```

- **k は 0 か 1 だけ。** π² 以上は持たない（§3.4 で印を落とす）。
- **印が付くのは虚部 0 の値だけ。** 複素数には付けない。
- **有理数は既存の `expr::rational::Rational`**（i128 の有界・既約分数。式入力の評価器が使っているもの）。新しい型を作らない。

### §3.2 どこに足すか——**`Value` には足さない（推し）**

**推し: engine の中だけに包みを作る。**

```rust
pub struct Held { pub value: Value, pub exact: Option<Exact> }
```

`EngineState` の `current`・`operands`・`ReplaceBase`・`ClosedGroup` が持つ型を `Value` から `Held` に替える。

**理由**:
- **`Value` は core の「唯一の数値型」で、使っている場所が多い**（`\bValue\b` の行数: scientific 139・engine 27・polar 15・numeric 14・tests 36）。`scientific::sin(Value, mode)` などの公開関数と golden（`golden.rs`）は `Value` を受け取る。**`Value` に欄を足すと、印を知らない計算にも印が流れ込む**。
- **`Value` は `PartialEq` を derive している。** 欄を足すと等値の意味が変わり、`assert_eq!(…, Value::real(0.5))` 形のテストが印の違いで落ちる。等値から印を外す手書きの `PartialEq` は、**印の取り違えを黙らせる**ので採らない。
- `Held` なら、**印を読むのは engine だけ**になる。`scientific` の関数と golden は 1 行も変わらない。

**代償**: engine の中で `.re` を読んでいる所は `.value.re` になる（機械的な書き換え）。`engine_robustness.rs` の `before.current == after.current` は印まで比べるようになる（**DEL や押し直しが印も戻すことを、そのまま見張れるので望ましい**）。

### §3.3 印が付く入口

| 入口 | 印 |
|---|---|
| 打った数（`Buffer::value`。整数・小数・`000`・指数入力 `1.5e-3`） | `q` = 打った十進そのもの、k=0。**i128 に収まらなければ印なし**（例: `1 EXP 40`。i128 の上限は約 1.7e38） |
| 60 進の入力（`1 °'" 30 °'"`） | `q` = 度 + 分/60 + 秒/3600、k=0 |
| `π` キー | `q` = 1、k=1 |
| 三角関数の表の答え（§4） | 0・±1/2・±1 なら k=0。√ を含む答えは印なし |
| `e` キー・`j`・虚数の入力 | 印なし |

**印は `re` の計算に使わない（段階 1）。** `re` は今までどおり f64 で計算する（§5 の段階 2 を除く）。**印を読むのは三角関数の入口だけ**である。

### §3.4 印の伝わり方と、落ちる演算

| 演算 | 印 |
|---|---|
| `a ± b` | k が同じなら `(qa ± qb, k)`。違えば落とす（`π + 1`） |
| `a × b` | k の和が 1 以下なら `(qa·qb, ka+kb)`。2 なら落とす（`π × π`） |
| `a ÷ b` | `qb ≠ 0` で k の差が 0 か 1 なら `(qa/qb, ka−kb)`。`π ÷ π` は `(1, 0)` に戻る。`1 ÷ π` は落とす |
| `+/−` | `(−q, k)` |
| `x²` | k=0 なら `(q², 0)`。k=1 なら落とす |
| `1/x` | k=0 で q ≠ 0 なら `(1/q, 0)`。k=1 なら落とす |
| `√`・`ln`・`log`・`eˣ`・`xʸ`・`n!`・`nPr`・`nCr`・逆三角関数 | 落とす（§11 の未決 3・4） |
| 複素数が混ざる演算 | 落とす |

**溢れの扱い**: 印の計算で i128 が溢れたら（`Rational` の `Overflow`）、**印を捨てるだけで、エラーにしない**。`re` は印と無関係に計算しているので、答えは今の道に戻る。
- **エラーの出どころは今と同じ**（`re` の f64 の溢れ・ゼロ除算）。**印が新しく生むエラーは、RAD の tan の極（§4.3）だけ**である。
- **段差が残る**: `π × 1 EXP 30 = sin` は 0、`π × 1 EXP 40 = sin` は印が落ちて f64 の答え（今と同じ `0.9995496644`）になる。§11 の未決 7。

## §4 三角関数の表（②）

### §4.1 引ける角

**角を「半周（π、180°）の何倍か」に直して、1/6 か 1/4 の倍数なら表を引く**（1 周で 16 の位置）。

- **RAD で印が k=1**: `r = q mod 2`（厳密な有理数の剰余）。`r` が 1/6 の倍数か 1/4 の倍数なら表に載る（π/6・π/4・π/3 の倍数）。**`12r` が整数、では広すぎる**（π/12 = 15° が入るが、sin 15° は表に無い）。
- **DEG で印が k=0**: `r = q mod 360`。`r` が 30 の倍数か 45 の倍数なら表に載る。
- **DEG で印が無く、f64 そのものが 30 か 45 の倍数**（`x % 360.0` は fmod で厳密）: これも表を引く。**整数は f64 で厳密に持てる**ので、1.0.0 §3.1 の「入力が厳密なら」に入る。今の `quadrant_exact`（90 の倍数だけ）を広げたもの。
- **RAD で印が k=0**（打った数）: q = 0 のときだけ表に載る。**`32993.006048 sin` は表に載らない。**

### §4.2 表の値

16 の角（0, 30, 45, 60, 90, …, 330 度。RAD ではその π 倍）について `(sin, cos)` を表から返す。

- **0・±1/2・±1 は厳密な f64** で、答えに k=0 の印を付ける。
- **±√2/2・±√3/2 は、正しく丸めた f64 定数**で、印は付けない。定数は実装時に mpmath で確かめてテストに書く（**`√2/2` = `0.7071067811865476`。`√3/2` が `0.8660254037844386` か `…387` かは未確認**）。
- **tan も表から返す**: 0・±1 は厳密、±√3・±1/√3 は正しく丸めた定数。**sin/cos の商にしない**（商は丸めを 2 回通る）。

**表に載らない k=1 の角**: `r` を `(−1, 1]` に畳んでから `f64(r) × π` の sin・cos を返す。
- **今の `sin(re)` より、大きな倍数で正確になる。** `π × 1000001 ÷ 3` の f64 は、巨大な数の ulp で真の角から外れている。畳んでからなら外れない。
- **小さな倍数では今とほぼ同じ値**（`f64(r) × π` と `re` は 1 ulp 級の差）。

### §4.3 RAD の tan の極（利用者の裁定 10-06）

- **k=1 で `r = 1/2` か `3/2`** なら `TrigPole`。DEG と揃う。
- **印の無い f64 の極の近く（`acos(0)` の答え）と、打った近似値（`1.57079632679 tan` = `1.053778575e10`）は今までどおり**、有限の巨大値を返す。入力が π/2 ではないので、それが正しい答えである。

### §4.4 1.0.0 の `quadrant_exact` との関係

- **置き換えではなく、広げる。** 今の 4 行（0・90・180・270）は新しい表の部分集合で、同じ値を返す。
- **複素の公式に表が入る点は今と同じ**（`sin(x+iy) = sin x·cosh y + i·cos x·sinh y` の `sin x`・`cos x` を表から取る）。印は実数にしか付かないので、複素は「f64 が 30・45 の倍数か」の判定だけを通る。
- **`is_tan_pole`（DEG の極の判定）は変えない。** 印のある DEG の値は、印の剰余で同じ判定をする（`r` が 90 か 270）。

## §5 四則を十進で厳密に（③）——**段階 2。1.3 に入れるかは未決 1**

### §5.1 何が変わるか

**段階 1**（§3・§4）は印を三角関数の入口でしか読まない。**`re` は今と同じ**なので、動くのは三角関数の答えと、それを使った後の計算だけである（`1 ÷ ( π sin ) =` が DivisionByZero になる、など）。

**段階 2** は、k=0 の印がある値について **`re` を「印の有理数を正しく丸めた f64」に置き換える。**
- `4548399.395 − 4548399.394` は印が `1/1000` になり、`re` は f64 の `0.001` になる。表示は `0.001`。
- **これで「答えは持っている数に対する答え」が、四則でも「打った数に対する答え」になる。**
- **k=1 の値の `re` は段階 2 でも変えない**（π を含む値は正しく丸められない。今の計算のまま）。

### §5.2 見込み（v1.2.0 のコーパスで実測。理想の場合）

**測り方**: 値ケースのうち、式が `+ − × ÷` と打った十進だけでできているもの **5,461 件**（指数表記を含む式は除いた）。
- 各式を Python の `Fraction` で厳密に評価する。
- 「1 回だけ正しく丸めた f64」の 10 桁と、今の engine の表示と、真値の 10 桁を比べる。

| シャード | 件数 | 今、真値の 10 桁と違う | 段階 2 で違う | 表示が変わる |
|---|---:|---:|---:|---:|
| cancellation | 1,102 | **527** | **0** | 527 |
| associativity・elementary・inverse-trig・operator-correction・precedence・scientific・typed | 4,359 | 0 | 0 | 0 |

- **変わるのは near_subtraction の 527 件だけで、全部が「違う → 合う」の向きである。** 合っていたものが外れる件数は 0。
- **これは「全体を 1 回で丸めた」理想の値である。** engine は演算ごとに丸め直すが、各段の印は厳密なので、最後の段の `re` は理想と同じになる見込み（**実測前**）。

### §5.3 有理数を f64 に正しく丸める

段階 2 には「i128 の分数 → 正しく丸めた f64」の関数が要る。
- **分子と分母が 2^53 以下なら、`num as f64 / den as f64` が正しく丸めた値**である（IEEE の除算は、厳密な 2 つの数に対して正しく丸める）。near_subtraction はすべてここに入る（`1/1000` など）。
- **それより大きいときは**、u128 の長除算で 54 ビット＋sticky を出してから丸める（30〜40 行の見込み、**実測前**）。
- **代わりに「大きいときは段階 1 と同じ f64 の計算に戻す」でもよい。** 印と `re` が 1 ulp ずれうるが、印は三角関数の入口でしか読まないので害は小さい。§11 の未決 2。

### §5.4 段階 2 の波及（**実測前**）

- **`equivalence` シャード**（`x` と `√(x²)` が同じ表示）: `x²` は印を保ち `re` が正しく丸めた値になる。一方 `√` は印を落とすので、往復が今と ulp 単位で変わりうる。表示 10 桁での食い違いはまず起きない見込みだが、**重量級の全走で確かめる**。
- `engine_values.rs`（有理数の評価器と engine の表示の照合）: engine が評価器に近づく向きなので、赤は増えない見込み。

## §6 WASM 境界と TS（④）

### §6.1 i128 の受け渡し——**前回の報告を訂正する**

前回の調査報告で「i128 が渡せないと、π を押すたびに黙ってリセットされる恐れ」と書いた。**これは誤りだった。**
- `serde-wasm-bindgen 0.6.5`（`crates/calcarc-wasm/Cargo.toml`）の `serialize_i128` は `JsValue::from(v)`（BigInt）を返し、`serialize_large_number_types_as_bigints` の設定に関係なく失敗しない。`deserialize_i128` は BigInt を受け取る（どちらも `~/.cargo/registry` のソースで確認）。
- **それでも、黙ってリセットされる経路は在る**: `reduce_key`（`crates/calcarc-wasm/src/lib.rs:112-116`）は、状態のデシリアライズに失敗すると初期状態で続ける。BigInt が JS 側で別の型に化ける（`JSON.stringify` は BigInt で例外を投げる。JSON を経由した写しは数値や文字列に変える）と、ここに落ちる。
  - **今の web は状態を JSON にしない**（`web/src` の非テストで `JSON.stringify`・`structuredClone` に状態を渡す所は 0 件）。
  - **重量級のハーネスは状態を node に返さない**（`runAll` が返すのは `main` と `error` の文字列だけ）。
- **推し: i128 を文字列で渡す**（`#[serde(with = …)]` で `"num/den"`）。BigInt の取り違えを、型の段で起きなくする。

### §6.2 TS の型

**変わらない。** `web/src/calc/types.ts:113` の `EngineState` は `{ readonly __engineState: unique symbol }`（中身を見ない印つきの型）である。`DisplayState` は `Value` も印も含まない。

### §6.3 STATE_SCHEMA

**8 → 9 に上げる。** `EngineState` は保存されない（`web/src/settings/index.ts:33`「STATE_SCHEMA とは別物……保存しない」）ので、移行は要らない。**履歴は答えを文字列で持つ**（`web/src/history/types.ts` の `answer: string`）ので、影響しない。

### §6.4 番人

- **wasm の往復テスト**（`crates/calcarc-wasm/tests/`）: 印つきの状態（`π × 2 =` の後、`1e30 ÷ 3 =` の後）が `to_js_value` → `from_value` で同じ状態に戻ること。
- **`reduce_key` の黙ったリセットを、印つきの状態で起こさないこと**: `π × 2` の後に `reduce_key` を 1 回通し、表示が `6.283185307` のままであること（初期化されていれば `0`）。

## §7 数値の規則の書き換え（⑤）

### §7.1 「答えは持っている数に対する答え」（`docs/numerical-policy.md` の「既知の制約」）

**今の文**（要旨）: 利用者から見た限界は「打った十進を f64 が持てないこと」だけである。`1e23` と打つと電卓が持つのは 9.999…e22 で、答えは「持っている数に対する答え」になる。

**文案（段階 1 のみの場合）**:
> **電卓は、打った数と π について「本当の値」を印として持つ。** 印は三角関数が読む。`π ÷ 2 = cos` は 0、`π ÷ 2 = tan` は TrigPole、DEG の `30 sin` は 0.5 ちょうどになる。
> **印が持てないもの**（√・ln・eˣ・xʸ の答え、π²、i128 に収まらない数、複素数）は、今までどおり **f64 が持っている数に対する答え**を返す。
> **四則の答えは、今も「持っている数に対する答え」である。** `4548399.395 − 4548399.394` は `0.0009999992326` と出る。

**文案（段階 2 まで入れた場合）**: 最後の段落を差し替える。
> **四則の答えは、打った十進に対する答えを正しく丸めた値である**（印が i128 に収まるあいだ）。`4548399.395 − 4548399.394` は `0.001`。

### §7.2 1.0.0 §3.1 の「RAD には広げない」

**今の文**（`scientific/mod.rs` の `quadrant_exact` の註と、numerical-policy の「Rad モードの `sin(π)` は `1.224646799e-16` を返す」の項）:
> RAD には広げない。あちらは入力そのものが厳密でないので、厳密な答えを返すと嘘になる。

**文案**:
> **RAD に広げるのは、入力が π の有理数倍だと「分かっている」ときだけである**——π キーから四則だけで作った値（印が k=1）。
> **打った `3.14159265359` は π ではない**（印は有理数で、k=0）。その `sin` は `8.979318434e-11` で、**それが正しい答えのまま**である。
> **1.0.0 の線引き「入力が厳密なら、答えも厳密に」は変えていない。** 変えたのは「厳密な入力」の数え方で、π キーの印がそこに入った。

### §7.3 マニュアル（3 冊とも変わる）

## §11 決められずに残った点（⑨）——利用者に聞くもの

1. **段階 2（四則を十進で厳密に）を 1.3 に入れるか。** 入れれば near_subtraction の 527 件が直る（§5.2）。入れなければ、1.3 で答えが動くのは三角関数だけになる。**推し: 段階 1 を先に出し、段階 2 は次の版**（範囲を分けて、戻せるようにする）。
2. **大きな分数の正しい丸め**（§5.3）: 長除算を書くか、大きいときは今の f64 の計算に戻すか。推し: 長除算（`re` は印を正しく丸めた値、という不変を 1 つにできる）。
3. **逆三角関数の答えに印を付けるか**: `0.5 asin` → RAD で `π/6`（k=1）、DEG で `30`（k=0）。付ければ `0.5 asin sin` が 0.5 ちょうどになる。推し: 1.3 では付けない（入口を増やすほど伝わり方の表が育つ）。
4. **整数乗・平方数の √ で印を保つか**（`2 xʸ 3`、`√(9/4)`）。推し: 1.3 では保たない。
5. **DEG の表を 30・45 の倍数に広げるのを、1.3 に入れるか**（§4.1）。理由は 1.0.0 と同じ（整数は f64 で厳密）。推し: 入れる（RAD の π ÷ 6 だけ 0.5 ちょうどで、DEG の 30 が 0.49999999999999994 のままだと、2 つのモードで答えが食い違う）。
6. **`Held`（推し）か、`Value` に欄を足すか**（§3.2）。
7. **i128 の溢れの段差**（§3.4）を受け入れるか。`π × 1 EXP 30 = sin` は 0、`π × 1 EXP 40 = sin` は f64 の値（`0.9995496644`）。推し: 受け入れて、numerical-policy に書く（溢れても答えは「持っている数に対する答え」で、嘘ではない）。
8. **マニュアルの書き方**: 「印」という語を利用者向けに使うか。推し: 使わない。「π キーと、打った数は本当の値として扱います。計算の途中で √ などを通ると、近い値に変わります」の形で書く。
