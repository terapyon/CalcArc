# Heavy corpus 改善 B+C — Finance コーパスの層別化と Finance 変異

改善指示書（2026-08-17 受領）の **§5・§9（層別生成と再現性）** と
**§6（Finance 用欠陥注入）** を担う。3 分割の 2 本目。

**A（`2026-08-19-heavy-detection-power-design.md`）に依存する。** §6 の変異は
A が作る `expectShards` / `minRate` / `ALL_SHARDS` の枠組みに載る。A が入る前に
§6 を足すと、Finance 変異も `shards.length >= 3` の素通り判定に落ちる。

## 1. いま何が偏っているか（実測）

`corpus/generated/finance-000.json`（2,000 件、`b223bde`）を集計した。

| | |
|---|---|
| 正常 | **1,431** |
| SyntaxError | **480** |
| Overflow | **89** |

op 別の正常件数:

| op | 総数 | 正常 | 備考 |
|---|---|---|---|
| `loan_forward` | 273 | 270 | |
| `loan_principal` | 269 | 269 | |
| `loan_term` | 243 | **90** | §5.1 の下限 100 に届いていない |
| `loan_bonus_forward` | 226 | 114 | |
| `loan_bonus_principal` | 251 | 229 | |
| `compound_grow` | 242 | 130 | |
| `compound_deposit_for` | 233 | 130 | |
| `compound_periods_for` | 263 | 199 | |

**偏りの中身。**

- **`periods_per_year` の 189 件がすべて `SyntaxError`。** 乱択が `(1,2,4,12)` から
  等確率で引くが、`4` は `Rate::from_annual_percent` が受けない
  （`rate.rs:32`、受けるのは 1・2・12 だけ）。複利の SyntaxError 191 件のうち
  **189 件がこの 1 経路**である。つまり複利の構文エラー検証は、実質ひとつしか
  踏んでいない。
- **正常な残価 0 が 2 件**（§5.2 は 100 件を要求）。`_loan_params` が
  `residual` を `randint(0, principal)` で引くので、0 を引く確率は 1/元本 である。
- **正常なボーナス 0 が 1 件**（§5.3 は 30 件を要求）。同じ理由。
- **金利は 0.1 刻みの 201 通りだけ。** `_rate()` が `randrange(0, 201) / 10` を
  返す。`0 < r < 0.1` は 0 件、小数 4 桁も 0 件。`Rate` は小数 4 桁まで受ける
  （`rate.rs:42`）ので、**受理する定義域の大半を一度も通っていない**。
- **`loan_term` の正常が 37%。** 乱択した `payment` が初回利息を覆わないと
  `run_schedule` が発散として SyntaxError にする（`schedule.rs:50`）。
  **乱択で正常を当てにいく設計そのものが、この op では機能していない。**
- **期間 `0` `599` `1199` `1200` `1201` が 0 件。** `MONTHS_MIN..MONTHS_MAX` が
  `1..480` に閉じている。`MAX_TERM_MONTHS` / `MAX_PERIODS` は 1200 なので、
  **上限の境界を一度も踏んでいない。**

`reference_gave_up` の 13 件は、生成器に計器を挟んで再生成し、内訳を実測した。

| 理由 | 件数 | 中身 |
|---|---|---|
| `compound_deposit_search_limit` | **10** | **全件が `tax: True`** |
| `near_yen_boundary` | **3** | `loan_forward` 2、`loan_bonus_forward` 1 |

原因は `compound_ref.deposit_for` の**種が税を見ていない**ことである。種は
Decimal 閉形式から取るが（`compound_ref.py`）、税 ON では目標と比べる値が
手取り（残高 − 国税 − 地方税）なので、税ぶんだけ下に外れる。利息が大きいほど
外れ幅が大きくなり、`MAX_WALK`（10 万歩）を使い切る。

## 2. 目的

1. **正常・異常・境界を、乱数の成り行きではなく設計で配分する**（§5）。
2. **2 因子の組み合わせを網羅する**（金利 × 期間、周期 × 税 など）。
3. **逆算の答が定義を満たすことを Heavy でも確かめる**（§5.8）。
4. **探索限界による取りこぼしを 0 にし、意図的な棄却と区別する**（§5.9）。
5. **層別の最低件数をテストで固定する**（§9）。
6. **Finance の欠陥を 10 種注入し、検出できることを測る**（§6）。

## 3. 非目標

- Finance の計算仕様・丸め慣行を変えない（指示書 §2）。**Rust に触れるのは
  §6 の変異だけで、変異はコミットしない。**
- 参照実装を Rust の移植にしない。§5.9 の探索改善も、二分探索への置き換えでは
  なく**種の改善**で行う（下記 4.9）。
- 他の 14 シャードを変更しない。`SCHEMA` 定数を上げない（下記 4.8）。
- レポートに層別の内訳を出すのは D+E（§3.4）。B+C は層を**作る**だけで、
  **書く**のは次の spec である。

## 4. 設計

### 4.1 層（stratum）という単位

コーパスの 1 件は、必ずちょうど 1 つの層に属する。層は次を持つ。

```python
Stratum(
    op="loan_forward",
    name="residual_zero",          # 層の名前。ケースの "stratum" に入る
    expect="ok",                   # "ok" | "SyntaxError" | "Overflow"
    minimum=100,                   # §9 のテストが固定する下限
    build=<params を作る callable>,
)
```

層の識別子は `"{op}/{name}"`（例 `loan_forward/residual_zero`）。この文字列が

- §9 の最低件数テストの主キー
- §6 の変異が「どの層が反応したか」を言うときの単位
- D+E がレポートに出す内訳の見出し

を兼ねる。**3 か所が同じ文字列を別々に組み立てないよう、層の一覧は
`corpus_calls.py` に 1 つだけ置く。**

### 4.2 因子と水準

**金利（§5.4）** — 名指し 11 種。うち正常は 10。

| 水準 | 結果 | 理由 |
|---|---|---|
| `"0"` | ok | 無利息 |
| `"0.0001"` `"0.001"` `"0.01"` | ok | **正の 0.1% 未満**（§5.4 が必須と書いている帯） |
| `"0.1"` `"1.5"` `"2.7125"` `"20"` `"99.9999"` `"100"` | ok | 小数 4 桁と上限ちょうど |
| `"100.0001"` | SyntaxError | 上限超（`rate.rs:67`） |

`"2.7125"` と `"99.9999"` は小数 4 桁。`rate.rs` は 5 桁以上を SyntaxError に
するので（`rate.rs:42`）、**4 桁は受理される定義域の端**である。

**期間（§5.5）** — 名指し 16 種: `0` `1` `2` `5` `6` `7` `11` `12` `13`
`479` `480` `599` `600` `1199` `1200` `1201`。

**期待は op に依存する。** `0` は loan・複利のどちらでもエラー水準
（`schedule.rs:40` の `n == 0`、`compound.rs:33` の `periods == 0`）。
`1201` は**複利だけ**がエラー水準で（`compound.rs:33` の
`periods > MAX_PERIODS`）、**loan では正常に計算される**。

**訂正（2026-08-19、実物のガードと突き合わせた）。** この節は当初
「`0` と `1201` はエラー水準（loan は `MAX_TERM_MONTHS = 1200`、複利は
`MAX_PERIODS = 1200`）」と書いていた。**loan について誤りである。**
`MAX_TERM_MONTHS` は `loan/inverse.rs:21` にあり、逆算 `term_for` の
**探索打ち切り**（`:134` の `while n < MAX_TERM_MONTHS`）であって入力のガード
ではない。`run_schedule` が見るのは `n == 0` だけで、上限は見ていない
（`schedule.rs:40`）。参照実装も同じ（`loan_ref.py:31` の `MAX_TERM_MONTHS` は
逆算の探索でしか使われない）。wasm 境界にも `web/src/calc/` にもクランプは無い。

**この誤りを実装に持ち込むと壊れ方が悪い。** `loan_*/term_over_max` 層を
`expect="SyntaxError"` で作ると落ち、そこで「期待を実測に合わせる」誘惑が
生まれる——このリポジトリが繰り返し禁じてきた形である。しかも設計書が
「Rust のガードから起こした」と書いているぶん、実装者は自分の実装を疑う側に
倒れる。

**仕様は変えない。** ローンの期間に製品としての上限を置くかどうかは
`calcarc-core` の実装変更であり、B+C の非目標「Finance の計算仕様・丸め慣行を
変えない」の外側にある。置かない選択もあり得る（`run_schedule` は `n` が
大きくてもループが伸びるだけで壊れない）。ここでは**実物どおりに層を作る**。
`5` `6` `7` はボーナスの `BONUS_INTERVAL_MONTHS = 6` の
両隣で、ボーナス > 0 のとき `n < 6` は SyntaxError になる（`loan_ref.py:296`）。

**複利周期（§5.6）** — 正常 `1` `2` `12` を**均等に**。異常は `0` `4` `13` を
名指しで少数（各 5 件）。**乱択層の周期は `{1, 2, 12}` だけから引く**——
`4` が乱択の 25% を占める現状を、指示書 §5.1 が名指しで否定している。

**税（§5.7）** — `False` / `True` を各 op で確保する。加えて利息が
`0` `1` `6` `7` `10` `19` `20` 円付近になる層を持つ（下記 4.6）。

**op 固有の軸**

- `loan_forward` の残価 7 層（§5.2）: `0` / `1` / 元本の 40% 前後 /
  元本の 50% / 元本 − 1 / **元本ちょうど（SyntaxError）** /
  **元本超（SyntaxError）**。後ろ 2 つがエラーなのは `run_schedule` の
  `residual >= principal` による（`schedule.rs:40`）。
- `loan_bonus_forward` のボーナス 9 層（§5.3）: `0` / 50% 未満 /
  **50% ちょうど（ok）** / **50% 超（SyntaxError）** / `n = 5`（ボーナス > 0 なら
  SyntaxError）/ `n = 6` / `n = 7` / 6 の倍数 / 6 の倍数でない。
  50% の境界は `bonus_principal * 2 > principal`（`loan_ref.py:289`）なので
  **ちょうど 50% は正常側**である。

### 4.3 ペアワイズ割付

**任意の 2 因子について、その水準の組がすべて少なくとも 1 回現れる**ように
正常層の行を作る。全交差（8 op × 11 金利 × 16 期間 × 6 周期 × 8 税 ≈ 67,000 件）は
件数の枠に入らず、一因子ずつ（OFAT）では軸をまたぐ相互作用——高金利 × 長期間 ×
税あり——を一度も踏まない。

- 生成は **IPOG を決定的に実装する**（乱数を使わない）。同じ因子表からは
  常に同じ行が同じ順で出る。
- **ペアワイズの水準は正常値だけで組む。** エラー水準（`100.0001`、期間 `0`、
  周期 `4`）を交ぜると行の大半がエラーになり、「2 因子網羅」が正常計算の
  網羅にならない。エラーは 4.5 の名指し層が担う。
- 網羅そのものをテストで見張る（4.11）。**「ペアワイズで作った」と書いてあるが
  実は網羅していない、という壊れ方を防ぐ**のがこのテストの仕事である。

### 4.4 正常を構成で保証する

**逆算 op の入力は、正算の答から作る。**

| op | 構成 |
|---|---|
| `loan_term` | 元本・金利・期間 `n` を選び、`loan_forward` で月額を出し、それを `payment` にする。答は `n` の近傍に落ちる |
| `loan_principal` | 元本・金利・`n` を選び、`loan_forward` の月額を `payment` にする |
| `compound_deposit_for` | 積立額を選び、`compound_grow` の到達値を `target` にする |
| `compound_periods_for` | 期数 `n` を選び、`compound_grow` の到達値を `target` にする。答は `n` 以下 |

これで `loan_term` の正常率は 37% から 100% になる。**同時に §5.5 の
「逆算結果が 480・600・1200 付近になるケース」が手に入る**——`n` にその値を
選べばよい。乱択で「答がたまたま 600 になる入力」を引く必要がない。

**構成は参照実装の移植ではない。** 作っているのは入力であって、期待値は
これまでどおり参照実装が独立に出す。

### 4.5 異常系の名指し

エラー経路を実物から数え上げ、各経路に最低 5 件を置く。**経路の一覧は
Rust のガードから起こした**（推測ではない）。

| 経路 | 発生元 | 期待 |
|---|---|---|
| 周期が 1・2・12 でない | `rate.rs:32` | SyntaxError |
| 金利の小数 5 桁以上 | `rate.rs:42` | SyntaxError |
| 金利が非数字・空・負 | `rate.rs:46` | SyntaxError |
| 金利が 100% 超 | `rate.rs:67` | SyntaxError |
| 複利の期数が 0 または 1200 超 | `compound.rs:33` | SyntaxError |
| ローンの期間が 0（**上限のガードは無い**） | `schedule.rs:40` | SyntaxError |
| 元本も積立も 0 | `compound.rs:38` | SyntaxError |
| 残価 ≥ 元本 | `schedule.rs:40` | SyntaxError |
| 残価あり かつ n < 2 | `schedule.rs:43` | SyntaxError |
| 月額が初回利息以下（発散） | `schedule.rs:50` | SyntaxError |
| 残価に届く前に完済 | `schedule.rs:74` | SyntaxError |
| ボーナスが元本の 50% 超 | `loan_ref.py:289` | SyntaxError |
| ボーナスあり かつ n < 6 | `loan_ref.py:296` | SyntaxError |
| 目標 0 | `compound_inverse.rs` | SyntaxError |

**訂正（2026-08-19）。** 表の 11 箇所を実物と突き合わせた。10 箇所は行番号まで
当たっていたが、2 箇所が違った。(1) 「期間 0 / 上限超」を 1 行にまとめて
`compound.rs:33` と `schedule.rs:40` を並べていたが、**上限を見ているのは複利
だけ**なので 2 行に分けた（§4.2 の訂正を見よ）。(2) 「残価に届く前に完済」の
`schedule.rs:73` はコメント行で、`return Err(CalcError::SyntaxError)` は 74 行目
——理由は正しく、行番号だけがずれていた。経路は 16 から **17** になった。

**この表は実装時に「全経路が 1 件以上コーパスに現れる」テストで固定する。**
表に書いたのに 0 件、という状態を緑のまま許さない（§9）。

### 4.6 税の境界を構成する

`ppy = 1`、`periods = 1`、`deposit = 0`、`rate = "0.0001"` のとき、1 期の利息は

```
floor(元本 × 1 / (10^4 × 100 × 1)) = floor(元本 / 1,000,000)
```

なので、**元本を選べば利息を 1 円単位で狙える**。

| 狙う利息 | 元本 | 国税 `floor(i×15315/100000)` | 地方税 `floor(i×5/100)` |
|---|---|---|---|
| 0 | 0（無効なので 999,999 で利息 0） | 0 | 0 |
| 1 | 1,000,000 | 0 | 0 |
| 6 | 6,000,000 | **0** | 0 |
| 7 | 7,000,000 | **1** | 0 |
| 10 | 10,000,000 | 1 | 0 |
| 19 | 19,000,000 | 2 | **0** |
| 20 | 20,000,000 | 3 | **1** |

**利息 6 → 7 が国税の床の跳び目、19 → 20 が地方税の床の跳び目である。**
指示書 §5.7 が挙げた 7 つの値は、この 2 つの跳び目を挟むためのものだった。

「国税と地方税の境界を同時に跨ぐ値」と「合計 20.315% の一括切り捨てと
別々の切り捨てで 1 円差が出る値」は、生成器の中で**決定的に探索して**名指し層に
入れる。後者は `tax.rs` のユニットテストが `2,648,906` を持っているので、
それを起点に探す。**探索結果は corpus に焼き付き、再生成一致ゲートが固定する。**

### 4.7 件数

**総件数は 3,500 を目標とする。** 内訳は「名指し層と ペアワイズ層を先に全部
入れ、残りを乱択層が埋める」——現在の生成器と同じ流儀である。

| 種別 | 概算 | 中身 |
|---|---|---|
| 名指し境界層 | 約 400 | 4.5 のエラー経路（各 5 件以上）、4.6 の税境界、残価 7 層とボーナス 9 層の名指し部分 |
| ペアワイズ層（正常） | 約 1,400 | 8 op × 約 175 行 |
| 乱択層 | 残り | 従来の広さを保つ。**周期は 1・2・12 のみ** |

**総件数を定数で決め打たない。** 層の下限の合計が総件数を超えたら生成器が
その場で落ちる（黙って層を削らない）。

`generate_corpus.py` の `main()` は現在すべてのシャードに同じ `count` を渡す。
**Finance だけ独自の件数を持たせる**——`main()` の中の表で finance の行だけ
`count` を使わないようにする。他の 14 枚を 3,500 件に増やすと golden が全部
書き換わり、B+C と無関係な差分になる。

`test_corpus_reproducibility.py` は `sys.argv` を潰して `main()` を呼ぶので
（既定 `count = 2000`）、この変更後もそのまま動く。

### 4.8 `stratum` ラベルとスキーマ

各 finance ケースに `"stratum": "loan_forward/residual_zero"` を足す。

**`SCHEMA` は 1 のまま上げない。** `corpus_calls.SCHEMA` は 15 シャードが
共有する 1 つの定数で、上げると**無関係な 14 枚の golden がバイト単位で
書き換わる**。読み手（`corpus.ts:407`）は未知のキーを弾かないので、追加は
後方互換である。

**「全 finance ケースが層を持つ」は Python 側のテストで固定する**（4.11）。
スキーマ番号ではなくテストが契約を担う、と設計書に書いておく——さもないと
「schema 1 なのに必須フィールドがある」が、根拠の無い例外に見える。

### 4.9 `reference_gave_up` の分類と探索の改善（§5.9）

**分類。** `ReferenceGaveUp` に `reason` を持たせ、3 つに分ける。

- `near_yen_boundary` — `loan_ref._guard_boundary` の意図的な棄却。
  **0 件必須にしない**（指示書 §5.9）が、件数と入力をシャードに記録する。
- `compound_deposit_search_limit` — `deposit_for` が `MAX_WALK` を使い切った。
  **コミット済みコーパスで 0 件にすることが目標。**
- `other` — 上の 2 つに当てはまらないもの。**`other` が 1 件でもあれば生成器が
  落ちる**（未分類のまま数だけ増える、を許さない）。

**探索の改善。** `deposit_for` の種が税を見ていないのが原因（実測 10 件すべてが
`tax: True`）。種の式に税を織り込む。

税 ON のとき目標と比べる値は `残高 − 国税 − 地方税` で、税は利息にかかる。
円未満切り捨てを無視した連続近似では

```
net ≈ balance − 0.20315 × (balance − 投入合計)
```

なので、`net = target` を `d` について Decimal で解けば種が得られる。切り捨て
2 回ぶんの誤差は数円に収まるので、そこから歩けば数歩で当たる。

- **二分探索にはしない。** Rust が二分探索をしているので、そちらを写すと
  独立性が消える（指示書 §5.9 が明示している）。**種 + 歩き + 証明書**という
  現在の構造を保ったまま、種だけを直す。
- 下向きの歩き（`while d > 0 and ...`）は現在**上限を持たない**。ここにも
  `MAX_WALK` を掛け、超えたら `compound_deposit_search_limit` として数える。
- 改善の正しさは `check_deposit_certificate`（既存）が担保する——種をどう
  作ろうと、答は「届く最小」であることを両隣 2 点で確かめてから返す。

### 4.10 逆算証明書を Heavy でも（§5.8）

**既存のハーネス呼び出しだけで組める。** 新しい wasm API も、ハーネスへの
計算の追加も要らない。

| op | 証明書 | 呼び出し |
|---|---|---|
| 借入可能額 `loan_principal` | 答では月額が `payment` 以下、答 + 1 円では超える | `loan_forward` × 2 |
| 返済期間 `loan_term` | 答の期数では月額が `payment` 以下、答 − 1 期では超える | `loan_forward` × 2 |
| 必要積立額 `compound_deposit_for` | 答で目標到達、答 − 1 円で未到達 | `compound_grow` × 2 |
| 必要期間 `compound_periods_for` | **答以前の全期間で未達**、答で到達 | `compound_grow` × n |

- 比べる値は**税 ON なら手取り（`net`）、OFF なら残高**（公開契約 6）。
- 必要期間の証明書だけが O(n) である。`n ≤ 1200`。**実行時間は実装時に
  実測し、10 秒を超えるようなら層の代表に絞る**（現在 `pnpm heavy` 全体で
  26.3 秒なので、そこを目安にする）。この判断は測ってから設計書に追記する。
- 証明書は**正常な逆算ケースだけ**に掛ける。エラーを期待するケースには答が無い。

### 4.11 テストが固定するもの（§9）

`reference/tests/test_generate_corpus.py` に足す。

1. **層別の最低件数** — 全層について `count >= minimum`。層の一覧は
   `corpus_calls` から読む（テストに写しを持たない）。
2. **正常件数** — 各 op に正常が 100 件以上（§5.1）。残価 0 の正常 100 件以上、
   ボーナス 0 の正常 30 件以上（§5.2・§5.3）。
3. **ペアワイズ網羅** — 正常層について、任意の 2 因子の水準の組がすべて
   1 回以上現れる。**「ペアワイズで作った」という主張そのものを見張る。**
4. **エラー経路の網羅** — 4.5 の表の全経路が 1 件以上現れる。
5. **`periods_per_year`** — 乱択層に `4` が 1 件も無いこと。正常の 1・2・12 が
   ほぼ均等（最小の層が最大の層の 0.8 倍以上）。
6. **金利** — `0 < r < 0.1` の正常が 1 件以上、小数 4 桁が 1 件以上。
7. **期間** — 名指し 16 種がすべて 1 件以上。
8. **`reference_gave_up`** — `compound_deposit_search_limit` が **0 件**、
   `other` が **0 件**。`near_yen_boundary` は件数と入力が記録されている。
9. **ID の重複が無い**、**同じ seed から同じ JSON**（既存の再現性テストが担う）。
10. **全 finance ケースが `stratum` を持ち、その値が層の一覧に存在する。**

## 5. §6 Finance 用の欠陥注入

A が作った枠組みに 10 種を足す。**すべて `expectShards` は
`["finance-000.json (calls)"]` の 1 枚**で、他の 14 枚は反応してはならない。
Finance は整数の厳密一致なので、反応すれば必ず不一致として出る。

| # | 変異 | ファイル | 形 |
|---|---|---|---|
| 1 | 毎期利息を切り捨てから四捨五入へ | `loan/rate.rs` `monthly_interest_floor` | 1 行 |
| 2 | 整数比の利息計算を f64 へ | `loan/rate.rs` `monthly_interest_floor` | ブロック |
| 3 | 積立を期末から期首へ | `compound.rs` `grow` のループ | ブロック（3 行の並べ替え） |
| 4 | 毎期切り捨てをやめ、満期時に一度だけ丸める | `compound.rs` `grow` | **ブロック** |
| 5 | 名目換算を実効換算に | `loan/rate.rs` `from_annual_percent` | **ブロック** |
| 6 | 国税・地方税を合計 20.315% の一括計算に | `tax.rs` `withholding` | 2 行 |
| 7 | ローン最終回の調整を削除 | `loan/schedule.rs:90-91` | 2 行（最終回に `due` ではなく `payment` を払わせる） |
| 8 | ボーナス列の半年利を月利へ | `loan/rate.rs` `half_year` | **1 行**（`denominator / 6` → `denominator`） |
| 9 | 必要期間を全走査から二分探索へ | `compound_inverse.rs` `periods_for` | **ブロック** |
| 10 | 税あり目標を手取りでなく税引前残高と比較 | `compound_inverse.rs` `reached` | **1 行**（`if !taxed` → `if true`） |

### 5.1 ブロック置換になる 3 件

**#4 #5 #9 は 1 行では表せない。**

- **#4** — 毎期の `floor` をやめるには、残高を分数のまま持つ必要がある。
  `u128` に固定スケール（10^9）を掛けて回し、最後に 1 度だけ落とす形に
  ループごと差し替える。
- **#5** — 実効換算 `(1+r)^(1/p) − 1` は無理数で、`Rate` の分数に載らない
  （`rate.rs` の docstring が「載らないから名目にした」と書いている）。
  f64 で近似した値を分母 10^12 の分数に丸めて `Rate` を作る形に差し替える。
- **#9** — 前進 1 本の走査を、期数についての二分探索に差し替える。

ブロック置換は `String.replace` で成立する（現在の仕組みが多行を扱える）。
**engine が動いて変異元が当たらなくなったら、A が入れた「変異元不在は明示的に
失敗」が赤くする**——黙って飛ばされることはない。

### 5.2 非単調ケースを探して入れる（#9 の検出に必須）

**手取りは期数について単調でない。** 税の 2 つの床が同じ期に跳ぶと、
`net(n)` が一度下がる。二分探索はこの谷を飛び越えるので、**谷を含むケースが
コーパスに無ければ #9 は 1 件も検出できない。**

指示書 §6 は「19 期で到達、20 期で未達、21 期で再到達」を例示している。
生成器が **`到達 → 未達 → 再到達` の形を持つ入力を決定的に探索し**、
`compound_periods_for/non_monotone_net` 層に入れる。期数が 19/20/21
ちょうどになるとは限らないので、**形で探して、見つかった期数を焼き付ける**。

§9 のテストが「この層が 1 件以上ある」ことを固定する。**この層が空になったら、
#9 の変異は静かに検出力を失う**——それを緑のまま許さない。

### 5.3 期待と下限

- `expectShards`: `["finance-000.json (calls)"]`（全 10 種）
- **反応してはならない**: 他 14 枚。A の完全一致判定がこれを保証する。
- `minRate`: 実装時に実測し、**実測率の半分**を初期値にする（A の方針）。
  #9 だけは検出が数件になりうるので、**最低 1 件**の側で担保する。
- 変異は Rust の finance を壊すので `cargo test` は当然赤くなる。
  `detection-power` は wasm ビルドと heavy しか回さないので影響しない。
  **変異中に `cargo test` を走らせない**ことを、スクリプトの注記に残す。
