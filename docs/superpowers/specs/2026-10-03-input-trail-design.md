# 入力経歴を表示に残す — 打った通りを、`=` のあとも（設計）

**利用者の言葉**（2026-10-01 の着想、10-03 に裁定）:

> **計算の経過をもう少し残したいです。特に `=` で消えるのはやめたい。**
> **履歴に残るようにしているし、それを活用したら、表示側に応用できないかな?**
> **何を計算したかをなるべく残したいんだよね。長くなったらスクロールしても良いし。**
> **履歴と書いてしまいましたが、計算途中の入力経歴に関しての作業です。**
> **履歴で使っている動作と同じになるんじゃないかと思うけど。**
> **横スクロールが正しいとおもうけど。**

**裁定**（監視役が利用者から取ったもの、2026-10-03）:

| | |
|---|---|
| 何を見せるか | **打った通り**（`spell`）——**いま打っている 1 つの計算の経緯** |
| **行の数** | **1 行。積み上げない**（**利用者の訂正 2026-10-03。下の ★**） |
| 長い行 | **横スクロール**（「打っている行」の箱と同じ性質） |
| `=` のあと | **消さない** |
| `=` をまたぐとき | **前の答えから始める**（`1 ×`。次の 1 行がそうなる） |
| 対象 | **まず関数電卓だけ** |

**★ 利用者の訂正（2026-10-03）**:

> **置き場ですが、過去のものを表示したいのでは無く、`=` が押されるまでの入力経緯を
> 残したいのです。なので、この表示は意味がわからない。**

**監視役が「履歴を活用したら」の一言を『過去の計算を並べる』と読み、その読みのまま

## 2. 何を変えるか

**表示欄が読む先を、状態（`echo_of`）から打鍵列（`spell`）へ替える。**

- **`EngineState` は触らない。** **`STATE_SCHEMA` も上げない。**
- **D7（毎打鍵で WASM 境界を往復する設計）に当たらない**——**理由は 1 行**:
  **打鍵列は既に web の `keysRef` に在り、`spell` はそれを引数で受け取る純関数だから**
  （`engine/spell.rs:165`）。**状態に履歴を足す話ではない。**
- **`echo` を消すのではなく、表示欄が読む先を替える**（`echo` そのものは
  `DisplayState` に残る。`crates/calcarc-wasm` の境界も変えない）。
- **★ 行を作るのは 1 か所——履歴の 1 件を作っているのと同じ関数**
  （**レビュー役の提案、2026-10-03**）。**`HistoryEntry` は既に `angle` を持ち、
  `spell`・前置・`=` の瞬間の `display` を同じ場所で読んでいる**
  （`ScientificPanel.tsx:506-564`）。**経歴の行と履歴の件を 1 つの builder から
  派生させれば、`angle`・`form`・「三角を使ったか」が 2 か所に分かれない**
  ——**[[same-defect-four-times]] の形を、そもそも作らない。**
- **上限は要らない**（**1 行だから**）。**初稿の「50 行」は取り下げ**（§3）。

### 2.2 `=` のあと、その行はいつまで残るか——**次のキーまで**

**いまの作りから自然に出る**（`keysRef` が `=` で空になる）:
- **`=` の瞬間、列は空になる**ので、**そこだけ「直前に閉じた綴り」を見せる。**
- **次のキーが来た瞬間、新しい列の綴りに替わる**（**前の答えの前置つき**。上の表の `1 ×`）。
- **`AC` で空。**

**「ずっと残す」「`AC` まで残す」は採らない**——**次の計算を打ち始めたら、
その行は『いま打っている計算の経緯』ではなくなる**（**要望は「`=` が押されるまでの
入力経緯」である**）。

### 2.3 どの枠に入れるか——**「打っている行」**

**表示欄は 3 つの枠を持つ**（`Readout.tsx`）。**面ごとに何が入っているかを測った**
（`390×844`、2026-10-03）:

| 面 | 打っている行（26.4px） | 入力済み（14.4px） | 答え（37.4px） |
|---|---|---|---|
| **関数電卓** | **空** | **空** | `1` |
| 金融 | `借入額 1000円` | 空 | （空） |
| 単位換算 | `値 123` | `変換元 km変換先 mi` | `76.42865665 mi` |

**関数電卓では、上の 2 枠がどちらも空である**（`=` のあと）。**経歴の行は
「打っている行」に入れる**——**あの枠は既に `overflow-x: auto; white-space: nowrap`**
（§1.5）で、**利用者の言う横スクロールがそのまま効く。** **答えはいままで通り
大きい欄（`.main`）に出す。**

### 2.4 「入力済み 2 行」の下限は、そのままにする

**下限は「打っている行 1 ＋ 入力済み 2」**（§1.4）。**関数電卓では入力済みの枠は

**この変更で行は増えない**（1 行のまま、`.entryActive` の中で横に伸びる）ので、
**下限を触る理由が無い。** **触れば盤面が動く**——**約束に正面から当たる。**

## 4. `=` をまたぐときの形

**裁定は「前の答えから始める」**（`3 + 4 =` のあと `× 2 =` なら **`7 × 2`**）。

**既に在る仕掛けで足りる**——**履歴が同じことをしている**（§1.3）:
**`SILENT_CONTINUATION_KEYS` を読み飛ばし、`CARRIED_VALUE_TOKENS` で連鎖を判定し、
`${carried} ${spelled}` を作る**（`ScientificPanel.tsx:514-528`）。

**新しく要るのは「どこまでを 1 本として見せるか」だけ**である:
- **`=` で 1 本を閉じ、次の行を始める**（履歴と同じ単位）なら、**いまの `keysRef` の
  切り方がそのまま使える**（`=` で切り出して空にする）。
- **`spell(=をまたいだ全列)` は使わない**——**実測で `3 + 4 = × 2 =` が
  `"3 + 4 × 2"` に繋がる**（§1.2）。**これは履歴の単位とも、裁定とも違う。**

### 4.1 打鍵と綴りが違う点（**利用者の目に触れるのは 3 つ。数えた**）

**初稿は「1 点だけ違う」と書いた。偽だった**——**レビュー役が `spell.rs` から 4 点を
挙げ、私が 1 つずつ測り直した**（2026-10-03）。**うち 1 つは、レビュー役の言い方とも違った。**

**数え直すと、利用者の目に触れるのは ①②④ の 3 点**である——**③（拒まれたキー）は
engine の腕としては在るが、押しても入らなかったものなので画面には出ない**
（レビュー役も自分の読みを訂正している）。

| | 実測 | 利用者の目に触れるか |
|---|---|---|
| **① 演算子の押し直しは最後の 1 つだけ** | `3 + × 4` → **`"3 × 4"`** | **触れる。** ただし **engine も `×` しか受け取っていない**ので、**答えと矛盾しない** |
| **② 符号は「押したキー」として綴る** | `3 +/−` → **`"3 +/−"`**（**`−3` とは綴らない**）。**指数の符号は数に入る**（`3 exp 2 +/−` → `"3e-2"`） | **触れる。** **レビュー役は「綴りに出ない」と言ったが、出る**——**出方が `−3` ではないだけである** |
| **③ 拒まれたキーは綴らない** | `5 π` の `π`、`1 (` の `(` は **engine が拒む**ので列に積まれない（§1.2.1） | **触れない。** **押しても入らなかったものが経歴に出ないのは、むしろ正しい** |
| **④ 角度・ENG・極形式の切替は綴らない** | `30 角度切替 sin =` → 綴り **`"30 sin"`**、**答えは −0.9880316241**（RAD） | **★ 触れる。答えと食い違って見える**——**`30 sin` が `0.5` ではない理由が、経歴の中に無い** |

**①②③ は「engine が受け取った通り」で説明が付く。** **④ だけは説明が付かない**
——**角度モードは状態であって、キー列に残らない**からである。

#### 4.1.1 先頭の `1` の件は取り下げる

**初稿は「`1 ( 2 + 3 )` と打つと綴りが `( 2 + 3 )` になる」と書き、監視役が
「落としたままにする」と裁定した。** **その前提が偽だった**——**拒まれたキーを
除いて測ると、綴りは `"12 + 3"` で、`1` は落ちていない**（§1.2.1）。
**そもそも値の上に `(` は押せない。**
