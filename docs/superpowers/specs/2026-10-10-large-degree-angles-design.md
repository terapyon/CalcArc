## §1 根

### §1.1 「印が表 → f64 が表 → 畳む」の 2 段目が、印より先に f64 を信じる

`exact::turn` は、Deg で印が k=0 の角の正体を、次の順で決める。

1. 印が表に載るか。
2. 印で決まらなければ、f64 の値が表に載るか（`scientific::turn_of`）。
3. どちらでもなければ、分母 ≠ 1 のときだけ印を畳む（`degree_fold`）。

壊れる形は 3 つある。どれも v1.2.3 で印字した。

| 形 | 例（Deg） | v1.2.3 の表示 | 真値の 10 桁 |
|---|---|---|---|
| **(a) 大きな整数が別の角に着地する**（2 段目も 3 段目も当たらず、f64 の `re % 360`） | `1 EXP 17 + 90 = tan` | `0.2867453858`（tan 16°） | `0.1763269807`（tan 10°） |
| **(b) 大きな角の f64 が、たまたま表に載る**（2 段目） | `1 EXP 17 + 86 = sin`・`1 EXP 17 + 80.5 = sin` | `0`・`0` | `0.1045284633`・`0.008726535498` |
| **(c) 畳んだ角を f64 にすると、90° の倍数からのずれが消える／相対で崩れる**（3 段目） | `1 EXP 17 + 170 + 1 EXP 16 +/− = tan`（90° + 1e-16°） | `1.633123935e16` | `-5.729577951e17` |
| (c) の小さな角の形（**台帳 §6 の外。今回見つけた**） | `180.0000001 sin` | `-0.000000001745329092` | `-0.000000001745329252` |
| 同上 | `90.0000001 tan` | `-572,957,827.5` | `-572,957,795.1` |

**(c) が小さな角でも起きる理由**: 3 段目は `r/d` を f64 に丸めてからラジアンにする。
- 180° の近くでは、角の f64 の丸め誤差（180 の ulp の半分、1.4e-14°）と、π を f64 に丸めた誤差が、`sin` の答え（ずれ δ に比例して小さい）に対して相対で効く。
- `180.0000001 sin` の答えは 1.7e-9 なので、7 桁目から崩れる。
- 0° の近くでは、角そのものが小さいので崩れない。崩れるのは 90°・180°・270° の近くだけである。
- `scientific::to_rad` の f64 の道（印の無い値）も同じ形だが、そちらは入力が f64 そのものなので直さない。

**台帳 §6 の (a)・(b) と (c) は、根が 1 つである。** どれも、**印が持つ角の正確さを、どこかで f64 に丸めてから使っている。**

## §2 直し方——**「印が表 → 印を 90° の倍数とずれに分けて畳む」。f64 の表は、ずれが ±30°・±45° のときだけ**

### §2.1 規則

Deg で印が k=0（`q = n/d`、既約）のとき:

1. **印が表に載れば表**（今と同じ。分母 1 で `n mod 360` が 30° か 45° の倍数）。
2. **分母が 1 で `|n| ≤ 2^53` なら、今までどおり f64 の道**（f64 は q を厳密に持つので、`to_rad` の `re % 360` が既に厳密）。
3. **それ以外（分母 ≠ 1、または |n| > 2^53 の整数）は、印を畳む。**
   - `r = n mod 360d`（**ユークリッドの剰余**、`[0, 360d)`。1 段目の表と同じ `r` を使う）。
   - `k = ⌊(r + 45d) / 90d⌋`（`k ∈ {0, …, 4}`）で、**いちばん近い 90° の倍数** `90k` を取る。
   - **ずれ `δ = r − 90k·d`（`[−45d, 45d)`、有理数）を、正しく丸めた f64 にする**（`x = ratio_to_f64(δ, d)`）。
   - **`x` が ±30 か ±45 ちょうどなら表**（位置 `6k ± 2`・`6k ± 3`）。
   - そうでなければ `Turn::Folded { quarter: k % 4, radians: x.to_radians() }`。`sin`・`cos` は、ずれの `sin x`・`cos x` を 90° ずつ回して作る（§3.2）。
4. **i128 が溢れたら**（`360d` の掛け算や `r + 45d` の足し算）`None` を返し、f64 の規則（`turn_of`）へ戻る。今の溢れの扱いと同じである。

**f64 の値で表を引く（`turn_of`）のは、f64 が q を厳密に持つとき（分母 1 で `|n| ≤ 2^53`）と、印が無い・溢れたときだけである。** それ以外の印のある Deg の角では、ずれ `x` が ±30°・±45° に丸まったときだけ表を引く。

**★ 表に吸う窓が狭くなる（意図した変化）。**
- **今**: 角の f64（`q` を丸めた値）が 30°・45° の倍数ちょうどなら表を引く。**吸う窓は「`q` の半 ulp」**である。
- **後**: ずれの f64 `x` が ±30・±45 ちょうどなら表を引く。**吸う窓は「`x` の半 ulp」**（30 なら 2^-49 ≈ 1.8e-15、45 なら 2^-48 ≈ 3.6e-15）である。
- **だから、30°・45° の倍数のうち絶対値が 60 以上の角では、窓が今より狭い**（`q` のほうが `x` より桁が大きく、ulp も大きい）。±30°・±45° そのものでは同じ幅である。0°・90°・180°・270° は、分数では窓が無くなる（ずれ `x` が 0 にならない。U1、§6）。
- 例（表示。v1.2.3 と試作 B の印字、真値は mpmath 50 桁）:

  | キー列（Deg） | 今 | 後 | 真値 |
  |---|---|---|---|
  | `150 + 5 EXP 15 +/− = sin − 0.5 =` | `0`（f64 が 150.0 に丸まり、表に載る） | `-5.551115123e-17` | `-7.557497351e-17` |
  | `330 + 5 EXP 15 +/− = sin + 0.5 =` | `0` | `5.551115123e-17` | `7.557497351e-17` |

  - 5e-15 は、150 の半 ulp（2^-46 ≈ 1.4e-14）より小さく、30 の半 ulp（≈ 1.8e-15）より大きい。今は吸われ、後は吸われない。
  - **真値に近づく向きである**（誤差は 7.6e-17 から 2.0e-17 へ）。ただし表示は今も後も真値の 10 桁と違い、**「0 のはずの所に見える 1e-17」の表示が 1 つ増える。** これを意図した変化とする（§2.1 の決め方「答えの相対誤差が小さいほうを取る」に従う）。
- **コーパスで「合う→違う」が 0 件なのは、この形がコーパスに無いからである。** 表示が動いた件数が 0（§2.2）なので、答えを直接見るこの形の行はコーパスに 1 件も無い。見張りは §4.1 の 2 行が持つ。

**なぜ ±30°・±45° だけなのか**: 決め方は「**答えの相対誤差が小さいほうを取る**」である。
- **ずれが 0 の近く**（角が 90° の倍数の近く）では、ずれの `sin x` は相対で正しい。表の 0 や極（相対誤差 100%）より常に近い。
- **ずれが ±30°・±45° の近く**では、表の 1/2・√ の値のほうが、`sin(30° を丸めたラジアン)` より真値に近い（1.2.3 の条件 1。`30 + 1 EXP 15 +/− = sin − 0.5 =` は `0`、計算すると `-5.551115123e-17`。真値は 1.5e-17）。
- ずれが ±30°・±45° 以外の値に着地しても、そこは表に無いので関係しない。

## §3 形

### §3.1 `exact::turn` と `degree_turn`

- **`turn` の 3 段目（`.or_else(|| … degree_fold(mark.q))`）を消す。** Deg の印は `degree_turn` 1 つが、表・畳み・`None`（f64 の道）を決める。
  ```text
  turn(arg, mode)
    = 印から決めた正体（RAD は今と同じ。Deg k=0 は degree_turn）
    or scientific::turn_of(arg.value, mode)   // 印が無い・溢れた・2^53 以下の整数
  ```
- **`degree_turn`** は §2.1 の 1〜3 をこの順で書く（`degree_fold` は消して、`degree_turn` に入れる）。素描を下に置く。**行の綴りは実装が決める。**
  ```rust
  fn degree_turn(q: Rational) -> Option<Turn> {
      let (n, d) = q.parts();
      let quarter = d.checked_mul(90)?;
      let r = n.rem_euclid(quarter.checked_mul(4)?);
      if d == 1 {
          if r % 15 == 0 {
              if let Some(table) = Turn::table(r / 15) {
                  return Some(table);
              }
          }
          if n.unsigned_abs() <= EXACT_INT {
              return None;
          }
      }
      let k = r.checked_add(d.checked_mul(45)?)?.div_euclid(quarter);
      let x = ratio_to_f64(r.checked_sub(k.checked_mul(quarter)?)?, d)?;
      let steps = x / 15.0;
      if steps.fract() == 0.0 {
          if let Some(table) = Turn::table(6 * k + steps as i128) {
              return Some(table);
          }
      }
      Some(Turn::Folded { quarter: u8::try_from(k % 4).ok()?, radians: x.to_radians() })
  }
  ```
  - `EXACT_INT`（2^53）は `expr/rational.rs` の private な定数である。これを `pub(crate)` にして使う（クレートの外の面は増えない）。写しを作らない。
  - `steps` が整数でも、±15°（位置 `6k ± 1`）は表に無い。`Turn::table` が `None` を返すので、畳みに落ちる。
  - **剰余は `rem_euclid` 1 回にする**（第 1 版は表の判定と畳みで 2 度取り、畳みは切り捨てだった）。`r ∈ [0, 360d)` なので `k ∈ {0, …, 4}` で、`k = 4` は 360° の近く（ずれは負）である。`Turn::table` は位置を 24 で畳むので、`k = 0` で `6k − 2`・`6k − 3` が負になっても同じ表を引く。
    - 切り捨ての剰余から変えても答えは変わらない。ずれを有理数のまま取るので、1.2.3 の「切り捨てでなければ小さな負の角が崩れる」理由は、この形では効かない。**理由の註は消す**。
    - 試作で確かめた: 切り捨て版と `rem_euclid` 版は、コーパス 25,099 件と乱択 3,647 本で、生の値（f64 のビット）まで全件同じ。`−0.0000001 sin`（`0 . 0 0 0 0 0 0 1 +/− sin`）は両方 `-0.000000001745329252`。`cargo test -p calcarc-core` の赤も同じ 2 行（§4.1）。

### §3.2 `Turn::Folded` に 90° 単位の回転を持たせる

- `Turn::Folded(f64)` を **`Turn::Folded { quarter: u8, radians: f64 }`** に変える。意味は「角 = `quarter × 90°` + `radians`」。
  - **新しい型名も、新しい変異体も足さない。** `Turn` は既に `pub` で、変えるのは既存の変異体の中身だけである。
- `scientific::circular` の腕:
  ```rust
  Some(Turn::Folded { quarter, radians }) => {
      let (s, c) = (radians.sin(), radians.cos());
      match quarter % 4 {
          0 => (s, c),
          1 => (c, -s),
          2 => (-s, -c),
          _ => (-c, s),
      }
  }
  ```
- `tan_at` は変えない（`Folded` は今までどおり `sin_at / cos_at` の商）。極の近くでは `cos` が `∓sin x`（相対で正しい小さな数）になるので、商は `-cot x` の正しい大きさを持つ。
- 複素の引数: 回すのは実部の `sin x`・`cos x` だけで、`cosh y`・`sinh y` はそのまま掛かる（1.2.2 §4.4 と同じ一本道）。コーパスの complex で、生の値が 10 件動く（近づく 5・遠ざかる 5）。表示は動かない。

## §5 tan の極と `TrigPole`

- **engine の `TrigPole` は表の位置 6・18（90°・270°）からしか出ない**（`tan_at` は `Turn::Table` の極で `Err(TrigPole)` を返す。f64 の `is_tan_pole` は印を知らない入口 `scientific::tan` だけが使う）。

- **印の無い値**（関数の答えを角にしたものなど）は、今までどおり f64 の規則で決まる。f64 が 90.0 ちょうどなら極である。
- **`scientific::is_tan_pole` と、表の極 ⇔ `is_tan_pole` の単体テストは触らない。**
