# Data Scale の電卓化（D）— 設計

日付: 2026-08-13
対象: base-spec §14〜§17（Data Scale）・§26（表示と値の分離）・§42/§43。
前提: L（Loan 電卓化）のマージ後。**計算コアは 1 行も変えない。**

## §0 位置づけ — 6 本目の spec、L の契約に乗る

| spec | 関心事 | engine への変更 |
|---|---|---|
| S1 | Scientific の外装（部品化） | ゼロ |
| S2 | Scientific の入力意味論 | あり（唯一） |
| S3 | Service Worker 更新トースト | ゼロ |
| L | Loan の電卓化（部品の初回再利用） | ゼロ |
| **D（本 spec）** | **Data Scale の電卓化** | **ゼロ** |

**本 spec は L の §4（`KeyDef<T>` のジェネリック契約と `pressed`/`disabled` の
述語）に依存する。** L はユーザー承認待ちであり、承認で §4 が変われば本 spec の
§3・§5 も追随する——**依存を先に書いておく**。

Data Scale の計算コアは engine を持たない純関数である（`data_scale::compute`）。
電卓化しても**打鍵の状態機械は増やさない**。変わるのは打ち方と見せ方だけで、
`data_scale.json` の 28 件は 1 件も動かない（§9）。

## §1 変えること

1. **入力を数字キーパッドにする**。text input と select を置かない。
2. **K・M・G のキー**を置く（×10³ / ×10⁶ / ×10⁹）。`100` `M` で 1 億件。
3. **データ型を 9 個のキー**にする。select をやめる。
4. **アクティブ項目**（件数 / 次元数 / データ型）を項目タブで選ぶ。
5. **10 進（KB 系）と 2 進（KiB 系）の主従を切り替えるトグル**を結果に置く。
   **両方表示は維持する**（§6。base-spec §17 との関係を先に裁く）。

## §2 盤面

```
┌────────────────────────────────────────────────┐
│ echo:                          件数 100M                │
│ main:                             307.2 GB            │
│ 10 進を主表示                        件数を入力中         │
├────────────────────────────────────────────────┤
│ [ 件数 ] [ 次元数 ] [ データ型 ]   ← 項目（半高）        │
├────────────────────────────────────────────────┤
│ [ 7 ] [ 8 ] [ 9 ] [ DEL ]      ← 件数・次元数のとき      │
│ [ 4 ] [ 5 ] [ 6 ] [ AC  ]                             │
│ [ 1 ] [ 2 ] [ 3 ] [ K   ]                             │
│ [ 0 ] [000] [ M ] [ G   ]                             │
├────────────────────────────────────────────────┤
│ [10 進 (KB)] [2 進 (KiB)]      ← 主表示の切り替え（結果領域） │
│ 307,200,000,000 bytes                                 │
│ 307.2 GB                       ← 主                    │
│ 286.1 GiB                      ← 副（小さく併記）        │
└────────────────────────────────────────────────┘

データ型がアクティブなときは、同じ 4 列 × 4 行の枠のまま中身だけ入れ替わる:

│ [ int8  ][ uint8 ][ int16 ] [ DEL ]                   │
│ [float16][bfloat16][ int32 ] [ AC  ]                  │
│ [float32][ int64 ][float64]                           │
│                                                       │
```

**この配置は既存製品の意匠を写したものではない**（base-spec §3、§12）。

- **キーパッド領域はアクティブ項目で中身が入れ替わる。** 数字を打つ項目
  （件数・次元数）では数字と単位、データ型では 9 つの型キー。**場所と高さは
  変えない**——入れ替えで画面が伸び縮みすると、押そうとした位置がずれる。
- 制御（DEL・AC）は**どちらの面でも右上**に残す。
- 数字面は 4 列 × 4 行で 16 キー（0-9・`000`・`K`・`M`・`G`・DEL・AC）。
  L と同じ寸法（約 85px 角）。
- **データ型面も 4 列 × 4 行の枠を保つ**。9 つの型は左 3 列に置き、
  **DEL は右上（1 行目の右端）、AC はその下**——数字面と同じ位置である。
  型名は文字数が多いので**キーの文字は小さめ**にする
  （`--key-font-size-function`）。
- **余った 5 セルにはボタンを置かない**（格子の高さは保たれるので、面を
  入れ替えても画面は伸び縮みしない）。**S1 の予約スロットとは別物**である
  ——予約は「ここに何か来る」ことを無効ボタンで示すもので、こちらは
  **恒久の空き**なので何も描かない。押せないボタンを並べても、来ないものを
  待たせるだけである。

### 縦の配分（390×844）

| 要素 | 高さ |
|---|---|
| ナビ 3 タブ | 44 |
| Readout（echo + status + main） | 約 110 |
| 項目（半高） | 34（+ gap 8） |
| キーパッド 4 行 | 85 × 4 + gap 8 × 3 = 364 |
| 主表示トグル | 44（+ gap 8） |
| 結果領域（bytes + 主 + 副） | 約 80 |
| padding と safe-area | 約 58 |
| **合計** | **約 750 / 844** |

## §3 区画の名前（E2E セレクタになる）

| 区画 | `ariaLabel` | 列数 | 高さ |
|---|---|---|---|
| 入力する項目 | `入力する項目` | 3 | half |
| 数字と単位 | `数字と単位のキー` | 4 | square |
| データ型 | `データ型のキー` | 4 | square |

**主表示のトグルは `Keypad` の区画にしない。** 区画の高さは `square`（正方）か
`half`（約 34px）の 2 つで、トグルに要る「44px の横長」はどちらでもない。
高さの語彙を増やすより、**結果領域が自前で 2 つのボタンを持つ**ほうが小さい
——あれは入力ではなく、出た結果の読み方を選ぶ操作である。アクセシブルネームは
グループとして `主に表示する単位系`、各ボタンは `10 進 (KB) を主に` /
`2 進 (KiB) を主に`。

`入力する項目` と `数字と単位のキー` は **L と同じ名前**である。E2E は
モジュールのパネル（`region` 名 `データスケール計算`）の内側で引くので
衝突しない——**引き方をパネル起点にすることを検証節で固定する**（§10）。

## §4 K・M・G の入力 — L の `entry.ts` を単位表つきに引き上げる

文法は L と同じである。**確定済みセグメントの列 + 入力中の数字**で、単位キーは
「いま打っている数字をその位で確定する」。

| 打鍵 | エコー | 値 |
|---|---|---|
| `100` `M` | `100M` | 100,000,000 |
| `1` `G` `500` `M` | `1G500M` | 1,500,000,000 |
| `100` `M` `G` | **契約は SyntaxError / 盤面では押せない** | 単位の逆順 |
| `M` | 同上 | 数字の無い単位 |
| `1` `G` `DEL` | `1` | 直前のセグメントを解く |

**L が `web/src/loan/entry.ts` に置いたものを、単位表を引数に取る形で
`web/src/units/entry.ts` へ引き上げる**（Loan は 万=10⁴/億=10⁸、Data Scale は
K=10³/M=10⁶/G=10⁹）。S1 が作った部品を L が一般化したのと同じ順序で、
**2 つ目の利用者が出た時点で共通化する**——最初から汎用に作らない。

- **逆順と数字なしの扱いは L §5 と同一**（契約は `SyntaxError`、盤面は
  押せなくする）。**L のユーザー確認事項が承認されればここも同じ**になる。
- **コアへ渡すのは素の数字列**。`parse_count` は数字だけを受ける（カンマも
  符号も小数点も拒否）。K/M/G は **UI 層の文字列展開**であり、丸めた表示値を
  入力に還流させない（base-spec §26）。
- 件数は u128 の定義域（10 進 39 桁）まで打てる。**`000` と単位キーがあっても
  桁数の上限は現行どおりコアが決める**（`parse_count` が上限超を SyntaxError に
  する）。

## §5 データ型をキーにする

- 9 つの型（`int8`〜`float64`）をキーにし、**選んでいる型が
  `aria-pressed="true"`**（L のモード行と同じく、押下状態は呼び出し側が決める
  ——L §4 の `pressed` 述語）。
- **トークン集合は変えない。** `DATA_TYPE_TOKENS`（TypeScript）と
  `DataType::ALL`（Rust）は `token_parity.rs` が照合しており、**キー化は
  同じ 9 個をボタンにするだけ**なので、この検査は不変である（トークンを
  足すなら話は別で、そのときは wasm 段が検証に加わる）。
- キーのラベルは型名そのまま（`float32`）。アクセシブルネームも同じでよい
  ——記号ではないので、読み上げが型名になる。
- **初期値は `float32`**（現行 UI の select の既定を引き継ぐ。基準例
  100M × 768 × float32 がそのまま打てる）。起動時からこの型が
  `aria-pressed="true"` である。

### 型面での DEL と AC

- **DEL は型面では無効**（状態依存の `disabled`）。型の選択はテキストの
  入力ではないので、1 文字ずつ消すものが無い。
- **AC はアクティブ項目をリセットする**（L §5 と同じ規律）。数字の項目では
  入力を空に、**型の項目では既定の型に戻す**（§5 の初期値）。1 つの文で
  両方を説明できる形にしてある——「AC はいま打っている項目を最初に戻す」。

## §6 KB と KiB — base-spec §17 との関係（要ユーザー確認）

base-spec §17 は「**両方表示する**」「両者を混同しない」と定めている。
一方でユーザーの方向は「**選択系を主表示 + 他方を小さく併記**」である。

**採る: 両方表示は維持し、どちらを主にするかだけを切り替える。**

```
307,200,000,000 bytes
307.2 GB        ← 主（大きい）
286.1 GiB       ← 副（小さい）
```

これは §17 に反しない——両方出ているからである。トグルが変えるのは**強調**
であって、表示の有無ではない。「混同しない」も、単位を併記したまま主従を
付けるほうがむしろ守りやすい（利用者が今どちらを見ているかが常に画面にある）。

**ユーザー確認事項**: この読み方でよければ、base-spec §17 に**1 行の注記**を
足したい——「両方表示する。既定でどちらを大きく見せるかは選べる（Data Scale
の主表示トグル）」。**§17 の規定そのものは変えない。** もし「主従を付けること
自体が §17 の趣旨に反する」という判断なら、トグルを外して現行の並列表示に
戻す（そのぶん画面は単純になる）。**どちらを採るかを承認時に決めたい。**

- トグルの選択は**表示だけ**に効く。コアは常に両方を返し（`decimal` と
  `binary`）、**表示層が主副を選ぶ**（§9 の golden 不変条件 3）。
- 最小単位未満（1000 bytes 未満など）で片方が `null` になる非対称は現行のまま
  （`numerical-policy` の既知の制約）。main は**主 → 副 → `bytes` の順に
  繰り上げる**:

| 主 | 副 | main に立つもの |
|---|---|---|
| あり | あり | 主（例 `307.2 GB`） |
| なし | あり | 副（1000..=1023 bytes で 10 進を主に選んでいるときなど） |
| なし | なし | **`bytes`（桁区切りつき。例 `999 bytes`）** |

  **結果領域は現行どおり「`null` の行は出さない」**。main だけが繰り上げる
  ——電卓の主表示が空になるのは、値が無いときだけであるべきだからである。

## §7 表示

- **echo**: `件数 100M` のように、**アクティブ項目の名前と打鍵中の値**。
  数の部分は**打った通り**（`1G500M` はそのまま）。桁区切りは付けない。
  **型の項目では選んでいる型を出す**（`データ型 float32`）——打鍵の履歴では
  なく「いまその項目に入っているもの」を見せる、という点で数字と同じである。
- **main**: 主表示の単位での結果（`307.2 GB`）。入力が揃うまでは中立。
- **status**: 主表示の系（`10 進を主表示`）とアクティブ項目名（`件数を入力中`）。
- **結果領域**: `bytes`（桁区切りつき）・主・副の 3 行。
- **項目タブを押すと、その項目の入力済みの値が echo に出る**（L §7 と同じ。
  フォームを廃した以上、入力を確かめる経路はここしかない）。
- エラーは現行どおり `Math ERROR` + `data-error`（`Overflow` / `SyntaxError`）。

## §8 44px の線引き

- **数字・単位・データ型の区画は 44px を守る**（数字面は約 85px 角、データ型面は
  4 列で約 85px×高さ 85px）。
- **半高は項目行だけ**（縦 34px、横は 3 列で約 112px）。
- **主表示トグルは 44px を守る**（結果領域の自前ボタン。§3）。結果を読み替える
  操作で、押し間違いが読み違いに直結するため、半高にはしない。
- 理由は S1 §4 / L §8 と同じ——**誤爆の実害に比例させる**。
- E2E は両側を検査し、理由をテストにも書く。

## §9 golden を動かさないための 3 条件

`testdata/data_scale.json`（28 件、schema 1、tolerance なしの完全一致）は
**1 件も変えない**。そのために守る:

1. **境界の署名 `data_scale(count, dimensions, dtype)` を変えない。**
   K/M/G は UI 層の文字列展開で、境界には展開後の数字列が渡る（`100 M` →
   `"100000000"`）。
2. **`format.rs` の単位テーブルに触らない**（TB / TiB の上限、最上位単位を
   再選択しない規則を含む）。
3. **KB/KiB は表示層の行選択である。** コアは常に両方を返す。トグルが
   `decimal` / `binary` の**どちらを主に描くか**だけを決める。

この 3 つが守られていれば、`cargo test --workspace` は無改修で緑のままである
（§10 の完了確認）。

## §10 検証段（tiering、ci.yml 導出）

- `cargo test --workspace`——**変更が無いことの確認**（`git diff --stat <分岐点>
  -- crates/` が空）。
- `pnpm typecheck` / `pnpm lint` / `pnpm test`。`units/entry.ts` の表駆動テスト
  （L から移設したものと、K/M/G の単位表）はここ。
- **E2E 必須**。
- `wasm-pack test` は**回さない**（トークンを増やさないため。§5）。
- Python と golden は不変。

### 書き換えと連鎖（見落としやすい順）

- **`pwa.spec.ts` のオフラインテストが `getByLabel("件数")` に依存している**
  （`tests/e2e/pwa.spec.ts` の Data Scale の行）。**電卓化でラベル付き
  input が消えるので、ここが直撃で赤になる。** キーパッド操作に書き換える
  こと。**これは D で最も見落としやすい連鎖**であり、忘れると「オフラインで
  計算できる」というオフラインの中核検査が落ちる。
- `data-scale.spec.ts`（185 行）: **約 100 行が書き換え**。ナビ・ディープ
  リンク・戻る（1〜78 行）は流用できる。期待値は golden 由来なので変えない。
- `DataScalePanel.test.tsx`（8 ケース）: 入力の与え方が変わるので大半が書き
  換え。**中立表示・null 行の非表示・エラー表示の 3 つは意味を保つ**こと。
- 区画名が L と重なるので、**E2E はパネル（`region` 名 `データスケール計算`）
  起点で引く**（§3）。`vertical-slice.spec.ts` の区画名正規表現は S1 で
  Scientific 限定に閉じてある。

## §11 スコープ外

- 計算の変更（`calcarc-core::data_scale` と `data_scale.json` は不変）
- **式入力（四則演算）**——ブリーフでは「キーパッドに演算キーを置くなら自然に
  入る」とあったが、**本 spec では入れない**。演算キーは打鍵の状態機械
  （優先順位・保留・括弧）を Data Scale に持ち込むことであり、engine 変更ゼロ
  の約束と正面から衝突する。必要になったら独立の spec で、`scientific` の
  engine を再利用する形を検討する。
- 単位の拡張（T / P、KiB より上の入力単位）
- 入力状態の永続化（base-spec §40）
- 複製・オーバーヘッド（base-spec §18）の計算

## §12 完了条件

1. Data Scale がフォームでなくなり、§2 の盤面で基準例（100M × 768 × float32 =
   307.2 GB / 286.1 GiB）が打てる。
2. **`git diff --stat <分岐点> -- crates/` が空**、`data_scale.json` も無変更。
3. K/M/G の入力が `web/src/units/entry.ts` の表駆動テストで固定され、**L の
   万/億が同じモジュールで動き続けている**（Loan 側のテストが無改修で緑）。
4. データ型 9 キーの選択が `aria-pressed` で表され、`token_parity` が緑のまま。
5. 主表示トグルが**表示だけ**を変える（同じ入力で `bytes` の値が変わらない
   ことを E2E で固定）。**主 → 副 → `bytes` の繰り上げ**（§6 の表）も、
   3 段すべてを固定する。
6. **面を入れ替えても格子の高さが変わらない**ことが E2E で固定されている
   （数字面とデータ型面でキーパッド領域の高さが同じ）。DEL・AC の位置も
   両面で同じであること。
7. **`pwa.spec.ts` のオフライン検査がキーパッド操作に書き換えられ、緑**。
8. 44px の線引きが E2E で両側から検査され、例外（項目行）の理由がテストに
   書かれている。
9. 既存の機能検査が電卓 UI に読み替えられて全緑（u128 境界・Overflow・
   単位未満の非表示・中立表示）。
