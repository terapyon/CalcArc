## 1. いまの姿（2026-10-04、`origin/main` = `9b392d8` で実測）

### 1.1 綴りは語の列を空白で繋いだもの

`crates/calcarc-core/src/engine/spell.rs` の `spell` は、`parts: Vec<String>` に語を積み、
最後に `parts.join(" ")` する（`spell.rs:326`）。**構文木は組まない**（同 `:3-5`）。
後置関数は `commit_glyph`（同 `:73-99`）の字面を 1 語として足すだけである。

**経歴の行も履歴の式も、ここから作られる**——ただし**前の答えを頭に付けるのは web**
（`web/src/ui/ScientificPanel.tsx:163` の `lineOf`、`${carry} ${spelled}`）。
**これが §2.5 の論点になる**: `3 =` のあと `sin` の `sin(3)` は、`spell` が `3` を知らないと書けない。

### 1.2 後置関数は「直前の値 1 つ」にかかる——ただし、値が無い場所でも押せる

engine の `apply_unary`（`engine/mod.rs:484`）は、**入力中の数を確定してから
`state.current` に関数をかける。** `refuses`（同 `:28`）は、**演算子の直後や `(` の直後の
関数キーを拒まない。** そのとき `current` に在るのは次の値である（2026-10-04 の実測。
使い捨ての `examples/probe.rs` で `reduce` と `spell` を回した印字。**コミットしていない**）:

| 打鍵 | engine の答え | いまの綴り | 関数がかかった値 |
|---|---|---|---|
| `2 + sin =` | `2.034899497` | `2 + sin` | **2**（左の値） |
| `2 × 3 + x² =` | `42` | `2 × 3 + x²` | **6 = 2 × 3**（**畳んだ**左の値） |
| `2 + 3 × x² =` | `29` | `2 + 3 × x²` | **3**（畳まれていない） |
| `( x² =` | `0` | `( x²` | **0** |
| `5 + ( x² =` | `5` | `5 + ( x²` | **0** |
| `x² =`（AC の直後） | `0` | `x²` | **0**（web は頭に `0` を足す——1.2.0 の「`0 ×` から始まる」） |
| `3 + +/− =` | `0` | `3 + +/−` | **3** |
| `2 xʸ +/−` | 表示 `-2` | `2 xʸ +/−` | **2** |

**演算子の直後の関数がかかる値は、演算子の優先順位で決まる**（2 行目と 3 行目）。
**それを綴りに書くことは、式を構文解析することと同じ**である——§9 の未決 1。

### 1.3 `xʸ` の優先順位と結合の向き（engine_table で確認済み）

- **右結合**: `2 xʸ 3 xʸ 2 =` → `512` = 2^9（`engine_table.rs:366`）
- **他の二項演算より強い**: `2 × 3 xʸ 2 =` → `18`（`:372`）、`2 xʸ 3 × 2 =` → `16`（`:373`）
- **`nPr`・`nCr` より強い**: `4 nCr 2 xʸ 2 =` → `1` = 4C4（`:497`、優先順位の註は `:495`）
- **左の負の数**: `2 +/− xʸ 3 =` → `-8`（`:379`）。`2 +/− xʸ 2 =` → `4`（§1.2 の probe）
- engine の `echo` は既に `2 ^` と書く（`:394`）

**数学の慣例（`^` が最も強く、右から結合する）と同じである。** **括弧を足す必要があるのは、
左の値が原子でないときだけ**——`2 +/− xʸ 2` を `−2 ^ 2` と書くと −4 と読める（engine は 4）。§2.4。

## 2. 規則

### 2.1 語の 3 つの種類

`parts` の語に種類を持たせる（**綴りの文字列から推し量らない**——推測は過去に同じ欠陥を
4 回入れた形である）。

| 種類 | 何か | 例 |
|---|---|---|
| **原子** | `Buffer::text()` が**符号・`e`・`°'"`・`j` を含まない**とき／`π`／`e` | `30`、`2.5`、`π` |
| **組** | `(` から対応する `)` までの語の並び | `( 2 + 3 )` |
| **そのほか** | 上のどれでもない値 | `−3`、`1.5e-3`、`30°15`、`3j`、`sin(30)`、`30²` |

**原子の判定は `Buffer` から取る**（`text()` の字面を正規表現で読むのではなく、`Buffer` が
指数・60 進・虚部を持っているかを見る）。**前の答え（§2.5）だけは文字列でしか来ない**ので、
そこだけは表示の文字列で判定する: **`^[0-9]+(\.[0-9]+)?$` に合えば原子。**
（engine の表示の負号は ASCII の `-` である——`engine_table.rs:379` の `"-8"`。
**`-3` は原子ではない**ので `sin(-3)`・`(-3)²` になる。負号の字形を `−` に揃えるかは §9 の未決 4。）

### 2.2 後置関数がかかる範囲

**末尾から 1 つ**——`top_open`（`spell.rs:120`）と同じ読み飛ばし:

- 末尾が `)` → **対応する `(` まで**（深さを数える）。種類は**組**
- 末尾が値の語 → **その 1 語**
- 末尾が二項演算子・`(`・空 → **かかる値が綴りに無い**（§1.2）。**§9 の未決 1**

かかった範囲を、**1 つの「そのほか」の語に畳む**。

### 2.3 キーごとの書き方

`x` を範囲の綴り、`x̂` を「組なら中身、そうでなければ `x`」とする。

| キー | 原子 | 組 | そのほか |
|---|---|---|---|
| `sin` ほか前置の 9 つ | `sin(30)` | `sin(2 + 3)` | `sin(−3)`、`sin(sin(30))` |
| `x²` | `30²` | `(2 + 3)²` | `(−3)²` |
| `n!` | `5!` | `(2 + 3)!` | `(−3)!` |
| `eˣ` | `e^2` | `e^(2 + 3)` | `e^(−3)` |
| `1/x` | `1/2` | `1/(2 + 3)` | `1/(−3)` |
| `+/−`（仮数の符号） | `−3` | `−(2 + 3)` | `−(−3)` |

- **関数は組の括弧を自分の括弧として使う**（「二重にしない」）。**後置・前置の記号は、
  組ならその括弧をそのまま使い、そのほかなら括弧を足す。**
- **指数入力中の `+/−` は変えない**——`Buffer` の中の指数の符号（`1.5e-3`）であり、語を作らない
  （`spell.rs:251` の `signed_exponent`）。
- **`nPr`・`nCr` は変えない。**
- **語を畳むのは確定した語だけ**——後置関数は `commit_into` のあとに来る（`spell.rs:289`）ので、
  **打ちかけの数が畳まれることは無い。** §3.2 の不変条件 A はこれに支えられている。

### 2.4 `xʸ` は `^` と書く。左が原子でも組でもなければ括弧で包む

- 字面を `xʸ` から `^` に変える（`commit_glyph` と `BINARY_GLYPHS`。押し直しの判定は
  `BINARY_GLYPHS` を読むので、2 つを一緒に変える——`spell.rs:334` の単体テストが見張っている）。
- **`^` を押したとき、左の語が「そのほか」なら括弧で包む**: `2 +/− xʸ 2` → `(−2) ^ 2`、
  `30 x² xʸ 2` → `(30²) ^ 2`、`30 sin xʸ 2` → `(sin(30)) ^ 2`。
- **右は包まない。** `^` が最も強く右結合なので、`2 ^ 3 × 2`・`2 ^ 3 ^ 2`・`4 nCr 2 ^ 2` は
  どれも慣例どおりに読める（§1.3）。`2 xʸ 3 +/−` は `2 ^ −3` で、慣例でも 2^(−3) と読める。

### 2.5 前の答えを頭に付ける規則を core に移す

`3 =` のあと `sin` を `sin(3)` と書くには、**`spell` が頭の `3` を語として持っている必要がある。**
いまは web が綴りのあとで繋いでいる（§1.1）ので、web の `lineOf` に括弧の規則を書くことになり、
**「計算ロジックは core に置く」に反し、規則が 2 か所に分かれる。**

**案**: core に `spell_line(carry: Option<&str>, keys: &[Key]) -> String` を置き、
**頭の値を最初の語として積んでから歩く**（種類は §2.1 の文字列判定）。
`spell(keys)` は `spell_line(None, keys)` として残す（テストと `engine_values.rs` が呼んでいる）。
**「綴りが空なら頭も付けない」**（`lineOf` の約束。`pushEntry` が空の式の行を捨てるため）も
core に移す。wasm の `spell_keys` は `carry: Option<String>` を受け取り、web の `lineOf` は
`spell_keys` を呼ぶだけになる。**wasm の公開関数の形が変わる**——web の呼び出しは
`ScientificPanel.tsx:676` と `:694`／`:718` の 2 つの経路。

### 2.6 括弧の空白

いまの綴りは `(` と `)` を 1 語として空白で区切る（`( 2 + 3 )`）。**新しい形は空白を入れない**
（`sin(2 + 3)`、`(−3)²`）。**このままだと 1 行の中に 2 つの書き方が混ざる**:
`( 2 + 3 ) × sin(4)`。**§9 の未決 2。**

## 4. 実装の形

### 4.1 語に種類を持たせる。包みは「最後に繋ぐとき」に付ける

```text
parts: Vec<Part>     Part = { text: String, kind: Atom | Group | Other }
```

- `(`・`)`・二項演算子は今と同じ 1 語（種類は持たせても使わない）。
- **後置関数**: §2.2 の範囲を `parts` から抜き、§2.3 の 1 語（`Other`）に畳んで積み直す。
- **`^` の左の括弧**（§2.4）は語に焼き込まず、**`join` のときに「次の語が `^` で、この語が
  `Other`」なら `(…)` で包む**——**押し直しで `^` が消えれば包みも消える**（§3.2）。
- **DEL の `closed` の控え**（`spell.rs:180`）は `parts.len()` を持っている。**畳むと長さが縮む**が、
  後置関数は `closed` を空にする（`spell.rs:313-323`）ので、**畳んだあとに古い長さへ
  切り詰めることは起きない。** 実装では、この前提を `debug_assert!` ではなく
  **spell_table の行で固定する**（`( 2 + 3 ) sin DEL`、§3.2）。
- **`top_open` は語の文字列が `(` か `)` に等しいかを見る**（`spell.rs:124-126`）。**畳んだ語
  `sin(2 + 3)` はどちらにも等しくない**ので、DEL の振る舞いは変わらない。

**構文木は組まない**——語の列を末尾から読み飛ばすだけで、`top_open` と同じ形である（発注の条件）。
**ただし §9 の未決 1 で案 B を採れば、演算子の優先順位を綴りの側に写すことになる。**

### 4.2 独立の宣言

`spell.rs` の `独立: 不可能` は変えない。**理由も同じ**——綴りは取り決めであり、別の手順で
同じ文字列に届く道が無い。**ただし §5.3 の番人の案 B は、取り決めのうち「読み違えない」
という数学の側の主張を、独立に確かめる**（綴りを読み直す評価器は engine を写していない）。

- **案 A（最小）**: spell_table の行だけ。§3 の表のどれにも当たらない形には黙る。
- **案 B（推奨）**: **網に `+/−` と `x²` を足す。** どちらも有理数で閉じるので、評価器
  （`Typed`、有理数で厳密）が読める。`keys_of_spelling` を**数学の書き方の読み手**に替える:
  `−` の前置、`²` の後置、`(…)` を、**慣例の優先順位（`²` > 前置の `−` > `× ÷` > `+ −`）で**
  読んでキー列に直す。**`−3²` と綴れば −9 と読まれ、engine の 9 と食い違って赤くなる**——
  **§0.2 の「`−3²` と書かない」理由そのものを機械が見る。** 読み手は engine を写さない
  （engine は後置のキーで、読み手は前置の負号を読む。**手順が違い、違いが答えに現れる**）。
  **値段**: 網が広がる（`spellings >= 919_493` の下限と走る時間が動く。**（実測前）**）。
  `Typed` に `Neg` と `Sqr` を足す（いまは無い。`engine_values.rs` を `Key::Neg` で grep して 0 件）。
- **案 C**: 案 B に `xʸ` も足す（整数の冪なら有理数で閉じる）。**`(−2) ^ 2` の包みと右結合を
  機械が見る。** 値段は B より大きい。

**どれを採るかは §9 の未決 3。**

## 9. 決められずに残った点

1. **演算子の直後・`(` の直後の関数**（§1.2）。`2 × 3 + x²` の `x²` は畳んだ `6` にかかる。
   - **案 A（推奨）**: **engine がそのキーを拒む**（`refuses` に「演算子の直後と `(` の直後の
     後置関数・`+/−`」を足す。0.9.2 の S1 と同じ形）。**綴りに書けない値に関数をかけさせない。**
     **値段**: 挙動の変更である——`engine_table.rs` を先に変え、盤面でキーが押せなくなる。
     **キーを拒むと数を数える床が層をまたいで動く**（D-2 の前例: 3 か所、最後は E2E）。
     `3 + +/−` を「次の数を負で打ちたい」つもりで押す使い方を塞ぐ。
   - **案 B**: 綴りが優先順位を写して、かかる値の範囲を探す（`2 × 3 + x²` → `2 × 3 + (2 × 3)²`）。
     **式を構文解析することになり、発注の「構文木を組まない」を破る。** 推奨しない。
   - **案 C**: 綴りに「画面の値」を表す印を書く（`2 + sin(□)`）。誤りではないが、読めない。
   - **案 D**: いまの書き方（`2 + sin`）のまま残す。**新しい規則と混ざる。**
   - `(` の直後と AC の直後は、かかる値が常に `0` なので `sin(0)` と書ける（AC の直後は web が
     頭に `0` を付けるので既に書ける）。**決める必要があるのは演算子の直後だけ**とも言える。
   **これは製品の挙動の判断なので、利用者に当ててほしい。**
2. **括弧の空白**（§2.6）。
   - **案 A**: 組は今のまま `( 2 + 3 )`、新しい形だけ `sin(2 + 3)`。**A がそのまま成り立ち、
     直す行も少ない。** 1 行に 2 つの書き方が混ざる。
   - **案 B（推奨）**: 全部 `(2 + 3)` に揃える。**A を A′ に置き換える**（§5.2）。
     `keys_of_spelling` も括弧を語から切り出すよう替える。spell_table と E2E の直す行が増える
     （`( ` を含む期待値。**数は未測**）。
   **見た目の判断なので、利用者か監視役に決めてほしい。**
3. **番人の案**（§5.3）。**推奨は B**（`+/−` と `x²` を読み直しの網に足す）。網の大きさと走る時間は
   **実測前**——**実装の最初の段で測ってから決め直してよい。**
4. **負号の字形**。綴りの負号は U+2212 の `−`（`commit_glyph`）、engine の表示は ASCII の `-`。
   **前の答えを頭に付けると `sin(-3)` と `sin(−3)` が同じ行に混ざりうる**（1.2.0 でも

   書ける（`²` は `sin²` と紛れるので包む）。**規則を単純に保つため、例外を作らないのを推奨。**
