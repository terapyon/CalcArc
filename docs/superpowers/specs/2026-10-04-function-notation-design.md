## 1. いまの姿（2026-10-04、`origin/main` = `9b392d8` で実測）

### 1.1 綴りは語の列を空白で繋いだもの

`crates/calcarc-core/src/engine/spell.rs` の `spell` は、`parts: Vec<String>` に語を積み、
最後に `parts.join(" ")` する（`spell.rs:326`）。**構文木は組まない**（同 `:3-5`）。
後置関数は `commit_glyph`（同 `:73-99`）の字面を 1 語として足すだけである。

**経歴の行も履歴の式も、ここから作られる**——ただし**前の答えを頭に付けるのは web**
（`web/src/ui/ScientificPanel.tsx:163` の `lineOf`、`${carry} ${spelled}`）。

### 1.2 後置関数は「直前の値 1 つ」にかかる——ただし、値が無い場所でも押せる

engine の `apply_unary`（`engine/mod.rs:484`）は、**入力中の数を確定してから
`state.current` に関数をかける。** `refuses`（同 `:28`）は、**演算子の直後や `(` の直後の
関数キーを拒まない。** そのとき `current` に在るのは次の値である（2026-10-04 の実測。
使い捨ての `examples/probe.rs` で `reduce` と `spell` を回した印字。**コミットしていない**）:

| 打鍵 | engine の答え | いまの綴り | 関数がかかった値 |
|---|---|---|---|
| `2 + sin =` | `2.034899497` | `2 + sin` | **2**（左の値） |
| `2 × 3 + x² =` | `42` | `2 × 3 + x²` | **6 = 2 × 3**（**畳んだ**左の値） |
| `2 + 3 × x² =` | `29` | `2 + 3 × x²` | **3**（畳まれていない） |
| `( x² =` | `0` | `( x²` | **0** |
| `5 + ( x² =` | `5` | `5 + ( x²` | **0** |
| `x² =`（AC の直後） | `0` | `x²` | **0**（web は頭に `0` を付ける——1.2.0 の「`0 ×` から始まる」） |
| `3 + +/− =` | `0` | `3 + +/−` | **3** |
| `2 xʸ +/−` | 表示 `-2` | `2 xʸ +/−` | **2** |

**かかる値は演算子の優先順位で決まる**（2 行目と 3 行目）。**キー列から書こうとすると
構文解析になる**——だから第 1 版は決められなかった。**裁定 1 は、キー列ではなく
engine が画面に出していた値から書く**ので、構文解析は要らない（§2.7）。

### 1.3 `xʸ` の優先順位と結合の向き（engine_table で確認済み。監視役も実物で確認）

- **右結合**: `2 xʸ 3 xʸ 2 =` → `512` = 2^9（`engine_table.rs:366`）
- **他の二項演算より強い**: `2 × 3 xʸ 2 =` → `18`（`:372`）、`2 xʸ 3 × 2 =` → `16`（`:373`）
- **`nPr`・`nCr` より強い**: `4 nCr 2 xʸ 2 =` → `1` = 4C4（`:497`、優先順位の註は `:495`）
- **左の負の数**: `2 +/− xʸ 3 =` → `-8`（`:379`）。`2 +/− xʸ 2 =` → `4`（§1.2 の probe）
- engine の `echo` は既に `2 ^` と書く（`:394`）

**数学の慣例（`^` が最も強く、右から結合する）と同じである。** **括弧を足す必要があるのは、
左の値が原子でも組でもないときだけ**——`2 +/− xʸ 2` を `−2 ^ 2` と書くと −4 と読める（engine は 4）。§2.4。

## 2. 規則

### 2.1 語の 3 つの種類

`parts` の語に種類を持たせる（**綴りの文字列から推し量らない**——推測は過去に同じ欠陥を
4 回入れた形である）。

| 種類 | 何か | 例 |
|---|---|---|
| **原子** | `Buffer` が**指数・60 進・虚部を持たない**とき／`π`／`e` | `30`、`2.5`、`π` |
| **組** | `(` から対応する `)` までの語の並び | `(2 + 3)` |
| **そのほか** | 上のどれでもない値 | `−3`、`1.5e-3`、`30°15`、`3j`、`sin(30)`、`30²` |

**原子の判定は `Buffer` から取る**（`text()` の字面を読むのではなく、`Buffer` が
指数・60 進・虚部を持っているかを見る）。**文字列でしか来ない値**——前の答え（§2.5）と
画面の値（§2.7）——**だけは表示の文字列で判定する: `^[0-9]{1,3}(,[0-9]{3})*(\.[0-9]+)?$` か
`^[0-9]+(\.[0-9]+)?$` に合えば原子。** **桁区切りの `,` を含めるのは監視役の裁定**（条件 2）——
`format_real` は整数部を 3 桁ごとに `,` で区切る（`numeric/format.rs:55` の `group_integer_part`）ので、
含めないと `1234 × 1000 =` のあとの `x²` が `(1,234,000)²` になる。含めれば `1,234,000²`。
**読み直しの側の `Q::from_decimal`（`engine_values.rs:71-72`）も `,` を剥いでから読んでいる。**
engine の表示の負号は ASCII の `-` である（`engine_table.rs:379` の `"-8"`）。
**`-3` は原子ではない**ので `sin(-3)`・`(-3)²` になる（**字形は直さない**。裁定 4、§9）。

### 2.2 後置関数がかかる範囲

**末尾から 1 つ**——`top_open`（`spell.rs:120`）と同じ読み飛ばし:

- 末尾が `)` → **対応する `(` まで**（深さを数える）。種類は**組**
- 末尾が値の語 → **その 1 語**
- 末尾が二項演算子・`(`・空 → **かかる値が綴りに無い。画面の値を 1 語として補う**（§2.7）

- **中身の無い組 `( )`**（**設計書の外で決めた端。監視役の裁定 2026-10-05**）→ **3 つ目と同じ
  「かかる値が綴りに無い」に扱う**。`( )` は書かず、押す直前の画面の値を書く: `( ) sin` → `sin(0)`、
  `( ) x²` → `0²`、`3 + ( ) sin` → `3 + sin(0)`（spell_table の `an_empty_group_has_no_value_so_the_screen_is_written`）

かかった範囲を、**1 つの「そのほか」の語に畳む**。

### 2.3 キーごとの書き方

| キー | 原子 | 組 | そのほか |
|---|---|---|---|
| `sin` ほか前置の 9 つ | `sin(30)` | `sin(2 + 3)` | `sin(−3)`、`sin(sin(30))` |
| `x²` | `30²` | `(2 + 3)²` | `(−3)²`、`(sin(30))²` |
| `n!` | `5!` | `(2 + 3)!` | `(−3)!` |
| `eˣ` | `e^2` | `e^(2 + 3)` | `e^(−3)` |
| `1/x` | `1/2` | `1/(2 + 3)` | `1/(−3)`、`1/(sin(30))` |
| `+/−`（仮数の符号） | `−3` | `−(2 + 3)` | `−(−3)`、`−(sin(30))` |

- **関数は組の括弧を自分の括弧として使う**（「二重にしない」）。**後置・前置の記号は、
  組ならその括弧をそのまま使い、そのほかなら括弧を足す。**
- **例外は作らない**（裁定 5）。`sin(30)` も「そのほか」なので `(sin(30))²`・`−(sin(30))`。
- **指数入力中の `+/−` は変えない**——`Buffer` の中の指数の符号（`1.5e-3`）であり、語を作らない
  （`spell.rs:251` の `signed_exponent`）。
- **`nPr`・`nCr` は変えない。**
- **語を畳むのは確定した語だけ**——後置関数は `commit_into` のあとに来る（`spell.rs:289`）ので、
  **打ちかけの数が畳まれることは無い。** §5.2 の不変条件 A′ はこれに支えられている。

### 2.4 `xʸ` は `^` と書く。左が原子でも組でもなければ括弧で包む

- 字面を `xʸ` から `^` に変える（`commit_glyph` と `BINARY_GLYPHS`。押し直しの判定は
  `BINARY_GLYPHS` を読むので、2 つを一緒に変える——`spell.rs:334` の単体テストが見張っている）。
- **`^` の左の語が「そのほか」なら括弧で包む**: `2 +/− xʸ 2` → `(−2) ^ 2`、
  `30 x² xʸ 2` → `(30²) ^ 2`、`30 sin xʸ 2` → `(sin(30)) ^ 2`。
- **右は包まない。** `^` が最も強く右結合なので、`2 ^ 3 × 2`・`2 ^ 3 ^ 2`・`4 nCr 2 ^ 2` は
  どれも慣例どおりに読める（§1.3）。`2 xʸ 3 +/−` は `2 ^ −3` で、慣例でも 2^(−3) と読める。

### 2.5 前の答えを頭に付ける規則を core に移す

`3 =` のあと `sin` を `sin(3)` と書くには、**綴る側が頭の `3` を語として持っている必要がある。**
いまは web が綴りのあとで繋いでいる（§1.1）ので、web の `lineOf` に括弧の規則を書くことになり、
**「計算ロジックは core に置く」に反し、規則が 2 か所に分かれる。**

core に `spell_line` を置き、**頭の値を最初の語として積んでから歩く**（種類は §2.1 の文字列判定）。
**「綴りが空なら頭も付けない」**（`lineOf` の約束。`pushEntry` が空の式の行を捨てるため）も
core に移す。**引数の形は §2.7.1 で画面の値と一緒に決める。**

### 2.6 括弧の空白を無くす（裁定 2）

**`(` の後ろと `)` の前に空白を入れない。** `( 2 + 3 )` → `(2 + 3)`、`2 × ( 3 + 4` → `2 × (3 + 4`。
**`parts` の中では今どおり `(` と `)` を 1 語として持つ**（`top_open` と DEL の規則が語を数えるため）。
**変えるのは繋ぎ方だけ**——`join` で「前の語が `(`」か「この語が `)`」なら空白を入れない。

**目に付く副作用**（どれも engine の振る舞いを写した形で、誤りではない）:

- `3 × ( + 4`（`(` の直後の演算子。engine は `0 + 4` と読む。`engine_table.rs:1462`）→ `3 × (+ 4`
- `3 +/− )`（DEL で `(` を消したあとの開いていない `)`。`spell_table.rs:400`）→ `−3)`

### 2.7 画面の値で書く（裁定 1）

#### 2.7.1 どこから取り、core の中でどう渡すか

**`spell` はキー列しか受け取らないので、値を知りえない。** 取り方は 2 つ考えた。

- **案 P（推奨）: web が、押した瞬間の画面を 1 つずつ添える。**
  `press`（`ScientificPanel.tsx`）は既に**押下の直前の `previous.display` を読んで**
  `carryAtDecisionRef` と角度の印を決めている（`:612-619`）。**同じ場所で
  `previous.display.main` を `keysRef` と同じ長さの列に積む。** **web は値を選ばない**——
  全キーぶん写すだけで、**どのキーでその値を使うかは core が決める**（§2.2 の「かかる値が
  綴りに無い」とき）。
  core の形: `spell_line(carry: Option<&str>, keys: &[Key], screens: &[&str]) -> String`。
  `screens[i]` は `keys[i]` を押す直前の `main`。wasm は `spell_keys(tokens, carry, screens)`。
- **案 R: core が engine を歩き直す。** `spell_line(start: &EngineState, …)` が `reduce` を
  走らせ、各キーの前で `render(state).main` を読む。**web は区間の始まりの状態を
  1 つ持つだけで済む。** ただし**区間の始まりの状態を web が正しく掴む**必要がある
  （`=` の直後・`AC` の直後・読み込み直後の設定の復元 `:417-428`）。**掴み損ねると、
  engine が出した画面と違う値を書く**——**それは推測の一種**である。

**案 P を推す。** 書くのは「そのとき画面に出ていた値」そのもので（裁定の言葉どおり）、
写し損ねる余地が無い。**前の答えを頭に付ける仕組み（`carryAtDecisionRef`）と同じ形**でもある。

**添える列が無い呼び出し**（`spell(keys)`——`spell_table`・`spell_differential`・
`engine_values` が呼ぶ）: **`spell(keys)` は `spell_line(None, keys, &[])` として残し、
画面の値が要る場所に列が無ければ `…` を書く**（`2 + sin(…)`）。**panic しない**
（`calcarc-core` は panic しない）。**本番の経路は必ず列を添える**ので `…` は画面に出ない
——**それを vitest で見張る**（§5.4）。
**表の行は engine を歩いて列を作る**: `spell_table.rs` と `engine_table.rs` の `spell_of` は
もう `reduce` を回しているので、各キーの前の `render(&state).main` を積んで `spell_line` に渡す。

#### 2.7.2 値の綴り方

**画面の文字列（`display.main`）をそのまま使う。** 10 桁で丸めた文字列なので、
**綴りに丸めが入る**: `1 ÷ 3 + x²` → `1 ÷ 3 + 0.3333333333²`。**これは前の答えを頭に
付けるときと同じ約束**（1.2.0。`4 ÷ 3 =` のあとの行は `1.333333333 …` で始まる）で、
**裁定の「画面に出ていた値」そのもの**である。**丸めない値を書く道は無い**——engine の内部の
f64 を全桁で書くと、利用者が見たことのない数が式に出る。
**表示の形式もそのまま入る**（ENG・極形式・60 進で見ていればその文字列）。どれも §2.1 の
文字列判定で原子にならないので、括弧で包まれる。

#### 2.7.3 負・指数表記のとき

**§2.1 の文字列判定に従う。** `3 +/− + x²` → 画面 `-3` → `−3 + (-3)²`。
`1 Exp 20 x² + x²` → `(1e20)² + (1e40)²`（`+` の直後の画面は `1e40`。2026-10-05 に印字で確認）。

#### 2.7.4 範囲

**画面の値で書くのは、かかる値が綴りに無いときだけ**（§2.2 の 3 つ目）。値の語や組がある
ときは今どおりそれを包む——`30 sin` を `sin(0.5)` と書かないのはそのため。**`(` の直後と
空の区間（前置も無い）でも同じ規則で、画面は `0`** → `(0²`、`0²`。

## 4. 実装の形

### 4.1 語に種類を持たせる。`^` の左の包みは繋ぐときに付ける

```text
parts: Vec<Part>     Part = { text: String, kind: Atom | Group | Other }
```

- `(`・`)`・二項演算子は今と同じ 1 語（種類は持たせても使わない）。
- **後置関数**: §2.2 の範囲を `parts` から抜き、§2.3 の 1 語（`Other`）に畳んで積み直す。
  **範囲が無ければ** `screens[i]`（無ければ `…`）を 1 語として積んでから畳む（§2.7）。
- **`^` の左の括弧**（§2.4）は語に焼き込まず、**繋ぐときに「次の語が `^` で、この語が
  `Other`」なら `(…)` で包む**——**押し直しで `^` が消えれば包みも消える**（§3.3）。
- **括弧の空白**（§2.6）も繋ぐときに決める。
- **★ 字面を作る関数は 1 つにする**（条件 3）。**行全体を繋ぐときと、組を 1 語に畳むときの
  両方が、同じ `render(&[Part]) -> String` を呼ぶ。** 別々に書くと、畳むほうが `^` の左の包みを
  忘れて `( 3 +/− xʸ 2 ) sin` を `sin(−3 ^ 2)` と書きうる（正しくは `sin((−3) ^ 2)`）。
  **畳んだ時点で中の `^` は押し直せなくなる**（`)` で閉じている）ので、畳んだ字面に包みを
  焼き込んでよい。spell_table に `( 3 +/− xʸ 2 ) sin` → `sin((−3) ^ 2)` の行を置く。
- **DEL の `closed` の控え**（`spell.rs:180`）は `parts.len()` を持っている。**畳むと長さが縮む**が、
  後置関数は `closed` を空にする（`spell.rs:313-323`）ので、**畳んだあとに古い長さへ
  切り詰めることは起きない。** この前提は **spell_table の行で固定する**（`( 2 + 3 ) sin DEL`、§3.3）。
- **web の画面の列は `keysRef` の鏡にする**（条件 3）。`ScientificPanel.tsx` で `keysRef` に
  触る所は**書く 3 か所・読む 2 か所**（審査の数え方）で、**`pendingSpellRef` を effect が
  消費して `null` に戻す 1 か所（`:688`）も含めて**鏡にする（2026-10-05、`9b392d8` で grep）、**画面の列
  （`screensRef` と、`=` のあとの `pendingScreensRef`）も同じ 5 か所に同じ形で置く**:

  | `keysRef` | 行 | 画面の列 |
  |---|---|---|
  | 積む `keysRef.current.push(token)` | `:621` | **同じ文の隣**で `screensRef.current.push(previous.display.main)` |
  | `=` で `pendingSpellRef` へ渡して空にする | `:626-627` | `pendingScreensRef` へ渡して空にする |
  | `ac` で空にする（`pendingSpellRef` も） | `:637`（`:644`） | 空にする（`pendingScreensRef` も） |
  | 打っている最中の行を綴る | `:676` | 一緒に渡す |
  | `=` の行を綴る（effect）。`pendingSpellRef` を読んで `null` に戻す | `:669`・`:688`・`:694` | 一緒に読み、一緒に `null` に戻す |

  **どの 5 か所も `keysRef` の文の隣に置く**——**離すと、片方だけ直る日が来る。**
  **長さがずれる経路は構造上無い**（審査の所見。積むのはどちらも同じ `if` の中で、空にするのも
  同じ腕）が、**vitest で長さの一致を見張る**（§5.4）。
- **`top_open` は語の文字列が `(` か `)` に等しいかを見る**（`spell.rs:124-126`）。**畳んだ語
  `sin(2 + 3)` はどちらにも等しくない**ので、DEL の振る舞いは変わらない。

**構文木は組まない**——語の列を末尾から読み飛ばすだけで、`top_open` と同じ形である。
**画面の値は値を写すだけで、優先順位を綴りの側に写さない**（裁定 1 で第 1 版の案 B は不要になった）。

### 4.2 独立の宣言

`spell.rs` の `独立: 不可能` は変えない。**理由も同じ**——綴りは取り決めであり、別の手順で
同じ文字列に届く道が無い。**ただし §5.3 の番人は、取り決めのうち「慣例どおりに読めば
engine の答えになる」という数学の側の主張を、独立に確かめる**（読み手は engine を写さない）。

#### 5.3.2 読み手

**`SIGN_NET` の綴りは、キーに打ち直さず、文字列のまま数学の慣例で読む。** 読み手は
`engine_values.rs` の中に置く小さな再帰下降で、**有理数（既存の `Q`）で評価する。**

**`Typed` を使わない理由**（条件 1 で差し替えた。第 2 版の理由「演算子の直後の `x²` の値を
求めるには畳み方が要る」は第 1 版のもので、**裁定 1 のあとは画面の値が綴りに書かれるので
畳み方は要らない**）: **綴りの `−` は単項（`−3`）と二項（`2 − 3`）の両方に使われる。**
`Typed` に渡すには `keys_of_spelling` で語をキーに打ち直すが、あれは**「二項演算子が 2 つ続く」で
panic する**（`engine_values.rs:569-600`。押し直しとして前を捨てる並びを拒むため）ので、
`2 − −3` を打ち直せない。**単項か二項かは文字列の段でしか見分けられない**——綴りでは
**二項の `−` は空白で区切った 1 語**、**単項の `−` は次の数や `(` に空白なしで付く**（§2.3・§2.6）。
だから**字句を切る段から自前で持つ読み手**が要る。

**字句**（空白で語に割り、さらに `(` `)` `²` と単項の `−` を語の端から切り出す）:

```text
数     = [0-9]+ ("," [0-9]{3})* ("." [0-9]+)?   ← "," は画面の値の桁区切り（条件 2）。剥いで読む
       | "-" 数                                  ← ASCII の "-" は画面の値・前置の負号だけ（§2.1）
二項   = "+" | "−" | "×"                         ← 空白で区切った 1 語のときだけ
単項−  = "−"                                     ← 次の字に空白なしで付くとき
```

**文法**（`²` は前置の `−` より強い——**`−3²` は −9 と読む**）:

```text
式   = 項 (二項 項?)*                  ← 項の省略は規則 1
項   = 単項 ("×" 単項?)*               ← 同上
単項 = "−" 単項 | 後置
後置 = 一次 "²"*
一次 = 数 | "(" 中身 ")"? | "(" 中身 行末
中身 = 空 | 二項 式 | 式               ← 空は規則 2、先頭の二項は規則 3
```

**省略の規則 3 つ**——**どれも engine の振る舞いで、`Typed` の各腕と同じ行を名指しする**
（`Typed` は `engine_values.rs:123-127` の `implied`、`:286-292`、`:437-448` の `fill_the_right_operand`、
`:367` の閉じ忘れ）:

| # | 形 | 読み方 | engine の答え（2026-10-05 実走） | engine_table の行 |
|---|---|---|---|---|
| 1 | **二項演算子のあとに項が無い**（行末か `)` の直前） | **右辺は「その演算子の段でそれまでに積んだ値」**——`式` の段の `+ −` なら式の累計、`項` の段の `×` なら項の累計。**`(` より前へは戻らない**（その段の累計は括弧の中から始まる） | `3 + =` → 6、`2 × 3 + =` → 12（右辺 6）、`2 + 3 × =` → 11（右辺 3） | `equals_after_an_operator_repeats_the_operand`（`:1212`）、`the_echo_shows_the_pending_expression`（`:149`、`2 × 3 +` が「6 +」） |
| 2 | **`(` の中身が空**（`( )`、閉じ忘れの `(` が行末） | **0** | `( ) =` → 0、`3 + ( =` → 3 | `( )` だけの行は**表に無い**（`:1295-1296` は `+ ( ) DEL =` で別の形）。**実装の最初の段で `engine_table.rs` に `( ) =` → `0` と `3 + ( =` → `3` の行を足す**（表が仕様書） |
| 3 | **`(` の直後が二項演算子** | **左辺は 0** | `( + 4 ) =` → 4 | `an_operator_right_after_an_open_paren_takes_zero_as_its_left_operand`（`:1461`） |

- **行末の閉じ忘れの `(` は閉じる**——`equals_closes_unclosed_parentheses`（`:716`）。
- **規則 1 は再帰下降の形にそのまま乗る**: 段ごとに累計を持っているので、「項が無ければ累計を
  右辺にする」で済む。**`implied` のように前へ遡って区間を探す必要は無い**——`implied` が
  遡る範囲（押した演算子より優先順位が低くない演算だけで結ばれた直前の項）は、再帰下降では
  **その段の累計そのもの**である。**`SIGN_NET` に `xʸ` と `÷` は無い**ので、段は `+ −` と `×` の 2 つ。
- **規則 3 の `( −` は二項として読む**（空白で区切られる。`(− 4`）。単項と読んでも値は同じ
  （0 − 4 = −4）。**`(− 4²` も二項なら 0 − 16、単項でも −16** で割れない（engine は `( − 4 x² =` → `-16`。
  2026-10-05 に実走）。
  **割れるのは単項の `−` が `²` の左に付くときだけ**（`−3²` と `(−3)²`）——そこを見るのが目的である。
- **比べる相手は engine の答え**（`render(state).main` と、読んだ値の `format_real`）。
- **数える**: 比べた回数・食い違い（形ごと）を数え、**下限を assert する**（0 本で緑にしない）。
  **下限は実装のときの実測値。**
- **行数の見込み**（**実測前**）: 字句 40〜60・文法と評価 80〜110・省略の規則 3 つで 30〜50・
  網の歩き方（`walk` の前置の判定を流用）と数え上げ 40〜60 で、**200〜280 行**。
  **第 2 版の「100〜150」は省略の規則を数えていなかった。**
- **既存の 2 本の網は `keys_of_spelling` のまま**——ただし**括弧の空白が無くなる**ので、
  `(` と `)` を語から切り出すよう替える（`(3` → `(` と `3`）。**読み方の規則は変えない。**
  **画面の値は `,` を含みうる**が、既存の 2 本の網は後置関数を持たないので画面の値を使う場面が
  無い（§2.7.4）。**前置の答えの `,` は今も `Q::from_decimal` が剥いでいる。**
