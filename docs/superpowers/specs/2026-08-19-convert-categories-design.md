## §0.0 この spec が守ること

**新しい節を書くときは、全節を読み直さず、この 4 行とだけ突き合わせる。**

1. **エンジンに 1 行も足さない。** 足すのは単位表と単位面だけである
2. **係数は定義値。** 測定値・慣用値を厳密な定義値のふりをさせない
3. **基準が 1 つに定まらない単位は、名前に基準を書く**（§3.2）
4. **1 カテゴリの単位は 16 個以内**（4 × 4 の面に載る）

**破っているものは無い。**

## §1 裁定（ユーザー、2026-08-19）

**Area に坪と畳の両方を入れる。**

## §2 カテゴリ

設計書 §37 の初期リリース範囲のうち、U-1 が持たない 4 つである。

| カテゴリ | 基準単位 | 単位数 |
|---|---|---|
| Area | m² | 11 |
| Volume | L | 15 |
| Speed | m/s | 4 |
| Data Size | byte | 12 |

**どれも 16 以内**なので、既存の型面と同じ 4 × 4 の枠に載る（§0.0-4）。

**Convert の Data Size は、Scale の Data Scale と別物である。** Convert は
**単位どうしの換算**（`1 GB = 953.674 MiB`）、Scale は**規模の計算**
（件数 × 次元数 × 型 → バイト数）。名前が似ているが重複していない。

## §3 表（すべて定義値）

**参照実装はこの節から書き、Rust の表を写さない**（U-1 §0.0-2 と同じ規律）。

### 3.1 Area（基準: m²）

| 単位 | factor（m²） | 出典 |
|---|---|---|
| `mm²` | 1/10⁶ | SI |
| `cm²` | 1/10⁴ | |
| `m²` | 1 | 基準 |
| `km²` | 10⁶ | |
| `ha` | 10⁴ | ヘクタール |
| `in²` | (127/5000)² = **16129/25000000** | 国際インチの 2 乗 |
| `ft²` | 144 × `in²` | |
| `yd²` | 9 × `ft²` | |
| `ac` | 4840 × `yd²` = **316160658/78125** | ちょうど 4046.8564224 m² |
| `坪` | **400/121** | 1 尺 = 10/33 m、1 坪 = 6 尺 × 6 尺 |
| `畳` | **81/50** | **1.62 m² ちょうど**（§3.2） |

### 3.2 畳には基準を名前に書く

**畳は地域で違う**（京間・中京間・江戸間・団地間）。**基準を選ばずに `畳` と
名乗ると、画面が嘘をつく。**

**採る基準は 1.62 m²**（不動産の表示に関する公正競争規約が広告で用いる 1 畳あたりの
下限。実務でいちばん流通している値）。**単位のラベルは `畳(1.62㎡)`** とし、
数を名前に含める——押す前に何の畳か分かる。

**【実装時の義務】この出典は一次情報で確認してから landing する。** 規約の条番号と
版を導出記録に書く。**確認できなければ畳を入れない**——出典の曖昧な係数を
「定義値」の表に混ぜることは、この spec がいちばんやってはいけないことである。

### 3.3 坪 ≠ 2 畳（先に書いておく）

```text
1 坪 = 400/121 m² = 3.30578512…
2 畳 = 81/25  m² = 3.24
差    = 0.0658 m²
```

**慣用では「1 坪 = 2 畳」だが、両方を定義値として厳密に持つと一致しない。**
坪は尺から導かれ、畳は不動産の規約から来ていて、**出自が違う**からである。

**画面は何もしない**——`坪 → m² → 畳` の換算は基準単位を経由するので、
`1 坪 = 2.040608101 畳`（= 20000/9801）と正直に出る。**丸めて 2 に見せない。**
これは `GB ≠ GiB` を曖昧にしない方針（設計書 §41-5）と同じ扱いである。

### 3.4 Volume（基準: L）

**US と Imperial は明確に区別する**（設計書 §5 が要求）。**区別が要る単位は、
ラベルに系を書く。**

| 単位 | factor（L） | |
|---|---|---|
| `mL` | 1/1000 | |
| `cL` | 1/100 | |
| `dL` | 1/10 | |
| `L` | 1 | 基準 |
| `m³` | 1000 | |
| `gal(US)` | 231 × `in³` = **473176473/125000000** | ちょうど 3.785411784 L |
| `gal(Imp)` | **454609/100000** | **ちょうど 4.54609 L**（1985） |
| `fl oz(US)` | `gal(US)`/128 | 29.5735295625 mL |
| `fl oz(Imp)` | `gal(Imp)`/160 | 28.4130625 mL |
| `pt(US)` | 16 × `fl oz(US)` | 473.176473 mL |
| `pt(Imp)` | 20 × `fl oz(Imp)` | 568.26125 mL |
| `qt(US)` | 32 × `fl oz(US)` | 946.352946 mL |
| `qt(Imp)` | 40 × `fl oz(Imp)` | 1136.5225 mL |
| `cup(US)` | 8 × `fl oz(US)` | 236.5882365 mL |
| `カップ(200mL)` | **1/5** | **日本の計量カップ。ちょうど 200 mL** |

**`cup` は 1 つでは足りない。** 米国慣用の 8 fl oz（236.588 mL）と、日本の計量カップ
（200 mL）は別物で、料理で使うのは後者である。**畳と同じ扱いにする**——
どちらもラベルに数か系を書き、`cup` という裸の名前は使わない。

**`quart` も US と Imperial の両方を置く。** 当初は `qt(US)` だけで、**除外の記録も
無かった**——`fl oz` `pt` `gal` は両系あるのに quart だけ片方、という無言の穴だった。
15 個で枠（16）に収まるので入れる。

（米国の「法定カップ」240 mL は入れない。3 つ目を足すと面が埋まる。**入れないと
決めたことを書いておく**。）

### 3.6 Data Size（基準: byte）

**SI と IEC を分離する**（設計書 §6）。

| 単位 | factor（byte） | | 単位 | factor（byte） |
|---|---|---|---|---|
| `bit` | **1/8** | | `KiB` | 2¹⁰ |
| `byte` | 1（基準） | | `MiB` | 2²⁰ |
| `kB` | 10³ | | `GiB` | 2³⁰ |
| `MB` | 10⁶ | | `TiB` | 2⁴⁰ |
| `GB` | 10⁹ | | `PiB` | 2⁵⁰ |
| `TB` | 10¹² | | | |
| `PB` | 10¹⁵ | | | |

**`bit` の factor は 1/8 である。** 有理数なので、`1 bit → byte` は `0.125` と
厳密に出る（f64 なら偶然合うが、ここでは偶然に頼らない）。

## §4 盤面

**単位面が増えるだけ**である。項目行・Swap・数字面・表示規則は U-1 のまま。

カテゴリは `#convert/area` `#convert/volume` `#convert/speed`
`#convert/data-size` の 4 つで、U-1 の 3 つと合わせて **Convert は 7 カテゴリ**に
なる。カテゴリ選択の `<select>` は U-0 の器のままで、行は増えない。

**ラベルが長い単位がある**（`fl oz(Imp)`、`カップ(200mL)`、`畳(1.62㎡)`）。
**44px の高さは譲らず、面の中で文字を縮める**。実測して spec に追記する
（U-0 §4 と同じ順序: まず gap、次に font-size）。

## §5 検証

**段ゲート**: Python 参照 ＋ golden → Rust → wasm → UI。**エンジンは U-1 が
検証済み**なので、この spec が守るのは**表の正しさ**だけである。

**golden**: `testdata/convert.json` に**追記**（U-1 のケースは 1 件も変えない）。

**名指しで置くケース**:

| | 何を守る |
|---|---|
| `1 坪 = 2.040608101 畳`（= 20000/9801） | **§3.3 の非整合が画面に出ること**。`2` に丸まっていたら赤 |
| `1 gal(US) = 3.785411784 L` / `1 gal(Imp) = 4.54609 L` | US と Imperial を取り違えていない |
| `1 cup(US) = 236.5882365 mL` / `1 カップ(200mL) = 200 mL` | §3.4 の 2 つが別物であること |
| `1 GB = 953.6743164 MiB` | SI と IEC の分離（設計書 §6 の例） |
| `1 bit = 0.125 byte` | `bit` が 1/8 であること |
| `1 ac = 4046.8564224 m²` | ヤード・ポンド系の積み上げ |
| `1 kn = 1.852 km/h` | 海里の定義が生きていること |

**赤確認**（変異前に一時コミット、戻すのは変異箇所の再編集）:

1. **`gal(Imp)` の係数を `gal(US)` の値にする**——US/Imperial の取り違えが赤になるか。
   **これが赤にならなければ、Imperial のケースを 1 件も置いていない**
2. **`畳` を `坪/2` にする**（慣用に合わせる変異）——§3.3 のケースが赤。
   **慣用の値に寄せた瞬間に赤くなることを、実物で見ておく**
3. **`bit` の factor を 8 にする**（逆数の取り違え）——`1 bit = 0.125 byte` が赤
4. **`KiB` を 1000 にする**——SI と IEC の分離が赤

**段付け**: `cargo test --workspace` ＋ `uv run pytest`（`--no-config`）。
UI は単位面が増えるだけなので `pnpm test` まで。**`pnpm e2e` は
「面が枠に収まっているか」を見る 1 本だけ**——ロールの意味論は U-1 で固定済みで、
ここは同じ機構の反復である。

**コーパス影響の宣言**: **無し**（U-1 と同じ理由）。
