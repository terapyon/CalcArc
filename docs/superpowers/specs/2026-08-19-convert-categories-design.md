前提: **U-1 の上に積む。** エンジン（アフィン変換・基準単位経由・厳密有理数・
表示規則）は U-1 が決めており、**この spec は表と単位面しか足さない。**

## §0.0 この spec が守ること

**新しい節を書くときは、全節を読み直さず、この 4 行とだけ突き合わせる。**

1. **エンジンに 1 行も足さない。** 足すのは単位表と単位面だけである
2. **係数は定義値。** 測定値・慣用値を厳密な定義値のふりをさせない
3. **基準が 1 つに定まらない単位は、名前に基準を書く**（§3.2）
4. ~~**1 カテゴリの単位は 16 個以内**（4 × 4 の面に載る）~~ →
   **1 カテゴリの単位は 15 個以内**（5 × 5 の枠の、**左 3 列 × 5 行**に載る）

**破っているものは無い。**

**【訂正 2026-08-20】上限は 16 ではなく 15 で、枠は 4 × 4 ではなく 5 × 5 である。**
ここには当初「1 カテゴリの単位は 16 個以内（4 × 4 の面に載る）」と書いていたが、
**実物と違う。しかも危険な方向に違う**——実物の容量は 16 **より小さい**。

- **枠は 5 列 × 5 行である。** 押さえているのは `UnitPanel.module.css` で、
  `fieldset[aria-label="単位のキー"]` に `grid-template-rows: repeat(5, 1fr)` と
  `aspect-ratio: 1 / 1` を掛けている。**「4 × 4」の前提は S-0 で既に否定済み**
  （`2026-08-19-scale-llm-transfer-design.md` §2 の【訂正 2026-08-19】）で、
  この spec は**否定された前提を引き継いでいた**
- **DEL と AC が 1 行目の 4 列目・5 列目を取る**（数字面と同じ位置）。単位は
  **左 3 列にしか置かない**——4・5 列目は恒久の空きである
  （`web/src/ui/Keypad/convert.ts` の `unitFace()`）
  - **【追記 2026-08-20（U-4）】「恒久の空き」は 2 行目以降についてはもう真ではない。**
    U-4 の為替（Convert の 8 番目のカテゴリ）は 16 通貨で、左 3 列では 6 行になって
    枠があふれる（実測 440.875 x 440.875）。**為替の面だけ 2 行目以降が 5 列**で、
    3 + 5 + 5 + 3 = 16 を 4 行に収める（実測 366.0625 x 366.0625）。**1 行目の
    3 列 + DEL + AC はどの面でも同じ**で、**この spec の 7 カテゴリの面は 1 キーも
    動いていない**。上の「15 スロット」は**左 3 列に詰める面の容量**として読むこと
- したがって単位に使えるのは **3 列 × 5 行 = 15 スロット**。`unitFace()` の行数は
  **単位数で決まる**（`do...while` が単位の尽きるまで行を足す）ので、16 個入れると
  6 行目ができ、CSS が保つ 5 行を超える

**実測**（2026-08-20、Playwright `convert.spec.ts`、mobile 390 × 844）。
`unitsOf("length")` が 16 個返すよう一時的に変異させて計測した:

```text
16 個 → 「swapping faces moves neither the frame nor DEL and AC」が赤
        数字面      366.0625 x 366.0625
        単位面      440.875  x 440.875   ← 6 行目のぶん +74.8125px 伸びた
        DEL の相対位置も 224.4375,0 → 269.3125,0 に動いた
15 個 → 同じ検査が緑。単位面は 366.0625 x 366.0625 で数字面と一致
```

**左 3 列に詰める限り、15 は入り、16 は入らない。** 面を入れ替えるたびに枠が 74.8px 動き、
DEL と AC が指の下から逃げる。

**【訂正 2026-08-20（U-4）】「これは枠の限界である」は言い過ぎだった。**
ここには当初「**これは枠の限界であって、選んだスコープではない**」と書いていたが、
**15 は「左 3 列に詰める」という置き方の限界であって、枠の限界ではない。**
U-4 が **2 行目以降の 4・5 列目にも置く**形を実測で見つけ、**枠も DEL/AC も動かさずに 16 を載せた**
（通貨面。3 + 5 + 5 + 3 = 16、4 行 20 セル、枠は 366.0625² のまま）。
**この置き方なら容量は 3 + 5 × 4 = 23 である。**

**訂正しても、U-2 で単位の増減はしない**——§2 の 11 / 15 / 4 / 12 はそのままである。
**変わったのは「足せない」ではなく「足すなら置き方を変える必要がある」**という点である。

**Volume は「左 3 列」の置き方では容量いっぱいである（15 個）。**
§3.4 が米国法定カップ 240 mL について「3 つ目を足すと面が埋まる」と書いているのは、
**左 3 列に詰める限り**正確には**「あふれる」**である。
**次に Volume へ単位を足そうとする人は、先に置き方を変える話をすること**
——**枠を広げる必要は無い**（U-4 が示した）が、**単位だけ足すと、この spec が守っている
「面を入れ替えても枠は動かない」が黙って壊れる**のは変わらない。

（件数 × 次元数 × 型 → バイト数）。名前が似ているが重複していない。

### 3.2 畳には基準を名前に書く

**畳は地域で違う**（京間・中京間・江戸間・団地間）。**基準を選ばずに `畳` と
名乗ると、画面が嘘をつく。**

**【訂正 2026-08-20】ラベルの「平方メートル」は `m²`（`m` + U+00B2）で書く。**
ここには当初 `畳(1.62㎡)` と、**互換文字 `㎡`（U+33A1）1 文字**で書いていた。
**同じ面に `m²` と書いた単位が並ぶ**（`m2` のラベルは `m` + U+00B2）ので、**同じものが 2 通りの字で出る**
——U-1 が `µ`（U+00B5 と U+03BC の 2 通り）で潰したのと同じ型の罠である。
**幅もフォントも読み上げも、互換文字では保証が別になる。** 正しい表記は **`畳(1.62m²)`**。

**採る基準は 1.62 m²**（不動産の表示に関する公正競争規約が広告で用いる 1 畳あたりの
下限。実務でいちばん流通している値）。**単位のラベルは `畳(1.62m²)`** とし、
数を名前に含める——押す前に何の畳か分かる。

**【実装時の義務】この出典は一次情報で確認してから landing する。** 規約の条番号と
版を導出記録に書く。**確認できなければ畳を入れない**——出典の曖昧な係数を
「定義値」の表に混ぜることは、この spec がいちばんやってはいけないことである。

**【出典の確認 2026-08-20】確認できた。畳を入れる。**

- **条番号**: 不動産の表示に関する公正競争規約**施行規則 第 9 条第 16 号**
- **版**: 現行。表示規約施行規則の最終変更は**令和 4 年（2022 年）9 月 1 日施行**
  （同施行規則の附則）
- **条文**（原文のまま）:

  > (16) 住宅の居室等の広さを畳数で表示する場合においては、畳１枚当たりの広さは
  > 1.62平方メートル（各室の壁心面積を畳数で除した数値）以上の広さがあるという
  > 意味で用いること。

- **出典**: 不動産公正取引協議会連合会『不動産の公正競争規約』（2026 年 3 月
  改訂第 2 刷）
  <https://www.rftc.jp/webkanri/kanri/wp-content/uploads/2025/08/20250826_kiyakushuu.pdf>
- **同じ冊子の中で条番号が裏取りできる。** 実施細則「ＤＫ・ＬＤＫの広さ（畳数）の
  目安となる指導基準」が「なお、一畳当たりの広さは、1.62平方メートル（各室の壁心
  面積を畳数で除した数値）以上をいう（**表示規約施行規則第９条第16号**）」と引いている
- **条番号は版で動く。引くときは版を添えること。** 同連合会が 2019 年に掲載した旧版
  では同じ規定が**第 10 条第 16 号**
  （<https://www.rftc.jp/webkanri/kanri/wp-content/uploads/2019/02/h_sekoukisoku.pdf>、
  附則の最終は平成 27 年 12 月 4 日）、平成 23 年の指導基準本文では**第 11 条第 16 号**
  と引かれている

**規約が定めるのは「1 畳あたり 1.62 m² 以上」という広告表示の下限であって、畳の
実寸ではない。** この spec はその**下限値を定義値として採る**——ラベルを
`畳(1.62m²)` と数入りにするのは、まさにこれが**規約の下限であって畳の実寸ではない**
からである（§0.0-3）。

### 3.3 坪 ≠ 2 畳（先に書いておく）

```text
1 坪 = 400/121 m² = 3.30578512…
2 畳 = 81/25  m² = 3.24
差    = 0.0658 m²
```

**慣用では「1 坪 = 2 畳」だが、両方を定義値として厳密に持つと一致しない。**
坪は尺から導かれ、畳は不動産の規約から来ていて、**出自が違う**からである。

**画面は何もしない**——`坪 → m² → 畳` の換算は基準単位を経由するので、
`1 坪 = 2.040608101 畳`（= 20000/9801）と正直に出る。**丸めて 2 に見せない。**
これは `GB ≠ GiB` を曖昧にしない方針（設計書 §41-5）と同じ扱いである。

ラベルに系を書く。**

| 単位 | factor（L） | |
|---|---|---|
| `mL` | 1/1000 | |
| `cL` | 1/100 | |
| `dL` | 1/10 | |
| `L` | 1 | 基準 |
| `m³` | 1000 | |
| `gal(US)` | 231 × `in³` = **473176473/125000000** | ちょうど 3.785411784 L |
| `gal(Imp)` | **454609/100000** | **ちょうど 4.54609 L**（1985） |
| `fl oz(US)` | `gal(US)`/128 | 29.5735295625 mL |
| `fl oz(Imp)` | `gal(Imp)`/160 | 28.4130625 mL |
| `pt(US)` | 16 × `fl oz(US)` | 473.176473 mL |
| `pt(Imp)` | 20 × `fl oz(Imp)` | 568.26125 mL |
| `qt(US)` | 32 × `fl oz(US)` | 946.352946 mL |
| `qt(Imp)` | 40 × `fl oz(Imp)` | 1136.5225 mL |
| `cup(US)` | 8 × `fl oz(US)` | 236.5882365 mL |
| `カップ(200mL)` | **1/5** | **日本の計量カップ。ちょうど 200 mL** |

**`cup` は 1 つでは足りない。** 米国慣用の 8 fl oz（236.588 mL）と、日本の計量カップ
（200 mL）は別物で、料理で使うのは後者である。**畳と同じ扱いにする**——
どちらもラベルに数か系を書き、`cup` という裸の名前は使わない。

**`quart` も US と Imperial の両方を置く。** 当初は `qt(US)` だけで、**除外の記録も
無かった**——`fl oz` `pt` `gal` は両系あるのに quart だけ片方、という無言の穴だった。
15 個で枠に収まるので入れる（**枠の上限は 15**。§0.0-4 の【訂正 2026-08-20】——
当初ここには「枠（16）」と書いていた）。

（米国の「法定カップ」240 mL は入れない。3 つ目を足すと面が埋まる。**入れないと
決めたことを書いておく**。）

## §4 盤面

**単位面が増えるだけ**である。項目行・Swap・数字面・表示規則は U-1 のまま。

カテゴリは `#convert/area` `#convert/volume` `#convert/speed`
`#convert/data-size` の 4 つで、U-1 の 3 つと合わせて **Convert は 7 カテゴリ**に
なる。カテゴリ選択の `<select>` は U-0 の器のままで、行は増えない。

**ラベルが長い単位がある**（`fl oz(Imp)`、`カップ(200mL)`、`畳(1.62m²)`）。
**44px の高さは譲らず、面の中で文字を縮める**。実測して spec に追記する
（U-0 §4 と同じ順序: まず gap、次に font-size）。

> **【訂正 2026-08-20】** ここには当初 `畳(1.62㎡)` と書いていたが、`㎡` は
> 互換文字 U+33A1 で、**§3.2 の【訂正 2026-08-20】が使うなと決めたほうの字**
> である。実物のラベルは `m` + U+00B2 の `畳(1.62m²)` で、上はそれに直した。

### 【実測 2026-08-20】縮めなかった。gap も font-size も届かないからである

実機ビルド（`vite build` + `vite preview`）を Playwright/Chromium で計測。
`--key-gap` は 8px、キーの `font-size` は 15px（`--key-font-size-function`）。

| | 390×844 | 360×640 |
|---|---|---|
| 単位面の枠 | 366.0625 × 366.0625 | 336 × 336 |
| キーの最小辺（7 カテゴリ・全キー） | **66.8125** | **60.7969** |
| キーの内寸（`clientWidth`） | 67px | 61px |
| ラベルのはみ出し（`scrollWidth > clientWidth`） | **0 件** | **0 件** |
| 横のはみ出し（`scrollWidth − innerWidth`） | 0 | 0 |
| 縦（`scrollHeight − innerHeight`、`#convert/volume`） | **0** | **66** |

**44px は割っていない。** 最小辺は 360×640 でも 60.80px で、**16.8px の余裕**がある
——**この面で 44px が問題になったことは一度もない**。

**ラベルは 1 文字も切れていない**（`scrollWidth`・`scrollHeight` がどのキーでも
内寸以下）。**その代わり、長い 3 つは面の中で 2 行に折り返している**。折り返さない
ときの実測幅（`white-space: nowrap` を当てて計測、font-size 15px）:

| ラベル | 1 行に要る幅 | 390（内寸 67px） | 360（内寸 61px） |
|---|---|---|---|
| `カップ(200mL)` | **102.16px** | 2 行 | 2 行 |
| `畳(1.62m²)` | **74.34px** | 2 行 | 2 行 |
| `fl oz(Imp)` | **66.38px** | 1 行（余白 0.62px） | 2 行 |
| `gal(Imp)` | 58.63px | 1 行 | 1 行 |
| `fl oz(US)` | 58.38px | 1 行 | 1 行 |

**U-0 §4 の順序で当たって、どちらも届かなかった。**

1. **gap は届かない。** `column-gap` を **0 にしても** 1 列は 390 で
   366.0625 ÷ 5 = **73.21px**、360 で 336 ÷ 5 = **67.2px** にしかならない。
   `カップ(200mL)` の 102.16px には**どちらも足りない**——`fl oz(Imp)` を
   360 で 1 行にするだけなら足りるが、**gap を 0 にするのは 3 つのうち 1 つの
   ためだけの代償になる**（gap はすべての面の押し分けを支えている）
2. **font-size も届かない。** `カップ(200mL)` を 360 で 1 行にするには
   15px × 67.2 ÷ 102.16 ≈ **9.9px**（gap 0 のとき。gap 8px なら 9.0px）。
   **10px を切る和文は 44px を守る意味を失わせる**——押せても読めない

**したがって「2 行に折り返す」を最終形として受け入れる。** 譲らなかったのは
44px と `gap` と font-size で、譲ったのは「1 行に収まること」である。
**これは劣化ではない**——`畳` / `(1.62m²)` は名前と基準が上下に分かれ、
`カップ` / `(200mL)` も同じ形になる。**基準を名前に書く（§0.0-3）という判断と、
2 行のレイアウトは相性が良い。**

**機械が見張っているもの / いないもの**:

- **44px** は `convert.spec.ts` の `every face keeps 44px touch targets` が
  **7 カテゴリ 140 キー**で見張る
- **枠のあふれ・潰れ**は `swapping faces moves neither the frame nor DEL and AC`
  が 7 カテゴリで見張る（§5）
- **ラベルが切れないこと（`scrollWidth ≤ clientWidth`）を見張る検査は無い。**
  上の 0 件は**この日の手計測**である。ラベルを伸ばす人は、ここを測り直すこと

**縦の予算は U-1 の 3 カテゴリと 1px も変わらない**（390×844 で 0、360×640 で 66）。
枠の高さは `aspect-ratio: 1 / 1` が決めており、**単位が 3 個でも 15 個でも面の寸法が
同じ**であることは上の枠の実測が示している。したがって
`docs/definition-of-done.md` の Convert の行は**書き換えない**——
**7 カテゴリで最も重い（= 15 単位 5 行の）volume が、いちばん軽い temperature と
同値だった**。

| `1 坪 = 2.040608101 畳`（= 20000/9801） | **§3.3 の非整合が画面に出ること**。`2` に丸まっていたら赤 |
| `1 gal(US) = 3.785411784 L` / `1 gal(Imp) = 4.54609 L` | US と Imperial を取り違えていない |
| `1 cup(US) = 236.5882365 mL` / `1 カップ(200mL) = 200 mL` | §3.4 の 2 つが別物であること |
| `1 GB = 953.6743164 MiB` | SI と IEC の分離（設計書 §6 の例） |
| `1 bit = 0.125 byte` | `bit` が 1/8 であること |
| `1 ac = 4046.8564224 m²` | ヤード・ポンド系の積み上げ。**【註 2026-08-20】画面には `4,046.856422` と出る**（下記） |
| `1 kn = 1.852 km/h` | 海里の定義が生きていること |

**【註 2026-08-20】`ac` だけは、厳密値と画面の表示が一致しない。**
`316160658/78125 = 4046.8564224` は**有効数字 11 桁**で、表示規則は 10 桁である
（`docs/numerical-policy.md`）。**画面に出るのは `4,046.856422` で、11 桁目の `4` は落ちる。**

**係数が守られていないわけではない。守る場所が 2 つに分かれている**:
- **厳密値**（`316160658/78125`）を固定するのは**参照実装とコアの単体テスト**
- **表示**（`4,046.856422`）を固定するのが golden

**この行だけ、golden は 11 桁目を見ていない。** `4046.8564225` に変異させても表示は変わらないので、
**11 桁目だけの誤りは単体テストでしか捕まらない。** 名指しケースの表を読む人が、
golden の文字列と spec の数字が違うことに驚かないよう、ここに書いておく。

**赤確認**（変異前に一時コミット、戻すのは変異箇所の再編集）:

1. **`gal(Imp)` の係数を `gal(US)` の値にする**——US/Imperial の取り違えが赤になるか。
   **これが赤にならなければ、Imperial のケースを 1 件も置いていない**
2. **`畳` を `坪/2` にする**（慣用に合わせる変異）——§3.3 のケースが赤。
   **慣用の値に寄せた瞬間に赤くなることを、実物で見ておく**
3. **`bit` の factor を 8 にする**（逆数の取り違え）——`1 bit = 0.125 byte` が赤
4. **`KiB` を 1000 にする**——SI と IEC の分離が赤
