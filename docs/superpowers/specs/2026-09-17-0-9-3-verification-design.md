# 0.9.3 検証側の設計——番人と文書の 5 件

**起点**: `2be381d`（= タグ `v0.9.2` = いまの `main`）。**この文書の行番号・数・引用は、すべて `2be381d` で当て直した。**
**扱うのは検査側だけ**である（製品側の UI・更新・挙動は calcarc-3d の設計書）。**承認まで実装しない。**

## §0 この 5 件に共通する形と、受け入れ条件

0.9.2 のマニュアル監査（`docs/superpowers/sdd/2026-09-17-manual-audit.md`）の所見は
**「マニュアルの主張には、意味を読む番人が 1 本も無い」**だった。5 件はその穴のうち**機械で塞げる所**である。

**監査そのものが踏んだ失敗を、この設計の受け入れ条件にする:**

1. **「定数が在る」は「その定数が効いている」ではない。**
   監査は `MAX_RATE_LEN = 8` の存在を確かめて「一致」とした。**数字の打鍵はその定数を通らない**
   （`web/src/ui/Finance/FinancePanel.tsx:590-592` `pressDigit` → `web/src/finance/entry.ts:44`
   `pushDigit(…, MAX_YEN_DIGITS = 20)`）。**番人は、打鍵から定数までの経路の上に置く。**
2. **数が同じでも別物のことがある。** `DISPLAY_DIGITS` は 2 つある——
   `crates/calcarc-core/src/numeric/format.rs:4`（`pub`）と `crates/calcarc-core/src/convert/format.rs:25`（非公開）。
   **今日はどちらも 10 なので、どちらを読んでも番人は緑になる。**片方が動いた日に、間違った方を読む番人は
   **黙って守らなくなる**。**設計はどちらを読むかを名指しし、理由を 1 行書く。**
3. **番人が読む数と、文書に書く数は、同じとは限らない。** §1.3 を見よ。**「文書の数 == 定数」を素朴に比べる番人は、
   正しい文書を赤にするか、文書に嘘を書かせる。**

### 1.3 **文書の数と定数の数は 1 ずれる**（設計の核）

`docs/manual/detail.ja.md` は「**小数点は、いま打っている数が 7 文字までのあいだしか打てません**」と書く。
定数は **8**（`MAX_RATE_LEN`）。**どちらも正しい**——`web/src/units/entry.ts:81` の `pushDot` は
`tail.text.length >= maxDigits` で拒むので、**7 文字までなら打て、8 文字で打てなくなる**。

**したがって番人は「文書の数 == 定数」を比べてはならない。**比べるのは
**「文書の数 == その定数から導いた、利用者に見える値」**である。**導き方（`− 1` など）を番人の中に書き、
その 1 行が壊れたら赤くなるようにする。**

**ずれ方は 2 種類ある**（2 つ目は calcarc-3d の実測、`2be381d`）:

| 形 | 例 | 番人が要るもの |
|---|---|---|
| **値がずれる** | 文書「**7 文字**まで」／定数 `MAX_RATE_LEN = 8`（`pushDot` は `length >= max` で拒む） | `− 1` の 1 行 |
| **表し方が違う** | 同じ「小数 4 桁まで」が、`rate.rs:42` では**桁数 `4`**（`frac_part.len() > 4`）、`expr/mod.rs:18` では**倍率 `10_000`**（`PERCENT_SCALE`） | **`4` と `10^4` の関係**の 1 行 |

**2 つ目のほうが危ない。** ずれているのではなく**同じ数がどこにも無い**ので、
**「同じ数を探す」形の番人は、何も見つけられないまま緑になる**——
**0 件で落ちる床（§1.7 の条件 1）が無ければ、気づけない。**

### 1.4 仕組みは既に在る。広げるだけである

`crates/calcarc-wasm/tests/token_parity.rs` が、**`include_str!` で `web/src/ui/Finance/FinancePanel.tsx` を読み**、
`number_in_ts_const`（`:193`）で TypeScript の定数を取り出して Rust 側と突き合わせている。
**`:204-212` の註は、C-1 が言おうとしていることを先に書いている**——盤面とコアが別々に 1200 を持ち、
**食い違っても誰も落ちない**（小さすぎれば打てない期数が静かに増え、大きすぎれば打てた値をコアが弾く。
**どちらも計算は正しいままなので、既存のどの検査にも映らない**）。

- `include_str!` なので**ファイルが動けばコンパイルエラー**になる（静かに死なない）。
- 取り出しは**宣言の先頭からの完全一致**（`"const MAX_PERIODS = "`）で、接頭辞の衝突を避ける（理由は `:190-192`）。
- **定数を突き合わせる向きは 1 つだけ**——Rust から TS を読む。**逆向きは無い**。
  ただし**「Rust の本文を読むもの」は在る**——`heavy/scripts/detection-power.mjs` が
  `crates/**/*.rs` を読んで変異を当てる（**定数の突合ではない**）。
  **「読むものが無い」ではなく「定数を突き合わせる向きが無い」**が正しい。
- **そして、これは 1 か所の工夫ではない。** `include_str!` で `web/` を読んでいる Rust のテストは
  **15 か所・3 ファイル**（`token_parity.rs`・`carried_value_parity.rs`・`label_parity.rs`）あり、
  **8 本の TS/TSX**（`calc/types.ts`・`datascale/types.ts`・`convert/types.ts`・`currency/types.ts`・
  `finance/types.ts`・`ui/Finance/FinancePanel.tsx`・`ui/ScientificPanel.tsx`・`ui/Keypad/scientific.ts`）を読む。
  **`crates/` 全体では 16 呼び出し・4 ファイル**で、4 つ目の `loan_boundary.rs` が読むのは
  `testdata/loan_boundary.json` である（`git grep -c` は **17** を返すが、
  **1 件は `token_parity.rs:9` の註**であって呼び出しではない）。
  **「ソースの本文を読んで数や綴りを突き合わせる」ことは、この repo では例外ではなく作法である。**
- **Rust から `docs/manual/*.md` を読むテストは 1 本も無い。** マニュアルを開いているのは
  **TS の 3 本**（`manual-key-names`・`manual-shots`・`manual-widths`。§1.1）であり、
  **そのうち数値を見ているのは `manual-widths` の画面幅 2 つだけ**である。

**この節は「証拠」であって「採用する仕掛け」ではない**（採るのは §1.7 の (B)）。ここで示したいのは 2 つ——
**(1) 塞ぐべき穴は、この repo が自分の言葉で既に名指ししている**（`:204-212`）、
**(2) ソースをまたいで数を突き合わせるのは、この repo で既に行われている**。
**どちらの言語で書くにせよ、新しい流儀は作らない。**

### 1.5 副産物——**偽の理由はコードの側に移っていた**

監査は `detail.ja.md:737` を誤りとしたが、**その文は 0.9.2 の直し（`ca6b608`・`d6aaed3`）で既に正しくなっている**。
**同じ誤りが、いまはコードの註に残っている**——`FinancePanel.tsx:144-146` は
「それ以上打てても SyntaxError になるだけなので、**入口で止める**」と書くが、`MAX_RATE_LEN` が届くのは
`pushDot`（`:662`）だけで、**数字は止まらない**。**この註は `e727a0c` から 1 文字も変わっていない。**
**番人の無い場所へ、偽の理由が移っただけ**である（記憶「理由は静かに腐る」）。
**同じ PR で直す**（見つけた経路をさかのぼって全部直す）。

**そして、同じ形がもう 1 つ在る。** `crates/calcarc-core/src/convert/settle.rs:21-23` の註は
「**機械の番人は無い**——この定数は境界を越えて公開されておらず、web 側から読めない」と書く。
**この註は 2 つの意味で古い**——(a) その宣言自身が **`pub`** である（`:24`）、
(b) **読む向きは既に在る**（`token_parity.rs` が Rust から TS を読む）。
**「番人を置けない」と自白している註が、実は置ける場所を指している。**

### 1.6 いちばん安い 1 本——両側に書かれた同じ数

`MAX_VALUE_CHARS`（Rust、`pub`、39）と `MAX_VALUE_DIGITS`（TS、39）は**同じ数を別々に持っている**。
役割は違う（片方は描き分け、片方は打鍵の壁）が、**食い違えば表示と入力の前提がずれる**。
**この組も §1.7 の (B) の番人が持つ**——`.rs` と `.ts` の本文から 2 つの 39 を取り出して比べる。
**別々の番人に分けない**（同じ種類の主張が 2 か所に散ると、次に足す人がどちらに足すか迷う）。
**上の註（1.5 の (b)）も同じコミットで直す。**

（`MAX_VALUE_CHARS` は `pub` なので、**`token_parity.rs` 側で値として比べることもできる**。
それでも (B) に寄せるのは、**マニュアルの数との突合と同じ場所に置くため**である——
この組だけ別の言語・別の仕掛けにする理由が無い。）

### 1.7 番人をどこに置くか——**(B) を採る。可視性は 1 つも広げない**

**採った案 (B)**: **JS/TS の番人（`tools/check-*.mjs` ＋ `tools/tests/`）が、`.rs` と `.ts` と
`docs/manual/*.md` の本文を読んで突き合わせる。**

**採らなかった案 (A)**: Rust の結合テスト（`token_parity.rs` の隣）に置き、定数を**値として**読む。
そのために Rust 2 本・TS 5 本に `pub`／`export` を足す。

**(A) を採らなかった理由**（2026-09-17、calcarc-3d の提起で裁定が変わった。**当初はこちらを推していた**）:

1. **突き合わせたいのは「マニュアルの数」と「コードに書かれた数」であって、実行時の値ではない。**
   当初の推しは「**番人が値を読む**」という前提に立っていたが、**その前提自体が要らなかった**。
   値を読まないなら、**そのために可視性を広げる理由も消える**。
2. **公開 API を広げる決定は、後から戻せない側の決定**である。`docs/superpowers/` には
   **1.0 の API 整理の宿題が既に在る**——検査のために 7 本増やせば、その宿題が 7 本増える。
3. **(B) はこの repo の既存の流儀そのものである。** `tools/check-version.mjs` は
   `Cargo.toml`・`Cargo.lock`（2 つの crate）・`web/package.json`・README 2 本の自由文・
   `CHANGELOG.md` の見出しという **6 か所を、種類ばらばらのまま本文として読む**。

**(B) の弱点と、その対策**——**正規表現で本文を読むので、綴りが変わった日に静かに 0 件になりうる**。
**対策も既存の番人が持っている**: `check-version.mjs:162-163` は「節が見つからなければ `null` が返り、
`compare` が『版数を読めなかった』で落とす——**知らない形を黙って通さない**」。**同じ床を置く。**

**(B) で守る条件（4 つ）:**

1. **定数ごとに「1 件見つかった」を assert する。0 件なら落ちる。**
   （`check-citations`・`check-conflict-markers`・`check-version` と同じ床の置き方。
   **見つからなかったときに緑にならないこと**が肝心である。）
2. **マニュアルの数と定数の数は 1 ずれる**（§1.3）。**導き方を番人の中に 1 行で書き、
   その 1 行が壊れたら赤くなるようにする。** 素朴な `==` は**正しい文書を赤にする**。
3. **「同じ数が両側に書かれている」組も拾う**（§1.6 の `MAX_VALUE_CHARS` / `MAX_VALUE_DIGITS`）。
4. **年利の定数化は、製品側（3d）の判断**として別建てにする。**定数が無いものは、番人が名前で掴めない。**

   **年利の壁は 2 つの経路に分かれている（`2be381d` で当て直した。当初の座標は誤りだった）:**

   | 規則 | 文字列の経路 | 式の経路 |
   |---|---|---|
   | **100% を超えない** | `finance/loan/rate.rs:67` の**裸の `100u64`**（`:71` の `checked_mul(100)` は分母の作り） | `expr/mod.rs:108-109` の**裸の `100`**（`evaluate_to_percent`。註に「100% 超」） |
   | **小数 4 桁まで** | `rate.rs:42` の**裸の `4`**（`frac_part.len() > 4`） | `expr/mod.rs:18` の**名前つき** `PERCENT_SCALE = 10_000`（註「年利の小数桁数。`Rate` と同じ線」） |

   **同じ規則が、片方の経路では名前を持ち、もう片方では裸である。**
   **式の経路は 0.9.2 で重みを増した**（年利・為替が式を受けるようになった）ので、
   **2 つの経路がずれていないこと自体が、番人を置く価値のある主張**である。

## §3 C-3 賞与の worked example に番人が無い

`detail.ja.md:471-472` の 6 つの数のうち、**値を主張しているテストは 1 つも無い**。

  `bonusRows == 70.0` と **`bonusPayment` が「何か文字列である」**だけ。

**grep の落とし穴（この節を読む人へ）**: マニュアルは `110,487` と**カンマ付きで**書くので、

（`3654` は `testdata/loan_boundary.json` の元本 `3654178923` の一部）。
**「grep で出ない＝守られていない」も「grep で出る＝守られている」も、そのままでは言えない。**

### 9.1 数（自分で数え直した。`2be381d`、21 シャード・36,798 ケース）

### 9.2 **本当に触れるのは「期待値」ではなく「番人」である**

監視役からは「**期待値そのものが変わる**」と伝えられた。**当て直した結果、それは 2 件だけだった:**

| 案 | 中身 | 失うもの |
|---|---|---|
| **A: 生成器の前置きを直す** | 散らかした前置きから**開いていない `)` を外す**（22 件）。`errors-000` の 2 件は**コーパスから外し、主張を `engine_table.rs` へ移す**（§9.3.1） | 再生成が要る。**コーパスからは「`)` のエラー」が消える**——ただし**D-2 の後はそれが仕様である** |

### 9.3.1 `errors-000` の 2 件——**失われる主張と、その行き先**（1 件ずつ）

**この 2 件は、コーパスの中で「開いていない `)` は `SyntaxError`」を主張する唯一の列である**
（全 21 シャードを走査し、`rparen` を含みエラーを期待するケースは**この 2 件だけ**だった）。

| 件 | いま主張していること | D-2 の後 | 行き先 |
|---|---|---|---|
| `err-000028`（`keys: ["rparen"]`） | **`)` だけを押すと `SyntaxError`／`Math ERROR`** | **押せない**ので**エラーにならない** | `engine_table.rs` の **`refused_after(&[], "rparen")`** |

paren を含む行はあるが、**どれも「閉じ終わった `(` の後で別のキーが拒まれる」文脈**である。
**したがって 2 行は新規であり、D-2 の主張を受け取る正しい後継である。**
