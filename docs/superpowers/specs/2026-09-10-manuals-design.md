## §2 元の文章の置き場と形式

### 推し: **Markdown を `docs/manual/` に置く**

```
docs/manual/quick.ja.md     簡易（日本語）
docs/manual/quick.en.md     簡易（英語）
docs/manual/detail.ja.md    詳細（日本語）
```

- **GitHub 上でも文章は読める**（Markdown をそのまま表示する）
- **画面写真はリポジトリに置かない**（§3）。Markdown の中では写真の場所を
  **印で書く**（例: `![画面: 金融・複利残高](shot:finance-compound)`）。
  **GitHub 上では写真の代わりに説明の文字が出る**——写真つきで読みたい人には、
  **各マニュアルの冒頭に「最新の PDF は Releases に在る」と 1 行**置く
- **写真まで GitHub 上で見せたいなら、生成した写真をリポジトリに入れる**道もある
  ——ただしその写真は**また古くなりうる**（撮り直しを忘れた日に）。**推さない。**
  （§9 #1）

## §3 画面写真 —— **その版の画面から自動で撮る**

- **撮るのはリリースの走行の中**で、**そのリリースでビルドした画面**から撮る
  （E2E と同じ `vite build` → `preview`（ポート 4179）を使う）
- **何を撮るかは台本（一覧）に書く**——画面の URL（`#finance` など）・押すキー・
  390×844 の大きさ。**台本はリポジトリに置く**（写真は置かない）。**Markdown の
  `shot:…` の印と台本の名前は、番人が突き合わせる**（§6）
- **写真は PDF の中にだけ入る。** 生成物としてリリースの走行が持ち、Release に
  付くのは PDF だけ

**★ 画面写真の書体に注意がある（未確認）。** 画面の書体は
`web/src/ui/tokens.css` の `font-family: system-ui, sans-serif` で、**端末の書体を
使う。** CI の runner に日本語の書体が入っているかは**確かめていない**——入って
いなければ、**写真の日本語が豆腐（□）になる。** 対策は §4 と同じ書体を撮影の前に
画面へ当てること（`page.addStyleTag`）。**ただしそうすると、写真は利用者が見る
画面と書体が違う**（利用者の端末の書体ではなく固定の書体になる）。**どちらを採るかは
§9 #6。**

## §4 PDF の作り方 —— **HTML にしてから Chromium で PDF にする**

**CI には Playwright（Chromium）が既にある**ので、新しいブラウザは要らない:

1. Markdown を HTML にする（下の道具）
2. `shot:…` の印を、§3 で撮った写真に差し替える
3. Playwright の `page.pdf()`（Chromium だけが持つ）で PDF にする

**新しく要る道具は 2 つ**（2026-09-10 に npm で公開日を確かめた）:

| 道具 | 候補の版 | 公開日 | 2 週間 | 用途 |
|---|---|---|---|---|
| `marked`（Markdown → HTML） | **18.0.11** | 2026-08-24 | **満たす**（17 日） | 最新の 18.0.12 は **2026-09-07 公開で 3 日しか経っていない**ので**取らない** |
| `@fontsource/noto-sans-jp`（日本語の書体） | **5.3.0** | 2026-07-19 | 満たす（53 日） | PDF と写真の日本語 |

- **書体は npm から入れて版を固定する**——runner に `apt` で入れる道（`fonts-noto-cjk`
  など）もあるが、**`apt` の版は runner の更新で動く**。**`pnpm-lock.yaml` で固定
  できるほうを推す。** PDF の HTML に `@font-face` で埋め込む
- **版は厳密に綴る**（`^` を付けない）。**入れる日に公開日を当て直す**
  ——ここに書いた版は 2026-09-10 の座標である
- **置き場は `web` の `devDependencies`**（推し）。Playwright と preview が既に
  そこに在る。**新しいパッケージ（`manual/` など）を作ると lockfile が 3 本になる**
  ——CLAUDE.md の「lockfile が 2 本あると片方だけ `pnpm install` が走った日に
  ずれる」が 3 本に増える。（§9 #2）

## §5 `release.yml` への足し方 —— **本番の前か後か**

**いまの並び**（`.github/workflows/release.yml`）:

```
version → CI → Heavy corpus → Deploy → Evidence and GitHub Release
```

`Evidence and GitHub Release` が証拠 3 点（各ジョブの結論・重量級の報告書・配った
`dist`）を付けている。**PDF の作成をどこに置くかで、失敗したときに起きることが
変わる**:

| 案 | 置き場 | PDF の作成が失敗したら |
|---|---|---|
| **(ア) 本番の前** | `CI` のあと、`Heavy corpus` と並べて新しいジョブ。PDF を artifact に置き、`Evidence` が添付する | **本番へ出ない**（`Deploy` の前で止まる） |
| **(イ) 本番の後** | `Deploy` のあと、`Evidence` と並べる | **本番には出る**が、Release に PDF が付かない。**`Evidence` は「マニュアル: 作れなかった」と証拠に書く**（黙って欠けさせない） |
| (ウ) `Evidence` の中 | 証拠を作る段の中 | 本番に出たあとで `Evidence` ごと落ちる——**証拠 3 点まで付かなくなる。採らない** |

**★ マニュアルの失敗で本番を止めるべきかどうかは、利用者の裁定である**（§9 #3）。
この設計書は決めない。判断の材料:

- **(ア)** —— 「マニュアルと画面がずれたまま出る」が起きない。代わりに、
  **書体の取得など計算と無関係な失敗でも本番が止まる**
- **(イ)** —— 計算と画面は予定どおり出る。マニュアルだけ遅れる。**遅れたことは
  証拠に残る**

**どちらを採っても、普段の CI（PR）でも PDF を作る**——リリースで初めて壊れて
いると分かる、を避ける。普段の CI では作るだけで、どこにも付けない。
（**走行時間は測っていない**——ジョブの時間制限は、測ってから ci.yml の規則
「観測の最大 ×2、5 分に切り上げ、最低 10 分」で決める。）

## §6 マニュアルのキー名を番人で守る

**マニュアルの中のキー名は、印を付けて書く**（例: `【返済月額】`）。

**番人（単体テスト）**: マニュアルの Markdown に出てくる**すべての `【…】` が、
いまの画面のラベルのどれかと一致する**こと。ラベルは定義元から読む——
キーは盤面の定義（`web/src/ui/Keypad/*.ts`。例: `finance.ts` の `"返済\n月額"`）、
金融の面の表示名は `web/src/ui/Finance/FinancePanel.tsx`（`FIELD_LABELS` や
`期末` / `期首`）。2 行のラベルは改行を除いて比べる（マニュアルでは `【返済月額】`）。

**これで「キー名を変えたのにマニュアルが古い」が CI で止まる。** 次のように鎖に
なる:

```
承認済みの綴り（finance.test.ts の 12 個）  ← 画面の綴りを利用者の承認に縛る
        ↓ 画面が変われば、こちらが先に赤くなる
マニュアルの【…】の番人                       ← マニュアルを画面に縛る
```

**★ 期待値をマニュアル側から組み立てない。** マニュアルに書いた綴りを正として
画面を直す、ではなく、**画面（承認済み）を正としてマニュアルを直す**向きである。

**`shot:…` の印も同じ形で見張る**——Markdown の `shot:…` がすべて撮影の台本に在り、
台本の名前がすべてどこかのマニュアルから使われていること（使われていない撮影を
残さない）。

**置けない番人**: **文章の中身が正しいか**（説明が画面の動きと合っているか）は
機械では見られない。**利用者が読むしかない。**

## §7 英語の簡易版 —— **画面の日本語のキー名をどう書くか**

**画面は日本語のままである**（英語の画面は無い）。英語の文章の中に、日本語の
キー名が出る。

**推し: 画面の日本語をそのまま書き、初出で英語の意味を括弧に添える**:

> Press **【返済月額】** (monthly repayment) to find the monthly payment.

- **日本語の部分は §6 の番人がそのまま見る**（日本語版と同じ印）
- **英語の意味は、冒頭の用語表 1 か所に置く**——画面のキー名 → 英語の意味。
  本文の括弧はそこから写す。**英語の意味は番人が見られない**（訳の良し悪しは
  機械で決まらない）ので、**置き場を 1 か所にして直す場所を 1 つにする**
- **キー名をローマ字にしない**（画面に無い文字列は、押す場所を探す手がかりに
  ならない）

## §8 章立て（**中身の文章は承認のあと**）

### 簡易（日本語・英語）—— 数ページ（見立て）

1. CalcArc とは（ブラウザで動く計算ツール。インストール不要、ホーム画面に追加できる）
2. 4 つのタブ（Scientific / Convert / Scale / Finance）——**各 1 枚の写真**
3. 基本の使い方（打つ・`=`・`DEL`・`AC`）
4. 各タブで何ができるか（1 段落ずつ）
5. 保存されるもの（設定と履歴。門 2 の約束と揃える）
6. 無保証であること・入力をサーバへ送らないこと（README の文と揃える）
7. 版の見方と、変更点の在りか（CHANGELOG / Releases）

### 詳細（日本語だけ）

1. はじめに（簡易の 1・6・7 と同じ）
2. **Scientific** —— キーの一覧、Shift の面、履歴（`hist`）、角度の単位、ENG、極形式、60 進
3. **Convert** —— 8 つのカテゴリ、単位の選び方、為替（レートの取得と、取れないとき）
4. **Scale** —— データ量、LLM のメモリ、データ転送
5. **Finance** —— ローン（返済月額・借入可能額・返済期間）と複利（複利残高・
   必要積立額・必要年数）、方式（周期と積立の位置）、税、**計算の決まり**
   （毎期 1 円未満切り捨て・期末/期首・税の 2 段切り捨て——常設の 2 行と同じ中身。
   詳しくは `docs/numerical-policy.md`）
6. 保存されるものと消し方（設定・履歴・為替のキャッシュ。門 2）
7. オフラインとインストール（PWA）、更新の知らせ
8. キーボードからの入力
9. 読み上げ（画面名・切り替えの知らせ）
10. 困ったとき（読み込めない・レートが取れない、など）

**画面写真の数は、章立てが承認されてから台本に起こす。**

## §10 この設計書の弱い所

- **PDF を 1 度も作っていない。** `page.pdf()` で日本語がどう出るか、ページの
