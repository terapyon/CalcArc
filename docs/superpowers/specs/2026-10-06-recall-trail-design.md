## 2. 見せ方

**呼び戻した直後は、その履歴の式を閉じた行として出す**: `display-echo` = **`<印> <式> =`**（`closedLineOf(entry.expression)`）。
**次のキー（何であれ）で、今の規則どおりの行に替わる**——呼び戻した数字から綴り直す（`7` → `7 +` …）。

- **答えは今どおり答えの欄に出る**（呼び戻した値）。**行は `=` の直後と同じ見た目**になり、利用者の要望「式を文字列として戻す」を満たす。
- **DEL で式は直せない**（要望どおり）。DEL を押せば、行は今の規則（呼び戻した数字の綴り）に戻る。
- **呼び戻せない行**（`canRecall` が偽: エラーの答え・`j`・`∠`・60 進・仮数が負で指数つき・上限超え）は、
  **今どおりボタンにならない**ので、この変更は届かない。

### 2.1 古い綴りの履歴（1.2.1 より前）

**式の文字列をそのまま出す**: `30 sin × 2 =`。**移し替えはしない**（1.2.1 の利用者の裁定と同じ）。
**履歴の欄が既に同じ文字列を見せている**ので、行が欄と同じなのは自然である。

### 2.2 角度の印（**決めきれない点 1**）

`=` の直後の行は「**三角キーを使った行か、極形式の行だけ**」に印が付く（`angleMarkOf`）。
**ところが履歴の件は「印を付けたか」を持っていない**——`angle` は常に入っている（`angleThatDrewIt` は三角キーが無ければ
`display.angle` を返す）。**だから件から「`3 + 4 =` には印が無かった」を復元できない。**

- **案 a（推し）**: **件に任意の欄 `mark`（`=` の行に付けた印の文字列。空もありうる）を足して保存する。**
  呼び戻した行はそれを使う。**`mark` を持たない件（1.2.2 より前）は、`angle` を大文字にした印を出す**
  ——`angleMarkOf` の註の方針「**保守的に出す。偽の精密さを避ける**」に合う（無いはずの印が付くことはあっても、
  要る印が消えることは無い）。**保存形式は足すだけ**: 古い版が新しい件を読んでも、`parseEntry`（`history/index.ts:29-40`）は
  知っている欄だけで件を作り直すので、`mark` は黙って落ちる（**読み込みは壊れない**）。
- **案 b**: 印は常に `angle` の大文字（件の欄と同じ）。**`3 + 4` を呼び戻すと `DEG 3 + 4 =` になり、`=` の直後の `3 + 4 =` と違う。**
- **案 c**: 印を付けない。**`sin(30) =` を呼び戻すと単位が見えない**——三角の答えは単位で変わるので、推さない。

## 3. 仕組み（**H-5 の族を踏まない形**）

**1 つの ref で閉じる**: `recalledLineRef: { line: string; mark: string } | null`。

1. **`press` の先頭で、どのキーでも `recalledLineRef.current = null`**（呼び戻しの連打の `ac` と数字も消す）。
2. **`recall` は、連打を終えた後に**（`for (const key of keys) press(key);` の次の行で）
   `recalledLineRef.current = { line: closedLineOf(entry.expression), mark }` を置く。
3. **effect の「`=` の行が保留されていない」枝**（打っている最中の行を作る所）の先頭で、
   **`recalledLineRef.current` が在ればそれを `setTrail`／`setTrailAngle` に使い、`spell` を呼ばない。**

**なぜこれで上書きされないか**:
- **連打は 1 回の描画にまとまり、effect はその後に 1 回だけ走る**（React はイベント処理の中の更新を束ねる）。
  **その時点で ref は既に置かれている**（2 は同じイベント処理の中で、連打の後に同期に走る）。
- **ref を書くのはイベント処理だけで、effect は読むだけ**——**H-5（effect が後追いで ref に写した値を、門番が古いまま読んだ）の形ではない。**
  **読む側（effect）が「後から書く者」なので、書く側（`recall`）の値を上書きしない構造にする**のが 3 の要点。
- **順序が逆（連打の前に ref を置く）だと、1 が消す**——**この取り違えは E2E で赤くなる**（§4 の変異 2）。

**触らないもの**: 前置の判定（`carryAtDecisionRef`・`decidedRef`）、画面の列、角度の印の列、`=` の行の作り方、
`mapAnswerToKeys`、`canRecall`。**呼び戻した後の計算の振る舞いは変わらない**（行の見た目だけ）。

**`mark` の保存**（案 a）: `=` の行を作る所（`:734-743`）で、件を積むときに `angleMarkOf(pendingTrigAnglesRef.current, step.display)`
——**既に計算して `setTrailAngle` に渡している値**——を件の `mark` に入れる。`HistoryEntry` の型に `mark?: string`、
`parseEntry` に「文字列なら取り込む、無ければ欄ごと省く」を足す。

## 4. 番人

1. **vitest（`ScientificPanel.test.tsx`、偽の calc）**:
   - 呼び戻した直後の行が `closedLineOf(entry.expression)`、印が `mark`。

   - `mark` の無い古い件は `angle` の大文字。

   - 続けて `+` → `display-echo` が `1 +`。

   - **古い綴りの件**（`localStorage` に `30 sin`・`mark` なしの件を置いてから開く）→ `DEG 30 sin =`。
3. **履歴の保存形式**（`history/index.test.ts`）: `mark` を持つ件・持たない件の読み込み、`mark` が文字列でない件の扱い（欄を省く）。

## 6. 決められずに残った点

1. **角度の印**（§2.2）。**推しは案 a**（`mark` を件に足す。古い件は `angle` の大文字）。保存形式に欄が 1 つ増える。
2. **角度の切り替えキー（DRG）を押したら、呼び戻した行を消すか**。§3 の 1 は「どのキーでも消す」。DRG は値を変えず、
   今の規則の行（`7`）に替わるだけなので、**推しは「消す」**（例外を作らない）。
3. **やらない場合**: 要望は「難しければ取りやめ」。**危うさは §3 の順序だけで、それは変異 2 が見張る**ので、やるのを推す。
