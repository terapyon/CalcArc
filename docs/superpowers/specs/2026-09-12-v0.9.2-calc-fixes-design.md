## §2 F1 —— 押し直しを「最初から正しく打った」と同じにする

### §2.1 原因（`crates/calcarc-core/src/engine/mod.rs:156` の `push_binop`）

押し直しの分岐は、演算子スタックの**先頭 1 つを差し替えて戻る**だけである。

1. **下にある保留演算子との優先順位を組み直さない**——`8 − 3 ×` の `×` を `+` にすると `[−, +]` が残り、`8 − (3 + 2)` になる
2. **最初の演算子を積んだときに畳んだものを戻さない**——`2 + 3 +` は積む時点で 2 + 3 を 5 に畳んでいる。
   `×` に押し直した時点で、2 と 3 はもう状態に無い

### §2.2 直し: 演算子を積む直前の状態を 1 つだけ持ち、押し直しはそこから積み直す

- `EngineState` に **`replace_base: Option<…>`**（演算子を積む直前の `operands`・`operators`・`current`）を足す。
  `push_binop` の通常の経路（差し替えでないとき）で、`commit_entry` の**あと**、`operands.push` の**前**に取る
- **押し直し** = `replace_base` に戻してから、**新しい演算子を通常の経路で積む**。畳み・優先順位・結合方向は
  いまのコードがそのまま担う（新しい計算の規則を作らない）
- **生きている間**: `operator_pending` が真のあいだ（演算子の直後から一歩も動いていない、の意味は今と同じ。
  数字を打って DEL で消して戻った `3 × 4 DEL ×` も押し直しになる——いまの `del_returns_to_the_pending_operator` の行）。
  `operator_pending` が偽になったら捨てる
- **表示は原則から自然に決まる**: 戻して `×` を積むと `current = operands.last()` = 3、echo は状態から導く（`spell`）ので
  「2 + 3 ×」。**`2 + 3 ×` と直接打ったときと 1 文字も違わない**。別の形を推す理由は無い
- **`STATE_SCHEMA` を 6 → 7**（`state.rs:14`）。`EngineState` はページのメモリの中だけに在り（`localStorage` に保存しない）、
  毎打鍵 wasm の境界を往復するだけなので、版を上げても利用者の保存物は壊れない
- 履歴の式・echo は状態から導くので、押し直し後の式が自動で正しくなる（`spell.rs` は変えない見込み。変えるなら実装で報告）

### §2.3 先に赤くする行（`engine_table.rs`、CLAUDE.md の規則）

新しい `#[test] fn a_corrected_operator_means_what_the_right_one_would_have()`:

- `8 − 3 × + 2 =` → 7、`3 − 3 ÷ − 3 =` → −3、`8 ÷ 2 xʸ × 2 =` → 8、`2 + 3 + × 4 =` → 14
- `2 + 3 + ×` の main が `3`、echo が `2 + 3 ×`
- **比べの形で書く**: 各行を「押し直した列」と「最初から正しい演算子の列」の `run()` の結果（main・echo・pending_op・pending_depth）の
  一致としても書く（値を手で書いた行と、原則そのものの行の両方）

### §2.4 既存の行への影響 —— **変わる行は 0**

`engine_table.rs` の 210 のキー列を機械で走査した（押し直しの前に、別の二項演算子が保留または畳まれている列を探す）。
**該当は 0 件**。いまの押し直しの行（`:787-797` ほか）はどれも「数・押し直す演算子・数」の形で、値は変わらない。

### §2.5 I4 の書き換え（`engine_robustness.rs:231`）——消さない

いまの I4 は「押し直しで `operands` も `current` も変わらない」を要求する。**直すと 2 + 3 + × で両方変わる**（5 → 2,3）ので、
そのままでは直しと衝突する。**監査の指摘どおり、内部構造を固定していた。**

書き換え後の I4:
- 走査器が **anchor の演算子を押す直前の状態**を持つ（`anchor` と同じ流儀で `Step` に載せる）
- **押し直した後の状態 ＝ その直前の状態に新しい演算子を直接押した状態**（`buffer`・`current`・`operands`・`operators`・
  `replace_base`）。これで「数を二重に積まない」（operands が直接の経路と同じ）と「訂正後の意味が直接入力と一致する」の両方を見る
- 既存の「押した演算子がスタックの先頭に載っている」の検査は残す
- **赤確認**: 押し直しを今の「先頭だけ差し替える」形に戻すと、I4 が `8 − 3 × +` で落ちること

### §2.6 全列挙に最終値の照合を足す（いまは数値の assert が 0 件）

- 実数だけの網を 1 つ足す: `3`・`4`・`+`・`−`・`×`・`÷`・`(`・`)`・`=`・`DEL`（長さは時間を測って決める。まず 6）
- **照合の相手は、テストの中に書いた別の手順の評価器**: キー列を、入力の決まり（押し直しは最後の演算子を残す／DEL は最後の
  数字か開き括弧を消す／押せないキーは何も起こさない／`=` は閉じ忘れを補う／`x op =` は `x op x`）で**式の文字列に正規化**し、
  **再帰下降の構文解析で有理数のまま評価**する。エンジンは演算子スタックの手順なので、**手順が違う**
- 比べるのは最終の main（書式を通した値）とエラーの種別。**比べた本数の下限**を置く（0 本で緑にしない）
- 走査の時間は既存の網と同じく実測して註に書く（`cargo test` 全体の予算を超えるなら長さを 1 下げる）
- **この評価器は仕様を写すので、同じ誤りを両方に入れる恐れがある**——入力の決まりは `engine_table.rs` の行を正とし、
  評価器の決まりはその行を名指しして書く（写しの出どころを 1 か所にする）

## §3 F5 —— 数を黙って捨てる入力を、押せなくする

### §3.1 どこで数が捨てられるか（`mod.rs` の現物）

| 起きる所 | 仕組み |
|---|---|
| `open_paren`（`:236`） | `buffer = None`・`current = 0`。**打ちかけの数と、手元の値を捨てる** |
| 数字・`000`・`.`・`Exp`・`j`（`:276-315`） | バッファを新しく始める。確定時に `current` を上書きする。**`)` や関数の答えのあとだと、その値を捨てる**。ただし `j` は、打ちかけの数に数字があれば虚部へ切り替えるだけ（`:288-302`。`5 j` → 5j）で、捨てない |
| `+/−`（`:330-339`） | 指数を打っている途中なら指数の符号を変えるだけ（バッファは残る）。**それ以外は `apply_unary` で、ほかの後置関数と同じ経路**——打ちかけの数を確定し、符号を変えた値が手元に残る。次の数字がそれを捨てる（`1 2 +/− 3` → 3） |
| `π`・`e`（`:369-377`） | `buffer = None` にして `current` を置き換える。**打ちかけの数も、手元の値も捨てる** |

### §3.2 状態ごとの列挙と、押せなくするキー

「手元の値」＝ まだどの演算子の被演算数にもなっていない、画面に出ている値。

| 状態 | 例 | 押せなくするキー | 推し |
|---|---|---|---|
| S0 初期・AC のあと | — | なし | — |
| **S1 数を打っている途中** | `2` | **`(`・`π`・`e`** | 押せなくする（`2 (`・`3 π`） |
| S2 二項演算子の直後 | `3 +` | なし（次の数は右辺になる） | — |
| S3 `(` の直後 | `3 + (` | なし | — |
| **S4 `)` の直後** | `( 3 + 4 )` | **数字・`000`・`.`・`Exp`・`j`・`(`・`π`・`e`** | 押せなくする（`) 5`・`) (`） |
| **S5 関数の答え（`+/−` を含む）・`π`・`e` の直後** | `4 √`、`1 2 +/−`、`π` | **S4 と同じ** | **押せなくする（★ §9 の 1・8）** |
| S6 `=` のあと | `2 + 3 =` | なし（**新しい計算を始める**。答えは履歴に残っている） | 押せるまま |
| S7 エラー中 | — | AC 以外（いまと同じ） | — |

- **S6 を押せるままにする理由**: `=` で計算は完了していて、答えは履歴に入る。数を打って新しく始めるのは電卓の普通の使い方で、
  **黙って消えるのではない**（`2 + 3 = 5 =` → 5 はいまの仕様どおり）
- **S5 の注意（利用者に確かめる点）**: `4 √` のあと新しい数を打ちたいとき、`AC` か `=` を先に押すことになる。
  `3 + 4 √ 5 =`（2 が消えて 8）を止めるにはここも押せなくする必要がある。**規則を 1 つにする**（手元の値があるあいだは、
  値を捨てるキーを押せない）ので、S4 と S5 を分けない案を推す
- 暗黙の掛け算は入れない（裁定）。押せなくするだけで、`2 (` を `2 × (` には読み替えない
- **S5 に入るもの**: 後置関数（√・x²・三角関数・n! ほか）と、**確定値に掛かった `+/−`**（`:338` の `apply_unary`）。
  **`+/−` が指数の符号を変えたとき**（`1 . 5 Exp +/− 3` → 1.5e-3、`engine_table.rs:131`）は打ちかけのまま＝S1 で、数字は押せる
- **`j`**: S1 では押せる（打ちかけの数を虚部へ切り替える。捨てない）。S2・S3 では新しい虚部の入力を始めるだけで押せる。
  S4・S5 では新しい数を始めて手元の値を捨てる（`4 √ j 5` → 5j、`( 3 ) j 5` → 5j）ので押せなくする（表のとおり）
- **どの状態でも押せなくしないキー**: **二項演算子**（**F1 の訂正＝演算子の直後の演算子は押せるまま**。calcarc-1e の注記 A）、
  後置関数と `+/−`（手元の値に掛かるだけで捨てない。`( 3 ) +/− =` → −3、`4 √ +/− =` → −2）、`=`、`)`、DEL、AC、表示トグル。
  **押せなくする集合は、数字・`000`・`.`・`Exp`・`j`・`(`・`π`・`e` の外に出ない**
- **`+/−` を S5 に数えると起きること（★ §9 の 8）**: `+/−` を先に押してから数を打つと、数字が押せなくなる（`+/− 5`、
  `3 + +/− 5`）。いまは符号や `+/−` の結果が黙って消えて 5・8 になる（§1）——**黙って違う答えを出すより、押せないほうが良い**
  と読む。負の数は「数を打ってから `+/−`」（`3 + 5 +/− =` → −2、いまも同じ）

### §3.3 拒む場所は 1 か所——エンジン（**二重に守る**）

- **コアに `refuses(state, key) -> bool` を置く**（§3.2 の表をそのまま書く純関数）。**判断はここ 1 か所だけ**
- **`reduce` の入口で、拒まれたキーは何も変えずに返す**（エンジンの側でも拒む）。**表示の一時状態（60 進・ENG）も戻さない**
  ——押せないキーは「押されなかった」のと同じにする
- **`DisplayState` に `refused: Vec<KeyToken>`** を足す（`render` が `refuses` から作る）。**UI はこれを読むだけ**
- **盤面**: `ScientificPanel` が `Keypad` に `off`（`Keypad.tsx:24` に既にある口）を渡し、`refused` に在るキーを
  **`"transient"`** にする。見た目と読み上げは既存の押せないキー（`Key.tsx:79-91`）のまま。新しい見た目は作らない
- **キーボード**: `useKeyboard` は画面のキーと同じ `press` → wasm の `reduce` を通るので、**エンジンが拒めば入らない**。
  抜け道は作りようがない（UI とキーボードで判断を共有する形が、構造でそうなる）
- 手元の値があるかどうかを状態から言えるよう、`EngineState` に **`on_hand: bool`** を足す（`)`・後置関数・`π`・`e` で真、
  二項演算子・`=`・AC・数字で偽）。**`operator_pending` と同じく、DEL と表示トグルでは動かさない**。`+/−` は確定値に掛けたとき真、
  指数の符号を変えたときは動かさない（`mod.rs:78` が `operator_pending` を同じ形で分けている）。§2.2 の版上げに含める

### §3.4 engine_table の書き方（二重に守るので、エンジン側の行で固定する）

- 補助の関数を足す: `refused_after(keys, key)`——`keys` を打ったあとで `key` が拒まれること、**押しても状態（main・echo・
  pending）が変わらない**こと
- 監査の例は「押せない」と「押しても何も起きない」の 2 つで書く:
  `2` のあと `(` は拒まれる／`2 (` と `2` は同じ表示／`( 3 + 4 )` のあと `5` は拒まれる／`( 3 + 4 ) 5 =` は `( 3 + 4 ) =` と同じ 7
- UI は vitest（`refused` を渡したときにキーが `disabled`）と E2E（Chromium・WebKit で、キーが押せないこと・キーボードの
  `(` が入らないこと）で見る

## §4 F3 —— Convert の `=` を、丸めずに値でまとめる

### §4.1 原因（`web/src/ui/Convert/UnitPanel.tsx:189-198`）

`settled()` は同じ単位への換算（為替は `length` の `m→m`）の **表示用の文字列**（有効数字 10 桁、`format_rational`）を
次の入力値に書き戻す。**コアの `convert` は正確な `Rational` を返している**（`convert/mod.rs:520`）——丸めているのは
wasm の境界で書式を通すところだけである。1e10 以上は表示が指数になり、書き戻しの形の検査で `null` になって `=` が何もしない。

### §4.2 直し: 正確な値の文字列を返す口を足す

- **コア**: `settle(text) -> CalcResult<String>`——`evaluate_to_rational(text, UnitSet::None)` の値を**正確に**書く。
  - 分母が 2 と 5 だけでできていて、10 進で **39 桁以内**に収まる → **有限小数**（指数もカンマも使わない。`0.123456789012`、
    `9999999999.4`、`12345678901.5`）
  - それ以外 → **既約分数 `p/q`**（`1/3`）。`Rational` は i128 なので分子・分母とも 39 桁以内に収まる
  - 負の値は先頭に `-`
- **wasm**: `settle_expression(value)` を足す（例外を投げない。`Outcome` で返す。境界のテストを `web.rs` に足す）
- **UI**: `settled()` は `calc.settle(typed)` を呼び、返った文字列から Entry を組み直す（数字・`.`・`/`。符号は `negative` に）。
  **`FOLD_CATEGORY` の恒等換算の迂回をやめる**——為替も同じ口を通る（通貨の桁にも 10 桁にも丸めない）
- **利用者に見える変化**: `1 ÷ 3 =` のあと、値の欄は **`1/3`** と出る（いまは `0.3333333333`）。**★ §9 の 3**。
  隠れた正確な値を別に持って表示だけ 10 桁にする案もあるが、**「値の欄に見えているものが次の計算に入る」が崩れる**ので推さない

### §4.3 検査（**実物の wasm を通す**。`UnitPanel.test.tsx` のモックとは別に）

- **Rust**: `settle` の単体テスト（有限小数・分数・長い 2 進小数が分数に落ちる境目・負・大きい値・エラー）
- **wasm の境界**: `crates/calcarc-wasm/tests/web.rs` に `settle_expression` の行（CI の `wasm-pack test` が回す）
- **UI × 実物の wasm（新しい vitest ファイル）**: `initSync` で実物の `.wasm` を読み、`initConvert` を実物で包んだ
  `ConvertCalc` を返す形にして `UnitPanel` を描く。`f3-probe.mjs` の例をそのまま入れる:
  `1/3 =` → 値の欄 `1/3`・続けて `× 3 − 1`（km→mi）→ `0`、`0.123456789012 =` → そのまま、`9999999999.4 =` → そのまま、
  `12345678901.5 =` → そのまま（`=` が効く）、**為替（JPY）で `12.5 =` → `12.5`、`0.123456789012 =` → そのまま**
- **E2E**（Chromium・WebKit）: Convert で `1 ÷ 3 = × 3 − 1` → 答えが `0`
- **赤確認**: `settled()` を今の「表示の文字列を書き戻す」形に戻すと、UI × 実物の wasm のテストと E2E が落ちること

### §5.1 F2 の上限 —— 月額が 10 億円を超えるローンはエラーにする（追加の裁定）

**なぜ**: 金額が大きいと 1 円に収まらない（calcarc-88 の実測: 最も小さい場合で月額約 45 億円から 1 円に届き、元本 10^18 円級では
