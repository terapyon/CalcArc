# 複利の期間の単位を方式に合わせる（2026-09-11）

**対象**: Finance の複利系モードの期間欄（複利残高・必要積立額）と、コアの単位表
`UnitSet::Periods`。**利用者から見える変更**である（§2 の決定 3・4）。

**1.0 の前に直す実際の不具合である。** 0.9.0 の退行ではない——2026-08-15 から
在った（コアの `期` は ddf95d1、盤面の 年/月 は c4bcf93、どちらも 2026-08-15）。

---

## §0 何が起きていたか

レビュー役が main を実ブラウザで叩いた結果（2026-09-11）:

| 方式 | 打鍵 | 表示 |
|---|---|---|
| 月ごと（元本 10,000・年 1%） | `1` `2` `月` | **Math ERROR** |
| 月ごと（同） | `1` `2` | 10,096 |
| 月ごと（同） | `1` `年` | 10,096 |
| 年ごと | `5` `月` | **Math ERROR** |
| 必要積立額の期間 | `5` `月` | **Math ERROR** |
| ローンの返済期間 | `5` `月` | 200,500（正常） |

**原因は 2 つが重なっていた。**

1. **コアが `月` を知らなかった。** `UnitSet::Periods(1)` は `年` だけ、
   `Periods(n≥2)` は `年` と `期` を持ち、**どの周期にも `月` が無かった**
   （`crates/calcarc-core/src/expr/mod.rs`）。月ごとでさえ `12月` は SyntaxError だった。
2. **盤面は方式を見ずに 年/月 を出していた。** `unitFor` は期間の欄なら何でも
   年/月 を描き（`web/src/ui/Finance/FinancePanel.tsx`）、複利系は期間を
   `periods:${periodsPerYear}` の表で評価させる。**押せるキーが、読めない綴りを作っていた。**

**設計書は最初から月ごとを 年/月 と書いていた**
（[2026-08-15 金融 UI](2026-08-15-finance-ui-design.md) §5「複利の期間は周期に従う」の表、
月次の行は `年`（scale 12）/`月`（scale 1））。**コアの `期` がそこから外れていた。**

---

## §1 裁定（利用者、2026-09-11）

**【月】を出すのは方式が月ごとのときだけ。半年ごと・年ごとは【年】だけ。**
ローンは変えない（いまどおり 年/月）。

---

## §2 決定

### 決定 1: 計算の側が `月` を知る

`Periods(12)` を **`[('年', 12), ('月', 1)]`** にする。**`月` は `期` を置き換える**
（並べて足さない）。`Periods(2)` は `[('年', 2), ('期', 1)]` のまま、`Periods(1)` は
`[('年', 1)]` のまま。

**置き換えを選んだ理由**（2026-09-11 に案 A/B/C を比べた。A を採った）:

- **設計書の表がそう言っている**（上の §0）。コアの `期` は表から外れていた。
- **月ごとの `期` はどこからも届かなかった。** 盤面の単位は `YEAR` と `MONTH` しか
  無く（`web/src/finance/entry.ts`）、`unitFor` は `期` を一度も出さない。golden にも
  `期` を使う式は 1 件も無く、`heavy` は単位表の名前を渡さない。**消しても、打てた人が
  打てなくなることは無い。**
- **案 B（`期` の横に `月` を足し、降順の検査を `>=` に緩める）は採らない。** 降順の
  番人（`the_unit_sets_are_ordered_downwards`）を弱めるうえ、構文解析器は**並び順**で
  「下る向き」を判定する（`parse.rs` の `rank`）ので、`1期2月` = 3 は通り `1月2期` は
  落ちる——**誰も決めていない文法が生まれる。** 足してみると検査は実際に赤くなった
  （`Periods(12) が降順でない`）。
- **案 C（並び順ではなく scale で比べるよう構文解析器を変える）は採らない。** 全部の
  単位表と参照実装が共有している契約を、この 1 件のために変えることになる。

**盤面の側で `月` を別の綴りへ読み替えることはしない。** 読み替えは単位の規則の写しを
もう 1 つ増やす——写しを増やす直しは、同じ族の欠陥を 1 つ先へ運ぶ。

### 決定 2: 参照実装の表も同じにする

`reference/src/calcarc_reference/expr_ref.py` の `unit_table` に同じ変更を入れた。
**独立性は変わらない。** `unit_table` の `独立: 不可能` はそのまま——表の中身が仕様
であり、コアと同じ係数でなければ単位の意味が変わる（docstring の共有契約 5「単位表
（ラベルと scale）とその並び」）。**独立に検証しているのは評価器の側**（コアは `i128`
有界の自作既約分数、参照は標準ライブラリの `Fraction`）で、そこには手を入れていない。

### 決定 3: 盤面の単位キーが方式に従う

`unitFor(field, slot, mode, periodsPerYear)`:

| 欄 | 上のマス | 下のマス |
|---|---|---|
| 金額 | 万 | 億 |
| 年利 | 空き | 空き |
| ローンの期間 | 年 | 月 |
| 複利系の期間・月ごと | 年 | 月 |
| 複利系の期間・半年ごと／年ごと | 年 | **空き** |

**空きは年利と同じ描き方である**（`token: null` の予約スロット）——`disabled` の
`<button>`、読み上げ名は「空き」、画には何も書かず、枠は残る（5×5 の格子は動かない）。
予約スロットは「永久に押せない」側に合流する（`Key.tsx`、利用者裁定 2026-08-31）
ので、読み上げには盤面共通の説明「この電卓では使えません」が付く。**方式を月ごとに
戻せば同じマスに `月` が出る**——年利の欄で項目を移ると 万/億 が出るのと同じ関係で、
その扱いは既存のまま変えていない。

### 決定 4: 月ごとを離れるとき、`月` を含む期間を空にする

**利用者から見える変更である。** 方式を半年ごと・年ごとへ切り替えた瞬間に、
**`月` を含む期間の入力だけを空にする。** 月ごとへ戻しても復元しない。

- **換算しない**——`12月` は 12 期であり、年ごとの 12 期は 12 年である。意味を変えて
  持ち越すのは、420 か月を 420 年として計算するのと同じ形の誤答になる。
- **残しもしない**——残すと、押した覚えのない Math ERROR が黙って出る（§0 の不具合
  そのもの）。
- **`月` を含まない期間（`10年`、`120`）は残す**——どの方式でも同じ意味で読める
  （2026-08-15 §5「周期を変えても期間の値は保持する」はそのまま生きている）。
- **見るのは複利系の全モードの期間**（複利残高と必要積立額。必要年数は期間が答なので
  欄が無い）。方式は 3 モードで共有なので、打っている最中のモードだけを見ると、別の
  モードに `12月` が残って戻った先で同じ Math ERROR が出る。
- **`月` の有無はトークンで見る**（単位のトークンの `label`）。打った文字列からは
  当てない。

**【訂正 2026-09-11】** 2026-08-15 §5「**周期を変えても期間の値は保持する**」は、
**`月` を含む期間に限って成り立たなくなった。** 同じ訂正をあちらの本文にも置いた。

### 決定 5: 計算は変えない

期数の数え方・正算・逆算・税はどれも変えていない。変わったのは「どの綴りを期数に
読むか」だけである。

## §5 変えていないもの（既知）

- **半年ごとの下の単位は、設計書では `半期`、コアでは `期` のまま食い違っている**
  （2026-08-15 §5 の表）。盤面はどちらも出さないので利用者には届かない。今回は直さない。
- **盤面の `unitFor` は「月ごとだけ `月`」をコアの表と別に持っている。** TypeScript は
  単位のラベルと並びだけを持ち、scale は持たない、という既存の分担（`expr/mod.rs` の冒頭）
  の範囲である。**2 つがずれたら E2E が赤くなる**——月ごとで `月` を押して答が出ること、
  半年ごと・年ごとで `月` が無いことを、実 wasm で見ている。
