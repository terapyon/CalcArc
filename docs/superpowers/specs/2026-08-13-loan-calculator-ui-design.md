# Loan の電卓化（L）— 設計

日付: 2026-08-13
対象: base-spec §12（キー配置）・§26（表示と値の分離）・§41（機微値）・§42/§43。
前提: S3（更新トースト）のマージ後。**計算コアは 1 行も変えない。**

## §0 位置づけ — 5 本目の spec

UX 改修は関心事ごとに分けて進めている。本 spec はその 5 本目で、**Scientific で
作った部品を Loan が最初に再利用する回**である。

| spec | 関心事 | engine への変更 |
|---|---|---|
| S1 | Scientific の外装（キーパッドと表示の部品化） | ゼロ |
| S2 | Scientific の入力意味論 | あり（唯一） |
| S3 | Service Worker 更新トースト | ゼロ |
| **L（本 spec）** | **Loan をフォームから電卓の体裁へ** | **ゼロ** |
| D | Data Scale を電卓の体裁へ | ゼロ |

**「あくまで電卓として」**——入力欄と select の見た目をやめ、上部表示 +
キーパッドにする。計算そのもの（`calcarc-core` の `loan`、`finance.json` の
36 件）は不変で、**変わるのは打ち方と見せ方だけ**である。

## §1 変えること

1. **入力を数字キーパッドにする**。text input と select を置かない。
2. **万・億のキー**を置く。`3000` `万` で 3,000 万円が入る。
3. **アクティブ項目**の考えを入れる。キーパッドが打ち込む先を項目タブで選ぶ。
4. **求めるもの（月額 / 借入可能額 / 期間）はトグル行**にする。
5. **上部表示**は S1 の `Readout` を使い、エコー行に**打った通り**（`1億2000万`）
   を出す。求めた値が main に立つ。
6. 結果の内訳（総支払額・総利息・最終回）は Readout の下の**結果領域**に残す。
7. **免責は常設のまま**（設計書 M6 §0）。

## §2 盤面

```
┌────────────────────────────────────────────────┐
│ echo:                          借入額 3000万円          │
│ main:                                   91,855 円     │
│ 月額を求める                          借入額を入力中      │
├────────────────────────────────────────────────┤
│ [月々の返済額][借入可能額][返済期間]   ← 求めるもの（半高）│
├────────────────────────────────────────────────┤
│ [借入額][年利][期間][月額][残価][ボーナス] ← 項目（半高）  │
├────────────────────────────────────────────────┤
│ [ 7 ] [ 8 ] [ 9 ] [ DEL ]                             │
│ [ 4 ] [ 5 ] [ 6 ] [ AC  ]                             │
│ [ 1 ] [ 2 ] [ 3 ] [ 万  ]                             │
│ [ 0 ] [000] [ . ] [ 億  ]                             │
├────────────────────────────────────────────────┤
│ 総支払額 38,579,007 円                                 │
│ 総利息    8,579,007 円                                 │
├────────────────────────────────────────────────┤
│ 実際の返済額は金融機関の計算方法により異なります。          │
└────────────────────────────────────────────────┘
```

**この配置は既存製品の意匠を写したものではない。** 参考にするのは電卓一般の
配置慣習と操作感までであり、配色・ボタン形状・書体・ロゴ・製品名は複製しない
（base-spec §3 Non-goals、§12）。

- **制御（DEL・AC）は右上**、**単位（万・億）は右下**。金額を打った直後に
  押すキーなので、数字の近くに置く。
- キーは 16 個ちょうどで **4 列 × 4 行**。Scientific（5 列 67px）より少ないぶん
  1 つが大きく（約 85px）なる——**意図した違い**である。Loan は大きな数を
  たまに打つ画面で、打鍵数より当てやすさが効く。
- **`=` は置かない。** 現行どおり、必要な項目が埋まった時点で結果が出る
  （結果を state に持たない規律を電卓化後も維持する。§5）。押さないと答えが
  出ない `=` を足すと、「押していないから出ない」のか「入力が足りないから
  出ない」のかが利用者から見分けられなくなる。

### 縦の配分（390×844、スマートフォン縦持ち）

|---|---|
| ナビ 3 タブ | 44 |
| Readout（echo + status + main） | 約 110 |
| 求めるもの（半高） | 34（+ gap 8） |
| 項目（半高） | 34（+ gap 8） |

| 結果領域 | 約 70 |

| padding と safe-area | 約 58 |
| **合計** | **約 760 / 844** |

## §3 区画の名前（E2E セレクタになるので先に決める）

`Keypad` の区画名はアクセシブルネームであり、そのまま E2E のセレクタになる。

| 区画 | `ariaLabel` | 列数 | 高さ |
|---|---|---|---|
| 求めるもの | `求めるもの` | 3 | half |
| 入力する項目 | `入力する項目` | 6 | half |
| 数字と単位 | `数字と単位のキー` | 4 | square |

`vertical-slice.spec.ts` の区画名正規表現（`/関数キー|数字と演算のキー/`）は
**Scientific 限定に閉じる**（Loan の区画を足して育てない——あの検査は
Scientific の盤面を見るものである）。

## §4 型の束縛をどう解くか — `KeyToken` のジェネリック化

S1 の `Keypad` / `KeyDef` は `KeyToken`（Scientific 専用の 30 トークン union）に
縛られている。Loan のキー（`man`・`oku`・項目タブ・モード）はそこに無い。

**採る: `KeyDef<T>` / `KeypadSection<T>` / `Keypad<T>` のジェネリック化。**
`T` は「押されたときに返るトークン」の型で、Scientific は `KeyToken`、Loan は
自分の union を渡す。**engine には触れない。**

**不採用: `KeyToken` の union に Loan のトークンを合流させる。** それは
`web/src/calc/types.ts` の union を膨らませ、`token_parity.rs` が Rust の
`Key::from_token` にも同じ追加を要求する。**engine が Loan のキーを知ることに
なり**、S1 §0 で置いた「Loan は engine 変更ゼロ」を破る。検証段も wasm-pack と
clippy まで広がる。UI の都合で計算コアの語彙を増やさない。

- `Keypad.test.tsx` の「`KEY_TOKENS` を過不足なく網羅する」検査は **Scientific の
  キー集合に対する検査**なので、`scientific.ts` 側のテストに移す。汎用
  `Keypad` のテストは「区画を描く・押されたトークンを返す・予約スロットは
  何も返さない」に絞る。
- `Key.tsx` も同様にジェネリックにする。`data-token` は文字列化して載せる。

### ジェネリック化で足りない 2 つの能力

Scientific には要らなかったが Loan には要る。**どちらも省略可能な述語**にして
渡す——Scientific は何も渡さないので、**無改修で動く**（完了条件 7）。

```ts
interface KeypadProps<T> {
  sections: KeypadSection<T>[];
  onPress: (token: T) => void;
  /** 押下状態を呼び出し側が決める(モード行・項目行)。省略時は押下なし。 */
  pressed?: (token: T) => boolean;
  /** 今は押せない(状態依存)。省略時はすべて押せる。 */
  disabled?: (token: T) => boolean;
}
```

- **`pressed`**: S1 の Shift は Keypad 内部の state で足りたが、モードと
  アクティブ項目は**画面全体の状態**であり、Keypad は知らない。`aria-pressed`
  の出どころを呼び出し側に移す。
- **`disabled`（状態依存の無効）は、予約スロット（`token === null`）とは
  別物である。** 予約は「ここに何か来る」という**永続的な空き**で、こちらは
  「今は押せないが、条件が変われば押せる」。同じ表現に畳むと、S1 で予約に
  与えた意味（S2 が埋める場所）が読めなくなる。描画は同じ `disabled` +
  `aria-disabled` でよいが、**由来が違うことをコードのコメントに残す**。

## §5 入力の意味論 — 万・億

**リポジトリに前例は無い。** ここで決める。

### 構造: 確定済みセグメントの列 + 入力中の数字

```
入力 = [{ digits: "1", unit: 億 }, { digits: "2000", unit: 万 }] + 入力中 "500"
値   = 1×10^8 + 2000×10^4 + 500 = 120,000,500
表示 = 1億2000万500
```

**単位キーは「いま打っている数字を、その位で確定する」**。累計は列から導出
できるので、値・表示・DEL のすべてがこの 1 つの構造から出る。

| 打鍵 | エコー | 値 |
|---|---|---|
| `3000` `万` | `3000万` | 30,000,000 |
| `1` `億` `2000` `万` | `1億2000万` | 120,000,000 |
| `1` `億` `2000` `万` `500` | `1億2000万500` | 120,000,500 |
| `12000` `万` | `12000万` | 120,000,000 |
| `3000` `万` `億` | **SyntaxError** | 単位の逆順（万の後に億） |
| `万` | **SyntaxError** | 数字の無い単位 |
| `1` `億` `DEL` | `1` | 直前のセグメントを解く |
| `1` `億` `2000` `DEL` | `1億200` | 入力中の数字を 1 文字 |

- **逆順は SyntaxError**（`3000万` の後に `億` は「3000 万億」で、意味が無い）。
- **`12000万` は通る**。口語の「1 億 2000 万」を `12000` `万` と打っても
  同じ値になる——加算合成なので自然に成立する。
- **DEL は 1 段ずつ**（engine の I7 と同じ思想）: 入力中の数字があれば 1 文字、
  無ければ直前のセグメントを解いて、その数字を入力中に戻す。
- 単位は**金額の項目だけ**（借入額・月々の返済額・残価・ボーナス）。年利と
  期間では単位キーを無効にする（§6）。

### 壊せない盤面と、モジュールの契約（要ユーザー確認）

**`entry.ts` は不正な列に `SyntaxError` を返す**（ユーザー決定どおり）。
`3000万` のあとの `億`、数字の無い単位キーがそれにあたる。

そのうえで、**盤面はその列を打てないようにする**: 逆順になる単位キーと、
数字が無いときの単位キーを `disabled` にする（§4 の状態依存の無効）。
理由は 2 つある。

1. 電卓で「押したらエラーになるキー」を押せる状態で置くのは、間違いを誘って
   から叱る形になる。**押せなければ間違えない。**
2. エラーにすると回復経路（DEL で戻す？ AC だけ？ エラー中に他のキーは
   効く？）を決める必要があり、規則が増える。押させないほうが規則が減る。

**ユーザー確認事項**: 決定は「逆順は SyntaxError」だった。ここで提案している
のは「**モジュールの契約はそのまま、盤面が到達させない**」という二段構えで
あり、文法を緩めるものではない。**この読み替えでよいかを承認時に確認したい。**

### それでもエラーが出たときの回復

盤面が塞いでいても、契約は守る側で持っておく（`entry.ts` を D が再利用する
可能性があり、そこでは別の盤面が載る）。UI に届いた場合の扱いを固定する:

| 何が | どうなる |
|---|---|
| `entry.ts` が `SyntaxError` を返す | main に `Math ERROR` + `data-error="SyntaxError"` |
| そのときの echo | **打った通りを残す**（何を打ってそうなったかが見えないと直せない） |
| DEL | **1 段戻してエラーを解く**（直前の打鍵を取り消す。engine の I7 と同じ） |
| AC | その項目の入力を空にする |
| 他のキー | 受け付ける（エラーは項目の入力に閉じており、画面は固まらない） |

engine の「エラー中は AC 以外を受け付けない」とは**わざと違える**。あちらは
状態機械の一貫性を守るためで、こちらは項目ごとの入力にすぎない。

### 置き場所と境界

- **`web/src/loan/entry.ts`（新規）**。`index.ts` は「型変換と初期化だけ」を
  自己宣言しているので汚さない。`types.ts` が「React も WASM も知らない純粋層」
  の前例である。
- 表示の桁区切り `grouped()`（現 `LoanPanel.tsx` の正規表現）も**ここへ移す**。
  入力の解釈と出力の整形を 1 つのモジュールに置き、両方向を同じテストで見る。
- **テストは jsdom 不要の素の vitest**（表駆動）。上の表がそのままケースになる。
- **コアへ渡すのは素の数字列**。`parse_yen` はカンマ・符号・小数点を拒否する
  ので、展開後の文字列に区切りを入れない（base-spec §26: 表示のための整形を
  入力に還流させない）。

## §6 モードと項目

### 求めるもの（3 択）

| モード | 求める値 | 必要な項目 |
|---|---|---|
| 月々の返済額 | 月額 | 借入額・年利・期間（+ 残価 か ボーナス） |
| 借入可能額 | 借入額 | 月々の返済額・年利・期間（+ ボーナス） |
| 返済期間 | 回数 | 借入額・年利・月々の返済額 |

- モード行は**押している 1 つが `aria-pressed="true"`**。
- **項目タブは 6 つ**（借入額・年利・期間・月々の返済額・残価・ボーナス）。
  **月々の返済額は、月額モードでは答だが他の 2 モードでは入力**なので、
  タブとして常に置き、モードに応じて無効にする。
- **求める値の項目タブは無効**にする（それが答だから。S1 の「求める値の欄は
  入力できない」と同じ規律）。
- **残価は月額モードのみ、ボーナスは期間モードで無効**（M6 設計書 §3/§4）。
- **残価とボーナスは排他**（コアに両者を重ねたモデルが無い。M6 設計書 §8 の
  【訂正 4】）。片方に値があるあいだ、他方のタブを無効にする。
- 無効なタブは `disabled` + `aria-disabled`。**値は保持する**（モードを行き来
  しても入力が消えない。S1 と同じ）。

### ボーナス欄はモードで意味が変わる（値を混ぜない）

現行 UI と同じく、ボーナスは**モードによって別のもの**である。

| モード | ボーナス欄の意味 | タブのアクセシブルネーム |
|---|---|---|
| 月々の返済額 | ボーナス返済分の**元本** | `ボーナス返済分（元本）` |
| 借入可能額 | ボーナス回の**返済額** | `ボーナス回の返済額` |
| 返済期間 | （無効） | `ボーナス返済分（元本）`（無効表示） |

- **値は意味ごとに別々に保持する**（`bonusPrincipal` と `bonusPayment`）。
  1 つの値を使い回すと、モードを跨いだ瞬間に**意味の違う数字が黙って流用
  される**。「値は保持する」は「同じ意味の欄の値が消えない」という意味である。
- タブのアクセシブルネームがモードで変わるので、**E2E のセレクタもモードごと**
  になる。区画名（§3）は変わらない。

### アクティブ項目

- 項目タブを押すと、キーパッドの打ち込み先が変わる。アクティブなタブは
  `aria-pressed="true"`。
- **「次へ」キーは置かない**。タブを直接押すほうが、どこに打っているかが
  常に見えている。

### 項目ごとのキーの可否

打てないものは押せなくする（§4 の状態依存の無効）。**押せるキーの集合が
項目の型を語る**ので、可否表そのものが仕様である。

| 項目 | 0-9 | `000` | `.` | 万・億 |
|---|---|---|---|---|
| 借入額 / 月々の返済額 / 残価 / ボーナス（金額） | 有効 | 有効 | **無効** | 有効 |
| 年利（%） | 有効 | **無効** | **有効** | **無効** |
| 期間（月） | 有効 | 有効 | **無効** | **無効** |

- 金額と期間で `.` が無効なのは、`parse_yen` が小数点を拒否し、期間が整数月
  だからである（コアの定義域をそのまま盤面に写す）。
- 年利で `000` を無効にするのは、`0.000` のような打ち間違いを誘うだけで、
  3 桁ゼロを一度に入れたい場面が無いため。小数は 4 桁までで、`.` の後は
  1 桁ずつ打つほうが確実である。
- 年利で万・億が無効なのは自明だが、**表に書く**——「無効の理由が自明か
  どうか」は読む人によって違う。
- **この表は項目による可否である。単位キーにはもう 1 つ条件が重なる**（§5）:
  金額の項目でも、**数字を打っていないとき**と**逆順になるとき**（`万` の
  あとの `億`）は押せない。2 つの条件は and で効く——項目が単位を許し、かつ
  いまの入力がその単位を受けられるときだけ押せる。

## §7 表示 — 何を main に立て、何を下に置くか

- **echo 行**: `借入額 3000万円` のように、**アクティブ項目の名前と打鍵中の値**。
  数の部分は**打った通り**で、桁区切りを入れ直さない（`1億2000万` はそのまま。
  `12,000万` にはしない）——打鍵と画面が 1 対 1 でないと、打ち間違いを目で
  追えなくなる。末尾の `円` は単位の表示であって整形ではない。
  **桁区切りが付くのは main と結果領域だけ**（求まった値の可読性のため。
  base-spec §26 の「表示の整形を入力に還流させない」の内側）。
- **main**: **求めた値**（月額なら `91,855 円`）。必要な項目が埋まるまでは
  中立（`0` ではなく空。M6 の「未入力は中立」を電卓の体裁で守る）。
- **status**: モード名（`月額を求める`）と、アクティブ項目名（`借入額を入力中`）。
- **項目タブを押したら、その項目の入力済みの値が echo に出る**（空なら空）。
  フォームを廃した以上、**入力済みの値を確かめる経路はここしかない**——タブを
  一巡すれば、何をどう打ったかが順に読める。これが無いと、利用者は自分の
  入力を再確認できないまま結果だけを見ることになる。
- **結果領域**（Readout の外）: 総支払額・総利息、残価があれば最終回。
  **main を 1 本に保つため**に外へ出す——電卓の主表示は「求めた答え」1 つで
  あり、内訳を同じ行に詰めると読めなくなる。
- エラーは現行どおり `Math ERROR` + `data-error`（M6 の流儀）。

### Scientific の `display-pending` との重複（S2 からの申し送り）

S2 でエコー行が入り、Scientific では `display-pending`（保留演算子と括弧の深さ）
の情報がエコーと重複している。**本 spec では触らない**——判定は「エコーがある
以上 `pending` は冗長」で、削るのが筋である。ただしそれは Scientific の表示
整理であり、Loan のレビューに混ぜると両方が濁る。**独立の小さな spec に送る**。
そのとき触るのは `vertical-slice.spec.ts` の status 検査と `Readout` の
`status[]` 契約の 2 か所である、と記録しておく。

Loan の status は `pending` を持たない（保留演算子という概念が無い）。同じ
`status[]` 契約に別の項目を載せるだけで、`Readout` の再利用は成立する。

## §8 44px の線引き

- **数字と単位の区画は 44px を守る**（約 85px 角）。
- **半高の 2 区画（求めるもの・項目）は縦 34px**で、S1 の関数列と同じ扱い。
  横は 44px 以上を確保する（項目は 6 列で約 54px、モードは 3 列で約 112px）。
- 理由は S1 §4 と同じで、**誤爆の実害に比例させる**: 数字と単位の押し間違いは
  金額を壊すが、モードや項目の押し間違いは押し直せば戻る。
