# 押せないキーを 2 段に分ける（0.7.0）

**対象**: 6 電卓の盤面。**利用者から見える変更**である（0.6.0 までの 14 本は全部内部だった）。

**この文書が最初の起票である。** この件は 2026-08-15 頃から「盤面の未決 2 件」として
預かられていたが、**repo に記録が 1 行も無かった**——`git grep` で 0 件で、在ったのは
セッションの記憶だけである。**だから 2 週間、誰も現物を見に行けなかった。**
（2026-08-31 に測って分かった。**「見に行く先が無い」は、腐りより静かな壊れ方である。**）

---

## §0 何が起きているか（2026-08-31 の実測）

### 淡さは 1 種類しかない

6 電卓の押せないキーを**計算済みスタイル**で分類した。**色は variant ごとに違うが、
淡さは全部 `opacity: 0.4`**（`web/src/ui/Key/Key.module.css` の `.key:disabled`）。

### ところが意味は 3 つある

「7」を 1 つ押して**生き返るかどうか**で分けた（390×844、Playwright、実測）:

| | Convert | DataScale | Transfer | Finance |
|---|---|---|---|---|
| 淡い（打鍵前） | 9 | 12 | 12 | 12 |
| **生き返った** | `÷ × − + =` | `G M K` | **なし** | `÷ 万 × 億 − + =` |
| **淡いまま** | `) —×3` | `( ) —×2 ÷ × − + =` | `( ) —×5 ÷ × − + =` | `月額 ) —×2 .` |

**3 つの意味:**

1. **予約スロット**（`—`）——**何も無い。永久に。** `token === null`
2. **この盤面では永久に使えない**——`÷ × − + =`（DataScale・Transfer・LLM）
3. **いまだけ使えない**——`÷ × − + =`（Convert・Finance）／`G M K`／`DEL`／`月額`／`.`／
   `( )`（Convert・Finance）

**★ 同じ `÷ × − + =` が、盤面によって 2 と 3 に分かれる。** Transfer では永久に死んで
いて、Convert では数字を打てば生き返る。**利用者から見ると、まったく同じ淡さである。**

### 起点は 0.5.0 の A1

**それ以前、淡色の意味は 1 つだけだった**（予約スロット）。0.5.0 の
`5011975 Dim the seven operator keys the three panels cannot use` が意味 2 を足し、
**意味 3 と同じ見た目にした。**

### ★ 契約は 2 つを分けていた。ただし散文でだけ——A1 はそれを破った

`web/src/ui/Key/Key.tsx` は **`reserved` と `disabled` を別々に受けている**:

```tsx
const reserved = token === null && !onActivate;
const off = reserved || disabled === true;
```

そして `disabled` の docstring はこう書いている:

> 今は押せない(状態依存)。**予約スロットとは由来が違う**——あちらは
> 「ここに何か来る」永続的な空きで、**こちらは条件が変われば押せる**（L 設計書 §4）

**この註は、いま偽である。** `isDeadOperator(token)` は**永続的な判定**なのに、
**`disabled`（＝条件が変われば押せる、の口）に入っている**。

**ただし「型が分けていた」は言い過ぎである**（2026-08-31 のレビューで訂正）。
**型が分けていたのは `reserved`（`token === null` から導出）と `disabled` の 2 つ**で、
**「永続」と「一時」を分けていたのは docstring の散文だけ**である——
**`disabled?: boolean` は、永続的な判定を入れても型では止まらない。**
**A1 が破ったのは型ではなく、散文の契約である。**

**そしてこの訂正は、§1.3 の推奨をむしろ強くする**——**散文で守れなかったのだから、
型に上げるのが正しい帰結である。**

**つまりこれは「淡色に意味を足す」話ではなく、「散文でしか守っていなかった区別を、
型と見た目に上げる」話である。**

## §1 決めること

### §1.1 予約スロット（`—`）は「永久に使えない」と同じ段（**ユーザー裁定 2026-08-31**）

**ユーザーは「`—` を消す」案を採らなかった。** だから**消さずにどう見せるか**を
決めることになる。**意味は 3 つ、見た目は 2 段**なので、**どこかで 2 つを 1 つに
まとめる必要がある。**

| 案 | `—` の扱い | 帰結 |
|---|---|---|
| **A** | **`—` と「永久に使えない」を同じ段**にする | 「**この盤面では押せない**」で 1 つにまとまる。利用者にとって**区別する必要が無い**——どちらも「ここは使えない」だから。**採るなら §1.2 は 2 値でよい** |
| **B** | **`—` を第 3 の見た目**にする（枠だけ／さらに淡く） | 3 段になる。**「淡さを 2 段」という裁定の範囲を超える** |
| **C** | **`—` を「いまだけ」と同じ段**にする | **偽である**——`—` は永久に何も来ない |

**★ 裁定は A**（2026-08-31）。**理由もそのまま採られた**——**利用者にとって、
予約スロットと死んだ演算子の違いは意味を持たない。どちらも押せず、これからも
押せない。**

**採らなかった B（第 3 の見た目）の理由**: **3 段になると「2 段に分ける」という
今回の趣旨を超える**。**次に「3 段にしよう」と思った人へ**——**3 段が要るのは、
利用者が「ここに将来キーが来る」と知る必要が出たときである。いまその必要は無い。**

**C は採らない**（`—` は永久に何も来ないので、「いまだけ」に置くのは事実に反する）。

**★ この裁定の帰結**〔**2026-09-02 に見た目の側だけ差し替え。§1.2 を見よ**〕:
**型は 2 群**（永久／いまだけ）で、`—` は永久側に合流する——**ここは変わらない**。
**見た目は 2 つになった**（生きている／押せない）。

**★ そして `—` は画に出さない**（2026-09-02）。**まだ何も入っていないセルに
記号を置くと、「そういうキーがある」に見える**。**セル（格子）は残す**
——5×5 は面をまたいで同じ位置に在り、そこは触らない。**記号を持つキー
（`÷ × − + =`・`( )`）は記号を残したまま**押せない見た目である。

**面のデータ（`dataScale.ts` ほか）は `—` を持ったままにしてある**——格子の
どこが空きかを読める形で残すため。**画に出すかは `Key.tsx` が決める**ので、
**データの `—` を書き換えても画は変わらない**（番人は `operators.test.tsx` の
「予約枠に文字が無い」）。

### §1.2 2 段を何で分けるか

**★ 色や濃さだけで分けると、見分けられない利用者が出る。** 選択肢を並べる:

| 案 | 中身 | 採る/採らない |
|---|---|---|
| **(a) `opacity` の 2 値** | `0.4` と `0.25` など | **単独では採らない**——**濃さの差だけ**なので、コントラストの低い環境・色覚・屋外で消える |
| **(b) 形を足す**（破線の枠・斜線） | 「永久」に破線の縁を付ける | **採る候補**。**濃さ以外の手がかり**になる |
| **(c) 読み上げで分ける** | 「永久」は `disabled`、「いまだけ」は `aria-disabled` のみ | **採らない**——`aria-disabled` だけだと**押せてしまう**（`onClick` が走る）。いまは両方付けている |
| **(d) 読み上げに足す** | **`aria-describedby`（または `title`）**に「この電卓では使えません」 | **採る候補**。**読み上げの利用者に届く唯一の手**。**★ `aria-label` に足してはいけない**——このリポジトリのテストは `getByRole("button", { name })` でキーを拾い、`vertical-slice.spec.ts:99` が「全キーに accessible name」を主張している。**名前そのものに文を足すと、名前で選ぶテストが広範に壊れ、名前の安定性も失う**（2026-08-31 のレビュー） |
| **(e) 何もしない** | 1 段のまま | **裁定で否定済み** |

**裁定（2026-08-31）: (b) ＋ (d)、(a) は補助。**〔**2026-09-02 に取り下げ。下記。**〕
**見える手がかりと、読み上げの手がかりを両方**置く。**濃さだけにはしない。**

**条件つきであった**——**67px のキーで破線が見えるかは撮ってから判断し、
見えなければ (a) ＋ (d) に落とす**。

#### ★ 裁定の差し替え（2026-09-02）: 見た目では分けない

**撮った。破線は見えた。そして、見えたうえで取り下げになった。**

> **あえて点線を入れていますが、不要ですね。逆に目立って押せそうに思います。
> 押せない物は押せない物とした方が良いですね。**（ユーザー、2026-09-02）

**★ (b) が失敗した理由は「見えない」ではない。「見えすぎる」である。**
**枠は「押せない」ではなく「押せる」に見えた**——枠線は**このリポジトリでは
押せるキーの合図**（`--key-border` は高コントラストでのみ出る）であり、
**押せないものにだけ枠を足すと、押せないものが一番目立つ**。

**条件の立て方そのものが片側だけだった**——spec は「**見えるか**」を条件に
書いたが、**実際の分岐は「見えるか」ではなく「押せそうに見えないか」**だった。
**次に見た目を足すときは、条件を「見えるか」で書かない。**

**★ 新しい裁定: 「永久に押せない」と「いまだけ押せない」を、見た目では分けない。**
**押せないキーは 1 つの見た目**（`opacity: 0.4`）である。**(a) の 2 段もやめる**
——分けないので、濃さを 2 つ持つ理由が無い。

**代わりに、予約スロットの `—` を出さない**（§1.1 の帰結が変わる。下記）。

**★ 区別を持つのは読み上げだけになった。** **(d) は残る**——永久側にだけ
`aria-describedby` が付く。**見た目で分けないぶん、そこが唯一の区別**であり、
**(d) の重みは増した**。

**★ 型（`Offness`）は残る。** 見た目が 1 つでも、**A1 の事故**（永続的な判定を
「条件が変われば押せる」の口に入れる）**を塞ぐ番人**は型の側に在る
（`check-boundary.mjs` の 3 つ目の規則）。**将来また分けたくなったら、
見た目だけの話で済む。**

**★ この経緯は失敗ではない。** **撮って見せたから、この判断ができた**——
**検査は全部緑のまま**であり、**撮らなければ「逆に目立つ」は分からなかった**。
plan に「撮って判断する段」を置いた形が、そのとおりに働いている。

#### ★ さらに 1 往復あった（2026-09-02）: 空欄にしたら、箱ごと消えた

**`—` を消したら、セルそのものが見えなくなった。** 撮って出したら:

> **薄い箱は残してください。**（ユーザー、2026-09-02）

**機構**: 予約スロットは `.function`（`#e8e8ed`）を `opacity: 0.4` で薄めていた。
**文字が在るあいだは文字が箱の位置を教えていた**ので気づかなかったが、
**文字を消すと、残るのは地（`#f2f2f7`）とほとんど同じ色の面だけ**になる。
**実測で 4**（地との差、3 channel の最大）——**7 で見え、4 で消える。**

**★ 直し方には条件が付いた**——**破線を退けたばかりである。**
**枠線で箱を出すと、また「押せそう」に戻る。** だから**地の色で出す**:

| | |
|---|---|
| **向き** | **押せるキーは地より明るく浮き、空きは地より暗く沈む** |
| **手段** | `--key-empty-bg`（3 テーマぶん）。**枠線は使わない** |
| **高コントラストだけ塗りで出す** | あそこはキーが白＋実線の枠なので、**空きに枠を付けるとキーと同じ形になる** |

#### ★ 1 度濃くしすぎた——**遠ざけるほど目立つ**

**最初 `#e4e4ea` を置いた。** 「沈ませる」つもりで**地から遠ざけた**ところ、
**LLM の空きが候補キー（`1B` / `3B` / `7B`）と同じ重さに見えた。**

**向きが逆だった。** **キーより弱くしたいのだから、地に近づけるのが正しい。**
**地からの距離がそのまま目立ちの強さ**であり、**「暗い＝引っ込む」は
効かない**——**明暗ではなく、地との差が効く。**

**実測（2026-09-02、390px の明るいテーマ、地との差の最大 channel）:**

| | 差 |
|---|---:|
| 生きた数字キー（`#ffffff`） | **13** |
| 濃くしすぎた空き（`#e4e4ea`） | **14** ← **キーより目立つ** |
| **採った空き（`#ebebf0`）** | **7** |
| 溶けた空き（地の色を与えず `opacity: 0.4`） | **4** |

**★ 次に色で「弱さ」を作る人へ: 地との差で考える。明暗で考えると逆に振る。**

#### ★ 番人が 1 度、仕事をしなかった

**下限を 3 に置いたら、「箱が消えた」変異（地の色を取り下げて `opacity: 0.4`）が
緑で通った。** **溶けた状態が 4 だったからである。**

**窓が狭い**（**4 と 7 のあいだ**）。**丸い数を選ぶと窓の外に出る**ので、
**下限は 5**——**「余裕を見た数」ではなく、実測の 2 つのあいだ**である。
**テストにその 3 つの数を書いた。**

**★ これは「番人を置いた」と「番人が見ている」が別だ、の実例**である。
**置いた直後に、番人が捕まえるべき当のもの（ユーザーが退けた見た目そのもの）で
壊して確かめる**——**それをしなければ、緑のまま通っていた。**

**採らなかった「濃さだけ」（(a) 単独）の理由**: **コントラストの低い環境・色覚・
屋外で消える**。**次に「`opacity` の値を 2 つにするだけでよいのでは」と思った人へ**
——**それは 1 度検討して、見分けられない利用者が出るという理由で退けてある。**

**★ 実測が要った**: **(b) の破線が 390px・67px のキーで見えるか**は、**撮って
確かめる**まで分からなかった。**撮った結果は §1.2 の差し替えのとおり**である。

**〔2026-09-02 に不要になった〕** **破線を採るなら検査の `looks` 文字列に
`border-style` を足すこと**——**破線を採らなくなったので、この宿題は消える**。
**押せない側は 1 群**になり、`opacity` と `cursor` だけで**画に出ている差は
全部見えている**。**代わりに要るのは「予約枠に文字が無い」**である
（`operators.test.tsx` に置いた）。

### §1.3 状態の型

**いま `keyDisabled(token): boolean` が 5 盤面に在る**（Scientific は持たない）:

```
web/src/ui/Convert/UnitPanel.tsx:207     web/src/ui/DataScale/DataScalePanel.tsx:122
web/src/ui/Transfer/TransferPanel.tsx:138  web/src/ui/Llm/LlmPanel.tsx:215
web/src/ui/Finance/FinancePanel.tsx:406
```

**★ 漏斗は 3 段ある。** 盤面 → `Keypad` → `Key` で、**真ん中を忘れると boolean が
生き残る**:

```
盤面           keyDisabled(token): boolean            5 盤面
Keypad.tsx:20  disabled?: (token: T) => boolean       ← ここを変えないと口が塞がらない
Keypad.tsx:77  disabled={token === null ? undefined : disabled?.(token)}
Key.tsx:29     disabled?: boolean
```

| 案 | 形 | 評価 |
|---|---|---|
| **(i)** | `keyDisabled` はそのまま ＋ `keyPermanentlyOff(token): boolean` を足す | **2 つの述語が矛盾しうる**（両方 true / どちらも true でない）。**型が不変条件を守らない** |
| **(ii)** | `keyOff(token): null \| "permanent" \| "transient"` に置き換える | **1 つの答しか返せない**ので矛盾が起きない。**5 盤面の署名が変わる** |
| **(iii)** | `Key` に `off?: "permanent" \| "transient"` を渡し、`disabled` を廃す | (ii) に加えて **`Key` の props も変わる**。**`reserved` は `token === null` のまま残る** |

**推奨（実測前）: (ii) ＋ (iii)。** **`disabled?: boolean` を残すと、A1 と同じ
「永続を transient の口に入れる」事故が繰り返せる**——**口を塞ぐ。**

**意味 1（予約スロット）は型では表さない。** `token === null` が既にそれで、
**`Key` の中で `reserved` として導出されている**。**§1.1 で A を採るなら、
`reserved` と `"permanent"` が同じ見た目になるだけで、型は増えない。**

### §1.4 どのキーがどちらか —— **コードから導出する。打鍵は検算**

**★ 「永久」の定義**: **この盤面のいかなる操作でも生き返らない。**

**この性質は測る必要がない。コードが静的に決めている**（2026-08-31 のレビューで
訂正。**私の最初の表は 1 手プローブから起こしており、3 件を取り違えていた**）:

```
永久 = token === null（予約スロット）
     ∪ isDeadOperator(token) を呼ぶ盤面での 7 トークン
       DEAD_OPERATOR_TOKENS = lparen rparen div mul sub add eq（静的な表）
       呼ぶのは DataScalePanel:123 / TransferPanel:139 / LlmPanel:216 の 3 盤面
一時 = それ以外の keyDisabled の true（全部、状態かモードに依存する）
```

**導出した表:**

| 盤面 | **永久に使えない** | **いまだけ使えない**（根拠） |
|---|---|---|
| Scientific | なし（`keyDisabled` を持たない。25/25 が生きている） | なし |
| Convert | なし | `÷ × − + = ( )`（`canPushOpenParen` / `canPushCloseParen` ほか） |
| Finance | なし | `÷ 万 × 億 − + = ( )` ／ `月額`（`fieldEnabledIn(field, mode)`）／ `.`（`active !== "rate"`） |
| DataScale | **`( ) ÷ × − + =`**（`isDeadOperator`） | `G M K` |
| Transfer | **`( ) ÷ × − + =`**（`isDeadOperator`） | なし |
| LLM | **`( ) ÷ × − + =`**（`isDeadOperator`） | `DEL` ほか |
| 全盤面 | **`—`（`token === null`）** | —— |

**★ 1 手プローブは、この表の導出には使えない。** 「7 を 1 つ押して生き返るか」は
**一時側を過小に数えることしかできない**——**1 手で生き返らない一時は、全部
「永久」に化ける。** 実際に **`月額`（モード依存）・`.`（項目依存）・Convert と
Finance の `( )`（entry 依存）の 3 件が化けていた。**

**打鍵は検算に回す**——**導出が「一時」と言ったキーが、実際に生き返る操作を
1 つ見つける**。**見つからなければ導出が疑わしい**（あるいは到達不能な一時である）。

### §1.5 検査

**既存の前例が在る**——`web/tests/e2e/convert.spec.ts:699-754` が
**`disabled` 属性ではなく計算済みスタイルを読む**:

```ts
return `opacity=${style.opacity} cursor=${style.cursor}`;
...
new Set(["opacity=1 cursor=pointer"])    // 押せる
new Set(["opacity=0.4 cursor=default"])  // 押せない
```

**この形を 2 段に広げる。** 決めること:

1. **E2E で、3 つの群が互いに区別できることを主張する**——「永久」「いまだけ」
   「生きている」の 3 集合が、**計算済みスタイルで 3 つの異なる値になる**
2. **件数を主張する**（§1.4 の表の数）。**ループが 0 周でも緑にならないように**
3. **既存の「押せないように見える」の検査は 1 本だけである**——
   `convert.spec.ts:721 shows unpressable currency keys as unpressable`。
   **`vertical-slice.spec.ts` にその主張は 1 行も無い**（`opacity` / `disabled` /
   「押せない」の grep が 0 件。**私が最初に書いた引用先は誤りだった**——
   2026-08-31 のレビューで訂正）。**2 段になっても「押せない側」は全部
   `opacity < 1` なので、この 1 本は成立し続けるはず**（**実測前。plan で確かめる**）
4. **jsdom では見ない。** **CLAUDE.md の規律**——ロールの意味論と見た目は
   **E2E で実ブラウザに確かめさせる**

## §2 採らなかった選択肢（ユーザー裁定 2026-08-31）

| 案 | なぜ採らなかったか |
|---|---|
| **`—` を消す** | 〔**2026-09-02 に採用へ転じた。§1.1 を見よ**〕当時の理由: 意味 1 が消えて枠も縮むが、**枠の話（5×5）と混ざる**。**0.7.0 は小さく確実に出す**方針。**転じた理由**: **破線を取り下げたので、見せ方の変更は `—` を消すことだけになった**——**「2 つ入れる」ではなく「1 つに減った」**。**枠は縮まない**（セルは残し、文字だけ出さない）ので、**5×5 の話とも混ざらない** |
| **両方やる**（淡さ ＋ `—` 削除） | 〔**同上**〕**淡さの 2 段をやめたので、そもそも「両方」が無くなった** |
| **枠から作り直す** | **6 電卓ぶんの寸法の検査が同時に動く**（`panel-sizing.spec.ts` の 366px/67px、各盤面の `columns`、`viewport-budget` の 11 route）。**規模が別物** |
| **何もしない** | 「押せない」は 1 つの意味でよい、という判断も成り立つが、**同じキーが盤面によって永久／一時に分かれる**ので、利用者は学習できない |

## §3 やらないこと

- **枠（5×5）は触らない。** `panel-sizing.spec.ts` の 366px / 67px は動かさない
- **キーの増減はしない。** どのキーが在るかは変えず、**見せ方だけ**
- **Scientific は変わらない**（押せないキーが 0 個）

## §4 裁定（**ユーザー。3 つとも決着済み**）

| | 決まったこと | いつ |
|---|---|---|
| **予約スロット `—` の型の扱い** | **「永久に使えない」と同じ段**（§1.1 の A）。理由も採用 | 2026-08-31 |
| ~~**何で分けるか**~~ | ~~形 ＋ 読み上げ、濃さは補助~~ **条件つきで採り、撮って取り下げた** | 2026-08-31 → **09-02 に差し替え** |
| **★ 見た目では分けない** | **押せないキーは 1 つの見た目**（`opacity: 0.4`）。**区別は読み上げ（`aria-describedby`）だけが持つ**。**予約スロットは `—` を出さず空欄**、記号を持つキーは記号を残す。**格子は触らない** | **2026-09-02** |
| **★ 薄い箱は残す** | 空欄にしたらセルごと見えなくなった。**地の色で箱を出す**（`--key-empty-bg`）——**枠線では出さない**（枠線は「押せる」の合図）。**向きは「地に近づける」**（遠ざけるほど目立つ） | **2026-09-02** |

**代わりに「予約枠に文字が無い」を主張する**（`operators.test.tsx` に置いた）。
