## 2. 規則

### 2.1 一文で

**`sin x` と `cos x` を求めたあと、`|x| < 2^22` で、その値の大きさが `|x| × 2^-52` 以下なら、0 にする。**
`x` は**ラジアンに直した後の実部**（`to_rad` の出力 `z.re`）。

### 2.2 どこで（(iii) の答え）——**core の値を 0 にする。表示だけではない**

**置き場は `scientific::circular`**——DEG の `quadrant_exact` が表を引いているのと**同じ関数の、表の後ろ**。
`sin`・`cos`・`tan` はどれも `circular` が返す `(sin x, cos x)` から作られているので、**1 か所で 3 つに効く。**

**表示だけを 0 にする案を採らない理由**（例は §1 の印字）:

| キー列（RAD） | 値を 0 にする（推し） | 表示だけ 0 にする |
|---|---|---|
| `π sin` | `0` | `0` |
| `π sin × 1 Exp 20 =` | **`0`** | **`12,246.46799`**——画面で `0` と見せた値に 1e20 を掛けて 1 万が出る |
| `1 ÷ ( π sin ) =` | **`Math ERROR`（0 で割った）** | **`8.165619677e15`**——`0` と見せた値の逆数が有限 |
| `π sin + 1 =` | `1` | `1` |
| 履歴の行 `sin(π) × 1e20 =` | 慣例で読むと 0、答えも 0 | 慣例で読むと 0、**答えは 12,246**——1.2.1 で揃えた「行を読めば答えになる」が破れる |

**利用者が画面で見た値で計算が続く**ほうが、電卓の期待に合う。**表示だけを丸めると、見えている数と計算に使う数が
食い違う**——それは 1.2.1 の「画面の値で書く」（関数表記の設計書 §2.7）とも矛盾する。

### 2.3 どの関数に（(i) の答え）

- **`sin`・`cos`。`tan` は `sin / cos` なので自動で従う**（`tan(π)` → `0 / -1` → `0`）。
- **`tan` の極**: `cos` が 0 になった実数の引数は **`TrigPole`（`Math ERROR`）** にする。**`0` で割った `DivisionByZero`
  ではなく**、DEG の極（`is_tan_pole`）と同じエラーに揃える。**`π ÷ 2 = tan` の `1.633123935e16` は消える**
  ——`numerical-policy.md` の既知の制約「Rad モードの `tan` は極を検出できない」が、**f64 で最も近い表現の極については**
  検出できるようになる（§5）。
- **複素の引数**: **表と同じく、`sin x`・`cos x` の因子を 0 にしてから複素の公式に入れる**
  （`sin(x+iy) = sin x·cosh y + i·cos x·sinh y`）。**結果の成分ごとには丸めない**——1.0.0 の設計書 §3.2 の裁定 (a)
  と同じ理由で、**`im == 0` と `im == 1e-300` のあいだに段差を作らない。** `(π + 1j) sin` は `-1.175201194j`
  （実部 `1.88972876e-16` が消える）。**`cosh`・`sinh` は触らない**（周期を持たない）。
- **DEG にも同じ規則が掛かる**（`circular` は角度モードを問わない。表が先に引かれ、表に無い角だけがここに来る）。
  DEG で掛かるのは「`0.1 × 1800 =` のように**計算で作った 180 に近い値**」だけで、**打った 180 は表が先に返す。**
- **`asin`・`acos`・`atan`・`ln`・`log`・`eˣ`・`√` などは触らない**（出力が角度や大きさで、「0 になる角」の問題が無い）。

### 2.4 閾値と範囲（(ii) の答え）——**2 つの数で挟む**

**上から押さえる数（0 にしたい側）**: `k × π` を電卓で作った値 `x = fl(k · PI)` の `sin`。
`x` と本当の `kπ` のずれは「`PI` 自体のずれ `k(π − PI)`」と「掛け算の丸め」の和で、
**`|x − kπ| ≤ |x| · ((π − PI)/π + 2^-53) ≈ |x| · (3.9e-17 + 1.11e-16) = |x| · 1.50e-16`**。
**実測**（`k = 1..10^7`、`PI * k`）: **`|sin x| / |x|` の最大は `1.4996e-16`**（`cos((2k−1)·PI/2)` も同じ）。
理論の上限にぴったり張り付く。

**下から押さえる数（0 にしてはいけない側）**: **正しく打った数の答えは、どれだけ 0 に近くても残す。**
`π` に近い整数（連分数の近似 `355`・`103993`・`833719`…）が一番危ない。**実測（整数 `n = 1..2^26` の
`min(|sin n|/n, |cos n|/n)`）**:

| 範囲 | 最小の比 |
|---|---|
| `n ≤ 2^20` | `5.13e-13` |
| `n ≤ 2^22` | `2.28e-13` |
| `n ≤ 2^23` | `7.05e-15` |
| `n ≤ 2^26` | **`2.74e-16`**（`n = 42,781,604`）——**閾値に触れそうになる** |

小数 1 桁（`x = n/10`、`≤ 838,860.8`）の最小は `1.29e-13`。**打てる数は 12 桁まで**なので、
`π` の近似を打っても `3.14159265358`（比 `2.9e-11`）が限界で、**打った数がこの規則に掛かることは無い。**

**決めた値**:

- **閾値 `T = 2^-52`（`f64::EPSILON`、`2.22e-16`）。** 上の `1.50e-16` に **1.48 倍**の余裕。
- **範囲 `|x| < 2^22`（4,194,304 ラジアン）。** この中の整数の最小比 `2.28e-13` に対して **約 1,000 倍**の余裕。
  `π × 1000000`（`x = 3.14e6`）は範囲に入る。**`2^22` を超えると規則を掛けない**——
  `π × 4194304 = sin` は今どおり `-5.136540968e-10` が残る（§6 の残る点）。

**10 桁の表示との関係**: 0 にされる値の大きさは `|x| · T < 2^22 · 2^-52 = 2^-30 ≈ 9.3e-10`。
**`sin`・`cos` の値域は ±1 なので、表示 10 桁の最後の桁（`1e-9` の位）より小さい。**
**0 にした値が、0 でない普通の答えの 10 桁に影響することは無い**——影響するのは「0 のはずの所に指数表記の
小さな値が出る」場面だけで、それが利用者の要望である。

### 2.5 「0 を返すと嘘になる」との整合（(iv) の前提）

いまの方針（`numerical-policy.md` の既知の制約）は「**f64 の π は本当の π ではないので、1.22e-16 は入力に対して正しい。
0 を返すと『入力が厳密な π だった』という嘘になる**」。**この理由は、半分正しく半分足りなかった:**

- **正しい半分**: `3.14159265358` と打った人に `0` を返せば嘘である。**この規則はそれを守る**——
  打った数の比は閾値の 10 万倍以上で、答えは残る（§2.4）。
- **足りなかった半分**: **`x` が「`kπ` に最も近い f64（またはその近く）」であるとき、`1.22e-16` は入力についての情報ではなく、
  f64 の刻みについての情報である。** `π` キーで作った値も、`π × 3` で作った値も、**f64 が `kπ` を表せる最善**であり、
  **その誤差の大きさ以下の答えは、`kπ` の正しい答え（0）と区別できない。** 区別できないものを 0 と書くのは、
  `sin(30°) = 0.4999999999999994` を 10 桁で `0.5` と見せているのと同じ種類の判断である。

**将来の案 A（値に「有理数 × π」の印を持たせる。利用者の裁定待ち、範囲外）との両立**: A が採られれば `π` キーの値は
本当に `kπ` になり、**多くはこの規則に来る前に厳密に 0 になる。** **残るのは印の無い値**——`3.141592653589793` と同じ
f64 を計算で作った場合など——で、**この規則はそれに対して今と同じに働く。** 2 つは同じ答えを出し、衝突しない。

### 3.3 独立検証（(v) の答え）

- **`reference/scientific_ref.py` は変えない**（変えてはならない。1.0.0 の §4 と同じ）。参照は `mpmath` で
  **f64 の 10 進の綴りそのもの**を 50 桁で評価するので、`sin(3.141592653589793)` の期待は `1.2246…e-16` のまま。
  **規則を参照に写すと、同じ判断が両方に入って照合の意味が消える。**
- **golden（`testdata/scientific.json`）**: `abs 1e-12 OR rel 1e-12` の許容なので、**engine の `0` と期待の `1.22e-16` は
  `abs` で一致する**——**golden はこの規則を見分けない**（見張れない）。いまの `cos/Rad/π = -1` は動かない。
  **golden に行を足さない**（足しても許容の中で緑になり、何も主張しない）。**番人は §3.1・§3.2 が持つ。**

  **重量級担当が「RAD × π の倍数 × sin・cos・tan」の層を足す前提**で、そのときの取り決めを 1 つ書く:
  **期待は `corpus_eval.py` が `mp.pi`（本当の π）で計算するので `sin(kπ) ≈ 1e-50` になり、比較は相対のみ
  （`corpus.ts` の `withinTolerance` は期待がちょうど 0 のときしか `abs` を使わない）なので、engine の `0` とは
  相対 1 で食い違う。** **これは今の engine（`1.22e-16`）でも同じく食い違う**。層を作るとき、**期待の側で
  「数学的に 0」を 0 として書く**（`|v| < 10^-(dps−5)` を 0 に畳む等）か、比較の側で扱うかを**重量級担当が決める**。
  **どちらを採っても、参照に engine の規則（`2^-52`・`2^22`）を写さない**こと。
- **独立の宣言**: `scientific_ref.py` の `独立: 別手順` は変わらない。**この規則そのものは「入力が `kπ` の最善の表現か」という

## 5. `numerical-policy.md` の書き換え（(iv) の文案）

**いまの段落**（`sin(π)` は `1.224646799e-16` を返す…0 を返すと嘘になる）を、次に替える:

> - **`sin`・`cos` は、引数の表現誤差より小さい答えを 0 にする**（1.2.2）。**`|x| < 2^22` のラジアンで、`|sin x|` か
>   `|cos x|` が `|x| × 2^-52` 以下なら 0**（`scientific::circular`、DEG の表の後ろ）。**`π` キーや `π × 3` で作った値は、
>   f64 が `kπ` を表せる最善で、そのずれ（`|x| × 1.5e-16` 以下、実測）より小さい答えは `kπ` の答え（0）と区別できない**
>   ——`1.224646799e-16` は入力の情報ではなく、f64 の刻みの情報だった。**打った数の答えは残す**: 入力は 12 桁までで、
>   `3.14159265358` の `sin` は `8.979318434e-11`（比 2.9e-11、閾値の 10 万倍以上）。**整数 `n ≤ 2^22` で最も 0 に近い比は
>   `2.28e-13`** で、閾値の約 1,000 倍の余裕がある。**`2^22` より大きい引数には掛けない**（`n = 42,781,604` の
>   `cos` の比が `2.74e-16` まで落ち、打った数と区別できなくなる）。**DEG の 90° ごとは従来どおり表から厳密に返す。**
> - **RAD の `tan` の極**: `cos` が上の規則で 0 になった実数の引数は `TrigPole`（DEG の極と同じエラー）。
>   **`π ÷ 2 = tan` は `Math ERROR`**。**`2^22` を超える引数の極は従来どおり検出しない。**

**理由の書き換えの要点**: 「0 を返すと嘘」は**打った数**については今も正しく、規則はそれを守る。
**`π` キー由来の値**については、`1.22e-16` のほうが「f64 の都合を利用者に見せている」側だった。

## 6. 決められずに残った点

1. **範囲 `2^22` の外の `kπ`**（`π × 4194304 = sin` → `-5.136540968e-10` が残る）。**閾値を引数の大きさに合わせて広げる
   案は、打った整数の答えを潰す**（§2.4 の表）ので採らない。**残すのを推す**——RAD で 400 万ラジアンを超える
   `kπ` を作る使い方は稀。案 A（π の印）が採られればここも厳密になる。
2. **DEG で計算した 180 近傍**（`0.1 × 1800 = sin` など）にも掛かる。**推しは「掛ける」**（`circular` は角度モードを問わない）。
   DEG だけ外すなら `mode == Rad` の条件を足すだけ。
3. **`tan` の極を `TrigPole` にする**のは、要望（0 に丸める）から一歩出ている。**推しは「入れる」**——`cos` を 0 と見せて
   `tan` だけ `1.6e16` を見せると、画面どうしが矛盾する。外すなら `DivisionByZero`（`checked_div` のまま）になり、
   **画面の文言は同じ `Math ERROR`** だが種類が違う。
4. **重量級の層の期待の作り方**（§3.3）は重量級担当の判断。
