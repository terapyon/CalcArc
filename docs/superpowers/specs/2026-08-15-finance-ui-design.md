# Finance の盤面（A）— 設計

日付: 2026-08-15
対象: Finance タブに複利を出す。あわせて**実運用で見つかった表示・入力の欠陥**を直す。
前提: B（`loan` の `finance` 下への移動）の上に積む。計算コアは F1 で完成済みで、
**この spec はコアを 1 行も変えない**。
**状態: 未承認のドラフト。** 未裁定 7 点（§12）はユーザーの選択を待つ。

## §0 位置づけ — 3 つの主題

1. **複利をタブの中に出す。** F1 が計算コアと WASM 境界まで作り、
   `web/src/finance/` のラッパーは**呼び出し元が無いまま**置いてある。ここに
   盤面を繋ぐ。
2. **入力が読めない・切り替えると計算根拠が消える**（実運用で報告された欠陥 1。
   §1）。「いま何で計算しているのか分からなくなる」——**答だけが見えて根拠が
   見えない**状態が、項目を切り替えるたびに起きている。
3. **`000` が効かない**（実運用で報告された欠陥 2。§2）。

2 と 3 は F1 の範囲外だったが、**Finance の盤面を触るこの spec が正しい置き場**
である。どちらも「盤面の入力体験」の問題で、複利の項目を足すときに同じコードを
触る。**しかも 2 は複利で悪化する**——項目が 6 つあり、周期と税まで含めると、
根拠が見えないまま答だけが出る画面になる。

## §1 欠陥 1: 入力が読めない・切り替えると計算根拠が消える

**2 つの症状は同じ原因から出ている。** どちらも「入力の見せ方」の設計が
足りていない。

### 症状 1: いま打っている数字が小さすぎる（実測）

`web/src/ui/Readout/Readout.module.css` の `.echo` は

```css
  color: var(--display-status-fg);
  font-size: var(--display-size-status);   /* 0.75rem = 12px */
```

**status 行と同じ扱い**になっている。

原因は**役割の取り違え**である。**Scientific では echo は副次表示**だ——答が
`main` に出ていて、echo は「いま何を打ったか」の控え。小さくて薄くてよい。

**Loan と Data Scale では echo が入力の主表示**である。`main` に出るのは
**答**（月額・データ量）で、**利用者がいま打っている数字は echo にしかない**。
金額を打っているあいだ、画面で一番大きいのは無関係な答か空欄で、打鍵の結果は
12px の薄い字で右上に出る。

サイズが合っていないのではなく、**役割が違うものを同じ見た目にしている**。

### 症状 2: 項目を切り替えると、前に入れた値が画面から消える

**echo はアクティブな項目しか出していない。**

```
借入額を選んで 3000万 と打つ  → echo: 借入額 3000万
年利に切り替える              → echo: 年利          ← 3000万 が消える
```

3,000 万・1.5%・420 か月を入れ終えた時点で、画面に残っているのは
**答と、最後に触った項目だけ**である。「この 91,855 円は何から出たのか」を
確かめる方法が、**項目タブを 1 つずつ押して回ること**しかない。

これは Loan で 6 項目、複利で 6 項目あるので、項目が増えるほど悪化する。
**答だけがあって根拠が見えない画面**は、金融計算では特に危うい——桁を 1 つ
間違えたまま答を読んでも気付けない。

### 直し方: echo を「名前つきの入力の列」にする

1 行の文字列ではなく、**入力の一覧**を見せる。いま打っている項目は大きく
はっきり、**打ち終わった項目は小さく副次的に、しかし画面に残す。**

```
┌──────────────────────────────────────┐
│                          年利 1.5     │  ← アクティブ（大きく・濃く）
│  借入額 3000万 · 期間 420か月          │  ← 入力済み（小さく・薄く）
│  月額を求める            年利を入力中   │  ← status（既存）
│                            91,855     │  ← main（答）
└──────────────────────────────────────┘
```

- **未入力の項目は出さない**（空の `残価` や `ボーナス` で埋めない）。
- **アクティブが未入力なら、ラベルだけを大きく出す**（いまの挙動と同じ）。
- 並び順は**項目行の並び**に合わせる（盤面と目の動きを揃える）。

### 機構（§12 Q1 で裁定）

- **(a) `Readout` の echo を構造化する**（推奨）:

  ```ts
  export interface ReadoutEntry {
    /** 項目名。Scientific のように名前が無い入力では空文字。 */
    label: string;
    /** 表示用に整形済みの値。**Readout は整形しない**（既存の規律）。 */
    value: string;
    active?: boolean;
  }
  ```

  `echo: string` を `entries: ReadoutEntry[]` に置き換える。
  **Scientific は「名前なしの 1 件」を渡す**（`[{ label: "", value: "sin 30 +",
  active: true }]`）ので、見た目も意味も変わらない——アクティブな 1 件しか
  無いから、いままでと同じ 1 行になる。

  この形なら **`echoRole` のような見た目の指定が要らない**。「アクティブか
  どうか」は入力の事実であって、装飾の指定ではない。

- **(b) `echo: string` のまま、パネル側で `借入額 3000万 · 年利 1.5` と組み立てる**:
  `Readout` を触らずに済むが、**どれがアクティブかを文字列で表せない**ので
  強弱が付けられない。症状 2 だけを直して症状 1 を残す形になる。

- **(c) 入力一覧を別の区画にする**（`Readout` の外）: 強弱は付けられるが、
  **表示が 2 か所に割れる**——`main` と入力が離れると視線が往復する。

**推奨 (a)。** ただし **Scientific の見え方を変えないこと**が条件である
（S2 のエコーは設計どおりに動いている）。`entries` が 1 件で `label` が空なら、
いまの `.echo` と同じ描画に落ちる、という形で守る。

**大きさの具体値は plan で決める。** 目安はアクティブが `--key-font-size`
（1.375rem）級・色は `--display-fg`、入力済みが `--display-size-status`
（0.75rem）級・色は `--display-status-fg`。**いまの echo の見た目が「入力済み」
側に降りる**と読むと分かりやすい。

### 縦の余地（§12 Q7）

入力済みの行が増えると `Readout` が縦に伸びる。390×844 で、Loan の
月額モード（借入額・年利・期間・残価・ボーナスまで入りうる）が最悪で、
**入力済み行が 2 行に折り返す**可能性がある。

- **(a) 折り返して伸ばす**（推奨）: 値が見えることが目的なので、隠さない。
- (b) 1 行に収め、溢れは横スクロール: 見えない値ができる。目的に反する。
- (c) 最新の n 件だけ出す: どれが消えたか分からない。

**キーパッドの 44px を割ってはならない**ので、伸びる余地があるかは
**実機で撮って確かめる**（§8 の完了条件）。足りなければ、入力済み行の
文字を詰めるか、`Readout` の縦 padding を削る——**キーの寸法は最後に削る**。

## §2 欠陥 2: `000` が 1 個しか入らない

### 実測（2026-08-15、jsdom で再現）

`月々の返済額` モードで「借入額」を選び、`3` → `000` と押した結果:

| 項目 | 打鍵 | 出た値 | 期待 |
|---|---|---|---|
| 借入額（金額） | `3` `000` | **`30円`** | `3000円` |
| 返済期間 | `1` `000` | `1000か月` | `1000か月` ✓ |
| 年利 | — | キーが無効 | 無効（設計どおり） |

**金額の項目だけが壊れている。**

### 原因

`LoanPanel.tsx` の `zeros3` は 1 打鍵を 3 回の数字入力に展開する:

```ts
      case "zeros3":
        for (const _ of [0, 1, 2]) pressDigit("0");
```

`pressDigit` は項目の種類で分岐する:

```ts
    if (MONEY_FIELDS.includes(active)) {
      setEntry(active, pushDigit(entryOf(active), digit));   // ← 値を先に計算する
      return;
    }
    if (active === "rate") {
      setRate((previous) => ...);                            // ← 関数型更新
    }
    setMonths((previous) => ...);                            // ← 関数型更新
```

**金額だけが「いまの値」をレンダー時のクロージャから読む。** `entryOf(active)` が
返すのは、この描画時点の `amounts` である。同じイベントの中で 3 回呼んでも 3 回
とも同じ値を読み、React がまとめて反映するとき**最後の 1 回だけが残る**。

年利と期間が無事なのは、関数型更新（`(previous) => ...`）が**直前の結果**を
受け取るので 3 回が積み上がるからである。

**Data Scale は正しい。** 同じ `000` を、ローカルで畳んでから 1 回だけ書く:

```ts
      case "zeros3":
        if (numberField) {
          let next = entry;
          for (const _ of [0, 1, 2]) next = pushDigit(next, "0");
          setEntry(next);
        }
```

### 検査の穴（記録）

**L には「`000` を押した結果」を見る検査が 1 つも無い。**

```bash
$ grep -rn "3桁のゼロ" web/src/ui/Loan/LoanPanel.test.tsx web/tests/e2e/loan*.spec.ts
LoanPanel.test.tsx:152:  expect(...{ name: "3桁のゼロ" })).toBeDisabled();     # 年利で無効
LoanPanel.test.tsx:157:  expect(...{ name: "3桁のゼロ" })).toBeEnabled();      # 金額で有効
loan-keypad.spec.ts:62:   const zeros = ...{ name: "3桁のゼロ" };              # 可否のみ
```

**押せるかどうかしか見ていない。** 押した結果を誰も見ていないので、キーが
何もしなくても全部緑になる。**Data Scale にも同じ穴がある**（`000` の押下結果を
見る検査は 0 件。実装は正しいが、正しさは検査に支えられていない）。

**実装側の自己レビューでも、読みの完了レビューでも捕まらなかった。**
可否表（disabled の条件）を丁寧に作ったことが、かえって「このキーは検査済み」
という錯覚を生んだ——**可否は入口の検査であって、出口の検査ではない。**
`000` は D でも「押した結果」が無検査なので、これは 1 つのキーの話ではなく
**「状態を持たないキーは検査を忘れる」という型**である。

### 裁定（§12 Q2）

- **(a) `000` を廃止する**（推奨・ユーザーの傾き）: 金額には `万`・`億` があり、
  `3000万` は `3` `000` `万` より `3000` `万` の方が短い。**`000` が短縮になるのは
  単位キーが無いときだけ**である。廃止すれば壊れた経路も消える。
- **(b) 直して残す**: Data Scale と同じローカル畳み込みにする。修正は 4 行。

**どちらを採っても、検査の穴は塞ぐ**——(a) なら「`000` のキーが存在しない」を、
(b) なら「金額で `3` `000` が `3000` になる」を検査にする。

**(a) を採った場合の空きセル**（§12 Q3）: `000` が抜けた 4×4 の 1 マスを
(i) 恒久の空きにする（D の型面と同じ。何も描かない） (ii) 予約スロットにする
（S1 の「ここに何か来る」。無効なボタンを描く） (iii) 他のキーを寄せる。
**推奨 (i)**——「ここに何か来る」予定が無いので、予約スロットは嘘になる。

**Scientific の `000` は廃止しない。** Scientific には単位キーが無いので
`000` は本当に短縮であり、しかも**Rust の engine 側で処理されていて壊れていない**
（`engine_table.rs` が仕様として持っている）。

## §3 複利を 1 つのモードにする

F1 のコアは `grow(principal, deposit, rate, periods_per_year, periods, tax)` の
**1 本**で、一括預入は `deposit = 0`、毎月積立は `principal = 0` の退化である。

**盤面もその形をそのまま写す。** 「一括」と「積立」を別モードにしない——
**モードが違うのに計算が同じ**という状態を作らないためで、利用者から見ても
「最初にまとまった額を入れて、毎月も積む」が自然に書ける。

### モード行（§12 Q4）

いまの区画は `求めるもの`（3 キー、半高）で、`月々の返済額` / `借入可能額` /
`返済期間`。ここに `複利` が入ると **区画名が嘘になる**（複利は「求めるもの」
ではなく「計算の種類」）。

- **(A1) 1 段 4 キーにして区画名を `計算の種類` に変える**（推奨）:
  390px で 4 列だと 1 キー ≈ 87px。**`月々の返済額` は確実に折り返す**ので
  ラベルを詰める（`月額` / `借入可能` / `期間` / `複利`）。読み上げ名は
  いまのまま（`月々の返済額を求める` など）残す。
- **(A2) 2 段にする**: 上段 `計算の種類`（`ローン` / `複利`）、下段 `求めるもの`
  （ローンのときだけ 3 キー）。ラベルは詰めなくてよいが、**半高の行が 3 本**に
  なり、キーパッドの 44px を守る余地が減る。

**推奨 (A1)。** 縦の余地の方が希少である（44px はキーの誤爆に直結する）。
ただし**折り返しの有無は実機で撮って確かめる**——L で「ボーナス」が 6 列で
折り返した前例がある。

### 項目行（複利のとき）

| 項目 | 種類 | 備考 |
|---|---|---|
| 元本 | 金額 | 一括預入ぶん。空なら 0 |
| 積立額 | 金額 | 毎期の積立。空なら 0 |
| 年利 | 数（小数可） | ローンと同じ入口 |
| 期間 | 数 | **単位は「期」であって月ではない**（§4） |
| 周期 | 選択 | 月 / 半年 / 年 |
| 税 | 選択 | なし / あり（20.315%） |

6 項目で、ローンと同じ列数（6）に収まる。

**可否表**（L の `fieldEnabledIn` と同じ方式）:

- 複利モードでは**すべての項目が有効**。ローン固有の項目（残価・ボーナス・月額）は
  出さない。
- **モードを切り替えたら、アクティブ項目を新しいモードで有効な先頭へ移す。**
  L の完了レビューで見つかった状態整合バグ（無効になった項目に居座り、
  「無効表示なのに入力先」になる）の再演を防ぐ。**ローン ⇄ 複利の切り替えは
  L の実装時に存在しなかった経路**なので、`fieldEnabledIn(field, forMode)` の
  ようにモードを引数で受ける形——切り替えの瞬間、まだ state に入っていない
  次のモードで判定する必要がある——をここでも守る。
- **元本と積立額が両方とも空**のときは計算しない（コアが `SyntaxError` を返す。
  空欄は「まだ入力していない」であってエラーではないので、**画面は中立のまま**
  にする——D の「両方の項目が埋まっているときだけ計算する」と同じ規律）。

## §4 周期と税をどう置くか

どちらも数字ではなく選択である。既存の前例が 2 つある:

| 前例 | 置き方 | 性質 |
|---|---|---|
| Data Scale の**データ型** | 項目タブを押すと**盤面の面が入れ替わる** | 計算に入る |
| Data Scale の**主表示トグル** | 盤面の外のトグル | **表示の読み方だけ** |

**規律を 1 つ決める: 計算に入るものは盤面の中、表示の読み方だけが盤面の外。**

周期も税も**計算に入る**（周期は分母を変え、税は出力を増やす）。したがって
**どちらも「面が入れ替わる項目」にする**——データ型と同じ機構で、周期は 3 キー
（`月` / `半年` / `年`）、税は 2 キー（`なし` / `あり`）。

**面の高さは 4 行ぶんを保つ**（D で確立した機構。外すと面の入れ替えで 93.5px
ずれて押す位置が動く）。周期面も税面も同じ枠に載る。

### 期間の単位は「期」である

**ここが誤解を生みやすい。** 周期が半年なら「期間 10」は 10 半期 = 5 年である。
月と決め打ちできない。

- echo は `期間 10期` のように**単位を出す**。
- 状態行に**周期を常時出す**（`半年複利` など）。D が主表示の系を status に
  出しているのと同じ。
- 上限は 1200 期（コアの `MAX_PERIODS`）。
- **周期を変えても期間の値は保持する。** L で立てた「打った値は消さない」の
  規律をそのまま引く。**保持すると意味が変わる**——`10` のまま月から半年へ
  移れば 10 か月が 5 年になる——が、それを引き受けるのが echo の「期」単位と
  status の周期常時表示である。**黙って空に戻す方が事故が大きい**（打ち直しに
  気付かないまま別の答を読む）。

## §5 結果の出し方

`main` = **満期の元利合計**（税ありなら手取り。§12 Q5）。

結果領域（D の `datascale-result` と同型）に併記する:

```
元本合計      7,200,000 円
運用収益      2,648,906 円
――― 税あり のとき ―――
国税            405,679 円
地方税          132,445 円
手取り        9,310,782 円
```

**エラー**: コアが返すのは `SyntaxError`（定義域外）と `Overflow`（u64 超え）。
`main` に `Math ERROR` を出し、`data-error` に種類を入れる（L・D と同じ）。

**免責と税の注記**（F1 spec §10）:

- 既存の免責（「実際の返済額は金融機関の計算方法により異なります」）は
  **複利にも掛かる文言に広げる**か、モードで出し分ける（plan の判断）。
- **税を出すときは、税務上の助言ではない旨を添える。** これは新規の文言で、
  「20.315% を引いた額」を見た人が申告の根拠にしないための最低限である。

## §6 区画の名前（E2E のセレクタになる）

| 区画 | 名前 |
|---|---|
| モード行 | `計算の種類`（**`求めるもの` から変わる**。Q4=A1 の場合） |
| 項目行 | `入力する項目`（据え置き） |
| 数字面 | `数字と単位のキー`（据え置き） |
| 周期面 | `複利の周期のキー` |
| 税面 | `税のキー` |

**`求めるもの` → `計算の種類` の改名は、L が書いた E2E のセレクタを動かす**
（`loan.spec.ts` と `loan-keypad.spec.ts`）。機械的な置換だが、**見落とすと
E2E が赤になる**ので plan の最初のタスクで扱う。

E2E は**パネル起点で引く**（`region` 名 `金融計算`）——`入力する項目` と
`数字と単位のキー` は Data Scale と同名である。

## §9 一貫性の論点（§12 Q6）

**`000` を「単位キーがあるから不要」として廃止するなら、同じ理屈が Data Scale
にも当たる**——`K` が `000` を包含する（`100K` = `100000`）。

- **(a) A では触らない**（推奨）: D の `000` は**正しく動いている**。変える理由が
  一貫性だけなら、動いているものを同じ PR で触る利は薄い。**別 PR に送る**
  （一貫性を捨てるのではなく、順序の話である）。
- (b) A で一緒に廃止する。
