# 横向きの配置 — 表示欄と関数を左へ、5×5 を右へ（1.1.0）

**2026-09-30。起点は `fc57633`（版数は既に 1.1.0、タグ未）。**

**利用者の裁定**: **「メインの 5×5 はそのままにして、表示エリアとファンクションを左側に持ってくる」**
／**「`j` や `Exp` などの重要なボタンは表から消さない」**／**「CSS だけでできるほうがよさそう」**
（2026-09-30）。

**★ 前の設計書（`2026-09-30` の 1 つ前、`2026-09-29-wide-layout-design.md`）は
「配置の変更は 1.2」と書いているが、それは監視役の取り違えである**——**利用者が最初に選んだ絵は
すでに「関数を左に寄せた配置」だった。** **選ばれた絵の名前（「Shift の裏を表に出す」）だけを
受け取り、絵の中身を読まなかった。** あちらにも訂正の印を入れた。

## 1. 測って分かったこと

### 1.1 いまの横向きは、中身が画面の 2 倍ある

**横向き（幅 667/844）でページ全体の高さは 831px、画面は 390px**
（2026-09-29、検証役の実測）。**441px 溢れている。**

### 1.2 溢れの主犯は「正方形のキー」である

`Keypad.module.css` の `.square > button { aspect-ratio: 1 / 1 }`。
**5 行の正方キーは、幅 480px の枠で `5 × 84.8 + 32 = 456px`** を占める。
**横向きは「幅は余るが高さが無い」**ので、**正方形はいちばん相性が悪い。**

### 1.3 `j` と `Exp` は 5×5 の中に在る

`scientific.ts` の `MAIN_GRID`（`:148`、`columns: 5`、25 キー）——
**`j` は `:205`、`exp` は `:239`。** **どちらもこの区画の中である。**

**→ 5×5 の配列に手を入れなければ、表から消えることは構造上ありえない。**

### 1.4 `.keypad` はランドマークではない

区画は `<fieldset aria-label={…}>`（`Keypad.tsx:59-64`）で、**`aria` は区画側に付いている。**
**`.keypad` はそれらを縦に並べるだけの入れ物**である。

**→ `.keypad` を箱から外しても、読み上げのランドマークには触らない**
（**`<main>` を外す案は採らない**——あちらはランドマークで、**箱から外すと読み上げの木から
消えるおそれがある**。**確かめていない。**§6）。

## 2. 決めたこと

### 2.1 配置

```
844×390
┌────────────────────────────────────────────┐
│ Nav                                        │ 48
├─────────────────────────┬──────────────────┤
│   123.456               │                  │
│  （表示欄 154px）         │   いまの 5×5      │
│                         │   25 キー・5 列    │
├─────────────────────────┤   5 行            │
│ 関数キー（7 列）           │   そのまま         │
│ 第 2 関数列（7 列）        │                  │
└─────────────────────────┴──────────────────┘
│ Footer                                     │ 41
└────────────────────────────────────────────┘
   左 476px                  右 332px
```

**Nav とフッタは、いまのまま全幅**（利用者の裁定「CSS だけでできるほうがよさそう」）。
**2 列に割るのはパネルの中だけ**である。

### 2.2 数

| | 844×390 | 667×375（いちばん厳しい） |
|---|---|---|
| **キー** | **60 × 47px** | **48 × 46px** |
| 右の段 | 332px | 275px |
| 左の段 | 476px（関数 7 列で 1 個 61px） | 356px（1 個 **44px ＝床ちょうど**） |
| 左の段の高さ | `154 + 12 + 76` = 242 | 同じ 242 |
| 右の段の高さ | `5 × 47 + 32` = **267** | `5 × 46 + 32` = **262** |
| **全体** | `48 + 12 + 267 + 12 + 41` = **380 ≤ 390** ✓ | **375 = 375**——**隙間を 12 → 8px に詰める** |

**縦持ちの 66.8px より小さくなる**（47px）。**引き換えにスクロールが 0 になる。**
**床の 44px は割らない。**

**左の段の幅の下限は 356px**（関数 7 列 × 44 ＋ 隙間 6×8）。**これが右の段の上限を決める**
——**667px では高さより幅が先に効く。**

### 2.3 仕組み——`.keypad` を `display: contents`

**横向きのときだけ**、`.keypad` を箱から外し、**パネルを 2 列の格子**にする。
**区画がパネルのマスになる**ので、**表示欄と関数 2 段を左、5×5 を右**へ置ける。

**キーの配列も列数も、`App.tsx` も、1 行も変えない。**
**`j` と `Exp` が動かないのは、構造上の保証である**（§1.3）。

**正方形をやめる**——横向きでは `aspect-ratio: 1 / 1` を外し、**幅と高さを別に決める。**

### 2.4 段の条件

```css
@media (min-width: 660px) and (max-height: 840px)
```

- **660px** は `667×375` から（**それより狭い横向きでは、左の段に関数 7 列が入らない**）
- **840px** は**積んだ配置の中身が 831px** だから（**それより高ければ積んだままで収まる**）

**当たる**: スマホの横向き（844×390・932×430・667×375）、タブレットの横向き（1024×768・1133×744）。
**当たらない**: **スマホの縦持ち**（1px も変わらない）、**タブレットの縦持ち**（1024 の高さがあるので
積んだままでよい）。

**§2026-09-29 の段（短辺 600px 以上でタブレット）とは別の段である**——
**あちらは枠を広げる段、こちらは 2 列に割る段。** **タブレットの横向きは両方に当たる**
（枠が 496px になり、かつ 2 列になる）。**それでよい**——**2 列のほうが後に来るので勝つ。**

### 2.5 4 つの電卓すべてに効く

**関数・単位換算・スケール・金融は、どれも「表示欄＋項目の行＋5×5」という同じ形**である
（`convert.ts`・`dataScale.ts`・`llm.ts`・`transfer.ts`・`finance.ts` の最後の区画が
すべて `columns: 5` の `square`）。**区画の数が違うだけ**なので、
**「最後の square の区画を右へ、残りを左へ」**で全部に効く。

## 3. 作らないもの

- **Shift の裏を表に出すこと。** **関数の段が 4 行必要**（7 列 × 4 = 28 マスで 23 キー）で、
  **`154 + 12 + 160 = 326 > 271`**——**横向きの高さに入らない。**
  **タブレットの話として後に。** **ここで混ぜない。**
- **`<main>` を箱から外すこと**（Nav とフッタを左へ入れる案）。**キーは 47 → 66px に育つ**が、
  **`<main>` はランドマークで、箱から外すと読み上げの木から消えるおそれがある**（未確認）。
  **利用者の裁定「CSS だけでできるほうがよさそう」**（2026-09-30）。
- **キーの配列の変更。** **1 つも触らない。**

## 4. 番人

| # | 何を主張するか | 置き場 |

| 1 | **横向きで 1 画面に収まる**（横にも縦にもはみ出さない） | 新しい E2E |
| 2 | **キーは 44px を割らない**（幅・高さとも） | 同上 |
| 3 | **5×5 は右、表示欄と関数は左**（箱の座標で。左の右端 ≤ 右の左端） | 同上 |
| 4 | **`j` と `Exp` が 5×5 の中に在る**（トークンと区画の対応） | 単体テスト |
| 5 | **横向きでも `main`・`nav`・区画がロールで引ける**（`display: contents` の確認） | 同上の E2E |
| 6 | **縦持ちは 1px も変わらない** | 既存の `panel-sizing` 366/67・`viewport-budget`・`display-stability` |
| 7 | **キーの配列が動いていない** | 既存の `scientific.test.ts` の並び固定 |

**#5 が要る理由**: **`display: contents` が読み上げの木に何をするかを、私たちは確かめていない。**
**`.keypad` はランドマークではないので心配は小さい**が、**確かめないまま進めない。**
**Chromium と WebKit の両方が回す。**

**#4 が要る理由**: 利用者の条件（**`j` や `Exp` を表から消さない**）は
**いまの設計では構造上満たされる**が、**「構造上そうだ」は将来の変更を止めない。**
**機械に言わせる。**
