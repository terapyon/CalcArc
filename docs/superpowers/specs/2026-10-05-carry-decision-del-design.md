# 前置の判定を DEL で未決に戻す（1.2.1、設計）

**発注**: 監視役（calcarc-cd）、2026-10-05。**利用者の裁定（10-05）で 1.2.1 に入れる。** 枝は `feat/function-notation`。
**直す欠陥**: 1.2.0 から出荷済み。関数表記の設計書（`2026-10-04-function-notation-design.md`）の実装中に、
読み直しの網 `SIGN_NET` が見つけて **54 件ちょうど**で固定した（`engine_values.rs` の `frozen_carry`、
E2E `entry.spec.ts` の「既知の欠陥を固定したもの」）。

## 1. いまの姿（`6423943`、2026-10-05 に印字で確認）

**前置**（行の頭に「決めた時点で画面に出ていた値」を置く）は、web の `press`（`ScientificPanel.tsx`）が決める:
**区間で最初に「画面の値を使うキー」**（`CARRIED_VALUE_TOKENS`。二項演算子 7 個・`=`・`)`・後置関数）を
押した瞬間に、**その直前の Step の `display.answerOnScreen`** を読み、真なら `display.main` を
`carryAtDecisionRef` に写し、`decidedRef` を真にする。**以後、その区間では二度と決め直さない。**

**欠陥**: 決めたキーを DEL が取り消しても、判定は固まったまま。

| 打鍵 | 各キーのあとの画面 [main・answer_on_screen] | 行 | engine の答え |
|---|---|---|---|
| `( ) DEL DEL × 3 =` | `( [0 -] ) [0 -] DEL [0 -] DEL [0 A] × [0 -] 3 [3 -] = [0 A]` | `× 3`（`)` で「前置しない」と固まる） | 0（echo `0 × 3`） |
| `5 = ( ) DEL DEL × 3 =` | `… ( [0 -] ) [0 -] DEL [0 -] DEL [0 A] × [0 -] …` | `× 3` | 0 |

（使い捨ての `examples/probe.rs` で `reduce` と `render` を回した印字。`A` は `answer_on_screen` が真。コミットしていない。）

`)` を押した時点の画面は `(` が出した `0` で、**答えではない**（`-`）ので「前置しない」と決まる。
**`DEL DEL` が `)` と `(` を消すと、engine は `answer_on_screen = true` に戻る**——**新しい計算の始まりと同じ姿**である。
続く `×` は画面の `0` を左辺に取るのに、判定は `)` のときのまま。

## 2. 直し方

### 2.1 判定の規則

**DEL を押したあと、engine の `answer_on_screen` が真なら、前置の判定を未決に戻す**
（`decidedRef = false`、`carryAtDecisionRef = null`）。**次に「画面の値を使うキー」を押したときに、
いまの規則のまま決め直す。**

- **読むのは engine の状態であって、キー列ではない**（1.2.0 の教訓「キー列から推測しない」。
  推測していた版は `DEL` で消えた数字を「新しい計算の始まり」と読み、364 件の行が答えを生まなかった）。
- **`answer_on_screen` が真とは、engine に保留が何も無く、画面の値が次のキーの左辺になる状態**である
  （定義は `engine/display.rs` の `answer_on_screen`: **打ちかけの数・保留の被演算子・保留の演算子・手元の値のどれも無く、エラーでもない**）。**それは「区間の始まり」と同じ姿**なので、
  判定も始まりと同じ「未決」に戻すのが正しい。
- **読む時点**: `press` の中で、**DEL を `dispatch` した戻り値（次の Step）の `display.answerOnScreen`** を
  その場で読む。**effect や ref の後追いで読まない**——**H-5（門番と `dispatch` が別の値を見ていた）と、
  H-3（エラー中の列）の族を踏まない**ため、`press` が既に使っている「`stepRef` から作った 1 つの `next`」を読む。
  **エラー中の DEL は今どおり列にも判定にも触らない**（`inError` の門の内側に置く）。
- **未決のときに DEL で `answer_on_screen` が真になっても、何もしない**（もともと未決）。

### 2.2 DEL が何を消すかで、判定がどう動くか（印字で確認した行）

| DEL が消すもの | 例（各キーのあとの画面） | DEL のあとの `A` | 判定 |
|---|---|---|---|
| **数字** | `5 = 3 DEL` → `[5 A]` | 真 | 未決のまま（数字は判定を決めない）。次の `+` で `5` を前置——**1.2.0 と同じ** |
| **数字**（演算子の後ろ） | `5 = + 3 DEL` → `[5 -]` | 偽 | `+` で決めた前置 `5` を保つ |
| **演算子**（engine は消さない） | `5 = + DEL` → `[5 -]` | 偽 | 保つ（`del_does_not_remove_an_operator`） |
| **後置関数のあと**（engine は何もしない） | `5 = sin DEL` → `[0.087… -]` | 偽 | 保つ |
| **`)`**（組を開き直す） | `5 = ( 3 ) DEL` → `[3 -]` | 偽 | `)` で決めた判定を保つ——**組はまだ開いていて、保留が残る** |
| **`)` と中身と `(`** | `5 = ( 3 ) DEL DEL DEL` → `[3 -] [0 -] [0 A]` | 3 つ目で真 | **未決に戻す** |
| **`)` と `(`**（欠陥の形） | `( ) DEL DEL` → `[0 -] [0 A]` | 2 つ目で真 | **未決に戻す** → 次の `×` が `0` を前置 → 行 `0 × 3`（engine 0） |
| **値の下の `(`**（演算子が残る） | `2 + ( ) DEL DEL` → `[0 -] [2 -]` | 偽 | 保つ（`+` が保留） |
| **`(` だけ** | `5 = ( DEL` → `[0 A]` | 真 | もともと未決（`(` は判定を決めない）。次の `+` で `0` を前置——**1.2.0 と同じ** |

**どの行でも、判定が戻るのは「engine が区間の始まりと同じ姿に戻ったとき」だけ**で、保留が 1 つでも残る
（演算子・開いた組・手元の値）あいだは戻らない。

### 2.3 DEL を繰り返す・打ち直す

- **繰り返し**: 真に戻った後の DEL（`( ) DEL DEL DEL`、3 つ目は `[0 A]` のまま）は、もう未決なので何もしない。
  `( 3 + 4 )` のあと DEL を 5 回押しても `+` の保留が残るので `A` が真にならず（印字 `[3 -]`）、`)` で決めた判定のまま——
  続けて `× 2 =` の行は `(3 × 2`、engine 6。**正しい**（左辺は前置ではなく組の中の 3）。
- **打ち直し**: 未決に戻った後に打ったキーは、**区間の始まりと同じ規則**で決める。`( ) DEL DEL ( 3 ) × 2 =` なら
  2 度目の `)` で（画面 `3`・`-`）「前置しない」と決まる。**決め直しは何度でも起きうる**——
  そのたびに「直前の Step の `answerOnScreen`」を読むので、写しは常に最新である。
- **角度の印**（`trigAnglesRef`）は**触らない**。DEL は三角キーを取り消せない（後置関数のあとの DEL は
  engine が何もしない）ので、積んだ印は打鍵の事実のまま残る。

### 2.4 写しの 3 か所を同じコミットで

**判定の規則は web と、それを写している検査の 2 か所にある**（`engine_values.rs` の `walk` と `walk_signs`）。
**3 か所を同じコミットで直す**（`frozen_carry` の註のとおり）——片方だけ直すと、網は古い写しで緑のまま、
web は直る（またはその逆）。**写しの側も「DEL のあとの `render(&next).answer_on_screen`」を読む**
（キー列から推測しない）。

## 3. 番人

1. **固定してある期待を先に反転して、赤を撮る**:
   - `engine_values.rs` の `frozen_carry` の `assert_eq!(…, 54)` を `0` に（**除外の仕組みごと外す**のは直したあと。
     まず期待だけ反転して、54 で赤くなることを撮る）。
   - E2E `entry.spec.ts` の「既知の欠陥を固定したもの」の期待を `× 3 =` → `0 × 3 =` に（テスト名と註も）。
2. **直す**（web と `walk`・`walk_signs`）。**除外の仕組み（形の判定と件数）を外す**——
   **直した後に除外が残っていると、別の欠陥がその形に隠れうる。**
3. **新しい不変条件を 1 つ足す**（`walk_signs` と `walk`）: **「DEL のあと `answer_on_screen` が真なら、区間の綴りは空」**。
   §2.1 の規則が正しいのは、そのとき行に前置を使う語が残っていないからである。**これが破れる列が在れば、
   未決に戻すと前置の要る行から前置が消える**——数えて、0 件を assert する（**比べた回数の下限も置く**）。
4. **変異で赤を確かめる**:
   - web の規則を外す（`answerOnScreen` を読まない）→ E2E が赤。
   - `walk_signs` の規則を外す → `SIGN_NET` が赤（54 件が戻る）。
   - `walk` の規則を外す → **既存の網が黙るか鳴るかを測って書く**（`Typed` は先頭の演算子の左辺を 0 で
     補うので黙る見込み——**それが 1.2.0 で見逃した理由**であり、黙るなら「`walk` の写しは `SIGN_NET` が見張る」と註に書く）。
5. **既存の網（`NET`・`PAREN_NET`）の件数**: 値の照合（`values`）は**前置と無関係なので動かない見込み**。
   読み直し（`spellings`・`prefixed`）は**動きうる**——`( ) DEL DEL` の形が `NET` にも在り、いまは前置が付かず
   `Typed` の 0 補いで一致している行が、直した後は `0` を前置して一致する（`prefixed` が増え、`spellings` は同数の見込み）。
   **動いた数と理由を印字から書く。**
6. vitest: `press` の単体（偽の `calc`）で、`DEL` の後の `answerOnScreen` が真なら判定が未決に戻ることを 1 本。
