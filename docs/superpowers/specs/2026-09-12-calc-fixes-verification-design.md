## §2 現物（`674b4df` で当て直した事実）

### §2.1 F1——演算子の押し直しは、重量級に 1 本も無い

- `main` のコミット済みのコーパスのキー列 **33,391 本**（`keys` / `left` / `right`）のうち、二項演算子のキー
  （`add` / `sub` / `mul` / `div` / `pow` / `n_p_r` / `n_c_r`。綴りは `crates/calcarc-core/src/engine/key.rs`）が
  隣り合う列は **0 本**。
- 訂正のシャード（`generate_corpus.py` の `build_corrections_shard`）の層は `typo-del` / `ac-rebuild` /
  `error-recovery` / `paren-edit` の 4 つで、演算子の押し直しを作る層は無い。
- Rust 側の押し直しの例（`engine_table.rs` の `a_second_operator_replaces_the_first`）は「数・演算子・演算子・数」の形で、
  **保留中の別の演算子**との組み合わせを持たない。

### §2.2 F1——公開の約束（期待値の根拠）

`docs/base-spec.md`:333-343: **`xʸ` だけが右結合**、四則は左結合。**`nPr` / `nCr` は `× ÷` より先、`xʸ` より後で左結合**。
よって優先順位は低い順に `+ −` < `× ÷` < `nPr nCr` < `xʸ`。

### §2.3 F2——境界と f64（**数は Python の写し**。Rust の実物は実装の段で取り直す）

「写し」は `closed_form::monthly_payment` を Python の `math.expm1` / `math.log1p` で書き写したもの。
Rust の wasm の libm と ulp で違いうる。スクリプトは scratchpad の `audit_loan_probe.py`・`f2_threshold.py`・`f2_above.py`。

- **参照実装のガードは境界ちょうどを必ず除く。** `loan_ref._guard_boundary`（`loan_ref.py`:191-197）は最寄りの整数との
  距離が `max(1e-6, 値 × 1e-9)` 未満なら棄却し、ちょうど整数なら距離 0 で必ず棄却する。境界ちょうどの入力を分数で
  **682 件**作ると **682 件すべて**棄却された。
- **参照実装の Decimal 50 桁も、境界ちょうどで整数の下に着地する**（720,600 円・年 2%・2 か月で `361200.99…9228`）。
  ガードを外すだけでは参照も 1 円下になる。**境界専用の検査の期待値は分数の厳密計算で出す必要がある。**
- 境界ちょうどの 682 件で、写しの切り捨ては理論値の切り捨てより **低い 401 件・高い 0 件**。
- **理論値が整数のすぐ下**（1e-6 円以内）の 2,455 件（連分数で作る）では **高い 274 件**・低い 459 件・同じ 1,722 件。
  例: 年 0.5%・3 回・元本 10,370,160 円で理論 3,459,600.999999994 円、写し 3,459,601 円（1 円高い）。
  **ずれは上下どちらにも出る。**
- 写しの誤差が初めて **1 円**に届く月額は、年利 8 種 × 期間 {2, 12, 120, 1200} の標本で最小 **約 45 億円**
  （年 0.0001%・2 回）、**0.5 円**に届くのは最小 **約 31 億円**。元本 10^18 円級では数十万〜約 10 億円ずれる。
- **検査が踏んできた正の年利の最大月額**は、重量級 `finance-000.json` で 243,285,690 円、golden `testdata/finance.json`
  で 3,005,998 円。それより上は未踏。
- 入力の上限: 元本は u64 の最大（`FinancePanel.tsx` の `MAX_YEN`、20 桁）、年利は小数 4 桁まで・100% 以下
  （`loan_ref.rate_fraction`）、期間は 1,200（`MAX_TERM_MONTHS`）。

## §3 F1——演算子の押し直しのシャード `operator-correction-000.json`

### §3.1 主張

**「演算子を押し直した列は、最後に押した演算子を最初から押した列と、同じ値に着く。途中で画面に値が確定していても
同じ」**（裁定）。主張しないこと: `=` のあとの押し直し、開き括弧の直後の演算子（それは押し直しではない）、
F5 で押せなくなる入力、**押し直しの途中の画面の表示**（値ケースなので `=` のあとの値だけを見る。修正後の途中の表示——
`2 + 3 + ×` で main が 3、echo が「2 + 3 ×」——は calcarc-3d の設計の範囲で、エンジンの表の検査が持つ）。

### §3.2 期待値——正規化した式を参照実装が評価する

1. 生成器はまず**正しい式の木**を作る（既存の `Num` / `Bin`、`corpus_expr.py`）。
2. その木を**平坦なキー列**にする（括弧は構造上必要なものだけ。結合方向のシャードと同じく自前で組み、
   既存の `to_keys` / `to_keys_minimal` は触らない——触ると既存シャードが総入れ替えになる）。
3. 演算子の位置を 1 つ選び、その**手前に誤った演算子を 1〜3 個**差し込む。最後に押すのは正しい演算子。
4. 期待値は**正しい式の木を mpmath で評価した値**（既存の `evaluate`）。誤ったキーは期待値に何も寄与しない
   ——**これが正規化**であり、エンジンの手順を一切写さない。

### §3.3 因子と水準（監査 §5.3）

| 因子 | 水準 |
|---|---|
| 保留中の演算子の段（選んだ位置の手前で未処理の演算子） | なし / `+ −` / `× ÷` / `nPr nCr` / `xʸ` |
| 誤った演算子の段 | `+ −` / `× ÷` / `nPr nCr` / `xʸ` |
| 正しい演算子の段 | 同上 |
| 誤った演算子の押下で途中が確定するか（`2 + 3 +` の形） | する / しない（上の 3 因子から決まる。層の名前に出す） |
| 保留の深さ | 1 / 2 / 3（手前に未処理の演算子がいくつ積まれているか） |
| 文脈 | 平坦 / 括弧の中 / 閉じ括弧の直後 |
| 押し直しの回数 | 1 / 2 / 3（誤った演算子の数） |
| 結合の向き | 正しい演算子と保留の演算子が同段のとき、左結合（四則・組合せ）/ 右結合（`xʸ`） |

**段の 3 つ組（保留 × 誤り × 正しい）は全列挙**する（5 × 4 × 4 = 80 組）。各組で文脈 3 × 回数 {1, 2} を少なくとも
1 件ずつ（格子 480 セル）。残りは乱択で埋める。格子のセルが 1 つでも埋まらなければ生成器が落ちる（§3.6）。

### §3.4 対照と、検出の意味を持たせるふるい

- **対照**: 各訂正ケースに、**同じ正しい式を訂正なしで打つ値ケース**を対にして同じシャードに入れる（層 `control`）。
  期待値は同じ。**対照が緑で訂正が赤なら、原因は訂正の処理に絞れる**（監査の対照実験）。結合方向のシャードの
  対照群（`ASSOC_CONTROL_STRATUM`）と同じ考え方である。
- **識別のふるい**: 訂正ケースは「**訂正後の演算子を、訂正前の演算子の優先順位で読んだ式**」の値と、正しい値の
  相対差が `1e-3`（既存の `ASSOC_MIN_RELATIVE_GAP` と同じ値）以上あるものだけを層 `discriminating` に入れる。
  - これは監査が報告した失敗の形を**数式として**書いたもので、エンジンの手順を写したものではない。
    監査が実測を載せた 3 本とは一致する: `8 − 3 × + 2` → `8 − (3 + 2)` = 3、`3 − 3 ÷ − 3` → `3 − (3 − 3)` = 3、
    `8 ÷ 2 xʸ × 2` → `8 ÷ (2 × 2)` = 2（監査の実測も 3・3・2）。**`2 + 3 + × 4` はこのモデルでは `(2 + 3) × 4` = 20**
    で、**現行のエンジンも 20**（calcarc-1e が `674b4df` で実測、2026-09-12: `2 + 3 +` で 5 に畳み、`×` が `+` を差し替えて
    5 × 4）。裁定の期待値 14 と違うので、この形は `discriminating` に入る。
  - **合否には使わない**。ふるいは生成側で、判定の許容は `tolerance`（既存の 5e-10）が持つ。
  - 段が同じ押し直し（`+` → `−` など）は優先順位の読み違いが起きないので、ふるいを掛けず層 `same-level` に置く
    （既存の `engine_table` の例と同じ形の回帰の見張り）。

### §3.5 値域と F4 の回避

- 葉は 1〜99（`xʸ` の底は 2〜9・指数は 2〜3、組合せは `n` 4〜20・`r` 2〜4）。中間値も含めて既存の `_within_range`
  を通す（`MIN_ABS`〜`MAX_ABS`）。
- **組合せの被演算子は葉だけ**にする。`nCr` の結果を次の整数関数に渡すと F4（既知の制限、DomainError）を踏むので、
  組合せの連鎖は作らない（`generate_corpus.py`:440-453 の結合方向のシャードと同じ理由）。
- ゼロ除算・定義域外は `OutOfShard` で捨てる（既存と同じ）。

### §3.6 件数と生成

- **2,000 件 = 訂正 1,000 件 + 対照 1,000 件**（結合方向のシャードと同じく `count` を半分ずつ使う）。seed は新しく取る。
- 訂正 1,000 件の内訳は `discriminating` と `same-level`。格子 480 セルの充足を生成器の assert で見る。
- 各ケースは既存の値ケースの形（`kind: "value"`・`keys`・`expr`・`expect: {re, im}`・`mode`）に、
  `stratum` と、訂正の形を読める `correction`（位置・誤った演算子の列・保留の段・文脈）を足す。
  既存のシャードが持つ `levels` の記録（`corpus_science.recorded_levels`）が値ケースに必須かどうかは、計画の段で
  既存の検査を当て直して決める。

### §3.10 F5（拒む入力）が重量級に効くか（`674b4df` のコーパスを走査、2026-09-12）

calcarc-3d の設計（§3.7）で拒まれる形——打ちかけの数のあとの `(`・`π`・`e`、`)`・関数の答え・`π`・`e` の直後の
数字・`000`・`.`・`Exp`・`j`・`(`・`π`・`e`——を、コミット済みのキー列 33,391 本で数えた。

| 形 | 出現する列 | どこに | 期待値への影響 |
|---|---:|---|---|
| 打ちかけの数 → `(` `π` `e` | 0 | — | なし |
| `)` → 数など | 22 | すべて `corrections-000.json` | なし（下） |
| 関数の答え → 数など | 244 | すべて `corrections-000.json` | なし（下） |
| `π` `e` → 数など | 0 | — | なし |
| `neg` → 数字 | 2 | `entry-000.json` | 1 件は裁定しだい（下） |

- 訂正のシャードの 266 本は、**すべて `ac` より前**にある（`error-recovery` の層で、エラーになる列が関数や `)` で終わり、
  その直後にでたらめの打鍵が続く形。`GARBAGE_KEYS` 自体は `)` も関数も含まない）。エラー中のキーは無視され、`ac` が

## §4 F2——許容の見張り（境界専用の検査）

### §4.1 主張

**f64 を通る出力（§2.4 の「対象」）は、月額が 10 億円以下の範囲で、理論月額の切り捨てから上下 1 円以内**。
「理論月額」は閉形式（残価ありは設計書 §3 の実慣行モデル）を**厳密な有理数**で評価した値。

### §4.2 期待値——分数の厳密計算

- 参照実装に `loan_ref.monthly_payment_exact(principal, num, den, n, residual) -> Fraction` を足す。
  docstring の宣言は **「独立: 一部（式は Rust と同じ閉形式、演算は厳密な有理数。f64 の評価の誤りは共有しない、
  式の誤りは共有する）」**。
- 期待値は `floor(理論月額)`。**`_guard_boundary` を通さない**（`loan_ref.monthly_payment` を呼ばない）。
- 賞与額は `half_year(num, den)` の月利で同じ関数を使う。

### §4.3 集合

| 集合 | 作り方 |
|---|---|
| 境界ちょうど | 理論月額 = 元本 × c（c は厳密な有理数）。元本を c の分母の倍数にすると整数（`audit_loan_probe.py` の式） |
| すぐ下 | c の連分数の近似分母 t で元本を t·m、t·m ± 1 にし、理論月額が整数の 1e-6 円以内・下にあるもの |
| すぐ上 | 同じく、整数の 1e-6 円以内・上にあるもの |
| 残価あり | 月額 A と残価 B を先に決め、元本 P = A·annuity(n−1) + B/(1+r)^n が整数になるよう A・B を分母の倍数に取る（ちょうど）。すぐ下・上は P を ±1 |
| 賞与 | 賞与分の元本を、半年利で上の 3 集合と同じく作る |

各集合で、年利の端（**0.0001%・100%**）と中間（0.5・1・2・15%）、期間の端（**2・1200**）と中間（3・12・120・360）、
月額は 1 円級から **10 億円の直下**まで（10 億円の近くを必ず含む）。件数は集合ごとに下限を置く（計画で決める。
目安は各 200 件以上）。

### §5.1 冒頭「内部表現」（:5-8）

### §5.2 expm1 の説明（:116-119）と `closed_form.rs` の註

- 実装は `pow_1p` が `expm1(n·log1p(r)) + 1` を返し、`annuity` がそこから 1 を引く（`closed_form.rs`:22・:30）。
  **1 を足した時点で下位の桁が落ち**、`x` は expm1 の値そのものではない（絶対誤差がおよそ ε/2 残る）。
- 文案: 「素朴な `powi` より桁落ちが小さい評価を使う。ただし 1 を足して引き戻すので、expm1 の精度をそのまま保つ
  わけではない。誤差の見積もり `月額 × max(n·ε/2, ε/(2r))` は見立てであって証明ではない。**円の境界での振る舞いは
  §（新節）の許容と、それを見張る境界専用の検査が決める。**」

## §6 判定名の改名

### §6.1 名前と基準

| 領域の比べ方 | 新しい名前 | 凡例 |
|---|---|---|
| 厳密（finance・data_scale・display） | **採録ケースで一致** | 採録 N 件で厳密一致（整数円・整数・表示文字列そのもの） |
| 閾値（scientific・cancellation・complex） | **採録ケースで表示精度内** | 表示の 10 桁から導いた相対誤差 ≤ 5e-10 |

「ある程度正しい」「多少疑問がある」「間違っている」「検証していない」は変えない（裁定の範囲外）。誤差の閾値
（`VERDICT_EDGES`）も変えない。

### §6.2 実装の形

- `verdictOf(cases, worst, mismatches)` に**領域の比べ方**（厳密／閾値）を足し、最上位の名前だけをそれで分ける。
- **比べ方は領域から明示で引く**（`EXACT_AREAS = ["finance", "data_scale", "display"]` のような 1 か所の表）。
  既存の行の `exact`（`relMeasured === 0`、「相対誤差を 1 件も測らなかった」）からは**引かない**
  ——【レビュー注記 D（calcarc-1e）】閾値の領域でも、測った件数が 0 の走行（全件がエラー経路など）では
  `exact` が真になり、「採録ケースで一致」と名乗ってしまう。表の「厳密一致」の列の表示は今のまま `exact` を使ってよいが、
  **判定名は比べ方の表から決める**。表と `areaOfShard` の領域の一覧が食い違ったら赤くなる単体テストを置く。
- `VERDICTS` は 5 → 6 語。`report.ts`:738-741 の註と :1759 の凡例を §6.1 の文に直す。
