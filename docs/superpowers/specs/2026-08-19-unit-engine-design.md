## §0.0 この spec が守ること

**新しい節を書くときは、全節を読み直さず、この 6 行とだけ突き合わせる。**

1. **換算に誤差を入れない。** 係数は厳密な有理数で持ち、f64 を経由しない
2. **参照実装を Rust の移植にしない。** 係数は §3 の**定義値**から書き起こす
3. **`KEY_TOKENS`（Scientific）と `engine_table.rs` を触らない**
4. **既存の WASM 署名を 1 つも変えない。** 足すだけ
5. **N × N の換算表を持たない。** 必ず基準単位を経由する
6. **温度は「点」である。** 温度差の換算はしない（§3.4）

**破っているものは無い。**

## §1 裁定（ユーザー、2026-08-19）

1. **数値は厳密有理数。** 既存の `Rational`（`expr/rational.rs`）を再利用する。
   起点の設計書 §30 は「内部計算は JavaScript Number」と書いているが、**採らない**
   ——係数がすべて定義値であり、有理数なら golden を**厳密一致**にできるからである
2. **Convert パネルは電卓に揃える。** 項目行は「値 / 変換元 / 変換先 / ⇅」で、
   単位は**面**で選ぶ（データ型面・次元数面と同じ機構）。設計書 §4 のフォーム式は
   採らない——Convert だけ OS のキーボードを使うことになり、他の 3 タブと
   操作感が分かれるためである

## §2 いま在るもの

**`Rational` は既にある**（`expr/rational.rs`、217 行）。i128 有界の既約分数で、
分母は常に正、符号は分子が持つ。`checked_add` / `checked_sub` / `checked_mul` /
`checked_div` を持ち、**あふれは `Overflow`、0 除算は専用のエラー**である。
`i128::MIN` は値として持たない（Python 参照の値域 `|値| ≤ 2^127−1` と揃えるため）。
Finance の式評価器が使っている。

**式の構文解析器は既に小数を扱う。** `parse.rs:42` に「小数点は数字列の一部として
拾う（年利だけが使う）」とあり、`parse.rs:165` の「数字列（小数を含みうる）を
分数にする」が既にある。**足りないのは着地だけ**である——今ある出口は
`evaluate_to_integer`（床関数で u128 に落とす）と `evaluate_to_percent` の 2 つで、
**有理数のまま受け取る出口が無い**。

**面の入れ替えは 2 つの先例がある**（データ型面、S-0 の次元数面）。同じ枠に載せる
規律は `dataScale.ts` の冒頭コメントが持つ。

**U-0 が `#convert` に準備中パネルを置いた。** この spec がそれを中身に置き換える。

## §3 換算（公開仕様）

**この節が参照実装との契約である。** Python はここから書き、Rust の実装を見ない。

### 3.1 形

**すべての単位はアフィン変換 1 本で表す。**

```text
base  = value × factor + offset
value = (base − offset) ÷ factor
```

`factor` と `offset` は厳密な有理数である。**倍率だけの単位は `offset = 0`**、
温度だけが `offset ≠ 0` を使う。設計書 §29 は温度のために `toBase` / `fromBase` の
関数対を用意せよと書いているが、**関数は要らない**——列挙されているどのカテゴリも
アフィンで足りる（長さ・質量・体積・面積・速さ・圧力・エネルギー・仕事率・時間は
倍率のみ、温度はアフィン）。**機構が 1 つなら、検査も 1 つで済む。**

**ただしこれは列挙されたカテゴリの性質であって、一般則ではない。** アフィンで
表せない換算は実在する——**逆数型**（燃費の `mpg` ↔ `L/100km`）と**対数型**（`dB`）。
どちらも現在のスコープに無いが、**足すときはこの機構の再利用可否を先に問うこと**。
黙って乗せると、`{factor, offset}` の表に嘘の行が入る。

換算は**必ず基準単位を経由する**（設計書 §28）。N 個の単位に N × N の式を持たない。

```text
変換元 → 基準単位 → 変換先
```

### 3.2 係数は定義値である

**下の表はすべて定義値であり、測定値ではない。** 出典は国際ヤード・ポンド協定
（1959）と SI。**参照実装はこの表から書き、Rust の表を写さない。**

**Length**（基準: メートル）

| 単位 | factor（m） | |
|---|---|---|
| `nm` | 1/10⁹ | SI 接頭辞 |
| `µm` | 1/10⁶ | |
| `mm` | 1/1000 | |
| `cm` | 1/100 | |
| `m` | 1 | 基準 |
| `km` | 1000 | |
| `in` | **127/5000** | **ちょうど 25.4 mm**（1959） |
| `ft` | 12 × `in` = **381/1250** | ちょうど 0.3048 m |
| `yd` | 3 × `ft` = **1143/1250** | ちょうど 0.9144 m |
| `mi` | 1760 × `yd` = **201168/125** | ちょうど 1609.344 m |
| `nmi` | **1852** | 海里。ちょうど 1852 m |

**Mass**（基準: キログラム）

| 単位 | factor（kg） | |
|---|---|---|
| `mg` | 1/10⁶ | |
| `g` | 1/1000 | |
| `kg` | 1 | 基準 |
| `t` | 1000 | メートルトン |
| `lb` | **45359237/10⁸** | **ちょうど 0.45359237 kg**（1959） |
| `oz` | `lb`/16 | 常衡オンス |
| `st` | 14 × `lb` | ストーン |

**Temperature**（基準: ケルビン）

| 単位 | factor | offset | |
|---|---|---|---|
| `K` | 1 | 0 | 基準 |
| `°C` | 1 | **5463/20**（= 273.15） | |
| `°F` | **5/9** | **45967/180** | `K = (F + 459.67) × 5/9` |

**不動点も検算しておく**: `−40 °C` は `−40 + 5463/20 = 4663/20 K`、
`−40 °F` は `−40 × 5/9 + 45967/180 = 4663/20 K`。**厳密に一致する**
——だから §6 の golden はこれを名指しで置く。

**`°F` の offset を検算しておく**: `F = 32` のとき
`32 × 5/9 + 45967/180 = 160/9 + 45967/180 = 3200/180 + 45967/180 = 49167/180 = 273.15`
= 0 °C。**合っている。**

### 3.3 表示

**新しい表示規則を作らない。** `docs/numerical-policy.md` の「表示」節が既に持って
いる規則を**そのまま採る**:

1. **有効数字 10 桁**
2. 丸めは **round-half-to-even**
3. **`|x| ≥ 10¹⁰` または `0 < |x| < 10⁻⁹` で指数表記**
4. **整数部に 3 桁ごとのカンマ**（`1,234,567`）。小数部には入れない
   （`1,234.5678`）。指数表記の仮数・指数部にも入らない

**当初この spec は小さい側の境を `10⁻⁴` と書いていた。** 上側も 10 桁も丸め方向も
Scientific と同じで、**1 箇所だけ違う 3 つ目の規則**になるところだった——S-0 で直した
「同じ字が 2 つの意味を持つ」と同じ型の罠である。**規則は 1 つに倒す。**

**違うのは値の出どころだけである**——Scientific は `f64`、Convert は `Rational`。
**規則の文言は共有し、実装は別**（有理数から 10 進を作る経路は整数演算で書ける）。

**境の判定は丸めた後の値で行う。** `9,999,999,999.5` は丸めると `10¹⁰` に達するので、
**指数表記になる**。小さい側も同じで、丸めて `10⁻⁹` に達したら固定小数点にする。
これを決めておかないと、丸めと境の適用順で 2 通りの答えが出る（`format.rs` の
「繰り上がりで単位を再選択する」と同じ隙間である）。

### 3.4 温度は「点」である

**温度差の換算はしない。** `10 °C の差` は `18 °F の差` だが、この spec の換算は
`10 °C = 50 °F` を返す。**アフィン変換は点の変換だからである。**

これは S-4（60 進）が「**60 進は時刻ではない。`13:45` の 3 時間後は範囲外——
時点と期間を区別する型が要る**」と裁定したのと**同じ話**である。同じ答えを出す:
**区別する型が要るので、やらない**（§7 スコープ外）。

### 3.5 あふれと定義域

- 演算は `Rational` の `checked_*`。あふれたら `Overflow`
- **あふれは実際に起きる。** 係数の比が大きい換算で、入力の桁が大きいと i128 の境に
  当たる。**黙って f64 に落ちるより、`Overflow` と言うほうがよい**（base-spec §25 の方針そのもの）
  - **【訂正 2026-08-20】向きを書き足す。** ここには当初「`nm → mi` のように」と書いていたが、
    **桁の大きい整数を入れる限り `nm → mi` ではあふれない**。実測: 35 桁の整数を `nm → mi` に通すと
    分子は `1.1e34 / 1.8e11` に**縮んで** i128 に収まる。あふれるのは**逆向き**——
    `mi → nm` は分子が約 1.6×10¹² 倍に伸び、1 段目で 134 bit（i128 は 127 bit）に達する。
  - **正しい言い方は「入力の桁数と、係数の比の向きの、両方で決まる」である。**
    大きい**整数**なら**大きい単位 → 小さい単位**（`mi → nm`）であふれ、
    小数桁の多い**小さい値**なら**小さい単位 → 大きい単位**（`nm → mi`）で分母が伸びてあふれる。
    **片方だけを例に書くと、その向きでテストを書いた人が緑を見て「あふれない」と結論する。**
- 空・不正な式は `SyntaxError`（既存の式評価器の契約）
- **負の値は正当である。** `−40 °C` は `−40 °F`
- **絶対零度より下も、この spec は止めない。** `−300 °C` は計算できる。
  物理の妥当性は単位換算器の仕事ではない（**裁定として明記する。
  止めるべきだと考えるなら、それは別の裁定である**）

## §4 盤面

### 4.1 パネル

```text
┌────────────────────┐
│ [ Length        ▼ ] │  カテゴリ（U-0 の器）
├────────────────────┤
│           100 km    │  入力（式が打てる）
│    62.13711922 mi   │  結果
├────────────────────┤
│ 値 │変換元│変換先│ ⇅ │  項目行
├────────────────────┤
│  数字面 または 単位面  │
└────────────────────┘
```

**「変換元」「変換先」を押すと単位面に入れ替わる。** 単位は 11 個（Length）なので
既存の型面（11 キー）と同じ枠に収まる。

**⇅（Swap）はキー 1 つ。** 変換元と変換先を入れ替え、**入力値はそのまま残す**
（設計書 §4.2）。

### 4.2 カテゴリ

U-1 は **3 つ**（`#convert/length` `#convert/mass` `#convert/temperature`）。
残りは U-2（設計書 §37 の初期リリース範囲: Area / Volume / Speed / Data Size）。

### 4.3 値は式で打てる

`5*12` と打って `inch` を選べば `60 inch` である。**既存の式評価器を再利用する**
（§2）。足すのは**有理数のまま受け取る着地** `evaluate_to_rational` だけで、
構文解析器・小数の扱い・演算子の優先順位は 1 行も変えない。

## §5 境界

**WASM は追加のみ**（§0.0-4）:

```rust
pub fn convert(value: &str, category: &str, from: &str, to: &str) -> JsValue
pub fn convert_units(category: &str) -> JsValue   // 単位トークンの一覧
```

戻り値は素の JS オブジェクトで、**例外は投げない**（`{ text: string|null,
error: CalcErrorCode|null }`）。

**トークンの二重管理に一致テストを置く。** Rust の `Unit::ALL` と TS の
`CONVERT_UNIT_TOKENS` がずれると、**未知のトークンは黙って no-op になり、
ずれが静かに沈む**。既存の `crates/calcarc-wasm/tests/token_parity.rs` と同じ形で
検査する（`api-cleanup` の決定事項に既に書かれている規律）。

## §6 検証

**段ゲート**: 数値方針 → **Python 参照 ＋ golden** → Rust → wasm → UI。

**golden**: `testdata/convert.json`（新設、**厳密一致**）。誤差の概念が無いので
`tolerance` は持たない——`data_scale` / `finance` / `display` と同じ強さになる。

**名指しで置くケース**:

| | 何を守る |
|---|---|
| `1 in = 25.4 mm` / `1 lb = 0.45359237 kg` | 定義値そのもの |
| `−40 °C = −40 °F` | 温度のアフィン変換の**不動点**。factor と offset の両方が同時に効く唯一の点 |
| `0 °C = 273.15 K` / `32 °F = 0 °C` | offset の検算（§3.2 で手計算したもの） |
| ~~`100 km → mi → km` が**厳密に 100 km に戻る**~~ | **【訂正 2026-08-20】golden では表現できない**（下記） |
| ~~`nm → mi` で桁を上げた `Overflow` 1 件~~ | **【訂正 2026-08-20】golden では表現できない**（下記） |
| `1 nm → km`（= 1×10⁻¹² km） | 指数表記の**小さい側の境**（§3.3-3） |
| `10⁴ km → mm`（= 1×10¹⁰ mm） | 指数表記の**大きい側の境**。上側を 1 件も置かないと赤確認 4 が空振りする |
| **half-even の tie を踏む 1 件** | 11 桁目がちょうど 5 で、10 桁目が偶数のケース。丸め方向の変異（赤確認 4）はこれが無いと当たらない |
| カンマが入る 1 件（`1,234,567`） | §3.3-4。整数部だけに入り、小数部には入らないこと |

**【訂正 2026-08-20】上の 2 行は golden の行ではない。単体テストの行である。** 実測で分かった:

- **往復**: `100 km → mi` の厳密値は `781250/12573 = 62.1371192237…` で、**表示は 10 桁に丸めた
  `62.13711922`** である。これを打ち直すと `99.99999999` になり、**100 には戻らない**。
  golden は「入力の文字列 → 表示の文字列」を突き合わせる表なので、**丸めを通した往復しか置けない**
  ——そして丸めを通せば戻らない。**厳密な往復は、有理数のまま往復する単体テストが持つ**
  （Python の `test_a_round_trip_returns_exactly_where_it_started`、Rust の同名テスト）。
  なお、**表示を通しても閉じる組は作れる**（`12573 km ↔ 7812.5 mi`）が、**それは f64 でも閉じる**
  ——10 桁は f64 の 15〜17 桁よりずっと粗い。**「有理数でなければ通らない」を表示層で示すことは原理的にできない。**
- **`Overflow`**: 参照実装の `Fraction` は**無限精度で、あふれない**。i128 の境は Rust 側の
  `Rational` の性質であって、2 言語で突き合わせられる値ではない。**あふれは Rust の単体テストが持つ**
  （`a_ratio_too_wide_for_i128_is_an_overflow_not_a_wrap`）。
  **参照実装に i128 の境を書き写すことはしない**——`checked_*` の刻み方まで写すことになり、
  「参照実装を Rust の移植にしない」に反する（§0.0-2）。

**この訂正は「検査を減らす」ものではない。** どちらの主張も検査は在り、**在る場所が違う**だけである。
表が golden の表として書かれていたので、読むと 2 行だけ嘘になっていた。

**U-0 から持ち越した検査を 1 件足す。** U-0 のルーティング表は `CATEGORIES`（系統ごとに
存在するカテゴリ）と `DEFAULT_CATEGORY`（無い・知らないときの倒し先）の 2 つを持つが、
**U-0 の時点では両者を区別できない**——`scale` の唯一のカテゴリが既定値と同じ値なので、
`CATEGORIES` を空にしても振る舞いが 1 つも変わらない（Task 1 のレビューで実測）。

**U-1 は `#convert/length` を足す最初の spec なので、ここで穴が埋まる。**
`#convert/length` が**既定カテゴリとは違う値**になるケースを 1 件置き、
**`CATEGORIES.convert` を空にすると赤になること**を赤確認で実測する。
**これを書かないと、2 つの表を持つ意味が誰にも守られないまま残る。**

**赤確認**（変異前に一時コミット、戻すのは変異箇所の再編集）:

1. **【対照確認——これだけは赤にならないのが正しい】** `in` の factor を
   `127/5000` から `254/10000` に。**約分前後で値は同じ**なので緑のままになる。
   既約分数を持つ意味を機械で確かめる 1 件で、**赤確認の失敗例ではない**
   （台帳に「5 件中 1 件が緑」と記録しないこと）。**最初に走らせる**
2. **`in` の factor を 25.4 mm から 25.4001 mm に**——golden が赤
3. **温度の offset を落とす**（`°C` の 273.15 を 0 に）——`−40` の不動点は
   **factor だけでは動かない**ので、**offset を落とすと赤になる**
4. **round-half-to-even を half-up に**——境の 1 件が赤。**赤にならなければ、
   境の格子を 1 件も置いていない**
5. **基準単位を経由せず直接の係数を 1 つ書く**（`km → mi` に専用の定数）——
   値が合っていれば赤にならない。**これは §0.0-5 が構造の約束であって、
   数で守れないことを意味する**。数で守れない約束は、**レビューで守る**と明記する

**段付け**: コアなので `cargo test --workspace` は毎回。`reference` は
`uv run pytest`（`--no-config`）。UI 段で `pnpm wasm && pnpm test`、
**面の入れ替えとロールに触るので `pnpm e2e` も必須**。

**コーパス影響の宣言**: **無し。** `KEY_TOKENS` と `engine_table.rs` を触らず、
既存の WASM 署名を変えず、call シャードにも UI 走行にも `#convert` は登場しない。
**新設の `ConvertKeyToken` は Convert パネル固有の型**で、Scientific の
`KEY_TOKENS` とは別物である。

**撮る**: 390×844 と 360×640。単位面（11 キー）が枠に収まっているか、
⇅ が押せる大きさか（44px）を目で見る。

## §7 スコープ外

- **温度差の換算**（§3.4。時点と期間を区別する型が要る）
- **絶対零度より下を止めること**（§3.5。裁定として「止めない」）
- **U-2 のカテゴリ**（Area / Volume / Speed / Data Size）と**第 2 段階**
  （Pressure / Energy / Power / Time。設計書 §38）
- **通貨**（U-4。唯一ネットワークを使う）
- **`畳`**（設計書 §5 が「地域差があるため初期バージョンでは除外してもよい」と
  書いている。**除外する**。`坪 = 400/121 m²` は定義値なので U-2 で入れられる）
- **§32 の URL state**、**§36 の Favorite / Recent**
