# Scientific 入力の意味論（S2）— 設計

日付: 2026-08-13
対象: base-spec §12・§26（表示と値の分離）・§27（panic しない）。
前提: S1（外装）のマージ後。`000`・`Exp`・エコー行の**場所**は S1 が確保済みで、
本 spec は**そこにトークンを配線して有効にする**。

## §0 位置づけ — engine を触る唯一の spec

4 spec のうち、**engine の状態機械に手を入れるのはここだけ**である（S1・S3・
L・D はいずれも UI 層）。危険が 1 本に集まっているので、検証もここに集める:
`engine_table` を先に書き換え、不変条件を分析し、網羅列挙の予算を測り直す。

変更は 4 つ。**engine の遷移が変わるのは前 3 つ**で、4 つ目は表示の導出だけ。

1. 後置 `j` — 入力中の数字を虚部へ転換する（前置 `j` は併存）
2. `Exp` — 指数入力（`1.5 Exp 3` = 1500）
3. `000` — 0 を 3 つまとめて入れる
4. 式エコー行（**簡易版**。状態を増やさない。§4）

## §1 後置 j

**規則は 1 行**: 入力中の数字があれば `j` は実部と虚部を切り替える。数字が
無ければ従来どおり新しい虚部入力を開始する。

| 打鍵 | 表示 | 理由 |
|---|---|---|
| `3 j` | `j3` | 数字があるので転換 |
| `3 j j` | `3` | トグルで実部へ戻る |
| `3 j 4` | `j34` | 転換後の数字は追記される |
| `3 . 5 j` | `j3.5` | 小数入力中でも同じ |
| `1 . 5 Exp 3 j` | `j1.5e3` | 指数入力中でも同じ |
| `j 4` | `j4` | 前置 `j`（現行）はそのまま |
| `j j 4` | `j4` | 数字が無い `j` の連打は新規開始（現行維持） |
| `3 j DEL` | `j` | 数字だけ消える（現行の I7 の段構成は不変） |
| `3 j DEL DEL` | `0` | もう一度でバッファごと破棄 |
| `3 + 4 j =` | `3+j4` | 式の途中でも同じ |
| `3 j + 2 j =` | `j5` | 虚部どうしの加算 |

**トグルにした理由**: 打ち間違いを同じキーで戻せる。状態は `imaginary` の
1 ビットのままで増えない。数字が無いときにトグルしない理由は、`j` を押した
直後にもう一度押すと「実部で数字なし」= `0` という無意味な状態になるため。

**I3（実軸は演算で閉じており、虚軸への出口は 2 つだけ）への影響**: 後置 `j` も
`j` キーであり、文言は成立する。検査は「`j` 押下で確定済みの値が変わらない」を
見ており、後置 `j` はバッファ内の転換なので確定値を触らない——**実装時に
`engine_robustness` を通して確認し、通ることを報告に書く**（通らなければ検査の
ほうが正しいので設計を疑う）。

## §2 Exp

`Buffer` を仮数と指数の 2 段にする。

```
Buffer { digits, imaginary, exponent: Option<Exponent> }
Exponent { digits: String（3 桁まで）, negative: bool }
```

| 打鍵 | 表示 | 値 |
|---|---|---|
| `1 . 5 Exp 3` | `1.5e3` | 1500 |
| `1 . 5 Exp 3 +/−` | `1.5e-3` | 0.0015 |
| `1 . 5 Exp 3 +/− +/−` | `1.5e3` | 符号はトグル |
| `Exp 3` | `1e3` | 仮数なしは 1（実機と同じ） |
| `1 . 5 Exp Exp` | `1.5e` | 連打は無視 |
| `1 . 5 Exp 3 DEL` | `1.5e` | 指数の桁 → `e` → 仮数の順 |
| `1 . 5 Exp DEL` | `1.5` | `e` が消えて仮数入力へ戻る |
| `1 Exp 3 0 9 9` | `1e309` | 指数は 3 桁で頭打ち（4 桁目は無視） |
| `1 Exp 3 0 9 =` | `Math ERROR` | f64 の範囲外。**確定時に Overflow** |
| `1 . 5 Exp 3 .` | `1.5e3` | 指数は整数。小数点は無視 |
| `4 +/−` | `-4` | 指数入力中でなければ従来どおり |
| `1 . 5 Exp +/− 3` | `1.5e-3` | 桁の前に符号を押しても同じ |

- **指数の符号は既存の `+/−` ボタンで変える**（専用キーを増やさない。決定:
  2026-08-13）。規則は「**指数を入力しているあいだは指数の符号、それ以外は
  確定値の符号**」。実機の関数電卓と同じ操作感である。
  実装上は `Key::Neg` が働く階層が 2 つになる（入力中のバッファか、確定値か）
  ので、`engine_table` の行で両方を固定する——上表の `1 . 5 Exp 3 +/−` と
  `4 +/−` がその 2 行にあたる。
  なお `Exp` を押した直後（指数の桁がまだ無い）でも符号は押せる
  （`1.5 Exp +/− 3` = `1.5e-3`）。指数入力に入った時点で「指数の符号」の面に
  切り替わり、桁の有無では変わらない。
- 指数を **3 桁**にしたのは、f64 の定義域（約 1e±308）を打鍵で覆えるようにする
  ため。2 桁（1e±99）だと golden の境界ケースを手で再現できない。
- 文字数制限: 仮数は従来どおり `MAX_ENTRY_LEN`(12)、指数は別枠で 3 桁。
- 指数の**先頭ゼロは仮数と同じ規則**にする（`"0"` は次の数字で置き換える）。
  したがって `1.5 Exp 0 0 3` は `1.5e3` であり `1.5e003` にはならない。
  規則を 1 つにしておくと、`000` が指数へ入ったときの答も自動的に決まる。
- **Overflow は確定時に出す**。入力中は `1e309` と打てるが、値になる瞬間に
  `Overflow` を返す（入力の途中で赤くしない——`1e30` を打つ途中に `1e3` を
  経由するのと同じで、打鍵の途中経過をエラーにしない）。

## §3 000

`Digit` とは別のトークンにする（`Digit(0)` の 3 連ではない——押した回数と
消える回数が食い違うと DEL の段構成が壊れる）。

| 打鍵 | 表示 | 理由 |
|---|---|---|
| `1 000` | `1000` | 0 を 3 つ |
| `000` | `0` | 先頭ゼロは増えない（現行の規則をそのまま適用） |
| `0 000` | `0` | 同上 |
| `1 2 3 4 5 6 7 8 9 0 000` | `123456789000` | 残り 2 文字なので 2 つだけ入る |
| `1 000 DEL` | `100` | DEL は 1 文字ずつ（`000` は 1 打鍵 3 文字） |
| `1 . 5 Exp 000` | `1.5e0` | 指数入力中は指数へ入る（3 桁上限） |

**残り字数に収まるぶんだけ入れる**のは、制限が「文字数」であってキーの意味では
ないため。`MAX_ENTRY_LEN` を超えるぶんを黙って捨てるのは現行の `push_digit` と
同じ振る舞いである。

## §4 式エコー行（簡易版）

**状態を増やさない。** `DisplayState` に導出フィールドを 1 つ足し、既存の
`operands` / `operators` / `buffer` から「保留中の式 + 入力中の値」を組み立てる。
`STATE_SCHEMA` は据え置き、不変条件も増えない。

| 打鍵 | echo | main |
|---|---|---|
| `3 +` | `3 +` | `3` |
| `3 + 4 ×` | `3 + 4 ×` | `4` |
| `3 + ( 4` | `3 + ( 4` | `4` |
| `3 + 4 =` | （空） | `7` |
| `3 0 sin +` | `0.5 +` | `0.5` |
| `j 4 ×` | `j4 ×` | `j4` |
| `1 . 5 Exp 3` | （空。まだ保留式が無い） | `1.5e3` |

**制限**: 後置関数は押した瞬間に値へ畳まれるので、`sin 30` ではなく `0.5` と
見える。`=` で確定するとスタックが空になるので echo も空になる。

**段階方針（記録）**: 利用者は当初「`sin 30 +` のように打った通りを数学表記で、
`=` の後も残して見たい」と述べた。それには**打鍵履歴を状態に持つ**必要があり
（`sin` を押した時点で値が畳まれるため、導出では復元できない）、
`STATE_SCHEMA` の bump・履歴と AC/DEL/`=` の整合規則・不変条件の追加が伴う。
S2 の危険度がそれで跳ね上がるため、**まず簡易版を出して実使用で判断する**と
決めた（2026-08-13）。要望が残るなら、履歴版を独立の spec として起票する。

## §6 不変条件と網羅列挙

### I7（DEL は一度に 1 段だけ）

現行の段は 3 つ（バッファの文字 → `j` マーカー → 先頭の開き括弧）。`Exp` で
段が増える:

```
指数の桁 → e マーカー → 仮数の文字 → j マーカー → 先頭の開き括弧
```

**I7 の検査はこの段構成を知っているので、更新が要る**。更新後は「壊して赤を
見てから信じる」を適用する（段を 2 つ飛ばす実装に変えて赤を確認し、戻す）。

### 等価類と予算

現在は等価類 14 個・長さ 6・約 1,350 万遷移。

- **`000` は `Digit` の等価類に畳む**。どちらも「バッファに数字を足す」枝であり、
  遷移の形が同じ。`MAX_ENTRY_LEN` の境界（残り 2 文字）は個別テストで固定する。
- **`Exp` は畳めない**。バッファの構造そのものを変え、`+/−` と `DEL` の意味まで
  変えるので、独立の等価類として足す（14 → 15）。

15 個で長さ 6 は約 2,000 万遷移になる見込みで、**実測して予算に収まるか確かめる**
（現行の壁時計と、増えた後の壁時計を報告に書く）。収まらなければ長さ 5 に落とし、
長さ 6 は `Exp` を含む列に絞った重点列挙にする——**どちらを選んだかと実測値を
記録する**（次に読む人が予算を再判断できるように）。

## §7 WASM 境界

新しいトークン（`zeros3`・`exp`）を `Key::from_token` / `token()` に足す。
`crates/calcarc-wasm/tests/token_parity.rs` が Rust と TypeScript の両方への
追加を強制する——この検査の初仕事になる。

S1 で無効表示にしていた `000`・`Exp` のスロットを有効にし、エコー行に導出値を
流す。UI 側の変更はこの 2 点だけで、盤面は S1 のまま触らない。
