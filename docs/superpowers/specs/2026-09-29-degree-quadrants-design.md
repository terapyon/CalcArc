## §1 いま何が起きているか（**すべて実行役の印字。2026-09-29、`92adf99`**）

| 入力（DEG） | `sin` | `cos` | `tan` |
|---|---|---|---|
| 0 | `0` | `1` | `0` |
| 30 | `4.9999999999999994e-1` | `8.660254037844387e-1` | `5.773502691896256e-1` |
| 90 | `1` | **`6.123233995736766e-17`** | `TrigPole` |
| 180 | **`1.2246467991473532e-16`** | `-1` | **`-1.2246467991473532e-16`** |
| 270 | `-1` | **`-1.8369701987210297e-16`** | `TrigPole` |
| 360 | **`-2.4492935982947064e-16`** | `1` | **`-2.4492935982947064e-16`** |
| −180 | **`-1.2246467991473532e-16`** | `-1` | `1.2246467991473532e-16` |
| 180.0000001 | `-1.7453290920217664e-9` | `-1` | `1.7453290920217664e-9` |

**原因は `sin` の精度ではない。** **180° を `to_rad` でラジアンに直すと `f64` の π になり、
それは本当の π より小さい**——**その差がそのまま答えになっている**
（`cos(90°)` はその半分、`sin(360°)` は 2 倍、`sin(540°)` は 3 倍。**上の表がそうなっている**）。

**★ 30° はずれているが、直す対象ではない**（`0.4999999999999994`）。**画面は `0.5` と出る**
（表示は 10 桁）。**ここで直すのは「真の値が厳密に表せる角」だけ**である（§3）。

## §2 前例——**このコアには既に「度のまま特別扱いする」判定が在る**

`scientific/mod.rs:88` の `is_tan_pole`: **`mode == Deg` かつ実数のとき、
`a >= 90 && (a - 90) % 180 == 0` で極を判定**している（**度のまま、剰余で**）。
**`tan(90°)` が `Math ERROR` になるのはこれ**である。**同じ形を `sin`・`cos` に広げる。**

## §3 直し方

**DEG の実数引数だけ、90° ごとの角で厳密値を返す。**

1. `let r = x % 360.0;`（**`f64` の `%` は IEEE の `fmod` で、これは厳密**
   ——実測: `540 % 360 = 180`、`(1e10 + 180) % 360 = 100`、`(1e16 + 90) % 360 = 10`。
   **丸め誤差が入らない**ので、**大きい角でも「どの象限の角か」は正確に決まる**）
2. `r` が **0・±90・±180・±270** のいずれかなら、**表の値を返す**:

| `r` | `sin` | `cos` |
|---|---|---|
| 0 | 0 | 1 |
| 90 | 1 | 0 |
| 180 | 0 | −1 |
| 270 | −1 | 0 |
| −90 | −1 | 0 |
| −180 | 0 | −1 |
| −270 | 1 | 0 |

3. **それ以外は、いままでどおり**（`to_rad` して `f64` の `sin`/`cos`）。

**`tan` は何もしない。** `sin / cos` なので、**0°・180° では `0 / ±1 = 0`**（`finalize` が `-0.0` を均す）、
**90°・270° は `is_tan_pole` が先に `TrigPole` を返す**。**新しい決め打ちと極の判定は衝突しない**
——**担当する `r` が重なっていない**（極は 90・270、決め打ちの `tan` は 0・180）。

### §3.1 **RAD は触らない**（**推し。理由を正面から**）

**利用者が【π】【sin】と打ったとき、コアに届くのは本当の π ではなく `f64` の π** である。
**その入力に対する `sin` の答えは、本当に `1.2246467991473532e-16`** であって、
**0 ではない**。**RAD で 0 を返すのは、「入力が厳密な π だった」という嘘をつくことになる。**

**DEG は逆である**——**`180` は `f64` で厳密に表せる**。**利用者が打ったのは「180 度」そのもの**で、
**その `sin` は厳密に 0**。**ずれは私たちの変換が持ち込んだもの**だから、**私たちが直す。**

**この線引きが、この設計の中心である。** **「入力が厳密なら、答えも厳密に」。**

### §3.2 **複素の引数は触らない**

**`im != 0` なら決め打ちしない**（`is_tan_pole` と同じ形）。
**`sin(180 + εj)` は連続に振る舞うべき**で、**実部だけ 0 に寄せると、
虚部の小さい変化で答えが飛ぶ**。

### §3.3 何を直さないか（**明示する**）

- **30°・60° のような「真の値が無理数」の角**——`0.4999999999999994` はそのまま。
  **直すには丸めの幅を決める話になり、別の裁定が要る**（`numerical-policy.md` の
  「厳密一致には厳密な入力が要る」の族）。
- **`180.0000001` のような非整数**——`r` が表に無いので、いままでどおり。
- **RAD のすべて**（§3.1）。**マニュアルに 1 行足す**（検証役の案）——
  **「角度の単位が RAD のときは、【π】で入る値が本当の π ではないので、
  `sin(π)` は 0 になりません」**。**直さないことを、利用者に伝える。**

## §4 参照実装は変えない（**変えてはならない**）

**つまり「直したのに許容が広いまま」ではない**。**許容を締める話は 1.0 のあと**

## §7 裁定（**2026-09-29。4 件とも決まった**）

- **Q1（RAD）**: **触らない**（実行役の推し。検証役・監視役も同意）。
  **§3.1 の 1 文「入力が厳密なら、答えも厳密に」を、マニュアルの説明にもそのまま使う。**
- **Q2（角の範囲）**: **0・±90・±180・±270 のみ**。**45° は `√2/2` が厳密に表せない**ので、
  **決め打ちしても「厳密な答え」にならない**——**足す理由が無い。**
- **Q3（マニュアルの書き方）**: **★ 推しは半分だけ採られた。**
  **「既知の制限」から `sin(180°)` の項を消すのは可**（**直ったものは制限ではない**）。
  **しかし現象そのものは消えない**——**RAD で【π】【sin】を押すと、いまも `1.224646799e-16` が出る。**
  **DEG だけ直すので、RAD では残る。**
  → **消さずに書き換える**: 「**DEG の 0°・90°・180°・270° は 0 や ±1 になります。
  RAD で【π】を押して【sin】を押すと `1.224646799e-16` が出ます——【π】で入る値が
  本当の π ではないからです**」。**「直した」と「まだこう見える」の両方を書く。**
  **置き場**: **詳細は「既知の計算制限」に残す**（**RAD の話は制限として真**）、
  **簡易 2 冊は 1 文に畳む**（**DEG は直った／RAD は残る**）。
