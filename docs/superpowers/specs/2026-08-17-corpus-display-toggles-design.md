# 表示のトグルを検証する（段階 I）設計

2026-08-17

前提: [重量級検証コーパス（Layer 6）設計](2026-08-15-heavy-corpus-e2e-design.md)。

## 1. なぜやるか

未押下キーのうち **`eng` と `dms` の 2 個**を扱う。

**どちらも値を変えない。表示だけを変える。** だからこのコーパスの既存の仕組み
——「値を比べる」——がそのままでは使えない。**比べるのは表示文字列そのもの**になる。

**それができるのは、独立実装が既にあるからである。**

| | 参照実装 | Rust |
|---|---|---|
| 60 進 | `sexagesimal_ref.format_sexagesimal(x) -> str \| None` | `numeric/format.rs:123` の同名関数 |
| 工学表記 | **無い**（本段階で書く） | `format_real_eng`（`format.rs:81`） |

60 進は**関数の形まで一致している**（`Option<String>` / `str | None`）ので、
**文字列を突き合わせるだけ**で済む。

## 2. 実装の事実（コードから確認、2026-08-17）

| | |
|---|---|
| `eng` | 指数を **3 の倍数へ下向きに丸める**。仮数は `[1, 1000)`。指数 0 なら平坦表示に落ちる |
| `eng` の丸め方 | `div_euclid` を使う。**`/` は 0 方向に切り捨てるので負の指数で向きを間違える**（コードのコメントが名指しで警告している） |
| `dms` | 入力中は 60 進の**区切り**、入力中でなければ**表示の一時トグル** |
| `dms` の解除 | **`dms` 以外のあらゆるキーで十進に戻る**。例外なし |
| `dms` が表せない値 | **`None` を返す**（呼び出し側が通常表示に落ちるので、エラーにはならない） |
| どちらも | 保持している値を変えない |

## 3. 設計

### 3.1 比べるのは表示文字列。値ではない

新しいケースの種別 **`display`** を足す。

```json
{
  "kind": "display",
  "id": "disp-000000",
  "keys": ["3", "dot", "7", "5", "eq", "dms"],
  "expr": "3.75 を 60 進で表示",
  "expect": {"main": "3°45'0\""}
}
```

- **`expect` は表示文字列そのもの。** 数ではないので許容誤差の概念が無い
- **厳密一致で比べる。** `parseDisplay` を通さない——あれは実数の書式の契約で、
  60 進も工学表記もその外にある
- **`parseDisplay` を広げない。** 広げると「数として読める文字列」の定義が
  緩み、**壊れた表示を黙って通す余地が生まれる**（あの契約は狭いことに価値がある）

### 3.2 期待値の出どころ

| キー | 期待値をどう作るか |
|---|---|
| `dms` | **`sexagesimal_ref.format_sexagesimal` をそのまま呼ぶ。** Rust と関数の形まで一致しているので、そのまま突き合わせられる |
| `eng` | **本段階で参照実装を書く。** `Decimal` で仮数と指数を出し、指数を 3 の倍数へ**下向きに**丸める |

**`eng` の参照実装は Rust の移植にしない。** Rust は
`format!("{:.*e}", ...)` で一度整形してから指数を読み直す。**参照側は
`Decimal` の指数を直接使う**——同じ答えに別の道で着く。

**`div_euclid` の罠は参照側でも起きる。** Python の `//` は**負の無限大方向**に
丸めるので `-1 // 3 == -1` で正しいが、**`int(-1/3)` は `0` になる**。
**`//` を使い、`int()` を経由しない。**

### 3.3 「押しても値が変わらない」を同値ケースで確かめる

表示のトグルは値に触らない。**それ自体を主張にできる:**

```
左: <式> eq
右: <式> eq eng eng        （2 回押すと元の表示に戻る）
```

`dms` も同じ形が使える。**Python は介在しない**——engine の自己整合である。

**`dms` は「あらゆるキーで解除される」ので、別の形も作れる:**

```
左: <式> eq
右: <式> eq dms 0 del      （dms で覗いて、何か押して戻す）
```

**ただしこれは `del` が要る**ので、段階 G に依存する。

### 3.4 `eng` は表示を変えるので、既存の照合と衝突しうる

**`eng` は押されたまま残る**（`Notation` は状態に載り、`AC` でも保たれる）。
つまり**同じ走行の中で `eng` を押すと、以後のケースの表示が変わる**。

harness は**ケースごとに `engine.initial()` を呼ぶ**ので、
実際には持ち越さない。**その事実に依存していることを明記する**——
harness が状態を持ち越す作りに変わったら、このシャードは黙って壊れる。
**「ケースごとに初期状態から始める」ことを主張するテストを置く。**

## 4. やらないこと

- **`parseDisplay` を広げない**（§3.1）
- **60 進の入力モード**（`1 dms 3 0` のような打ち方）。これは**入力**の話で、
  入力モードが 3 つで相互排他という構造ごと扱う必要がある。別段階
- **`polar_toggle`**——複素数と一緒に扱う（段階 J）
- **既存シャードを作り直さない**

## 5. 要件

- **R1** ケースの種別 `display` を新設。`expect.main` は**表示文字列**
- **R2** 比較は**厳密一致**。`parseDisplay` を通さない・広げない
- **R3** `dms` の期待値は `sexagesimal_ref.format_sexagesimal` から取る
- **R4** `eng` の参照実装を**新しく書く**。`Decimal` の指数を直接使い、
  **Rust の「一度整形してから読み直す」手順を写さない**
- **R5** 負の指数の丸めは **`//`（負の無限大方向）**。`int()` を経由しない
- **R6** 「2 回押すと戻る」の同値ケースを作る
- **R7** harness が**ケースごとに初期状態から始める**ことを主張するテストを置く
- **R8** レポートの未押下キーが減ることを実データから示す
- **R9** 再生成一致ゲートの対象に含める

## 6. リスク

- **`dms` が `None` を返す値がある**（表せない大きさ）。そのとき engine は
  通常表示に落ちる。**参照側の `None` と、engine の「通常表示」を突き合わせる**
  必要があり、**`None` を「どちらも何もしない」と読むと検査が消える**
- **`eng` の指数 0 は平坦表示に落ちる。** `format_real_eng` が
  `e0` を出さない分岐を持つので、**参照側も同じ判断を独立に持つ必要がある**
  ——ここは「同じ結論に別の道で着く」ことを確かめる場所である
- **表示文字列の比較は書式の変更に弱い。** 3 桁区切りが入ったときのように、
  **書式が変われば全件赤くなる**。それは仕掛けとして正しいが、
  **件数が多いと原因が読みにくい**ので、失敗の報告に「何件が同じ形で違うか」を出す
