# API スタイルガイド

命名と API 形状の判断基準。issue 単位で議論を再燃させないためにここに集約する。

## 原則

**std の慣習は「名前の嘘」を直すために採り、ドメイン語彙を消すためには採らない。**

- 名前の嘘 = 名前が std の契約や意味を偽っているもの。直す。
  例: Option を返さない `pop()`、述語に見える関門 `finite()`、
  `f64::to_radians` と同名で別動作のメソッド
  （いずれも 2026-08 の API 整理で解消済み。歴史的例）。
- ドメイン語彙 = 設計書・base-spec が定義した概念を指す名前。守る。
  例: `token`（境界トークン）、`sqr`（x² キー）、`CalcError`、
  `to_polar`/`from_polar`、`Buffer::text`（打鍵エコー）。

## 個別規約

- **Error 型**: クレート接頭辞付き（`CalcError`/`CalcResult`）を維持する。
  無修飾 import でも曖昧にならないことを優先する。
- **From/Into**: 「意味を持たない機械的変換」にのみ実装する。意味のある
  操作は名前付き関数にする（`to_polar` は From にしない）。
- **Display trait**: 値に正規の文字列表現が 1 つあるときだけ実装する。
  UI エコーや文脈依存の文字列化は名前付きメソッド（`text()` など）。
- **import 方針**: flat import（`format_real` を直接 use）を維持する。
  モジュール修飾呼び出しへの寄せ替え（`format::real()`）はしない。
  この帰結として `format_*` の接頭辞は残す（flat import で使う以上、
  接頭辞が無いと `real()` だけでは何の実数か読めない）。
- **述語**: `is_` / `has_` で始める。検査して返す関門は動詞で始める。
- **可謬な操作**: **std の名前を借りていて、かつ std のそれが失敗しないなら、
  `try_` を付ける**（`Vec::push` は `()` を返して失敗しないので、
  `push_…() -> bool` は「押せなかったことがある」を名前が隠す）。
  **std の名前でないものには付けない**——`toggle_…() -> bool` は偽っている
  契約が無く、戻り値も失敗の合図ではなく割り振りである。
  `try_` が `Result` ではなく `bool` を返してよいのは、**断る理由が呼び出し側に
  とって 1 つしかない**ときに限る。
- **`#[must_use]`**: **戻り値が唯一の合図であるとき**に付ける（可謬な操作の
  成否、どちらが処理するかの割り振り）。**値を返すだけの関数には付けない**
  ——crate 全体で 2 件、という状態を保つ。付けた日に既存の 2 行が
  「戻り値を捨てている」で落ちた（2026-08-28）ので、**これは飾りではない**。
- **スタッター**: `module::module()` の形を避ける（関数名の変更で解消する。
  From 化は上の規約により不採用）。**例外は下に 1 つだけある。**
- **スタッターの例外**: 次の 2 つを**同時に**満たすときだけ許す。
  **片方でも欠けたら関数名を変える**（上の規約に戻る）。
  1. **モジュール名がそのままドメイン語彙である**——設計書か base-spec が
     その語で概念を定義している。
  2. **flat import したとき、関数名だけで意味が立つ**——`convert("1",
     Category::Length, Unit::In, Unit::Mm)` は立つが、`between("1", …)` は
     立たない。
  **認めたのは `convert::convert` の 1 つだけ**（ユーザー裁定 2026-08-28）。
  **避けようとすると、この文書の 2 つの規約が正面から衝突する**からである
  ——「スタッターを避ける」と「flat import を維持する（**だから `format_*` の
  接頭辞を残す**）」。後者はこの文書が `format_*` について明示的に選んだもので、
  `convert` はまったく同じ形である。
  **代償を引き受けること。** モジュールを `use` する側は別名が要る
  ——`calcarc-wasm/src/lib.rs` は `use calcarc_core::convert as convert_core;`
  と入れて `convert_core::convert(…)` と呼んでいる（そこの註が実例）。
  **flat import の方針を、そこ 1 か所だけ曲げている。** 例外を認めるとは、
  この曲がりを引き受けることである——**呼ぶ側が 1 か所なら安いが、
  増えるなら関数名を変えるほうが安い。**
- **コンストラクタ / `Default`**: ドメイン語彙の生成関数（`EngineState::initial()`
  = 電源投入時の状態）があるとき、`Default` を重ねない。生成点が 2 つになるうえ、
  `Default` の不在は名前の嘘ではない。`mem::take` 等で実需が生じたら再考する。
- **玄関（crate root の再エクスポート）**: 利用側が状態機械を回すのに要る一式
  （`Value` `CalcError` `CalcResult` `AngleMode` `Key` `EngineState`
  `DisplayState` `reduce` `render`）だけを置く。最上位モジュールの型
  （`polar::Polar` など）は上げない——モジュール名が既に玄関である。
  ネストが実装都合であるもの（`engine::` の中身）だけを引き上げる。

## 運用

迷ったらこの基準で判断し、判断したらこのファイルに追記する。
基準で説明できない変更提案は「好み」であり、現状維持とする。
