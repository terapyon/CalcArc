# CalcArc

**[日本語](README.md)**

A suite of calculation tools that run in the browser: a scientific calculator, a data-size calculator, and a finance calculator.
Calculations complete entirely on-device; nothing is sent to a server.

## ▶ Try it

**https://calc.terapyon.net/**

No installation needed. Add it to your home screen to launch it like an app — it also works offline.

## What it can do

### Scientific — a scientific calculator

In addition to the four arithmetic operations, parentheses, and sign flip:

- **Complex numbers and polar conversion.** Type `3 + j4` and convert it to `5 ∠ 53.13010235`
- `sqrt` `x²` `xʸ` `1/x` `eˣ` `ln` `log`, and trigonometric / inverse trigonometric functions.
  **Functions are closed over the reals** (inputs whose real answer is not uniquely determined
  return an error)
- `n!` `nPr` `nCr` (defined only over non-negative integers)
- **Sexagesimal (base-60) input and output** (`°'"`). Usable for both elapsed time and angles.
  An angle entered in degrees-minutes-seconds can be fed directly into `sin`
- ENG (engineering notation), thousands separators, Degree / Radian

### Data Scale — data-size calculation

From element count × dimensions × data type, it computes the required memory in both decimal
(KB / MB / GB / TB) and binary (KiB / MiB / GiB / TiB) units. It's meant to give a sense of
scale for vector search and machine learning workloads.

### Finance — financial calculations

- **Loan** (equal principal and interest) — monthly payment, borrowable amount, and reverse
  calculation of repayment period. It also supports residual value and bonus payments
  (**residual value only works in payment mode. Bonus payments don't work in term mode.
  In payment mode, only one of the two — residual value or bonus — can be used**)
- **Compound interest** — lump-sum deposit and monthly contributions. You can choose whether
  tax (separate withholding tax) applies
- **Reverse compound-interest calculation** — from a target amount, the required contribution
  amount, or the required number of years

**Matching the exact figures of any particular lender is not a goal.** The value returned is
a deterministic approximation (the screen also carries a standing disclaimer).

## Characteristics

- **Completes entirely on-device.** Entered numbers are never sent externally for calculation
  purposes
- **Calculation history stays on the device.** The Scientific calculator saves up to 50
  completed calculations (expression, answer, and angle mode) to `localStorage`. Recording
  can be turned off from the history screen (`Shift` then `hist`; on by default, and turning
  it off keeps what's already saved). Delete entries from the same screen — one at a time,
  or all at once
- **PWA.** Can be added to the home screen and works offline
- **The calculation core is Rust, and runs as WebAssembly in the browser**
- **Verified with an independent Python implementation.** Rather than relying only on Rust's
  tests, results are checked against expected values generated by a separate implementation
  using SymPy / mpmath / `decimal.Decimal`. Writing the same algorithm in both would let the
  same bug slip into both, so **the implementation approach is deliberately different**

## Questions, Requests, and Bugs

**Please use [Issue](https://github.com/terapyon/CalcArc/issues).** Either Japanese or
English is fine.

When reporting a bug, it helps to include **the keys you pressed, in order** (e.g., `3 + 4 =`).
This project has a table mapping key sequences to display output as its test suite, so
**a report in that form becomes a test case as-is**. The issue template prompts for this.

## Numerical Policy

The handling of numbers is defined in [docs/numerical-policy.md](docs/numerical-policy.md).
The main points:

- **Numerical handling differs per module.** Scientific uses floating point, Data Scale
  uses exact integers, Finance uses a deterministic approximation
- **Scientific** holds every value as a complex number. Real numbers are complex numbers
  with zero imaginary part. Display uses 10 significant digits, and rounding is
  round-half-to-even
- **Data Scale holds its internal values as exact integers (`u128`).** Rounding happens
  only at display time
- **Finance returns a deterministic approximation.** Matching the exact figures of any
  particular lender is not a goal — how repayment amounts get rounded differs by
  institution. **Only the monthly payment is decided in floating point; the amortization
  schedule is exact-integer.** See [docs/numerical-policy.md](docs/numerical-policy.md)
  for details
- **Expressions typed into the Finance and Data Scale fields are not rounded partway
  through.** They are evaluated as a rational number and rounded exactly once at the end,
  so entering the same answer via a different sequence of keystrokes does not change the
  result
- **Rounding done for display is not written back into the held value.** Switching to
  polar form is a display change, not a calculation, so the rounded value never leaks into
  the next calculation
- **The calculation core does not panic.** Every error passes through `Result` and reaches
  the UI as a return value

## Development

Required: Rust (stable), wasm-pack, Node.js + pnpm, uv.

```bash
# Calculation core tests
cargo test --workspace

# WASM boundary tests
wasm-pack test --headless --chrome crates/calcarc-wasm

# Web (on a fresh clone, run pnpm wasm first)
cd web && pnpm install && pnpm wasm && pnpm dev

# Regenerate the reference implementation's expected values
cd reference && uv sync && uv run pytest
cd reference && uv run python scripts/generate.py
```

When you change a number in `crates/calcarc-core`, the expected values need to be
regenerated. **Do not hand-edit `testdata/` instead of regenerating it.**

When bumping the version number, set the same value in **six places** —
`Cargo.toml`, `Cargo.lock` (both `calcarc-core` and `calcarc-wasm`),
`web/package.json`, "Current version" in `README.md`, "Current version" in this
file, and the heading in `CHANGELOG.md`. `pnpm check:version` checks all six.
**When a tag is pushed, CI additionally requires the version numbers to match
the tag name, and the CHANGELOG heading to carry a date rather than "未リリース"
(unreleased).**

For more detail, see [CONTRIBUTING.md](CONTRIBUTING.md) and
[docs/base-spec.md](docs/base-spec.md) (the overall specification).
